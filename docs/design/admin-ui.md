# 管理画面の UI の決まり

運営の管理画面（`resources/admin`）の見た目と操作の決まり。画面を足す・直すときはこれに従う（ADR 0017）。
下敷きはベイジ「管理画面の UI デザインにおける 25 の改善ポイント」（2024 年 6 月バージョン）。各項目の末尾の（ベ n）はその番号。

方向: **モダンで統一感があり、清潔な、落ち着いた業務ツール**（見本 A′ を運営が選んだ）。PC から作り、スマホは崩れない程度に留める（スマホの作り込みは保留）。
2026-10-29 に見た目を明るく軽くした: 少し濃い灰の地に、浮かせた角の丸い白いメニューの板と白い大きなカードを、輪郭も影も付けずに置く。広い余白・太い見出し。決めの色は藍のまま。
2026-10-30 にメニューの骨組みを案 C（よく使うものだけを上に並べ、残りは設定の下にまとめる）にした: 主なメニューはホーム・注文・商品・写真・デザイン・App、下に「設定 ›」とヘルプ。運営全体は店の切り替えの中から（4 章）。

## 1. 仕組み

- CSS は **Tailwind CSS v4**。ビルドの時だけ動き、静的な CSS を出す（本番で Node.js を常駐させない。ADR 0015）
- 見た目の値は `resources/admin/admin.css` の**トークン**（CSS の変数）だけ。色の値・Tailwind の既定の色（`bg-blue-600` など）・その場限りの色（`bg-[#…]`）を画面に書かない（`AdminShellTest` が落とす）
- Tailwind のクラスは **`components/ui` の部品の中**に書く。各画面（`pages/`）に書いてよいのは**並べ方のクラスだけ**（flex・grid・gap・col-span・幅・高さ・余白・位置・左右の揃え・表の `num`）。色・文字・角丸・影を画面に書くと `AdminShellTest` が落とす。部品に無い見た目が要るときは、部品を足すか直す
- インラインの style・`v-html`・外部の URL・ブラウザの保存領域は使わない（CSP と Trusted Types で止まる。ADR 0016）

## 2. トークン

| 種類 | 名前 | 使いどころ |
|---|---|---|
| 面 | `canvas` / `surface` / `subtle` / `hover` / `selected` / `line` / `line-strong` | 地（灰）/ 白いカードと板 / 入力欄・バッジ・カードの中の小さな面 / ホバー / メニューの選択中 / 行の区切り / 枠 |
| 文字 | `ink` / `ink-muted` / `ink-soft` / `ink-faint` | 本文 / 項目名 / 補足 / 飾りと「0」だけ |
| 差し色 | `accent`（藍）/ `accent-hover` / `accent-soft` / `on-accent` | 主なボタン・選択中・リンクだけ。面を塗らない |
| 状態 | `ok` / `warn` / `danger` / `idle` と各 `-soft`・`-ink` | 状態の丸、お知らせ |

- 色は「地・文字・差し色 1 つ」が基本。状態の色は小さな丸とお知らせだけに使う（ベ 3）
- 文字と地の組み合わせは WCAG AA（4.5:1）。ライトとダークの両方を `AdminContrastTest` が検査する
- ダークモードは同じ名前の値を入れ替えるだけ（`prefers-color-scheme`）。画面ごとの `dark:` は書かない
- 余白は 4px 刻み（基本は 8 の倍数）。中身の左右は `gutter`（40px）、大きなカードの中は `card`（32px）
- 角丸は 8px（ボタン・入力欄）、`rounded-board`（16px、メニューの板）、`rounded-card`（20px、カード・ログインの枠・エラーの画面）
- 影は使わない（地の色との差で分ける）。例外は画面の下に浮かせるツールバー（`shadow-float`）と、押して開く小さな窓（店の切り替えの中。`shadow-pop`）だけ
- フォントは OS 標準（Mac はヒラギノ、Windows はメイリオ / Segoe UI）。Web フォントは使わない（ベ 21）。数は等幅（`tabular`）

## 3. 部品

|---|---|---|

| `AppPanel` | 内容のまとまり | 白い大きなカード（角 20px、線も影も無し）。`title`・`description` と `#actions` で欄の見出し（16px の太字）と右上の操作 |
| `InsetSection` | パネルの中の小さなセクション | 細い輪郭で囲む。`as="form"` でフォームにもなる |
| `SearchSnippet` | 検索の結果の見え方のプレビュー（ADR 0061） | 白い地に細い輪郭。上に「検索の結果の見え方（目安）」、URL（小さく 1 行）・タイトル（藍、1 行で切る）・説明（2 行で切る）。値は呼ぶ側が作る（`SeoFields`） |
| `SeoFields`（`components/`） | 「検索と共有」の欄（ADR 0061） | 「検索の結果に出すタイトル」（`AppInput`）と「検索の結果に出す説明」（`AppTextarea`。改行を打つと空白に替える）を `layout="row"` で並べ、下に `SearchSnippet`。空なら自動（`fallback-title`・`fallback-description`）で、欄の下の説明に自動の元（`auto-note`）と文字数（目安はタイトル 30・説明 120。超えたら「切れることがあります」）。タイトルには「 \| 店の名前」を付けて見せる（トップは `:suffix="false"`）。上限（タイトル 70・説明 200）は `maxlength` とサーバー。商品・カテゴリ・ページ・設定 › SEO で同じ部品 |

## 4. 画面の骨組みと流れ

- 左のメニュー（畳める。ベ 12）と中身。メニューは灰の地に浮かせた白い板で、選択中は灰の面・太字・藍のアイコン。メニューは**対象**で並べる（ベ 5）
- メニューの板の並び（案 C）: いちばん上に製品名と店の切り替え（`ShopSwitcher`）、その下に主なメニュー（**ホーム・注文・売上・お客さん・商品・クーポン・写真・デザイン・App**、続けて「ショップを開く」。お客さんは で注文の隣に、クーポンは で商品の下に、売上は で注文の下に〔会計の段階の人だけ〕足した）、下の区切り線の下に**「設定 ›」とヘルプ**、いちばん下に自分（名前・パスキー・ログアウト・バージョン）
  - 項目の中の画面はタブで: 商品＝商品の一覧・カテゴリ、デザイン＝テーマ（今のテーマとほかのテーマのカード）・ページ（自由なページ）。ページの編集の画面（全画面）はデザインの中から入る
  - **運営全体（運営ダッシュボード・店の一覧・メンバーと権限・App とテーマ・ログインの履歴）は店の切り替えの窓の中から**。店の中のメニューに混ぜない
  - **できた画面だけをメニューに出す**。画面のまだ無いものは設定の目次の「近日」のバッジだけ
- **メニューの項目は `resources/admin/navigation.js` の 1 か所で決める**（名前・アイコン・行き先・まとまり・見るのに要る段階・中のタブ・設定の目次・運営全体・ヘルプのページ）。メニュー・店の切り替えの窓・設定の目次・タブ・パンくず・画面のタイトル・ブラウザのタブのタイトル（店の中では店の名前つき。「画面 — 店 — EC-SUGAR 管理」）はここから作り、画面ごとにコピーしない
- **設定**: 「設定 ›」で設定の目次の画面（まとまりごとのカード）へ。項目を選ぶと、広い画面では横に目次を開いたまま 1 項目 1 画面（`SettingsLayout`）。目次は **ショップ**（基本・特商法の表記・注文の案内・注文の項目〔ADR 0066。上に項目の一覧〔`AppTable` の `stack`。名前と説明は `CellTitle`、種類、「使う／使わない」「必須」「注文に使われた」の `StatusBadge`、行ごとに上下の並べ替え〔アイコンだけの `AppButton`、`aria-label` に項目の名前〕・「直す」・「消す」〔`ConfirmButton`。注文に使われた項目には出さない〕〕、下に「項目を足す／直す」のフォーム〔名前・説明・種類〔`AppSelect`〕・選ぶの選択肢〔`TagInput`〕・必須と使う〔`AppCheckbox`〕〕。上限は応答の `limits` から〕）／**お金と配送**（支払い・配送と送料・お届け日時〔ADR 0059。日付の指定を受けるか〔`ChoicePills`〕・受ける時間帯と休みの曜日〔`AppCheckbox` の並び〕・発送までの日数・お届けまでの日数・選べる日数・締め切りの時刻・休みの日〔`TagInput`。`2026-12-29` の形〕。欄の下に「今注文すると ◯から◯までを選べます」の見本をサーバーの計算で出す〕・税率〔近日〕。税率は今は商品ごとに商品の登録の「税率」で決める。ADR 0063）／**App**（使う App。店の App の画面へ・同意バナー〔。解析・広告のタグを同意したお客さんにだけ読み込むか。「出さない」「出す」の 2 つから選び、選んだ方の説明を欄の下に出す。既定は出さない〕）／**記録**（記録の確認・メールの記録〔ADR 0095。一覧の型〔`ListFilters` に状態と種類の `FilterSelect`〕で、送れなかったものは `StatusBadge` の `danger`、この 7 日に送れなかったものがあれば上に `AppNotice` の `error`。「開く」で 1 通の状態〔理由の説明の `AppNotice`・`DescriptionList`・注文とお客さんへの `CellTitle`〕、宛先は運用からの「宛先を見る」、下に「テストメールを送る」〕）／**AI**（AI エージェント〔ADR 0100。自分の AI エージェントから MCP で店を読み取り用のアクセスキー。上から、作った直後だけの鍵のバナー〔`CodeBlock` の `select-all` と「鍵をコピー」・「控えたので閉じる」。鍵は画面の中の値にだけ置き、閉じる・画面を離れると捨てる〕・鍵を作る〔名前・店〔見られる店が 1 つなら出さない。今の店が先〕・期限〔`ChoicePills` の 30・90・180・365 日、既定 90〕。送るとサーバーが直前の再確認を求める〕・作った鍵〔`AppTable` の `stack`。名前と店〔オーナーにはほかの人の鍵も持ち主の名前つき〕・鍵の頭の 8 文字・最後に使った日時・期限・状態〔使える・期限切れ・取り消し済み〕・取り消す〔`ConfirmButton`。済んだら読み直す〕〕・接続方法〔MCP の URL は画面のオリジン ＋ `/mcp`。ターミナルの `claude` コマンド・HTTP の設定のファイル・Claude Desktop の例。例の鍵は「ここに鍵」〕・読めるものと渡さないもの。どの運営にも出す〕）。各画面は長いフォームの型（`AppField` の `layout="row"`、`FormActions` の `sticky`）。テーマの選択は「デザイン」、説明のページは「ヘルプ」
  - 前の URL `/settings/publish`（ショップの公開）は `/settings/basic` へ送る。Stripe の登録の画面からの戻り（`/settings?stripe=…`）は支払いの画面へ
- **ヘルプ**: `/help` に説明のページの目次と、ヘルプの中を言葉で探す欄。説明のページは `/help/<名前>`（パンくずは「ヘルプ / ページ」）。店をまたいで同じなので店の外の画面。中身の決まりは下の「ヘルプ（説明のページ）」
- 段階での出し分け: 読む API が断る（403）段階の人には、その項目をメニューに出さない。読める画面は出し、変えるボタン（保存・登録・足す）は段階が足りなければ出さず、欄は押せなくして「〜の権限の人だけです」と添える。見た目のためだけで、守るのはサーバー（ADR 0014・0024）
- **App が持つ画面**（ADR 0051。定期便の一覧など）は、使っている App ごとに主なメニューの「App」のすぐ下に 1 行（字下げ）で出す。店ごとに変わるので、項目は店の応答（`GET …/app-pages`）から作る（4 章の「App が持つ画面」）
- 階層は「店を選ぶ → 店の中のメニュー」の 2 階層まで（ベ 6）。今いる場所はメニューの印・タブの印・パンくずで示す（ベ 19）。パンくずは「店の一覧 / 店 / 項目 / 画面」（見られる店が 1 つなら「店の一覧」を出さない）
- 画面の言葉: プラグインは「App」、テナントは「店」（docs/design/terms.md）。注文の一覧と詳細は、タイトルも中の言葉も「注文」（コードの名前 `Transaction` と API のパス `/transactions` はそのまま）。会計の言葉（仕訳・勘定・フェーズの名前）はそのまま
- 画面の流れは全体でそろえる（ベ 25）: **一覧（絞り込み・検索・並べ替え）→ 詳細＝編集 → 一覧に戻る**。登録は一覧の右上の主なボタンから。削除は詳細の画面で、確認してから
- 一覧の絞り込み・検索・並べ替え・ページは URL に持つ（戻る・共有で同じ表示になる）

### 一覧の型

注文・商品の一覧で決めた形。ほかの一覧（店の一覧・メンバー・App）も表は `stack`、空はアイコンつきの `EmptyState` にそろえた。

- **上に絞り込みの箱**（`ListFilters`）: 言葉で探す（`SearchField`。Enter で探す・`/` で検索欄へ）・状態で絞る（`FilterSelect`。選択肢に「入金待ち（2）」の形で件数）・並べ替え（`FilterSelect`。見出しの並べ替えと同じ候補）・件数・「条件を外す」（言葉・状態・ページを外し、並べ替えは残す）。箱は読み込みの間も出す
- **条件は URL に**（`resources/admin/listQuery.js` の `useListQuery`）: `?q=`・`?status=`・`?sort=`・`?page=`。決まった候補だけを使い、知らない値は既定に戻す（サーバーも同じ候補で確認する）。戻る・進むで URL が変わると、検索欄の文字も URL に合わせる。「/」で検索欄へは `useSearchShortcut`
- **状態のバッジ**: 行の状態は `StatusBadge`（丸の色と文字。色だけで伝えない）
- **まだ 1 件も無いとき**（絞り込んでいない・すべて 0 件）: 箱も表も出さず、`EmptyState` にアイコンと次にやることのボタン（主なボタン）。商品は「商品を登録する」（運用の段階から。足りない人には権限の一言）、注文は「ショップを開く」（新しいタブ）。**同じボタンを見出しの右上（`PageHeader` の `#actions`）に重ねて出さない**（真ん中の 1 つだけ。2026-10-30、運営の判断）。右上に出すのは、1 件以上あるとき（絞り込んで 0 件のときも）。読み込む前は出さない（空の店で一瞬出て消えないように）、読めなかったときは出す
- **絞り込んで 0 件のとき**: 箱は残し、表の代わりに `EmptyState`（アイコンは虫眼鏡）で「条件に合うものがありません」と「条件を外す」
- **狭い画面（390px）**: 表はカードの並び（`AppTable` の `stack`）。見出しが隠れるので、並べ替えは箱の選択で。画面の横にも、表の中でも横に動かさない
- 注文の一覧: 言葉は注文番号（ID の先頭）か商品名の一部。状態は物販の対応の状況（入金待ち・入金済み・受付済み・発送済み・完了・注文取消し・返金。API の `order_status` と `order_counts`）。商品の一覧: 言葉は商品名か品番、状態は下書き・公開中・終了。列は商品・状態・価格・税率（`tax_rate_bp` を「8%」の形で。ADR 0063）・在庫・確保済み
- **隔離した複製環境のバナー**（ADR 0082）: 本番のバックアップを確認のために立てた複製環境（`/auth/me` の `isolated` が true）では、骨組み（`AppShell`）の中身のいちばん上に、どの画面でも `IsolatedCopyNotice`（`AppNotice` の warning・`:live="false"`）で「これは確認のための複製環境です（本番のバックアップから立てたもの）。メール・支払い・外への通知は送られず、定期の処理も止めています。確認し終わったら複製環境ごと消します。」。消すボタンは置かない（複製環境である間ずっと出す）
- **商品の一覧のサンプルのバナー**: 入れたときのサンプルの商品が残っている間だけ、見出しのすぐ下に `AppNotice`（info・`:live="false"`）で「サンプルの商品が n 点あります。ご自分の商品を登録したら、まとめて消せます。」。数はホームと同じ `GET …/setup` の `samples.remaining.listings`（閲覧の段階から読める。読めなければバナーを出さないだけ）。「サンプルをまとめて消す」は**オーナーにだけ**（ほかの人には「消せるのはオーナーだけです。」）。確認・直前の再確認・結果の文はホームの開設の手順と同じ部品（`samples.js` の `useSampleRemoval`・`SampleRemoveButton`・`SampleRemovalNotices`）。消したらバナーは消え、一覧を同じ条件で読み直す
- 店の App（プラグイン）も同じ流れ: App の画面（目的ごとのカードの並び。下の「App の画面の型」）→ App ごとの画面（使う・使わないの切り替え・設定の欄・外部送信の公表・保存）。設定の欄は App の画面に出さない。使っていないプラグインの設定も保存でき、その間は「この店では使っていません」と通知する（`AppNotice` の `:live="false"`）。入っていない名前は `ErrorState` の 404 と一覧への戻り
- ショートカット: `/` で検索へ（入力中は奪わない。ベ 14）

### App の画面の型

店の App（`/tenants/{店}/plugins`、`TenantPluginsPage`）。**目的ごとのまとまり**にカードで並べる（買取・定期・予約などの App が増えても、まとまりが増えるだけで崩れない）。

- **目的の言葉と並びはサーバーが返す**（`GET …/plugins` の `categories`。コアの `AppCategory`。画面にコピーしない）。App ごとの目的は `plugins[].category`（マニフェストの `category`。書かなければ `other`）。App の無いまとまりは出さない。知らない目的は「そのほか」へ。まとまりごとのアイコンは画面の `CATEGORY_ICONS`
- **まとまり**は `AppPanel`（タイトルは目的の名前・説明は目的の一言・右上に「n 個」）。中は `PluginCard` の格子（狭い画面 1 列・sm 2 列・xl 3 列）。まとまりの中は名前の順（API の順）
- **カード**: 名前・一言の説明・「使う／使わない」のカード・設定がそろっているか（設定のある App だけ。そろっていれば「設定済み」、まだなら「設定がまだ」。使っているのにまだなら警告の色で「設定がまだ（動いていません）」。判定はサーバーの `settings.complete`）・使う・使わないのボタン（運用の段階から。足りない人には上に一言）。カードを押すと App ごとの画面へ
- **上に絞り込みの箱**（一覧の型の `ListFilters`）: 言葉で探す（名前・説明・目的の名前・App の名前に含まれるか。Enter で）と「この店では」（すべて・使っている App だけ・使っていない App。件数つき）。条件は URL（`?q=`・`?status=enabled|disabled`。`useListQuery`）。App は多くても数十なので、絞り込みは画面の中で行う（API は全部を返す）
- **空**: App が 1 つも入っていなければ、箱を出さず `EmptyState`（差し込みのアイコン）。絞り込んで 0 件なら箱を残して `EmptyState`（虫眼鏡）と「条件を外す」。使っている App が 1 つも無い店で「使っている App だけ」にしたときは「この店で使っている App はまだありません」と、カードの「使う」を押すと出ること
- 使う・使わないの切り替えは、今までどおり `PUT …/plugins/{名前}`（運用の段階・直前の再確認）。ボタンはカードが並ぶので主な操作の色にしない（「使う」は `secondary`、「使わない」は `ghost`）

### App が持つ画面（ADR 0051。定期便の一覧など）

App が管理画面に持つ一覧と 1 件の画面（`/tenants/{店}/apps/{App}` の `AppRecordsPage` と `…/apps/{App}/{ID}` の `AppRecordPage`）。**中身（タイトル・絞り込みと件数・列・行・事実・表・操作）は App が API で渡し、描くのはコアの部品だけ**（App の画面のコードは管理画面に読み込まない）。API の形は `app/Core/Plugin/Services/AdminPages.php` の説明。

- **メニュー**: 使っている App のうち画面を持つものを、主なメニューの「App」のすぐ下に 1 行ずつ（字下げ。アイコンは一覧の印）。並びは店の応答（`GET /api/tenants/{店}/app-pages`。`resources/admin/appPages.js` が店ごとに 1 回読む）。メニューの定義（`navigation.js`）には形と作り方（`appPageItems`）だけを置き、店の応答は引数で渡す（ほかを読み込まない決まりのため）。経路は App をまたいで 2 つなので、今いる項目は App の名前で決める（`isCurrentItem`）。App を使う・使わないを切り替えると読み直す（読み込み直さなくても出る・消える）。読めなければ項目を足さないだけ
- **タイトルとパンくず**: 見出しは App の名前（1 件の画面は App の渡す見出し）。パンくずは「… / 店 / App / App の名前 / 1 件の見出し」。ブラウザのタブのタイトルは App の名前
- **一覧**: 上の絞り込みの箱（`ListFilters`）の中に、状態のタブ（`SegmentedTabs`。件数つき。7 個を超える App は `FilterSelect` に替える）と件数。表は列の順（`AppTable` の `stack`）。最初の列が文・数・金額・日付なら、その欄を行の名前（`CellTitle`）にして 1 件の画面へ。状態のバッジやリンクの列から始まる App は、行の終わりに「開く」。絞り込みとページは URL（`?filter=`・`?page=`。形の合わない値は使わない。知らない絞り込みはサーバーが 404）。どの絞り込みも 0 件なら箱も表も出さず「まだ〜はありません」、選んだタブが 0 件なら「「〜」の〜はありません」
- **1 件**: 上に「操作」（App が今押せると言った操作だけ。`ConfirmButton` で、1 回目に App の確認の文を出し、2 回目で送る。`danger` の操作は危ない見た目、ほかは `secondary`）→「内容」（`DescriptionList` の `#value` に `AppPageValue`）→ 表（回の履歴など。行が無ければ「まだありません。」）。操作が済んだら応答の 1 件に入れ替えて「「〜」が済みました。」。断られた（409）ら App の文（`user_message`）。404（ほかの人が先に状態を変えた・古い画面からの押し直し）は「状態が変わっていたため、行えませんでした。画面を読み直したので…」と出して読み直す。事実に「コピー」の印（`copy`。文の値だけ）があれば、値の下に `CopyButton`（商品フィードの URL など、ほかのサービスの画面に貼る値。ADR 0051 の作って決めたこと）
- **段階**: 見るのは閲覧から、操作は運用から。運用より下の人には操作のボタンを出さず「操作は「運用」以上の権限の人だけです。」。見た目のためだけで、守るのはサーバー（POST が 403）
- **値の型ごとの描き方**（`AppPageValue`。値は `app/Core/Plugin/AdminPage/CellType.php` の型だけ）:

  | 型 | 描き方 |
  |---|---|
  | `text` | 文字だけ（Vue の文字の差し込み。`v-html` は使わない） |
  | `number` | そのままの数（表では右揃え） |
  | `money` | `formatAmount` の「¥5,400」（表では右揃え） |
  | `date` | 日付だけ（「2026/11/01」。`formatDay`。時刻を足して読まないので時差でずれない） |
  | `datetime` | `formatDate` の日時（ほかの画面と同じ形） |
  | `status` | `StatusBadge`。色の種類は good → ok・warn → warn・bad → danger・muted → neutral（知らない種類は neutral） |
  | `link` | 種類と ID からコアの経路の名前で作るリンク（customer → お客さんの画面・transaction → 注文の画面・listing → 商品の画面）。ID は ULID の形だけ（小文字にそろえる）。知らない種類・形の合わない ID は文字だけ。**URL を API から受け取って使わない** |
  | 値が無い（null） | 「—」 |

- **説明を見る**: その App の説明のページ（`resources/admin/help/<ページ>.js` の `plugin` が App の名前）の、`appScreens` にその画面（`app-page`・`app-record`）を持つ節へ（`appHelpLink`）。無ければリンクを出さない。定期便は「定期便」のページ、よくある質問は「商品のよくある質問（App）」のページ、商品レビューは「商品レビュー（App）」のページ、再入荷のお知らせは「再入荷のお知らせ（App）」のページ、お問い合わせは「お問い合わせ（App）」のページ
- **足す・直す**（よくある質問など、App が足す欄を持つときだけ。API は一覧と 1 件の応答の `form`）: 一覧の見出しの右上に App の決めたボタン（「質問を足す」など。主なボタン、運用の段階から）。押すと一覧の上に足す欄の板が開き（もう一度押すと閉じる）、「足す」で送ると板を閉じて一覧を読み直し「足しました。」。まだ 1 件も無いときの空の案内は「「〜」から足すと、ここに並びます。」。1 件の画面には「操作」の下に「直す」の板（今の値の欄と「保存する」。運用の段階から）。欄は `SettingFields`（`pages/app/AppRecordForm.vue` が包む）で、1 行の文・何行かの文（`AppTextarea`）・切り替え（はい・いいえ）・選ぶ（選択肢は並びのとおり）。誤りは欄の下（`values.<名前>`）と板の中（`values`）
  - **写真・ブロック・日時の欄**（ADR 0072、App「お知らせ・ブログ」）: 写真（`media`）は `PhotoPicker`（ショップの写真から選ぶか新しく上げる）、ブロック（`blocks`）は商品の説明と同じ `DescriptionEditor`（上限は欄の `limits`。誤りのパスは `values.<名前>.3.text`）、日時（`datetime`）は `AppInput` の `datetime-local`（手元の時刻で入れ、送るときに UTC の ISO 8601 へ）。写真の一覧は、写真かブロックの欄のある App のときだけ `AppRecordForm` が読む（店の ID を `tenant` で渡す）。自動の保存は無く、「保存する」で送る
- **直すだけ**（2026-11-04。App「商品レビュー」の店からの返信）: ハンドラーの `createLabel()` が null の App は、一覧に足すボタンと足す欄を出さない（API の一覧の `form` は null、足す経路は 404）。1 件の画面の「直す」の板だけを出す
- **直す欄の言葉**（2026-11-05。App「お問い合わせ」の返信）: 1 件の応答の `form` に `wording`（`title`・`submit`・`done`）があれば、板の見出し・送るボタン・送った後の通知にそれを使う（お問い合わせは「返信する」「メールで返信を送る」「返信を送りました。」）。無ければ「直す」「保存する」「保存しました。」
- **個人情報のフラグ**（2026-11-05。App「お問い合わせ」の名前・メール・本文）: サーバーは印の付いた事実と表を運用の段階の人にだけ返し、見たことを監査ログに残す。閲覧の人には外して返し、応答の `personal` が `hidden` なので、画面は操作の下に「名前・メール・本文などの個人情報は、「運用」以上の権限の人だけが見られます。」（`AppNotice` の info）を出す
- **お金の操作**（`money`。当日払いの代金の受け取り・来店なしの取消など）: 「会計」の権限の人にだけボタンを出し、足りない人には「代金の受け取り・取消などお金を扱う操作は、「会計」の権限の人だけです。」の一言（守るのはサーバーの 403 と直前の再確認の 423）
- **くり返す操作**（`repeatable`。並べ替えの「上へ」「下へ」など）: 確認の文を出さずにふつうのボタンで送る（`ConfirmButton` を使わない）。**操作で記録が無くなった**（「消す」）ら、一覧へ戻って「消しました。」（戻り先の印は画面の移動の state）
- **CSV の書き出しと取り込み**（配送の CSV など、App が口を持つときだけ。API は一覧の応答の `export`・`import`。形は足す欄と同じ `{ label, fields, values }`）: 一覧の見出しの右上に App の決めたボタン（「CSV を書き出す」「CSV を取り込む」。運用の段階から。足すボタンがあればそれが主なボタン、無ければ取り込みが主なボタン）。押すと一覧の上に板が開く（もう一度押すと閉じる。開くのは 1 つだけ）
  - 書き出し（`pages/app/AppExportForm.vue`）: 欄は足す欄と同じ部品（`AppRecordForm`）で、ボタンは「書き出す」。送るとファイルとして保存し（`api.js` の `download`。画面は移らない）、「〜.csv を書き出しました。」。断られたら欄の下か板の中に誤り
  - 取り込み（`pages/app/AppImportForm.vue`）: 上にファイルを選ぶ枠（`FileDrop`。選んだファイルの名前を下に）、その下に App の欄と「取り込んで確認する」。ファイルを選ばずに押すと「ファイルを選んでください。」、ファイルの誤り（`file`）は枠の下。取り込むとサーバーは確認の記録を作るだけなので、**その 1 件の画面へ移り、店の人が中身を見てから操作（「◯ 件を発送にする」など）を押す**
  - まだ 1 件も無いときの空の案内（足す欄の無い App）は「「CSV を取り込む」から取り込むと、ここに並びます。」
- **メルマガ・一斉メール**（2026-11-05。App の画面の部品だけで作った例）: 記録は配信。足す欄（「配信を書く」）はタイトル・本文（文だけ）・予約の日時（「2026-11-20 09:00」の 1 行の文。日時の欄の型はコアに無いので文で受け、App が読む）。1 件の操作は「自分にテスト送信する」（ふつう）・「今すぐ配信する」「予約する」「配信を止める」「消す」（`danger`。直前の再確認の後）・「予約をやめる」（ふつう）。本文は表「本文」に 200 文字ずつ（改行は「↵」）。購読者は数だけ（1 件の事実の「いま届ける人」「確認待ち」）で、アドレスは出さない
- **カゴ落ちのお知らせ**（2026-11-05、ADR 0067。App の画面の部品だけで作った例）: 記録は払われずに消えた注文ごとのお知らせ。絞り込みの数を直近 30 日の数（送った・リンクから戻った・払われた・送らなかった）に使い、別の数の欄は作っていない。列は消えた注文と払われた注文（コアの注文の画面へのリンク。注文番号の末尾 8 文字）・状態（送らなかった時は理由つき）・日時だけで、宛先のメールは出さない。操作は無い。ホームのやることは「送り主の表示が足りず送らなかったお知らせ」（直近 7 日）
- **予約販売**（2026-11-05、ADR 0073。App の画面の部品だけで作った例）: 記録は予約の商品（商品へのリンク・状態・発売日・予約の数・上限）。絞り込みは「予約を受付中」「発送を始められる」「すべて」。足す欄は無く（予約販売にするのは商品の画面の App の欄）、1 件の直す欄で発売日・受付の終わり（「2026-11-20」の 1 行の文。日付の欄の型はコアに無いので文で受け、App が読む）・上限。1 件の表は予約の注文の新しい 200 件（注文へのリンク・数・状態・約束した発売日。名前と連絡先は出さない）。1 件の操作は「次の予約を始める」（発売日を過ぎ、発送の前の予約の注文が無く、この回に予約がある時だけ。確認の文の後）。ホームのやることは「発送を始められる予約の注文」。注文の画面の「配送」の表は、発送を始める日のある配送に「◯ から発送（予約の品の発売日）」を添え、その日の前は発送の選択肢から外す（`held_for_release`。守るのはサーバー）
- **ラッピング・のし**（2026-11-05、ADR 0078。App の画面の部品だけで作った例）: 記録はラッピングの種類（名前・料金〔税込み〕・状態〔使う・使わない〕）。絞り込みは「すべて」「使う」「使わない」。足す・直す欄は名前（1 行の文）・料金（1 行の文で受け、App が 0〜100,000 の整数として読む）・ショップで選べる。消すは直前の再確認の後（受けた注文の内容は変わらない）。商品の画面の App の欄は「ラッピングできる」「のしを付けられる」の切り替え 2 つ。のしの決まりは App の設定。注文の画面の「個人情報を見る」に「ラッピング・のし」の節（名入れの文字。`charge_notes`）
- **友だち紹介**（2026-11-05、ADR 0075。App の画面の部品だけで作った例）: 記録は紹介された人ごとの紹介。絞り込みは確認待ち・注文と発送を待つ・付けた（絞り込みの名前に付けたポイントの合計「付けた（計 2,000 ポイント）」を入れ、別の数の欄は作っていない）・付けなかった・すべて。列は紹介された会員と紹介した会員（コアの「お客さん」の画面へのリンク。名前は「会員」とお客さんの記録の ID の末尾 8 文字だけ）・状態（付けなかった時と確認待ちは理由つき）・最初の注文・付けたポイント（2 人の計）・会員になった日時。確認待ちの 1 件の操作は「ポイントを付ける」「付けない」（どちらも取り消せないので `danger`。直前の再確認の後。「ポイントを付ける」はポイントが動くので `money` も付け、会計の段階の人だけ）。ホームのやることは「確認待ちの友だち紹介」と、ポイントを使わない設定の時の「友だち紹介を受け付けていません」

### 注文の書類（App の納品書・領収書。ADR 0051 の作って決めたこと）

使っている App が注文の書類を持つとき（`GET /api/tenants/{店}/order-documents`）、管理画面に入口を出す。書類そのものは管理画面の SPA の外の印刷用のページ（新しいタブ。サーバーが描き、スクリプトなし）で、画面の部品では描かない。

- **注文の画面の支払い**（ADR 0058）: 上の要約に「お支払いの方法」（クレジットカード・Apple Pay・Google Pay・コンビニ払い・PayPay。API の `payment.method_label`）。コンビニ払いの入金待ちの注文には、操作の欄の上に `AppNotice`（期限と、期限で自動で取り消すこと・取り消すと払込票も使えなくなること）。払込票の画面の URL は管理画面には返さない
- **注文の画面の銀行振込・代金引換**（ADR 0074）: 操作の欄（`AppPanel`「注文の操作」）の中に `InsetSection` で「入金を確認した」（受け取った額の `AppInput`、注文の額と違えば「違いを確認した」の `AppCheckbox`、`ConfirmButton`）・「受取拒否で取り消す」（在庫に戻すかの `AppCheckbox`）・「返金を記録する」（返した額）。どれも会計の段階の人にだけ出し、押すとパスキーの再確認。入金待ち（振込）・代引きの注文には操作の欄の上に `AppNotice`。対応の状況のカードに「代引き・発送待ち」（`cod_pending`）
- **注文の一覧の「お支払い」**（ADR 0074）: 絞り込みの箱に `FilterSelect`（すべて・入金待ち〔振込〕・代引き〔未入金〕。件数はサーバーの `payment_counts`。URL の `payment`）。ホームのやることに「発送を待つ代引きの注文」「期限の近い入金待ち（振込）」「入金の確認を待つ代引き」
- **設定 › 支払い の「銀行振込・代金引換」**（`DirectPaymentSettings`、ADR 0074）: 使う支払いの手段の下に別の `AppPanel`。2 つの `InsetSection` に、使うかの `AppCheckbox`、振込先（銀行名・支店名・口座の種類・口座番号・名義）と払う期限（1〜14 日）、代引きの手数料の行（「この額未満」と手数料の行を足す・外す。最後の行は「それより上」）と上限の額。振込先は会計の段階の人にだけ出す（ほかの人には「入っています」の一言）。特商法の表記への書き足しの案内は `AppNotice`。保存は会計の段階・パスキーの再確認の後
- **設定 › 支払い の「使う支払いの手段」**（`PaymentMethodsSettings`、ADR 0058）: 鍵・接続の欄の下に別の `AppPanel`。コンビニ払い・PayPay は `AppCheckbox`、コンビニ払いを選ぶとお支払いの期限（`AppSelect`。1〜30 日）。Stripe へ接続した店では PayPay を押せず、理由の 1 行。Stripe のダッシュボードの「決済手段」でも有効にする案内は `AppNotice`（リンクはサーバーが渡す `dashboard.payment_methods`）。保存は会計の段階・パスキーの再確認の後
- **注文の画面**: 見出しの右（状態のバッジの後ろ）に書類ごとの小さなボタン（`AppButton` の `href`。新しいタブ。アイコンは `file`）。物販の注文で、運用の段階の人にだけ出す（見た目のためだけで、守るのはサーバーの 403）
- **注文の画面の「配送」の表**（ADR 0059）: 「お届けの希望」の列に、お客さんが選んだお届けの日と時間帯（「2026年11月7日（土） 午前中」。選ばなかった配送は薄い文字の「指定なし」）。個人情報ではないので閲覧の段階から見える（文はサーバーの `delivery.label`）
- **注文の画面の「注文の項目」**（ADR 0066）: お客さんが回答した項目を `DescriptionList` で（注文の時の名前で）。選ぶ・チェックの回答はそのまま、1 行・複数行の文の回答は個人情報を含みうるので「（文の回答。「個人情報」を表示すると出ます）」と出し、値は「個人情報」の表示（運用から・見た記録が残る）の「注文の項目の文の回答」で見せる
- **注文の一覧**: まとめて出せる書類（`bulk`）があれば、表の最初の列に選ぶ欄（`AppCheckbox`。見出しは「すべて」。物販でない取引は選べない）。1 件でも選ぶと、表の上に `FormActions` で「n 件を選んでいます。」と「〜をまとめて開く」。選んだものはそのページの中だけ（一覧が変わると選び直し）
- **App の設定の「写真」の欄**（`media`。ロゴなど）: `SettingFields` がセクションと同じ写真の欄（`PhotoPicker`。ショップの写真から選ぶか、新しく上げる）で描く。写真の一覧は設定の画面（`TenantPluginPage`）が、写真の欄のある App のときだけ読む

### ホームの型

店のホーム（`/tenants/{店}`、`TenantPage`）。形: 開設までの番号つきの手順と、数・やること・最近の注文。**店の状態で形が変わる**（並びは DOM の順そのものを替え、見た目と読み上げ・キーボードの順をそろえる）。

- **準備中の店**: 開設の手順が主役（いちばん上）。注文が無ければ数も最近の注文も出さない（空の 0 を並べない）。やることは 1 件でもあれば出す
- **公開した店**: 数（今日の注文・今月の売上・平均注文単価）→ やること・最近の注文（広い画面で 2 列）→ 開設の手順（畳んで下に。「開く」で手順が出る。サンプルが残っていれば最初から開く）
- **設定 › 配送と送料**（ADR 0064。`GET`・`PUT …/shipping-methods`。読むのは閲覧から、変えるのは運用から）: 配送の方法ごとに 1 枚の `AppPanel`（方法の名前・全国の送料・この金額以上で送料無料・地域ごとの送料の表〔`AppTable`。地域の欄は中の県が同じ額ならその額、違えば空で「県ごとに違う」〕・「県ごとに直す」で 47 県の表を `AppReveal` で開く・上へ／下へ／この方法を外す）。いちばん上の方法が、方法を選んでいない商品の方法。「配送の方法を足す」（10 まで）。保存は表をまとめて 1 回（`FormActions` の `sticky`）。県の欄に誤りがあれば県の表を開いたままにし、全国の送料の欄の下に理由を出す
- **商品の配送の方法と送料無料**（ADR 0064）: 商品のフォームの「詳しい設定」に「配送の方法」（`AppSelect`。空は「いちばん上の方法」）と「送料無料の商品にする」（`AppCheckbox`）。選択肢は `GET …/listing-options` の `shipping_methods`
- **開設の手順**（`SetupSteps`・`ProgressSegments`）: 店の情報と特商法 → 送料 → 支払い → 最初の商品 → デザイン → 公開 → お客さんを集める。**済んだかはサーバーが店のデータから決める**（`GET …/setup`。手で「済」にしない。決まりは `ShopSetup` の頭の説明）。各手順のボタンは該当の画面へ（設定の特商法・送料・支払い、新しい商品、デザイン、設定の基本、App）。まだの手順のいちばん上が主な操作の色（「ようこそ」を出している間は、そちらが主な操作）、済んだ手順は「開く」。言葉と行き先は `resources/admin/setup.js`
- **サンプルの手順**: サンプルを入れた店だけ、「最初の商品」の下に `SubSteps` で「サンプルを見る → 自分の商品に置き換える → サンプルをまとめて消す」。まとめて消すのはオーナーだけ（ほかの人には一言）。サンプルが残っている間は「公開」の手順に通知
- **数**（`StatCard`）: 数えるのは支払いが済んだ物販の注文（入金済み・受付済み・発送済み・完了）。入金待ち・取消・返金・テストの注文（Stripe のテストのモードで払われた）は数えない。テストの注文があれば数の下に「n 件は数えていません」。日と月は日本の時刻、平均は 1 円未満を切り捨て（`ShopHome`）。金額は `formatAmount`（¥5,400）
- **やること**（`TodoList`）: 発送を待つ注文（入金済み・0 円の受付済み）→ 注文の一覧の状態で絞った画面、在庫切れの商品 → 商品の一覧（公開中・在庫の少ない順）。返金が要る支払い・確認が要る返金は、今までどおり上の通知（`AppNotice`）で注文ごとに
- **動きに問題があることのバナー**（ADR 0043）: 運営ダッシュボードの要対応が 1 件以上なら、ホームのいちばん上（見出しのすぐ下）に `AppNotice` の `error` で「動きに問題があります（要対応 n 件）。運営ダッシュボードを見る」。**オーナーにだけ**（スタッフの画面は数を聞きにも行かない）。0 件なら出さない。数は店の API でなく中央の `GET /api/operations/alerts`（店の文脈の中で中央の表を読まない）。取れなければ出さないだけで、ホームは止めない
- **最近の注文**: 新しい 5 件（注文番号・日時・明細の数・状態のバッジ・合計。テストの注文は「テスト」のカード）。お客さんの名前などは出さない。右上に「すべての注文」
- **「ようこそ」**（`WelcomeCard`）: 運営ごと・店ごとに最初の 1 回だけ、いちばん上に。3 枚（何ができるか／サンプルが入っていること〔無ければ準備中か公開中〕／次にやること）。閉じたフラグはサーバーに置く（`PUT …/welcome`。ブラウザの保存領域は使わない。ADR 0016）。「あとで見る」は印を置かず、この画面を開いている間だけ隠す（読み込み直すとまた出る）。開設の手順の「はじめにの説明」でいつでももう一度見られる
- **権限**: ホームの数・やること・最近の注文・開設の手順は閲覧の段階から読める（注文の一覧と同じ。会計の段階が要るのは、お金を動かす・鍵を変える操作だけ。ADR 0024）。「ようこそ」を閉じるのも閲覧の段階から（店のデータは変えない）
- 画面の上の吹き出しの案内は、画面が固まってから（運営の判断）

### お客さんの画面（ADR 0044 の 2・4）

- **一覧**（`/tenants/{店}/customers`。一覧の型）: 注文のメールアドレスごとに 1 人。列は番号（1 人の画面へのリンク・はじめての日）・会員のバッジ（会員／ゲスト）・注文の数・合計（`formatAmount`）・最後の注文・まとめた記録の数。数と合計は払われた注文だけ（ホームの売上と同じ数え方）で、まとめた記録の注文は親に足す。絞り込みの箱は言葉の検索の代わりに一言の説明を置き、「会員」（すべて・会員・ゲスト。件数つき）と並べ替え（最後の注文・注文の数・合計・はじめての日。どれも多い順・新しい順だけ。見出しは `SortHeader` の `descending-only`）。条件は URL（`?status=member|guest`・`?sort=`・`?page=`）。まだ 1 人もいなければ `EmptyState` だけ。**名前とメールアドレスは一覧に出さない**（API も返さない）
- **番号**: お客さんの記録は ID の**後ろの 8 文字**（`format.js` の `customerNumber`）で見せる。注文の番号（`shortId`、頭の 10 文字）と違うのは、ULID の頭が作った時刻で、今までの注文からマイグレーションで一度に作った記録は頭がそろうため
- **1 人の画面**（`/tenants/{店}/customers/{ID}`）: 見出しの右に会員のバッジ。上に `StatCard` を 4 つ（注文の数・合計・最後の注文・会員になった日）、下に「注文」の表（払われていない・取り消した注文も、新しい順に 100 件まで。行から注文の画面へ。まとめた記録の注文は補足の行に「まとめた記録の注文」）。ここまでは閲覧の段階から
- **名前と連絡先**: `AppPanel` の右上の「名前と連絡先を表示する」を押したときだけ別の API（`…/personal`）から取る。説明の文に「表示すると、誰がいつ見たかが記録に残ります」。出すのはメール・まとめた記録のメール・最後の注文の名前と電話と住所（とその注文へのリンク）・会員の届け先。「隠す」で消す。運用の段階より下の人にはボタンの代わりに「〜の権限の人だけです」
- **同じお客さんかもしれない記録**（運用の段階から。まとめられた記録の画面には出さない）: 名前と電話が同じでメールの違う記録を表で。行ごとに「この記録をまとめる」（`ConfirmButton`。問いに「注文そのものは書き換えず、あとで『分け直す』で元に戻せます」）。断られたら（会員はまとめられる側にしない・入れ子にしない など）サーバーの文を `AppNotice` の error で欄の中に。言葉は「同じお客さんをまとめる」「まとめた記録」「分け直す」（「名寄せ」と書かない。docs/design/terms.md）
- **まとめた記録**: まとめた記録の一覧（番号・まとめた日・注文の数）は閲覧の段階から見え、「分け直す」（`ConfirmButton`）は運用の段階から。まとめる・分け直すの後は画面を読み直し、表示していた名前と連絡先は閉じる（まとめた記録のメールが変わるため）
- **まとめられた記録を開いたとき**: いちばん上に `AppNotice`（info・`:live="false"`）で「この記録は、お客さん（番号）にまとめられています」と、まとめた先へのリンク

### クーポンの画面（ADR 0054 の段階 2。自動の割引は ADR 0065）

- **メニュー**: 主なメニューの「商品」のすぐ下に「クーポン」（アイコンは `ticket`）。見るのは閲覧から
- **一覧**（`/tenants/{店}/coupons`。一覧の型）: 新しく作った順。列はコード・名前（`CellTitle`。自動の割引はお客さんに見せる名前。補足の行にメモ、押すと 1 枚の編集へ）・種類のバッジ（`StatusBadge`。「クーポン」neutral・「自動」accent。`coupons.js` の `COUPON_METHOD_LABELS`）・値引き（「¥500 引き」「15% 引き（¥3,000 まで）」「送料無料」）・条件の要約（全品／カテゴリ n 個／商品 n 点・「¥3,000 以上」・「3 点以上」・会員だけ・1 人 n 回）・使われた数（「3 / 100」。上限が無ければ数だけ）・期間・状態のバッジ（使える・始まる前・終わった・回数の上限・止めている。状態はサーバーの `state`）。絞り込みの箱はコード・メモ・名前の言葉と、使っている・止めている。右上は「自動の割引を作る」（`?method=automatic` で作る画面を開く）と「クーポンを作る」。表示の形は `resources/admin/coupons.js` にまとめ、一覧と編集で同じものを使う
- **作る・直す**（`/tenants/{店}/coupons/new`・`/tenants/{店}/coupons/{ID}`。1 枚のフォーム）: 上から 基本（作るときだけ作り方〔`ChoicePills`: クーポン（コード）・自動の割引。作った後は変えない〕・コードか、自動の割引ならお客さんに見せる名前〔40 文字〕・メモ）→ 値引き（種類を `ChoicePills` で選び、種類ごとに値の欄）→ 対象（全品・カテゴリ・商品。カテゴリは `CheckList` のカード、商品は選んだものの並びと「外す」、検索欄と「商品を足す」の選択。セクションの欄の「選んだ商品」と同じ形）→ 条件（最低の購入額・対象の商品の数〔まとめ買い〕・期間〔`datetime-local`〕・全体の回数・1 人の回数〔新しく作るときはクーポン 1・自動の割引は空〕・会員だけ）。自動の割引の数の上限（20 件）に当たった時は、欄でなく上の `AppNotice` に出す。保存は下の浮かせたバナーの 1 つのボタン（`FormActions` の `sticky`）
- **コード**: 作るときだけ入れられ、横の「作る」で 8 文字のコードが入る（`coupons.js` の `generateCode`。ブラウザの暗号の乱数）。直すときは等幅の文字で見せるだけ
- **使われた数と状態**（直すときだけ、いちばん上）: 使われた数・値引き。右上に「止める」（`ConfirmButton`。問いに、ショップで使えなくなることと再開できること）か「再開する」。一度でも使われたクーポンは `AppNotice`（info・`:live="false"`）で「種類・額・対象は変えられません」と、その欄を押せなくする（サーバーも 422 で断る）
- **段階**: 運用より下の人には欄を押せなくし、保存のボタンの代わりに「〜の権限の人だけです」。守るのはサーバー

### 売上の画面（ADR 0060）

- **メニュー**: 主なメニューの「注文」のすぐ下に「売上」（アイコンは `chart`）。**会計の段階の人にだけ出す**（`level: 'money'`。API も 403 で断る）
- **画面**（`/tenants/{店}/sales`、`SalesPage`）: 上から 期間の欄（`SegmentedTabs` で 今日・今週・今月〔既定〕・先月・期間を選ぶ。期間を選ぶと日付の欄 2 つ〔`type="date"`〕と「表示する」。説明の文に日付の範囲と「日本の時刻で区切ります」。期間の誤りは欄の下の `AppNotice`）→ 数のカード 6 枚（`StatCard`。売上〔補足に「入金 − 返金」〕・注文の数〔補足に「うち取消・返金 n 件」〕・平均の注文額・返金・クーポンの値引き・送料）→ テストの注文の件数（あれば薄い文字で 1 行）→ 日ごとの売上（`DailyBars`。入金 − 返金で、負の日は線だけ）→ 下の行に よく売れた商品（`AppTable`。金額の多い順・数の多い順を `SegmentedTabs` で切り替え、10 件。商品名から商品の画面へ）と お客さん（小さな `StatCard` で 新しいお客さん・また来たお客さん・記録の無い注文）
- **CSV**: 右上の「日ごとの CSV」「商品ごとの CSV」（`downloadGet`。選んでいる期間で書き出す）
- 数え方（お金が動いた日・注文は払った日・テストの注文は数えない）は画面の補足とヘルプ（`help/sales.js`）に書き、画面の中で計算しない（サーバーの数をそのまま出す）

### 運営ダッシュボード（ADR 0042）

EC-SUGAR を提供する側のオーナーが、全部の店を 1 枚で見る画面（`/operations`、`OperationsPage`）。店の切り替えの窓の「運営全体」の先頭。**オーナーだけ**（API は `RequireOwner`。スタッフには項目を出さず、開いても 403 の `ErrorState`）。形は運営が選んだ案 A「問題を先に」。

- **いちばん上に問題**: 要対応（`AppNotice` の `error`）と近いうちに（`warning`）。1 行ずつ「どこの何が何件か」で、店の問題は押すと店の中の該当の画面へ（返金が要る支払い・確認が要る返金は店のホーム、記録の検証の失敗は設定の記録の確認、届いていないメールは注文の一覧）。**何も無ければ「困っていることはありません。」の 1 行だけ**（`success`）。どれも開いた時からある通知なので `:live="false"`
- **数**（`StatCard`。狭い画面では 2 列）: 店（公開中・準備中）・今月の売上（全部の店。支払いの済んだ注文、取消と返金は除く）・今月の注文（テストの注文は数えない）・動いているバージョン（イメージのコミットの印。無ければ「開発中」）
- **売上の動きとシステムの状態**（広い画面で 2 列、上に揃える）: 日ごと 30 日の棒（`DailyBars`）と 30 日の合計。システムの状態（`HealthList`）は定期の処理（最後に数えた時刻）・キュー（待ちと 7 日の失敗）・通知メール・記録の改竄の検証（1 日 1 回）・証明書の期限・空き容量・更新。**まだ見る仕組みの無いもの（証明書・空き容量・更新）は「まだ見ていません」と出す**
- **エラー**（ADR 0043。`AppTable` の `stack`）: この 7 日に起きたエラーを最後に起きた順に。何が（例外のクラスの短い名前と種類〔画面や API のエラー・バックグラウンド処理の失敗・定期の処理の失敗〕）・どこで（場所。`CodeText`）・店（押すと店のホーム。店の外なら「—」）・回数・最初と最後。100 件まで（越えたら「ほかに n 件」）。無ければ `EmptyState`「この 7 日にエラーはありません」。この 24 時間に起きていれば、要対応のいちばん上に「この 24 時間に起きたエラーが n 件あります」。メッセージはサーバーが持っていないので出さない。読むだけ（「直した」の印は後の段階）
- **店の一覧**（`AppTable` の `stack`）: 店（名前と ID。押すと店のホーム）・状態（公開中・準備中・まだ数えていません）・今月の売上・今月の注文・問題（件数のバッジ。無ければ「—」）。問題のある店から、次に売上の多い店。200 店まで（越えたら「ほかに n 店」）
- **数はどれも、各店が店の中で数えて中央に置いた件数と金額**（10 分ごと。この画面は店の DB を読まない）。文は画面が作り、API は `key`・`level`・`count`・店だけを返す
- **問題の行に付く操作**は `ConfirmButton`（`secondary`）で、済んだら下に結果の `AppNotice` を出して読み直す: 止めた・待ちの通知の「再実行する」と、APP_KEY のバックアップの「バックアップを取りました」（1 回目で「サーバーの外に保管しましたか」と「やめる」、2 回目の「保管しました」で送る。`POST /api/operations/app-key-backup`、オーナーだけ・直前の再確認の後。済んだら「APP_KEY のバックアップを取ったことを記録しました。」で、問題が消える）。APP_KEY のバックアップの問題は、インストーラーで入れたサーバー（ホストの報告が来た所）で、回答するまで「近いうちに」に出し続ける。鍵・設定の値はこの画面に来ない

### 商品のフォームの型（1 枚の長いフォーム）

商品の登録と編集（`ListingPage`。節は `pages/listing/`）。形: **1 枚の長いフォームを上から順に入れ、下の 1 つのボタンで保存する**。保存のたびに画面を移らない（新しい商品は、作れたら URL だけが編集の形になる）。

- **節の並び**（`AppPanel` に `id`）: 基本（商品名・価格・税率・状態〔編集だけ〕。出品者は 2 人以上のときだけ。税率は `AppSelect` で「標準 10%」「軽減 8%（食品・飲み物）」。選択肢は `listing-options` の `tax_classes`、率は区分からコアが決める。ADR 0063）→ 写真 → 説明（短い説明・説明のブロック・仕様の表）→ 種類（色・サイズ）→ オプション → 在庫 → App（下の「商品の画面の App の欄」）→ 検索と共有（`SeoFields`。ADR 0061。目次に「検索と共有」）→ 詳しい設定（品番・商品の扱い・カテゴリ。**畳んでおく**。保存の誤りがこの中にあれば開く）。必須は基本だけで、ほかの節には「使わない商品は空のままで大丈夫」と書く。欄は `AppField` の `layout="row"`（左に項目名・右に入力・下に短い説明）。入力欄 1 つでない欄（カテゴリのカードなど）は `as="div"`
- **目次**（`FormOutline`）: 広い画面（lg 以上）だけ右に留める。押すとその節へ移り焦点も移す（動きを減らす設定では飛ぶ）。今見ている節に印、保存していない変更のある節に藍の小さな丸（読み上げは「変更あり」）。狭い画面では出さない
- **下のバナー**（`FormActions` の `sticky`）: 左にバージョンと「保存していない変更があります」。新しい商品は「下書きで保存」と「公開する」（主な操作）、今ある商品は「保存する」。保存すると消える種類があるときは、「保存する」が `ConfirmButton` になり、消えるものを書いてから「消して保存する」。結果の通知（済んだ・途中で止まった・同時の編集の衝突）はバナーのすぐ上に出す（どこまで読んでいても見える）
- **保存の流れ**（`resources/admin/listingSave.js`）: 変えた所の API だけを、決まった順に 1 つずつ呼ぶ。今ある商品は 基本の情報と説明（`PATCH`）→ 種類の選ぶ項目（`PUT …/options`）→ 種類ごとの行（`PATCH …/variants/{id}` を行ごと）→ オプション（`PUT …/addons`）→ カテゴリ（`PUT …/categories`）→ App の欄（`PUT …/apps/{App}` を変えた App ごと。商品のバージョンは進めない）→ 公開。新しい商品は 作る（`POST`。いつも下書きで）→ 写真 → 最初の在庫 → 種類 → オプション → カテゴリ → 公開。バージョンは毎回直前の手順が返した商品から取る（同時の編集の衝突の監視が手順の間で途切れない）
  - **公開はいつも最後**: 新しい商品の「公開する」も、状態を「公開中」に変えた保存も、ほかの手順がすべて済んでから公開する。途中で止まったら公開しない（「公開はまだです」）
  - **途中で失敗したら**、そこで止めて「保存できたもの・保存できなかったもの（理由と「その欄へ」）・まだ保存していないもの」を通知する。済んだ手順は取り消さない（API ごとに確定している）。済んだ節の「変更あり」は消え、残りの書きかけは残るので、直してもう一度押すと残りだけを送る。誤り（422）はその欄の下にも出す
  - **同時の編集の衝突**（409）: どの手順でも止めて、上書きしない。保存のボタンを押せなくし、「最新の内容を読み込み直す（入力した変更は消えます）」
- **すぐ反映するもの**: 写真（選ぶ・並べ替える・消す・代わりの文字）と在庫の入庫・調整は、ファイルと在庫の記録の操作なので、押すとすぐ反映し、通知はその節の中に出す（節の中に「下の「保存する」は要りません」と書く）。在庫の操作の答えからは在庫の数だけを取り込み、商品のバージョンは取り込まない（取り込むと、別の人の変更に気づかず上書きする）。新しい商品では、選んだ写真（送る前はファイルの名前で並べる。CSP で選んだファイルの画像は出せない）と最初の在庫を覚えておき、作った後に送る。色・サイズを分ける新しい商品の品番と在庫は、種類ができてから種類の表と在庫の節で
- **離れる前の確認**: 保存していない変更があるまま画面の中で移ると `window.confirm`、タブを閉じる・読み直すとブラウザの確認（`beforeunload`）。運用の段階に足りない人には出さない
- プレビューと「ショップで見る」は見出しの右上のまま。保存していない変更があれば「プレビューとショップは、保存した内容を見せます」

#### 商品の画面の App の欄（ADR 0050）

この店で使っている App のうち、商品ごとの欄を持つもの（定期便の「定期でも買える・お届けの周期・定期の値引き」など）を、在庫の後の「App」の節（`pages/listing/ListingApps.vue`）に並べる。

- **欄の形は App が宣言し、描くのはコア**: App は `ListingPanelHandler`（`fields()` で `SettingSpec` の並び・`read()`・`write()`）を `PluginDefinition` の `listingPanel` に渡すだけ。画面は App ごとに `InsetSection`（タイトルは App の名前）の中に `SettingFields`（切り替えは「はい・いいえ」）。App の Vue のコードは読み込まない
- **出す条件**: 欄を持つ App を使っている店の、作った後の商品だけ（新しい商品は最初の保存の後に出る）。1 つも無ければ節も目次の項目も出さない
- **API**: `GET /api/tenants/{店}/listings/{商品}/apps` → `{ apps: [{ plugin, title, fields, values }] }`（閲覧から）。`PUT …/apps/{App}`（`{ values }`）→ `{ app }`（運用から）。使っていない・欄の無い App は 404、形の誤りは 422（`values.<欄の名前>`。欄をまたぐ決まり〔定期便の「周期を 1 つ以上」〕も欄の名前で）。書かなかった欄は今の値のまま
- **保存**は下の「保存する」でまとめて（変えた App ごとに 1 つの手順。名前は App の名前）。閲覧の段階の人には値を見せるだけ（欄を押せず、保存のボタンも無い）
- **ファイル**（ADR 0084。App「ダウンロード販売」の売るファイル）: App が `ListingFilesHandler` も渡すと、応答の `files`（`items`・`max_files`・`max_bytes`・`chunk_bytes`・`accept`・`used_bytes`・`quota_bytes`。置かない App は null）を、同じ `InsetSection` の欄の下に `pages/listing/ListingAppFiles.vue` が並べる（表 `AppTable`・消すは `ConfirmButton`・選ぶ枠 `FileDrop`）。上げる・消すは**すぐ反映**（「保存する」を待たない）。上げるのはチャンクに分けて順に（`POST …/apps/{App}/uploads` → `POST …/uploads/{ID}` に `offset` と `chunk` → `POST …/uploads/{ID}/finish`。落ちたら `DELETE …/uploads/{ID}`）。送っている間は「◯ MB / ◯ MB を送っています…」。形・数・大きさ・店の合計はサーバーが確認し、誤りは枠の下に
- **注文の画面の App の 1 件**: App が `AdminOrderPanelProvider` を渡すと、注文の画面（`pages/transaction/TransactionApps.vue`）に App の画面の 1 件の事実と表を、個人情報を出さずに並べる（`GET …/transactions/{注文}/apps`。閲覧から）。操作は置かず、「App の画面で開く（操作はこちら）」のリンクだけ

### ページの編集の画面（ADR 0039 段階 2・3）

見本の A（左にセクションの一覧、真ん中にショップのプレビュー、右に選んだセクションの欄）。経路は `/tenants/{店}/theme/pages/{ページ}?theme=テーマ`（`theme-page`。ページは `home` か自由なページの `page-{ID}`。テーマが無ければショップで使っているテーマ）、入口はトップなら「デザイン」（テーマのタブ）の今のテーマの「編集する」かほかのテーマの「試しに編集する」、自由なページなら「ページ」の一覧の「中身を作る」。セクションの中身を入れるのはこの画面だけ（テーマのタブにはセクションの欄を置かない）。戻るボタンも入口の画面へ。メニューを出さず画面の全体を使う（`meta.fullscreen` と `EditorLayout`）。

- **上のバナー**: 「デザインに戻る」（自由なページは「ページの一覧に戻る」）・タイトル（ページの名前・店・テーマ）・下書きのフラグ（`StatusBadge`: 保存中・保存していない変更・保存できなかった・下書き〔公開していない変更あり〕・公開中と同じ）・パソコンとスマホの切り替え（プレビューの幅。スマホは 390px）・ショップで見る・公開する（`ConfirmButton` で確認してから。保存していない変更があれば先に保存。公開はバージョンごとですべてのページ）
- **「雛形から作り直す」（`RebuildFromTemplate`）**: 「＋ セクションを足す」の下。雛形を選び、確認してから今の並びを雛形の並びに置き換える（`POST …/pages/{ページ}/template`。下書きに入るだけで、公開するまでショップは変わらない）。お知らせバナー・フッターのように決まった場所に出るセクションは残る。待っている自動の保存は捨て、送っている途中の保存は待ってから最新の改訂で送る。作り直したら一覧・プレビューを読み直し、「雛形の並びに作り直しました（下書き）…」を出す。決まった並びのテーマと閲覧の段階の人には出さない
- **左（`PageSectionList`・`AddSectionPicker`）**: セクションの一覧。押して選ぶ。タイトルは 2 行まで折り返し、それより長ければ省いて（…）、マウスを重ねくと全部のタイトル（`title`）。行の操作はアイコンだけの小さなボタン（`AppButton` の `icon`）で、1280px の幅でもタイトルがボタンに重ならない。行をつかんで動かす（HTML のドラッグ。ライブラリは使わない）か、↑ ↓ のボタンか、行の中で Alt + ↑ / ↓（`BlockFrame` と同じ決まり。動かした後も同じボタンに焦点を残す）。目のボタンで隠す・出す。選んだセクションの下にブロックの並び（選ぶ・↑ ↓・外す・「＋ ブロックを足す」）。下に「＋ セクションを足す」（1 ページに置ける数〔limit〕と 40 セクションに届いたら押せない。選んでいるセクションの後ろへ足す）
- **「＋ セクションを足す」（`AddSectionPicker`・`SectionWireframe`）**: 種類の見出しの下に、パターンごとのワイヤーフレームの画像のカード（アイコンの下にパターンの名前。パターンが 1 つの種類は種類の名前）。列の数は欄の幅で決める（`@container`。左の狭い列では 2 列、狭い画面で縦に積んで広くなれば 3 列）。アイコンはテーマが `theme.json` で選んだコアの語彙（`wireframes.js`。docs/design/theme-api.md の「ワイヤーフレームの画像」）で、書いていないパターンは汎用のアイコン。色はトークンだけ（写真は無地の枠＝`line-strong`、文は `ink-faint`、見出しは `ink-soft`、濃い地は `ink-muted` の面。ダークは値が入れ替わるだけ）。アイコンは飾り（`aria-hidden`）で、読み上げの名前は「種類の名前の パターンの名前」。置ける数に届いた種類のカードは押せない
  - **プレビュー**: アイコンにマウスを重ねく（hover）・キーボードで焦点を当てると、真ん中のプレビューの選んでいるセクションの後ろに、そのセクションを見本の値で仮に出す（点線の輪郭。0.2 秒で透明から出す。動きを減らす設定では出すだけ）。離れると消える（隣のカードへ動かすときにちらつかないよう 0.12 秒待つ）。押すと足す。指で触ったとき（`pointerType` が touch）は、1 回目でプレビューとカードの藍の輪郭、カードの下の「「…」を足す」（`primary`）か同じカードをもう 1 度で足す。「やめる」で消す。Esc で欄を閉じる。プレビューは何も保存しない
  - 枠への通知は `PagePreview` の `trial`（`{ type, pattern, label, after: [前の区画の ID…], before: [後ろの区画の ID…] }`）。枠の中には保存してあって隠していないセクションしか無いので、位置は近い順の ID の並びで伝え、枠の中の部品が見つかるものを使う。読み込み直した後も通知し直す
- **真ん中（`PagePreview`）**: ショップのホストの下書きのプレビュー（署名つきのリンクを API で作る。切れる 3 分前に作り直す）を枠に開く。保存のたびに読み直す。枠の中でセクションを押すとそのセクションを選び、左で選んだセクションは枠の中に輪郭で出る（postMessage。相手のオリジンと窓を確認する）
- **「見た目」のカード（`ThemeStylePanel`。ADR 0097）**: 見た目を宣言したテーマでは、左の欄の上に「セクション」「見た目」のカード（`SegmentedTabs`）。「見た目」に、カラーパレット（`PaletteChoices`）・主な色（`ColorField` と「組の色に戻す」。テーマが許すときだけ）・フォントと角の丸み（`ChoicePills`。2 つ以上あるときだけ）。変えて少し待つと下書きに保存し（セクションの保存と同じ順番待ちで改訂を進める）、プレビューの CSS だけを読み直す（`PagePreview` の `look`。リンクの期限が近ければ枠ごと読み直す）。読みにくいかもしれない組み合わせは `AppNotice` の warning（止めない）。誤りは欄の下に（`style.accent` など）。公開はセクションといっしょに上の「公開する」で。閲覧の段階の人には押せなくする
- **右（`SectionSettings`）**: 見た目のパターン（`ChoicePills`）・ショップに出す・欄（`SectionEditor` を `narrow` で 1 列に）・「このセクションを消す」（`ConfirmButton`。問いを開いた形は選んでいるセクションとその位置に結びつけ、消す・別のセクションを選ぶ・並べ替えると閉じた形に戻す。部品を使い回すと、消した後に次のセクションの問いが開いたまま残る）。ブロックを選んでいればそのブロックの欄だけ。欄の種類 `html`・`richtext`（カスタムセクション）は `SectionHtmlField`・`RichTextEditor`
- **保存**: 変えて 0.8 秒待つと、並びを丸ごと下書きに保存する（手で押すボタンは無い）。足したセクションは ID を付けずに送り、応答の ID をコピーする（送った後に打った分は上書きしない）。誤りはセクションの行を赤くし、欄の下に書く。同時の編集（409）は保存を止め、読み込み直すボタンを出す
- **決まった並びのテーマ**（`page.fixed`。今の公式テーマ）: 足す・消す・並べ替え・ブロックの操作は出さない（値と隠す・出すだけ）。閲覧だけの人には欄を押せなくし、保存も公開もしない
- **自由なページ**（`page.free`）: タイトルはページのタイトル。置けるセクションはテーマの雛形（`pages.page`）かコアの汎用のセクション。「公開する」はこのページも公開の状態にする（確認の文に URL を出す）。「ショップで見る」は公開しているときだけ、そのページを開く
- **CSP**: 管理画面は枠を一切読まない（`default-src 'none'`）。この画面の殻にだけ、ログイン中でその店に入れる運営のとき、その店のショップのオリジンを `frame-src` に足す（`ShellController`）。SPA は画面を移る時に殻を読み直さないので、ほかの画面からこの画面へは文書ごと読み直して入る（`router.js` の `beforeEnter`）

### デザインのテーマの画面

### 検索と共有（ADR 0061）

- **設定 › SEO**（`/tenants/{店}/settings/seo`、`SeoSettingsPage`。設定の目次の「ショップ」のまとまり）: 上のパネルに トップのタイトルと説明（`SeoFields` の `suffix` なし）と「共有の写真」（`PhotoPicker`。ショップの写真から選ぶか、新しく上げる）、下のバナーに「保存する」。下のパネルに「古い URL からの転送」: 古い URL と新しい URL の 2 つの欄と「転送を足す」、その下に一覧（`AppTable` の `stack`。古い URL・新しい URL・入れ方〔「URL を変えた時に自動」は藍のバッジ、「手で足した」は灰色のバッジ〕・「消す」の `ConfirmButton`）。無ければ「まだ転送はありません。」。誤りは欄の下（サーバーの応答のまま）。運用より下の人には欄とボタンを出さない
- **商品**: 商品のフォームの「検索と共有」の節（上の「商品のフォームの型」）。自動の説明の元は短い説明、無ければ説明のブロックの文の頭
- **カテゴリ・ページ**: 一覧の「編集」「タイトルと URL」で開く欄の下に `SeoFields`。slug（URL）を変えると、欄の下に「前の URL を開いた人は新しい URL へ自動で移ります」

### ページの一覧（自由なページ。ADR 0039 段階 3）

経路は `/tenants/{店}/pages`（`shop-pages`）、メニューの「デザイン」の「ページ」のタブ。

- **ページを作る**（運用の段階から）: タイトル・URL（`/pages/` のあとに続く部分。英小文字・数字・ハイフン）・「ショップのメニューに載せる」・雛形（`PageTemplatePicker`。白紙が既定。雛形を選ぶと、ショップで使っているテーマの下書きにセクションの並びが入る）。作ったページは下書き。URL の形・予約語・重なりの誤りは欄の下に（サーバーの応答のまま）、雛形の誤り（置けないなど）は上の通知に
- **一覧**（並び順＝メニューの順）: タイトル・URL・メニューに載せるか・状態（`StatusBadge`: 公開中・下書き）・「中身を作る」（ページの編集の画面へ。文書ごと読み直して入る）・「見る」（公開中だけ）・公開する／非公開にする・上へ／下へ・「タイトルと URL」（行の下に `InsetSection` で開く）・「ゴミ箱へ」（`ConfirmButton`）
- **ゴミ箱**（あるときだけ）: 戻す（並びの最後へ。同じ URL のページがあれば断る）・「完全に消す」（`ConfirmButton` で確認してから。戻せず、すべてのテーマの中身も消える）。ページは 1 つの店に 50 個まで（ゴミ箱も数える。完全に消すと空く）
- **テーマを替える前の通知**（「デザイン」のテーマのタブの、ほかのテーマのカードの「このテーマにする」の問い）: 問いを開くと、替えるとコピーできないセクション（テーマ固有のセクション）のある自由なページと、コピーできないセクション・コピーするセクションの数を `AppNotice`（warning）で出す。基本のセクションはコピーし、コピーできないセクションは前のテーマに残る（戻せば戻る）と書く

### ヘルプ（説明のページ）

- **中身はデータ、画面は 1 つ**: 目次の順・タイトル・一言の説明は `navigation.js` の `HELP_PAGES`、節は `resources/admin/help/<名前>.js`（`help/index.js` がまとめる）。描くのは `HelpArticlePage` の 1 つだけで、ページごとの画面を作らない。目次・検索・各画面の「説明を見る」・よくある質問は同じデータから作る
- **節の形**: `{ id, title, screens, body, list, steps, figures, notes, caution }`。`id` は URL の `#` の後ろ（英小文字・数字・ハイフン）。`screens` はその節を「説明を見る」の行き先にする画面（router.js の名前。1 つの画面はすべての節を通して 1 か所だけ）。文は文字列か部品の並び（文字・`{ strong }`・`{ help, section, text }`）で、HTML と外の URL は書かない
- **書く中身**: 今のコードと画面を見て確認したことだけ（無い機能・違う手順を書かない）。お店の人向けの言葉（`docs/design/terms.md`）。他社の製品名は書かない（接続する先のサービス名はよい）。機能や画面の言葉を変えたら、関係する節も同じ段階で直す
- **スクリーンショット**: `tests/e2e/help-shots.spec.js` で撮る（`HELP_SHOTS=1 npm run e2e -- help-shots.spec.js`）。場面ごとに新しい店（`showcase` で店の名前は SAMPLE SHOP）を作り、見本の値を入れて撮る。お金や外のサービスの状態は API の応答を差し替えて出す。ほかの会社の画面は撮らない。撮った png は `resources/help/` に置き、データの `width`・`height` をスクリーンショットの大きさに合わせる（違うと `help-data.spec.js` が今の大きさを示して落ちる）
- **説明のページの画面**: 節ごとに白いカード、広い画面では右に節の目次（`FormOutline`）。`#節` で開くとその節へ移り、焦点も移す。`?shop=店` で来たとき（各画面の「説明を見る」から）と見られる店が 1 つのときは、節の右上に「（画面）を開く」で元の画面へ戻れる。最後に「よくある質問」への案内
- **検索**: 目次の画面で、打つたびに手元のデータから探す（サーバーへは送らない）。空白で区切ったすべての言葉を含む節を、タイトルに当たったものから並べる。全角と半角・大文字と小文字はそろえて比べる。言葉は URL（`?q=`）に置き、戻っても残る
- **確認**: `tests/e2e/help-data.spec.js`（ブラウザを開かずにデータの形・行き先の画面・スクリーンショットのファイルと大きさ・ヘルプの中のリンク・HTML と他社の製品名が無いこと・検索）、`tests/e2e/help.spec.js`（目次から全部のページ・検索・各画面の「説明を見る」から該当の節へ）

## 5. 言葉

- ボタンは押した結果が分かる言葉にする（「保存」より「保存する」、「戻る」より「一覧に戻る」）。消す・取り消すなど本人の意思が要る操作は「〜する」（ベ 10）
- 誤りは「何が・どこで・どうすれば」（ベ 17）。技術用語を出さない（状態の番号は括弧で添えるだけ）
- 数は単位を付ける（「7 件」「¥1,500」）。空は「—」

## 6. これからの画面で守ること

- 対処の要るもの（記録のチェーンの切れ、在庫切れ、要対応の取引）は、メニューか概要の画面ですぐ目に入るようにする（ベ 16）
- 飾りのダッシュボード（使われないグラフ）は作らない。概要の画面は「次にやること」と数を出す（ベ 20）
- 複数を選んで一括で操作するときは、選んだ行を目立たせ、操作を選択のすぐ近くに出す（ベ 23）
- トグルスイッチは、押した瞬間に切り替わる ON/OFF だけに使う。保存ボタンで反映するものはチェックボックスかラジオ（ベ 24）
- 使う頻度が低く影響の大きい操作は、手順を分けて確認を挟む（クリック数を減らすことに固執しない。ベ 7）
- アイコンだけで意味を伝えない（ベ 2）

## 7. 動き

共通の決まり（控えめに・何を動かすか・「動きを減らす」の扱い）は [docs/design/motion.md](motion.md)。ここは管理画面の画面を作る人向けの使い方。

### 画面に何も書かなくても動くもの

| どこ | 動き | 置き場所 |
|---|---|---|
| 画面の切り替え | 別の画面（経路の名前か引数が変わった）へ移ると、中身が下から 4px でふわっと出る（0.2 秒）。前の画面はすぐ消す。絞り込み・並べ替え（URL の `?` の後ろ）では動かない | `AppShell`（`fadeUp`） |
| 押した手ごたえ | `AppButton`・`ChoicePills`・`SegmentedTabs`・`LinkList` の行・メニューの項目・店の切り替え・メニューを畳むボタンは、押している間だけわずかに縮む | `controlClasses.js` の `PRESS` / `PRESS_WIDE` |
| 保存した印 | `loading` で回していた `AppButton` は、回し終えた時に済んだ通知（`AppNotice` の `success`）が出ていれば、スピナーの場所にチェックを 1.2 秒出す。失敗した時は出ない | `AppButton`・`AppNotice` |
| 通知 | `AppNotice` が下から少し浮いて出る（消える動きは付けない） | `AppNotice` |
| メニューを開く | 畳んだメニューを開くと、項目の名前が横から 4px で出る（最初に描く時は動かない） | `AppShell`（`animate-reveal-x`） |
| 開き閉じの欄 | `AppReveal` の中身は上から 4px で出て、閉じる時は同じ道を戻る。`details` の中身は開いた時だけ出る | `AppReveal`・`admin.css` |
| 店の切り替えの窓 | `AppReveal` と同じ（上から 4px で出て、閉じると戻る） | `ShopSwitcher` |
| 押す前に確認する | `ConfirmButton` の問いと 2 回目のボタンが横から出る | `ConfirmButton` |
| 「ようこそ」をめくる | 次の 1 枚が横から 4px でふわっと出る（0.2 秒） | `WelcomeCard` |
| 本人確認の窓 | 少し縮めた形から出て、後ろの幕は薄く出る | `ConfirmDialog`（`animate-pop`・`animate-fade`） |

画面（`pages/`）で保存の印を付けたいときは、いつもどおり `AppButton` に `:loading` を渡し、済んだら `AppNotice tone="success"` を出すだけでよい。

```vue
<AppNotice v-if="message" tone="success">{{ message }}</AppNotice>
<AppButton type="submit" variant="primary" :loading="busy">保存する</AppButton>
```

### 部品に動きを足すとき

- 動きは**部品（`components/ui`）の中だけ**に書く。画面に動きのクラスや motion-v を書かない（画面は並べ方だけ。`AdminShellTest`）
- 長さ・イージング（速さの付け方）・距離は `components/ui/motion.js` の値を使う（`DURATION`・`EASE_OUT`・`SHIFT`・`TRANSITION`・`TRANSITION_FAST`）。CSS で書くときは `admin.css` の `--ease-soft` と `animate-reveal-x`・`animate-reveal-y`・`animate-pop`・`animate-fade`。その場で秒数を作らない
- 出る・変わる動きは motion-v の `m.*`。`App.vue` が全体を `MotionConfig`（`reducedMotion="user"`）と `LazyMotion`（`domAnimation`）で包んでいるので、部品は `m` を書くだけ（`motion.*` は全部の機能を読むので使わない）

```vue
<script setup>
import { m } from 'motion-v';
import { TRANSITION_FAST } from './motion.js';
</script>

<template>
    <m.span :initial="{ opacity: 0, scale: 0.6 }" :animate="{ opacity: 1, scale: 1 }" :transition="TRANSITION_FAST">…</m.span>
</template>
```

- 開き閉じは `AppReveal` で包む（`<AppReveal :show="open" class="flex flex-col gap-3">…</AppReveal>`）。消える動きに motion-v の `AnimatePresence` を使わない（それだけで gzip +4.4 kB。`AppReveal` は Vue の `Transition` と CSS）
- 押した手ごたえは、押せる要素のクラスに `PRESS`（幅の広い行は `PRESS_WIDE`）を足す。`transition-colors` は外す（`PRESS` が色の移り変わりも持つ）
- ブラウザの Web Animations で直に動かすときは `motion.js` の `reducesMotion()` を先に見る（`fadeUp` が見本）

### ブラウザのテスト

- `playwright.config.js` で `reducedMotion: 'reduce'` にしてある。動きは止まり、`AppReveal` は閉じたらすぐ消える。テストで動きの終わりを待たない（`waitForTimeout` を足さない）
- 保存の印は `data-test="button-done"` で見られる（「動きを減らす」でもチェックは出る。止まるのは動きだけ）

### やってはいけないこと

- 幅・高さ・余白・位置（`width`・`height`・`margin`・`top` など）を動かす。動かすのは `transform` と `opacity` だけ（レイアウトをずらさない）
- インラインの style（`:style`・`style="…"`）で動かす。CSP で止まる。motion-v かクラスか Web Animations で
- 0.25 秒より長い動き・10px を超える移動・はねる動き・くり返す動き（スピナーの `animate-spin` は除く）・読み込みのたびに動くもの
- 「動きを減らす」の人に動きを見せる。CSS は `motion-reduce:` か `admin.css` の受け皿、motion-v は `MotionConfig` か `useReducedMotion` で止める
- 通知（`AppNotice`）を全部の画面で `AnimatePresence` に包んで消える動きを付ける（出る動きだけと決めた）

## 8. 確認の方法

- `make e2e`: 本物のブラウザで操作をエンドツーエンドで確認し、CSP と Trusted Types の違反が 0 件であることも見る
- `E2E_SCREENSHOTS=1 npm run e2e`: 主な画面のスクリーンショットを `test-results/screens/` に撮る（ライトとダーク）。見た目を変えたら目で見る
- `php artisan test --filter='AdminShellTest|AdminContrastTest'`: 危ない書き方・色の直書き・コントラスト
