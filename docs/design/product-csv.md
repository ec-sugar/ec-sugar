# 商品の CSV（まとめて登録・書き出し）

ほかのサービスから移る店の入口として、商品と種類を CSV で書き出し・取り込む（2026-11-04）。
店の人向けの使い方は管理画面のヘルプ（「商品の登録」の「CSV でまとめて登録・書き出し」。`resources/admin/help/listings.js`）。ここは形と決まり（エンジニア向け）。

コードは App の `plugins/plugin-product-csv/src/`（読む・行を確認する・商品ごとにまとめる・確認と反映〔`ProductCsvImporter`〕・記録を進める〔`ProductImports`〕・キューの仕事〔`Jobs/`〕・書き出す）、記録の表は店の DB の `product_imports`（コアのマイグレーションのまま）、エンドポイントは `app/Admin/Http/Controllers/Api/ListingCsvController.php`、画面は `resources/admin/pages/ListingImportPage.vue` と商品の一覧の右上のボタン。
2026-11-18 にコア（`app/Core/ProductCsv`）から App へ出した（ADR 0107 の段階 1。配送の CSV が App なのに商品の CSV がコアにあったため）。動かしたのは居場所と名前空間（`EcSugar\PluginProductCsv`）だけで、画面・経路・CSV の形・DB の形は変えていない。**画面とエンドポイントはコアのまま**（ファイルを上げる・確認の画面を挟む・ファイルを返すは App の画面の口では描けない。ADR 0036）で、下の経路はどれも使う店の印（`plugin:product-csv`）を通るので、App を止めた店では 404 になる。CSV の欄の差し込みよけ（`CsvCells`）は、売上の集計の CSV も同じ決まりで書き出すのでコアに残した（`app/Core/Csv/`）。

## 経路

| 経路 | すること | 段階 |
|---|---|---|
| `GET /api/tenants/{店}/listings-csv` | 書き出し（`text/csv`、添付の名前は `products-{店}-{日時}.csv`） | 運用 |
| `POST /api/tenants/{店}/listings-csv/check` | 上げる（`file`。写真の ZIP は `photos`、なくてもよい）。ファイルの形を見て（ZIP はここで展開して）記録を作り、確認の仕事を出す（202）。形が違えば 422 で記録を作らない | 運用（1 分 30 回まで） |
| `GET /api/tenants/{店}/listings-csv/imports` | 新しい記録から 5 つ（画面を開いたとき） | 運用 |
| `GET /api/tenants/{店}/listings-csv/imports/{ID}` | 1 つの記録（画面はこれを読み直して待つ） | 運用 |
| `POST /api/tenants/{店}/listings-csv/imports/{ID}/apply` | 反映を依頼する（202）。誤りの無い確認済みの記録だけ。ほかの反映が待ち・進行中なら 409 | 運用 |
| `POST /api/tenants/{店}/listings-csv/imports/{ID}/retry` | 止まった記録を、同じ CSV の新しい記録で確認からやり直す（202） | 運用（1 分 30 回まで） |

記録（`product_imports`。店の DB）の形: `status`（checking 確認中・checked 誤り無し・rejected 誤りあり・queued 反映の待ち・running 反映中・done 済み・stopped 止まった・expired 確認したまま 1 日たった）・`rows`・`report`（確認の結果: `counts`〔`create`・`update`・`skip`・`error` の行の数〕・`products`・`extra_variants`〔CSV に無いのに組み合わせでできる種類の数〕・`errors`〔`line`・`column`・`message`。200 件まで〕・`errors_total`・`photos`〔`add` 足す写真・`keep` もう付いている写真・`warnings` 入れない写真の行と理由〔200 件まで〕・`warnings_total`〕）・`applied`（反映で入った行の数）・`applied_rows`・`has_archive`（写真の ZIP を一緒に上げたか）・`photo_phase`（反映の後半の写真の行にいるか）・`photos_done`（写真の行で済んだ数）・`photos`（写真の反映の結果: `total`・`added`・`kept`・`failed`・`problems`〔行・列・理由。200 件まで〕・`problems_total`）・`stopped_line`・`stopped_reason`・`retryable`。CSV の中身と ZIP の中身の一覧は画面に返さない。

## 形（EC-SUGAR の形）

UTF-8 の BOM つき・改行は CRLF・1 行目が見出し。**1 行が 1 つの種類**（色・サイズの組み合わせ）。軸の無い商品は 1 行。

| 見出し | 中身 | 空のとき |
|---|---|---|
| 商品ID | 商品の ULID（書き出しの値をそのまま） | 品番か商品名で決める |
| 品番 | 種類の品番（半角英数字と `. _ -`、64 文字まで） | 品番を外す |
| 商品名 | 200 文字まで | 変えない（新しい商品には要る） |
| 状態 | 下書き・公開中・終了（`draft` などでも読む） | 変えない（新しい商品は下書き） |
| 価格 | 商品の価格（円の整数。3 桁ごとのカンマと全角の数字は読む） | 変えない（新しい商品には要る） |
| 種類の価格 | 種類だけの価格 | 商品の価格で売る |
| 在庫 | **この数にする**（足す数ではない） | 変えない |
| 種類の販売 | 販売中・停止中 | 変えない（新しい種類は販売中） |
| 選ぶ項目1〜3 / 選ぶ項目1〜3の値 | 軸の名前と、この種類の値（名前と値はペアで、1 から順に） | 軸の無い種類 |
| カテゴリ | カテゴリの slug をカンマで区切る。最初が主カテゴリ（10 個まで） | カテゴリを外す |
| 短い説明 | 200 文字まで | 外す |
| 説明 | 説明の文（ブロックの文をつないだコピー） | 外す |
| オプション | JSON の並び（AddonService の入力と同じ形: `kind`・`name`・`required`・`choices` か `amount`・`max_length`） | 外す |
| 税率 | 標準・軽減（`10%`・`8%`・全角の `８％`・`standard`・`reduced` でも読む。書き出しは「標準」「軽減」。ADR 0063） | 変えない（新しい商品は標準） |
| 写真1〜写真10 | 商品の写真を並べたい順に。https の URL か、一緒に上げる ZIP の中のファイル名（下の「写真」） | 変えない（写真は足すだけで消さない） |

- 列が無ければ、その項目は変えない（ほかのサービスの形で列が少ないとき）。商品を決める列（商品ID・品番・商品名）のどれかは要る
- 商品の欄（商品名・状態・価格・カテゴリ・短い説明・説明・オプション・税率）は、同じ商品の 2 行目からは空でよい。書くなら 1 行目と同じ値に（違えば誤り）
- 書き出しは消していない「商品」（kind = product）だけ。在庫は出品者の最初の拠点の数。写真はショップの写真の公開の URL（`https://{ショップ}/media/listings/{写真の ID}/large`）を並び順に（ショップのドメインが無い店は空）

## 決まり

- **商品の決め方**: 商品ID → 品番（今の種類の品番。店の中で 2 つの商品に当たるなら誤り）→ 前の取り込みでその商品名で作った商品（もう一度取り込むとき）→ 商品名（同じ名前の行が 1 つの新しい商品）の順。商品ID と品番が別の商品を指せば誤り
- **種類の決め方**: 選ぶ項目の値の組み合わせ。選ぶ項目の列が無い形では品番、それも無ければ軸の無い商品のただ 1 つの種類
- **消さない**: CSV に無い商品も種類もそのまま。今の商品の選ぶ項目の名前と順は変えない（違えば誤り。変えるのは商品の画面）。値は後ろに足せる。足すと全部の組み合わせの種類ができる（在庫 0・販売中。報告の `extra_variants`）
- **在庫**は出品者の最初の拠点で、今の数との差を棚卸しの調整（`AdjustmentReason::Stocktake`）として `InventoryOperations::adjust` に渡す。確保中の数より少なくはできない
- **説明**は `ListingService` の「前の形（文だけ）」の道を通る。書き出したままの文なら変えない（ブロックの形が残る）。文を変えると 1 つの段落になる
- **新しい商品**は最初に作った出品者に登録する（マーケットの形で出品者を選ぶのは、まだ無い）
- **差し込みよけ**: 書き出しで、文字の欄が `= + - @`・タブ・CR（全角の `＝＋－＠` も）で始まるとき頭に `'` を付ける。取り込みでは、`'` の次がその文字のときだけ外す
- **文字の形**: UTF-8（BOM はあってもなくてもよい）か、表計算ソフトの既定の Shift_JIS（CP932）。NUL のあるファイルは断る
- **上限**: 5MB・2,000 行（見出しと空の行を除く）・1 つの欄は 5 万文字・写真は 1 回に 2,000 枚（写真の列の空でない欄の合計）

## 確認と反映

- **どちらもキューの仕事**（`CheckProductImport`・`ApplyProductImport`）。上げたファイルは UTF-8 の文にして記録に置き、仕事は記録の ID だけを受け取る（店の文脈は stancl/tenancy が接続する）。確認もキューにしたのは、2,000 行の確認が手元で約 26 秒、前の測りでは約 41 秒で、nginx の既定の 60 秒に近く、本番のマシンの速さで超えうるため。画面は記録を 1.5 秒ごとに読み直して待つ
- **1 回の仕事は約 45 秒で区切る**（`ProductImports::$jobSeconds`）。過ぎたら、次の商品の最初の行を `next_line` に書いて続きの仕事を出す。本番のランナーの時間の上限（`--timeout=75`）と送り直しまでの時間（`retry_after` 90 秒）より短くし、長い仕事が二重に動いたり途中で切られたりしないように。1 回に少なくとも商品 1 つは進める
- **確認**は、商品ごとに短いトランザクションを開いて本当に書き、毎回巻き戻す（チェーンのロック → コアのサービス → ROLLBACK）。誤りがあっても次の商品へ進み、誤りの行をまとめて記録に書く。商品どうしは独立している（品番の重なりはファイルの中で先に見る）ので、1 つずつ巻き戻しても、反映したときと同じ数になる。誤りが 1 つでもあれば rejected で、反映できない
- **反映**は、商品 1 つずつコアのサービスの短いトランザクション（いつもの `EventStore::lock()` の入れ子）で書いて確定する。チェーンのロックを持つのは 1 つの商品の間だけなので、商品の間にショップの注文などが割り込める（テストで、商品ごとに別の接続からチェーンのロックと行のロックを 2 秒の待ちの上限で取れることを確認している）。商品を 1 つ確定するたびに、記録の進み具合（`applied`・`applied_rows`・作った商品）を書く
- **途中で断られたら、そこで止める**（全部は巻き戻さない）。確認で誤りが無いことを保証してあるので、止まるのは確認の後に店の中身が変わった時（注文で在庫が確保された、など）か思わぬ誤りの時だけ。記録に「入った行の数・止まった商品の最初の行・理由」を残す。入った商品はそのまま
- **もう一度取り込む**: 止まった記録の CSV で新しい記録を作り、確認からやり直す。商品は ID・品番で合わせ、品番の無い新しい商品は前の取り込みが作った「商品名 => ID」（記録の `created`）で合わせるので、入った分は「変わらない」になり、残りだけが入る
- **同じ店で反映は 1 つだけ**: 依頼するときに待ち・進行中の記録があれば 409。DB でも部分の一意の索引（`status IN ('queued','running')`）で 2 つ目を断る（同時に押しても入らない）
- **片付け**: 進行中のまま 15 分進み具合が書かれない記録・待ちのまま 60 分始まらない記録は、次に取り込むときに止まった扱いにする（ランナーが落ちた時に、ずっと 409 にならないように）。キューの仕事が時間切れで落ちたときも止まった扱い。済んだ・断った・古くなった記録の CSV は消す
- 記録（`product_imports`）は取り込みの仕事の進み具合で、商品・在庫の状態ではないので、チェーンのロックとイベントを使わない（conventions.md の 3 の例外）。状態の書き換えは「今の状態がこれなら」の 1 文の更新で取り合う。商品・在庫の変更は、コアのサービスがそれぞれイベントに取り込んだ人の actor（`operator:<ID>`）で残す
- 反映を依頼したら、誰が・何件（確認の数）を中央の監査ログ（`operator.listings_imported`）に残す
- 時間（2026-11-04、手元のテストの環境。sync のキューで測った）: 2,000 行の新しい商品で確認約 26 秒・反映約 37 秒。1,000 行の書き出し約 3 秒

## 写真

ほかのサービスから移る店が、写真を 1 枚ずつ上げ直さずに済むように。コードは `ProductCsvPhotos`（値の確認・見積もり・1 枚を入れる・並べる）・`PhotoArchive`（ZIP）・`ProductImportPhotos`（反映の写真の行）・コアの `Media\RemoteImages`（外の URL から取る）。

**列の形（決めたこと）**: `写真1`〜`写真10` の 10 列（1 つの商品の写真の上限と同じ）。1 つの欄に区切りで並べる形にしなかったのは、URL にはカンマ・セミコロン・空白の入ったものがあり区切りの文字を決められないこと、表計算ソフトで 1 枚ずつ直しやすいこと。列は CSV の末尾に足した（前からの列の並びを崩さない。ほかの列を足すときも末尾に）。写真は商品の欄で、同じ商品の 2 行目からは空でよい（書くなら 1 行目と同じ）。

**値は 3 つのどれか**:

| 値 | すること |
|---|---|
| この店の写真の公開の URL（書き出した CSV の値。パスが `/media/listings/{ID}/large` か `medium` で、その ID の写真がこの店にある） | 同じ商品の写真なら何もしない（「付いている」）。ほかの商品の写真なら保存先からコピーする（外へ出ない）。ホストは見ない（店のドメインを替えても往復できる）。ほかの店の写真の URL は、この店に無いので外の URL として扱う（ほかの店の保存先は読まない） |
| `https://` の URL | 反映のときにサーバーが取りに行く（下の「外へ取りに行く」） |
| それ以外 | 一緒に上げた ZIP の中のファイル名。まず名前そのまま、無ければフォルダを除いた名前が 1 つだけ当たるもの（`b.jpg` で `mug/b.jpg`）。名前は NFC にそろえて比べる（macOS の ZIP は NFD で書く） |

- **足すだけで消さない**。CSV に無い今の写真は残し、CSV の写真を CSV の順で前に、残りをその後ろに今の順で並べる（`ListingImageService::reorder`）。並び順だけを変える取り込み（足す写真も変わる行も無い）は反映できない（「変わる行がありません」）。並べ替えは商品の画面で
- **二重に作らない**: 写真に元のファイルの中身の SHA-256（`listing_images.source_digest`）と、取りに行った URL の SHA-256（`source_url_digest`。URL そのものは残さない）を残し、その商品の写真と照らす。同じ URL は取りに行き直さない。違う URL でも中身が同じなら入れない。書き出した CSV をそのまま取り込むと、写真は全部「付いている」になる
- **1 枚が駄目でも止めない**: 形の違う値・http・内向きの IP アドレス・ZIP に無い名前・画像でない・大きすぎる・取れない・11 枚目は、その写真だけを飛ばし、行・列・理由を残す。確認の画面には取りに行かなくても分かるもの（形・http・URL そのもの・ZIP の中身・10 枚を超える）を「写真が取れない行」として出し、反映の後に取りに行って分かったものも合わせて出す
- **反映は商品を全部入れた後に写真の行**（`photo_next`）: 写真は 1 枚ずつコアの写真のサービス（`ListingImageService::add`。チェーンのロックとイベント `listing.image_added`、actor は取り込んだ人）で作り直して入れる。1 枚ごとに進み具合を書く。1 回の仕事は約 45 秒で区切り、1 枚の取りに行きは 15 秒まで（ランナーの `--timeout=75` に収める）
- **写真の保存先の上限**（`MediaQuota`）: 1 分に作り直せる数（既定 30）に触れそうなら、ランナーを眠らせずに、空くまで遅らせた続きの仕事を出す（ほかの仕事を止めない）。店の合計（2 GB）とその日の量（500 MB）に触れたら、そこで止めて理由を残す（入った写真は残る）。空けてから「もう一度取り込む」と、商品は「変わらない」で、残りの写真だけが入る（ZIP の保存先も新しい記録へ引き継ぐ）
- 写真だけを足す取り込み（行が全部「変わらない」で写真を足す）も反映できる

### 外へ取りに行く（SSRF よけ。`RemoteImages`）

- https だけ・443 番だけ・ユーザー名とパスワードつきは断る。点の無い名前・`localhost`・`.local`・`.internal` などの内向きの名前、終わりが数の名前（`0x7f.1`・`2130706433` のような IP アドレスの別の書き方）も断る
- 名前を解決した IP アドレスが **1 つでも**内向き（127/8・10/8・172.16/12・192.168/16・169.254/16・100.64/10・0/8・224/4・::1・fc00::/7・fe80::/10・IPv4 を埋めた IPv6・NAT64・6to4 ほか。PHP の `FILTER_FLAG_GLOBAL_RANGE` と明示の一覧の両方）なら断る。接続する先は確認した IP アドレスに固定する（curl の `CURLOPT_RESOLVE`。確認した後に DNS を引き直させて中へ向ける DNS rebinding を断つ）。応答の後に、接続した相手の IP アドレスも確認し直す
- リダイレクトは自分でたどり（3 回まで）、行き先ごとに名前を引き直して同じ確認をする。プロキシは使わない（環境変数も）。https 以外へは Guzzle の `protocols` でも断る
- 時間切れ: 接続する 5 秒・リダイレクトを含めた全体 15 秒。大きさ: 10 MB（Content-Length・受け取りの途中〔Guzzle の `progress` で打ち切る〕・受け取った量の 3 つで）
- 画像の形: Content-Type が画像（か、通知が無い・`application/octet-stream`）で、中身も JPEG・PNG・WebP として読めるものだけ。入れるときは必ず作り直す（`ImageProcessor`）
- 送るのは写真の URL への GET だけ（店の名前や中身は送らない。User-Agent は `EC-SUGAR product import`）
- テストでは名前を解決する部品（`HostResolver`）を差し替え、`Http::fake` で外へ出ない

### ZIP（`PhotoArchive`）

- 上げた要求の中で展開する。上限: ZIP 90 MB（受付の nginx は CSV の取り込みの経路だけ 100m。前に置く Cloudflare の 1 回の要求の上限 100 MB に収めた）・中のファイル 2,500 個・展開した合計 300 MB（書いてある大きさを信頼せず、読みながら数えて超えたら全部を断る。ZIP 爆弾よけ）・1 枚 10 MB。ZIP として開けない・数・合計で断るときは 422 で、記録もファイルも残さない
- ZIP の中の名前はパスとして使わない（`extractTo` を使わない）。置くファイルの名前はこちらが決める番号（`00001.img`）で、名前は CSV と照らすためだけに使う。`..`・`/` で始まる名前・ドライブ名・制御文字の名前・シンボリックリンク・暗号化したファイル・同じ名前の 2 つ目・画像として読めないものは、置かずに理由だけを一覧に残す（CSV がその名前を指すと「写真が取れない行」になる）。名前は UTF-8 でなければ Shift_JIS（CP932。日本の Windows の ZIP）として読む。macOS が足す `__MACOSX/`・`._*`・`.DS_Store` は黙って飛ばす
- 保存先は写真の保存先（`media`）の `tenants/{店}/imports/{ULID}/`。記録（`product_imports.archive`・`archive_files`）に保存先の名前と中身の一覧を残す。済んだ・断った・確認したまま 1 日・止まったまま 1 日で消す（止まったまま 1 日たった記録は CSV も消し、もう一度取り込めなくなる）。店を消すと店の写真と一緒に消える
- CSV に写真の列が無いのに ZIP を上げたら 422

### 受付の大きさ（本番）

商品の CSV と ZIP を上げる経路（`/api/tenants/{店}/listings-csv/check`）だけ、受付の nginx が本文を 100m まで受ける（管理画面のホストの POST だけ。ほかの経路は管理画面の API が 12m、ショップ・通知・ログインは 1m〔〕。`docker/nginx/prod.conf`）。PHP は `upload_max_filesize = 91M`・`post_max_size = 100M`（ほかの経路は nginx が先に断るので PHP まで大きな本文は届かない）。受けた本文は nginx の `/var/cache/nginx` と PHP の `/tmp`（どちらも tmpfs）に一時に置かれるので、どちらも 256m にした（使った分だけメモリを取る）。前に別の Web サーバーを置く形は、その Web サーバーの上限も 100m に（docs/install.md）。

## ほかのサービスの形を足す

`ProductCsvFormat` に形を 1 つ足し（見出しの名前 → 列の鍵の対応と、状態・種類の販売の呼び名）、`ProductCsvFormat::formats()` に並べる。見出しの行の名前が全部わかる最初の形を使う。値の形（価格の書き方など）が違うときは、`ProductCsvRows` の読み方を形ごとに分ける。
