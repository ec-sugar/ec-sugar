# 0081 守りは核の部品と経路の宣言で掛け、付け忘れは全部の経路を調べるテストで落とす

状態: **採用**（2026-11-06）。ADR 0013（管理画面）・0018（ショップ）・0025（プラグインの登録簿）の上に置く

## 要点（先に）

1. **守りの位置づけを進める**: 「用意された守りを、新しい機能を作る人が呼ぶ」から、「対象の機能には核が自動で掛ける。掛からない書き方は、全部の経路を一度に調べるテストか、コードを静的に探すテストが落とす」へ
2. **秘密の道筋の宣言 `secret-link`**: URL に署名か合い言葉を持つショップの画面は、経路に `->middleware('secret-link')`（署名を核に確かめさせるなら `secret-link:signed`）と書く。宣言した経路のどの応答（403・404・419・429・転送も）にも、核が「参照元を渡さない（`Referrer-Policy: no-referrer`）・残さない（`Cache-Control: no-store, private`）・検索に載せない（`X-Robots-Tag: noindex, nofollow`）」をまとめて掛ける
3. **署名つきの URL は核の `SecretLinks` だけで作り、確かめる**: 行き先が宣言を持たなければ作らない。店の ID（`shop`）を必ず入れ、期限は必ず付けて 31 日まで
4. **回数の上限は核の `Throttle` だけで数える**: 先に数えてから比べる（足し算の戻り値で）。いくつかの上限は狭いものから数え、越えた所で止める。店の中のキーは `Throttle::shopKey`。足し算そのものも、Laravel の数え方の競合を直した `AtomicRateLimiter`（経路の throttle も同じ）
5. **必須の守りはミドルウェアかサービスで強制する**。実行の順が決まらないイベントやフック（App の口）に任せない。App が足すのは知らせ・集計などの付け足しだけ
6. **見張り**: 全部の経路の調べ（`RouteAudit` の規則 10〜15）と、コードの静的な調べ（`SharedGuardsTest`）。例外は理由つきの一覧にだけ書き、要らなくなった例外が残っても落ちる
7. **検査がどこでも同じ結果に**: `make check-docker` で、本番と同じ PHP と拡張のコンテナの中で pint・phpstan（CI と同じ設定）・テストを流す

## 文脈

- 外からの見直しの総評（2026-11-06）: 「参照元への署名漏れやメール制限の競合は、既存の対策を新機能で適用し忘れた種類の問題。個別の注意でなく共通処理や自動検査で防ぐ余地がある」「依存とローカル環境のずれで PHPStan にエラーが残った。誰がどの環境で検査しても同じ結果になる状態に」
- 前回の指摘の直し（PR 100）は、署名つきの注文とレビューの画面に参照元の決まりを足し、お問い合わせとメルマガの回数を先に数える形に直した。どちらも、ほかの機能では既に正しく書いていた守りを、新しい機能で書き忘れた・別の書き方をしたもの
- それまでの形: 参照元の決まりは、コントローラーが `StorefrontSecurityHeaders::withoutReferrer` を呼ぶ形と、App が見出しを直に書く形（商品フィード）が混ざっていた。`no-store` と `noindex` も画面ごとに書いていた。署名つきの URL は App ごとに `URL::temporarySignedRoute` を呼び、店の ID を入れるかどうかも App ごとに違った（注文と贈り物は入れていなかった）。回数の上限は、`tooManyAttempts` で見てから `hit` で数える形（同時の要求が上限を越える）と、先に数える形が混ざっていた
- 要求の段階ごとに担当する守りを決める考え方（受付 → 店の特定 → 認証・認可 → 入力検証 → 処理 → 応答）で並べると、どの段階でも「核が自動で掛ける」「経路に宣言する」「自分で書く」の 3 つに分けられる（docs/development/conventions.md の 4b の表）

## 決めたこと

### 秘密の道筋（応答の段階）

- 宣言は経路のミドルウェア `secret-link`（`App\Storefront\Http\Middleware\SecretLink`）。経路の名前や引数から推し量って黙って掛ける形にはしない（宣言を読めば分かる・見張りのテストが宣言の有る無しで落とせる）
- 3 つの見出しは、ショップのミドルウェア群の一番外側の `StorefrontSecurityHeaders` が、決まった経路の宣言を見て掛ける。宣言のミドルウェア自身は経路のミドルウェアの中ほどにいるので、そこで掛けると、それより外で断った応答（CSRF の 419・回数の上限の 429・準備中の関所の転送）に掛からない。一番外側で掛ければ、どの応答にも掛かる
- 書き方は 2 つ: `secret-link:signed` は核が署名を確かめる（`SecretLinks::valid`。合わなければ中身の無い 404）。`secret-link` は確かめをコントローラーに任せる（道筋の合い言葉を App の表と照らす・署名か会員のどちらかで開く・用途ごとの鍵の署名〔プレビュー〕）。知らない書き方は 500 で止める（中身は出さない）
- 応答ごとに秘密を持つ時と持たない時がある経路（公開の写真の経路に、プレビューの署名が付いた時だけ）は、今までの `withoutReferrer` を残す
- 宣言した経路（2026-11-06）: ご注文の確認（`/orders/{ID}`）・商品とテーマのプレビューと区画の試し見、App のレビュー・お問い合わせ（注文から）・領収書・贈り物（注文と受け取り）・再入荷・メルマガ・お気に入り・カゴ落ちのリンク、商品フィード、お知らせ・ブログのプレビュー、LINE のログインの戻り（認可コードが問い合わせに載る）
- 秘密でない引数（郵便番号・配るための紹介のコード）は、理由つきの一覧 `RouteAudit::OPEN_PATH_SECRETS` にだけ書く

### 署名つきの URL

- 作る: `SecretLinks::signed('経路の名前', [引数], 期限)`。名前は文字で書く（テストがコードから集めて、行き先の宣言を確かめる。集められない書き方は落ちる）。用途ごとの鍵で自分で署名するもの（プレビュー）は `SecretLinks::path` で道筋だけ作る（行き先の宣言を確かめる）
- 確かめる: `SecretLinks::valid($request)`。署名・期限・店の ID が今の店か。ここの外で `URL::temporarySignedRoute`・`hasValidRelativeSignature` などを使うと `SharedGuardsTest` が落ちる
- 店の ID の無い前の形（ご注文の確認のメールのリンクと贈り物の注文の画面。期限 30 日）は、2026-12-08 まで、その 2 つの経路でだけ受ける。それより後は消す

### 回数の上限（受付の段階）

- 数えるのは `Throttle::allow`（1 つ）・`Throttle::firstOver`（いくつか。狭い上限から渡す）・`Throttle::hit`（数えた後の数が要る時）。数えた 1 回を戻すのは `Throttle::refund`（合い言葉が合った・比べずに断った時）
- 断った回も数える（窓は最初の 1 回から数え、延びない）。`firstOver` は越えた所で止め、後ろの広い上限（メールごと・店ごと）を数えない。1 つの接続元が断られ続けても、ほかの人のメールの枠・店の枠を使い切らせない（前のお問い合わせ・メルマガ・0 円の注文・メールでの戻しは全部の上限を数えていた）
- 寄せた所: ご注文の照会・会員のログインのコード・LINE のログイン・ショップのパスワード・0 円の注文・ギフトカードのコード・写真の 1 分の上限・管理画面の App の画面の操作と書き出し・運営の回復用のコードとメールでの戻し、App のお問い合わせ（受付と返信と店への知らせ）・メルマガ・再入荷・贈り物・レビュー・カゴ落ち・商品フィード・予約・LINE の知らせ
- 運営の回復用のコードの接続元の上限（1 日 30 回の間違い）は、確かめる前に数え、合えば戻す形にした（前は間違えた後に数えていたので、同時に送ると上限を越えた）
- **足し算そのものも原子的に**（作っていて見つけた）: Laravel の `RateLimiter::increment` は「無ければ 0 を置く → 足す → 自分で置いていないのに 1 なら窓が切れたとみなして 1 を置き直す」の 3 手で、窓の始まりに同時に来ると、ほかの要求が足した数を置き直しで消す。本物の Redis に 40 の処理から同時に数えると、上限 5 で 9 つ通った（見てから数える形に戻すと 8 つ）。核の `AtomicRateLimiter` を Laravel の RateLimiter と差し替え（`AppServiceProvider` の extend）、Redis では足すのと窓の期限を 1 つの Lua で、ほかの置き場ではキーごとの錠の中で数える。数えの形（期限つきの数と `:timer`）は Laravel と同じなので、`attempts`・`availableIn`・`clear` はそのまま
- 経路ごとの上限（`throttle:<名前>`。Laravel が同じ形で、同じ `AtomicRateLimiter` で数える）はそのまま使う。ショップで書き込む経路には必須（規則 13）

### 強制する場所

- 必須の守り（認可・店の境界・回数の上限・秘密の道筋・書き込みの決まり）は、ミドルウェアかサービス（核の部品）で掛ける。イベントの購読やフック（App の口）は実行の順が決まらず、App を止めると動かないので、守りを任せない
- App が核の口で足してよいのは、知らせ（メール・LINE・店への知らせ）・集計・表示の付け足しだけ。App の経路は核が `/p/<名前>` の下に `plugin:<名前>` を付けて置く（規則 14 が名前と印のずれを落とす）

### 見張り（全部の経路を一度に）

`tests/Support/RouteAudit.php` に足した規則（`RouteAuthorizationTest` が全経路を一度に調べる。わざと付け忘れた経路で落ちることも同じテストで確かめる）:

| 規則 | 中身 |
|---|---|
| 10 | 道筋に合い言葉（`{token}`・`{code}`・`{secret}` など）を持つ経路は `secret-link` を持つ（管理画面は全部の応答が `no-referrer`・`noindex` で、合い言葉は URL の断片に載せる） |
| 11 | `SecretLinks` の行き先と、Laravel の `signed` を通る経路は `secret-link` を持つ |
| 12 | `secret-link` はショップの経路にだけ |
| 13 | ショップで書き込む経路は `throttle:<名前>` を通る（1 クリックの配信停止など理由つきの例外だけ） |
| 14 | App の経路の名前と `plugin:<名前>` が合う |
| 15 | ショップのセッションの群で CSRF を外すのは、理由つきの一覧の経路だけ（メールのソフトの配信停止・LINE の Webhook） |

`tests/Unit/SharedGuardsTest.php`（コードを静的に探す。コメントは数えない）: `tooManyAttempts`・`RateLimiter` で数える操作・署名つきの URL の関数・合い言葉を載せた `route()`・`Referrer-Policy` を、核の部品の外で書いていないか。入口の nginx の本文の上限（12m）と、大きな本文を受ける経路（商品の CSV と写真の ZIP だけ）。

### 検査がどこでも同じ結果に

- `make check-docker`: `docker/Dockerfile` の `check`（本番と同じ PHP と拡張の土台 `php-base` に composer を足しただけ）の中で、`composer install`・pint・phpstan（CI と同じ `phpstan.ci.neon`）・PHP のテストを流す。コードは作業場所を重ね、vendor は名前つきの volume（手元の vendor と混ぜない）。本番のイメージ（`app`）は同じ土台から作るので、中身は変わらない
- 手元の phpstan の結果が CI と違う時（11-05 は `bootstrap/cache/packages.php` が古いまま）は、まずこれで確かめる

## 作って決めたこと

- 宣言を足した経路では、コントローラーや App が書いていた `withoutReferrer`・`no-store`・`noindex` の行を消した（核が掛けるので二重にしない）。動きは同じ（前は `noindex` だけ・`no-referrer` だけの画面もあったが、今はどれも 3 つ）
- 回数の上限の部品の誤りは全部の機能に広がるので、部品のテストを厚くした（`ThrottleTest`: 上限ちょうど・1 つ越え・窓の切り替わりの前後・本物の Redis に 40 の処理から同時に数えて上限の 5 だけ通り、窓の期限も付く・キーごと・店ごと・狭い上限から数えて止める・戻す・経路の throttle も同じ数え方）。秘密の道筋も同じ（`SecretLinkTest`: 宣言した全部の経路に App を使う店と使わない店の両方で・ふつうの画面には掛からない・エラーと転送の応答・署名の書き換え・ほかの店・期限切れ・前の形の締め切り・作る時の守り）
- 機械で見張らなかったもの: 入力の上限（件数・長さ・数の範囲）・個人情報の暗号化・イベントの actor・平文の個人情報を新しい列に入れない。コードの形から正しさを決められないので、見直しの目で見る（conventions.md の「自分で付けないといけない守り」）
