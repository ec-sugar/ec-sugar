# 0063 軽減税率は商品ごとの税区分で持ち、率は核が区分から決める

状態: **採用**（2026-11-05。軽減税率を作ることは運営が決めた〔食品を売る店では 8% の品が要る〕。形は作りながら決めた）。ADR 0011（取引と仕訳）・0036（種類とオプション）・0054（値引きの行）の上に置く

## 要点（先に）

1. 商品が**税区分**（標準 10%・軽減 8%）を持つ。率そのものは区分から核が決める（表は `App\Core\Tax\TaxClass` の 1 か所）
2. 明細は**注文の時の率を写して持つ**（今までどおり `transaction_lines.tax_rate_bp`）。区分を後で変えても、作った注文は変わらない
3. オプションの行は親の商品の率、**送料は標準 10%**、クーポンの値引きは**対象の行の率ごとに行を分ける**
4. 消費税は**税率ごとに合計して 1 回だけ切り捨て**（インボイス制度。1 行ごとに丸めない）。内税のまま
5. 確かめの画面・注文の画面・メール・管理画面・領収書と納品書は、核の内訳（`TaxBreakdown`）を同じように出す

## 文脈

- 今まで店頭の注文の税率は設定の 1 つ（`storefront.tax_rate_bp` = 10%）だけだった。本番の店（お菓子）の商品は飲食料品で、軽減税率 8% の対象
- 核はもともと率の混ざった取引を扱える: 明細ごとに率（`tax_rate_bp`）を持ち、合計（`Totals`）は率ごとに合計してから 1 回だけ丸める。足りないのは「どの商品がどの率か」と、値引きと送料の率、見せ方

## 決定

### 1. 区分は商品に、率は核の表に

- 商品（`listings.tax_class`）に区分: `standard`（標準 10%）・`reduced`（軽減 8%。飲食料品〔酒類・外食を除く〕）。DB の CHECK で 2 つの値だけを受ける。既定は標準
- **種類（色・サイズ）ごとには持たない**。1 つの商品の種類は同じ物の違い（味・大きさ）で、飲食料品かどうかは商品で決まる。食品と食品でない物の詰め合わせは、別の商品にする（一体資産の判定は店が商品ごとに決める）
- 率は `TaxClass::rateBp()` が区分から決める（標準 1000・軽減 800）。**率の表はここだけ**。率が変わる時はここを直し、前の率で残った明細を読めるよう、前に軽減だった率を `TaxClass::isReducedRate()` に足す（領収書の「※」は明細の率から `TaxClass::isReducedRate()` で決める）
- 設定の `storefront.tax_rate_bp` は外した（2 か所に率を持たない）。読む所が残ると 0% になって気づけないので、テスト（`TaxClassTest`）が `app`・`plugins` に読み残しが無いことを見張る

### 2. 明細の率

| 明細 | 率 | 理由 |
|---|---|---|
| 商品 | 商品の区分の率 | |
| オプション（名入れ・ギフト包装など） | 親の商品の率 | ADR 0036・0048 のまま。下の「決めきれなかったこと」を見る |
| 送料 | **標準 10%** | 商品と別に受け取る送料は「配送」という役務の対価で、飲食料品の譲渡ではない（国税庁「消費税の軽減税率制度に関する Q&A（個別事例編）」の送料の問い）。送料込みの価格にした場合は商品の率になるが、EC-SUGAR の送料は別の行なので標準 |
| クーポンの値引き | 対象の行の率（率ごとに行を分ける） | 下の 3 |
| 定期便の約束の価格との差・定期便の値引き | 商品の率 | 1 つの商品の注文なので |

- 定期便の毎回の請求は、その回の時の区分で明細を作る（区分を変えたら次の回から。税込みの値段は変わらないので、値段の変更の知らせは要らない）

### 3. 値引きは率ごとに行を分ける

- 値引きの行（`kind = 'discount'`）は **率ごとに 1 行**（名前は同じ「クーポン（CODE）」）。割り振りは 2 段: まず値引きを、対象の明細の額の率ごとの合計で率へ割り振り（ADR 0054 の割り振りの決まり〔金額の割合・端数は大きい順〕）、次に率の中で明細へ割り振る（使った記録 `coupon_redemptions.allocations` は今までどおり明細の位置ごと）
- カートの確かめの画面も、同じ 1 段目の割り振り（率ごとの合計）で内訳を出す。注文の明細は拠点ごとに分かれるが、1 段目は率ごとの合計しか見ないので、確かめの画面と注文の内訳が 1 円もずれない
- **1 行のまま税額だけ分ける形は採らない**: 明細は率を 1 つ持つ形（`tax_rate_bp`）で、合計（`Totals`）・仕訳・領収書・管理画面がそれを前提にしている。1 行に 2 つの率を持たせると、明細の形と、それを読むすべての所を変えることになる。行を分ければ、今の合計の計算がそのまま率ごとに正しくなる
- お客さんの画面（ご注文の確認・メール）は、同じ名前の値引きの行を 1 つにまとめて見せる。領収書・納品書は、率が 2 つ以上の注文では値引きの名前に「（8% 対象）」を添える。管理画面の明細は行のまま（率の列がある）
- 送料無料のクーポンは今までどおり行を作らない（送料の行が無いだけ）

### 4. 丸めと仕訳

- 消費税は率ごとに合計してから 1 回だけ丸める（`Totals`。既定は切り捨て）。取引の `tax_amount` は率ごとの税額の合計
- 仕訳（`ledger`）の消費税は、今までどおり取引の `tax_amount` の 1 本（`tax` の口座）。率ごとの内訳は明細から出す（明細は合意の後に変わらないので、いつ出しても同じ）。取消・全額返金は今までどおり合意の仕訳を逆にする
- 一部返金（ADR 0048）の率ごとの扱いは、返金の行を作る時に決める（今は消費税の仕訳を動かさない）→ 2026-11-05 で決めた: 返した額は率ごとに「返す前の残りの額の税 − 返した後の残りの額の税」で税を出し、率ごとの調整の仕訳（`adjustment`、reference `return-rate-<率>`）で請求と消費税を減らす（ADR 0048 の作って決めたこと）

### 5. 見せ方

- 核の `App\Core\Transaction\TaxBreakdown`: 率ごとの「対象の額（税込み）」と「消費税額」、軽減の印。作った注文は明細から（`ofTransaction`）、注文の前は率ごとの額から（`ofAmounts`）
- ショップ: 価格は税込みのまま。確かめの画面（`$order->cart->taxBreakdown()`）・ご注文の確認（`$order->taxes`）は核の部品 `<x-storefront::tax-breakdown>` で「（8%※ 対象 ¥1,080　うち消費税 ¥80）」と出す。軽減の商品の名前に「※」、「※ は軽減税率（8%）の対象です。」。確かめの画面の指紋に内訳を入れる（確かめた後に区分が変われば確定しない）
- メール（注文の知らせ）・領収書と納品書（App）・管理画面の取引の画面も同じ内訳

## 採らない案

- **率そのものを商品に持つ**（8%・10% を数で）: 率が変わった時に全商品を書き換えることになる。区分なら表を 1 か所直せばよい
- **店ごとに既定の区分を持つ**（お菓子の店は全部 8%）: 送料・ギフトの箱など 10% の物が混ざる。商品ごとの方が誤りにくい。サンプルのセット「お菓子のお店」は商品ごとに軽減にした
- **値引きを 1 行のまま、税額だけ率ごとに分ける**: 上の 3

## 決めきれなかったこと

- **別料金のオプションの率**: 引き継ぎどおり親の商品の率にした。ただ国税庁の Q&A では、飲食料品に付ける包装材料でも「別に対価を定めている」もの（有料のギフト包装の箱）や名入れの作業は、飲食料品の譲渡ではなく標準 10% と読める。お菓子の店で有料のギフト包装を出すなら、オプションに区分を持たせる（既定は親の率、店が 10% にできる）のが正しそう。次の区切りの候補
- 店の設定の「税率〔近日〕」（管理画面の設定の目次）は今回は触っていない。商品ごとの区分で足りるなら、目次から外すか「商品ごとに決めます」の案内にする

## 結果

- 得たもの: 8% と 10% の混ざった注文の合計・税額・領収書が、インボイスの決まり（率ごとに 1 回の端数処理・率ごとの対価と税額）どおりに出る。率の変更は表の 1 か所
- 失ったもの: 値引きの行が率の数だけ増える（画面ではまとめて見せる）。種類ごとに率を変えられない

## 作って決めたこと（2026-11-05）

- 移行（`2026_11_05_000100_add_tax_class_to_listings`）は今ある商品を標準で埋めるだけ。作った注文の明細には触らない
- 商品の CSV に列「税率」（書き出しは「標準」「軽減」、読むのは「10%」「8%」・全角・英語の値も）。空なら変えない（新しい商品は標準）
- 管理画面: 商品の登録の「基本」に「税率」の欄（標準 10%／軽減 8%〔食品・飲み物〕）、商品の一覧に税率の列、取引の画面の内訳に「（軽減税率）」
- テーマ API: `ListingCard::$taxRateBp`・`reducedTax()`、`CartView::taxBreakdown()`、`OrderView::$taxes` と `items[].reduced`

## 作って決めたこと（2026-11-12、リリース 1.0 の R6）

- オプション（ADR 0036）に税区分（`listing_addons.tax_class`。`standard`・`reduced`・空）を持たせた。空は今までどおり商品の区分に従う。軽減の商品（食品）に別料金のギフト包装を付けると、包装は標準 10% になる（国税庁の案内）ので、店が「標準 10%」を選べる
- カートの行は税率ごとの内訳（`rateParts`）を持ち、確かめの画面の内訳・クーポンの値引きの率ごとの割り振り・ポイントの割り振りは内訳で数える。注文の明細のオプションの行は、そのオプションの率（`AddonSelection::rateOf`）。確かめの画面と注文の内訳は今までどおり 1 円もずれない（テストで見張る）
- 有料のオプション（名入れなど）の区分の決め方は店に任せる（管理画面の欄の案内は「別料金の包装は、食品でも標準 10% です」）
