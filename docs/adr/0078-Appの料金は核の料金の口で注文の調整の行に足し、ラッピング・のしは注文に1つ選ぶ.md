# 0078 App の料金は核の料金の口で注文の調整の行に足し、ラッピング・のしは注文に 1 つ選ぶ

状態: **採用**（2026-11-05。作ることは運営が決めた。形は先に出した案で、細部は作りながら決めて下の「作って決めたこと」に書いた。核の口なので、取り込みの前に確かめる）。ADR 0010（個人情報）・0011/0012（取引と台帳・イベント）・0025（App）・0036（オプション）・0050（商品の画面の App の欄）・0051（App の画面）・0054（値引きは調整の行）・0055（贈り物）・0063（税）・0066（注文の項目）・0068（ポイント）・0074（代引き手数料）・0076（ギフトカード）の上に足す。置き換えるものは無い

## 要点（先に）

1. **核に「App が注文に料金の行を足す口」**（`App\Core\Plugin\Contracts\OrderChargeHandler`、`PluginDefinition::$orderCharges`。店で 1 つの App だけ）。App は注文の入力の欄（選ぶ・1 行の文）を渡し、入れた値を見積もって**行（種類・名前・税込みの額）**を返す。核はそれを**調整の行（標準の率）**として注文に足す
2. **足す順**: 商品 → 値引き（送料の前）→ 送料 → ポイント → **App の料金** → 代引き手数料。**ポイントでは払わない**（代引き手数料と同じ）。**ギフトカードは料金を含めた合計に充てる**。代引きの手数料の段と上限は料金を含めた合計で決める。付くポイントの元（商品の代金）には入らない
3. **額はいつもサーバーが店の設定で決める**（お客さんの入力の額は使わない）。注文の入力・確かめの画面・確定（錠の中）が同じ見積もりを使い、**確かめの画面の指紋に行と「選んだ値と使った設定の要約」を入れる**。確かめの後に店が値段・選択肢・決まりを変えたら確定しない
4. **App「ラッピング・のし」**（`plugins/plugin-wrapping`）: ラッピングの種類（名前・税込みの料金）は App の画面、のしの決まり（受けるか・表書きの選択肢・料金・名入れの欄と文字数）は App の設定、商品ごとの「ラッピングできる」「のしを付けられる」は商品の画面の欄。**注文に 1 つ**（ご注文の商品をまとめて 1 つに包み、のしを 1 枚）。品ごとに選ぶのは後で（下の「後でやること」）
5. **名入れは個人情報**として扱う: 店の鍵で暗号化して App の表に置き（ADR 0010）、記録（イベント）・行の名前・ご注文の状況・メールには入れない（行の名前は「名入れあり」だけ）。中身を出すのは、入れた本人の確かめの画面・納品書・配送の CSV・管理画面の注文の「個人情報」（運用から・見た記録が残る）だけ

## 文脈

- 日本のネットの店で、贈答の品にラッピングとのしは定番。店ごとに種類と値段が違い、のしは表書き（御祝・内祝・御礼・御中元・御歳暮・粗品・無地など）と掛け方（外のし・内のし）、名入れ（贈る人の名前）を聞く
- 今の核で足せる道は 2 つあった: 商品のオプション（ADR 0036。品ごとに値段を足せるが、商品ごとに定義が要り、注文全体の包装に向かない）と注文の項目（ADR 0066。値段を持てない）。値段を持つ注文全体の選び物の口が無かった
- 値引き（ADR 0054）・ポイント（0068）・代引き手数料（0074）・ギフトカード（0076）が注文の確定の錠の中で順に決まるので、新しい料金はその並びのどこに入るかを決めないと、合計・税・指紋が食い違う

## 決定

### 1. 核の口

- `OrderChargeHandler`: `form(ChargeCart)`（注文の入力の欄。選べるものが無ければ null）・`quote(ChargeCart, values)`（行と要約と digest。選べない値は `ChargeRejected`〔欄の鍵 => 理由〕）・`placed(取引, ChargeCart, values, actor)`（確定の錠の中で App の表に残す）・`notes(取引, private)`（納品書・配送の CSV・管理画面の備考。private が偽なら個人情報を入れない）
- App に渡すのは `ChargeCart`（今買える行の商品の ID・名前・数と、贈り物か）だけ。値段・お客さんの情報は渡さない
- 行の形は核が確かめる（`ChargeQuote`）: 種類は英小文字・数字・下線で、核の種類（`shipping`・`discount`・`points`・`addon`・`cod_fee`・`price_agreed` ほか予約した言葉）は使えない・1 つの見積もりで重ねない・4 行まで。額は 0〜1,000,000 円の整数。名前は 100 文字までの 1 行（制御文字なし）。要約は 6 個まで
- 窓口は `App\Core\Order\OrderCharges`（使う店だけ。App が落ちたら欄を出さない・値があれば断る・備考は空）。ショップの側は `App\Storefront\Checkout\CheckoutCharges`（カートから `ChargeCart` を作り、見積もりを足し、ギフトカードを充て直す）

### 2. 注文の入力と確かめの画面と確定

- 入力の形は `charges[<欄の鍵>]` の文字だけ（8 個まで・1 つ 200 文字まで。`CheckoutInput`）。**出した欄の鍵だけを受け**、出していない欄（使わない店・選べる商品が無い・名入れの欄を出していない）の値は捨てる
- 確かめの画面に出る前に、カートが変わって選べる商品が無くなった・App をやめたなら、選んだ値を外す（料金の無い合計を見てもらう）。欄はあるが選んだものが消えた・使わなくなったなら、入力の画面で選び直してもらう（欄の下・見出しの下に理由）
- 確定は錠の中で見積もり直し、選べなければ・指紋が合わなければ確定しない（確かめの画面へ）
- 0 円の行も注文に残す（のし「無料」など。管理画面・納品書・ご注文の状況に何を選んだかが残る）

### 3. App「ラッピング・のし」

- 表（店の DB）: `wrapping_types`（種類。20 個まで）・`wrapping_listings`（商品ごとの印）・`wrapping_orders`（注文ごとに選んだもの。種類の名前と額・表書き・掛け方・のしの額の**写し**と、暗号化した名入れ。**追記だけ**で DB のトリガーが直す・消すを断る。名入れは暗号文だけを DB の制約でも守る）
- 書き込みは連鎖のロック → 行のロック → 同じトランザクションのイベント（`wrapping.type_created`・`type_updated`・`type_deleted`・`listing_updated`、注文の時は `wrapping.recorded`。中身は ID・料金・真偽・掛け方だけ）
- 行の種類は `wrapping`（「ラッピング（リボン）」）と `noshi`（「のし（御祝・外のし・名入れあり）」）

## 結果

- 得たもの: 店が包装とのしを売れる。額・税・ポイント・ギフトカード・代引きの順が決まり、確かめの画面と確定が食い違わない。ほかの「注文に足す料金」（メッセージカード・保冷剤・紙袋など）も同じ口で App にできる
- 失ったもの・気をつけること: 料金は**ポイントで払えない**（代引き手数料と同じ。払いたいという声が出たら決め直す）。品ごとには選べない（注文に 1 つ）。料金の行は返品の割り振りの対象にならず、返すなら「金額だけの返金」（代引き手数料と同じ）。口を持つ App は店で 1 つだけ

## 作って決めたこと（2026-11-05）

- **税は標準の率**（10%）。軽減税率の商品（食品）を包んでも、別に料金を受ける包装は標準の率になる（国税庁の案内）。App の画面の料金の欄の説明に書いた
- **選べるのはカートに対象の商品がある時だけ**。対象でない品が混ざる時は「ラッピングできない商品（N 点）は、そのままお送りします。」を欄に添える（全部が対象でなくても選べる）
- **名入れの決まり**: 1 行、店が決めた文字数（1〜20、既定 10）まで、前後の空白を取って見える文字（コードポイント）で数える。`<` と `>`、制御文字・書式の文字（向きの印・幅の無い文字・絵文字をつなぐ印を含む）・私用の文字、行と段落の区切りを断る。**のしの表書きを選ばずに名入れだけは断る**。名入れの欄を出していない店では受けない
- **掛け方は既定で外のし**（選ぶ欄の最初）。のしを選ばない時は掛け方を見ない
- **ご注文の状況・メールには名入れの文字を出さない**（ADR 0066 の決定 5 と同じ理由: 注文はメールの完全一致でつなぐので、打ち間違えたメールの持ち主にも届きうる）。確かめの画面は入れた本人のセッションなので出す
- **納品書は店の人の画面だけに備考**（「備考: ラッピング: リボン／のし: 御祝・外のし・名入れ 鈴木一郎」）。領収書には出さない
- **配送の CSV は B2 クラウドの「記事」とゆうプリR の「備考」**に同じ 1 行を入れる（e飛伝とクリックポストの並びには自由な文の欄が無いので入れない）。名入れが欠けないように**切らずに出す**（欄の長さの上限は各ソフトの確かめに任せる。B2 の記事の長さの上限は未確認。App「配送の CSV」の README）
- **種類を直す・消す・使わなくするは、受けた注文に響かない**（名前と料金は注文の行と App の表に写してある）。消すのは直前の再確認の後
- **ついでに直したこと（同じファイルの不具合）**: 代引き手数料を足す時（`CartView::withPaymentFee`）にギフトカードが落ちていた（代引きを選ぶと、入れたギフトカードが確かめの画面から消え、使われずに全額を代引きで受け取っていた）。料金の行と一緒にギフトカードも持ち越すようにした（ギフトカードは手数料の前の合計に充てたまま、手数料は残りのお支払いに入る）。取り込みの前に確かめる

### 見直しの後に直したこと（2026-11-05、見直し）

- **料金を足した後のお支払いが 1〜49 円の注文は断る**: ポイントは料金の前の合計で決まる（0 円か 50 円以上が残る）ので、ポイントで 0 円にした注文に 30 円の料金を足すと、決済代行で払えない 30 円のお支払いができていた。`CheckoutCharges::apply`（入力・確かめの画面・確定の錠の中の 3 か所が通る）で、料金とギフトカードの後の `due()` が 1〜49 円なら断り、「使うポイントを減らして」の理由を料金の欄の見出しの下に出す（ポイントの決まり `CartPoints::BELOW_MINIMUM` と同じ考え方）。料金まで払えるギフトカードがあれば 0 円で通る
- **App の答えの型を核が確かめる**: 行は `kind`（文字）・`title`（文字）・`amount`（整数）の 3 つの鍵だけ、要約は `name`・`value` の文字だけ、どちらも並び（list）。PHP の型の宣言に頼らない
- **核の行の種類は 1 つの一覧**（`ChargeQuote::CORE_KINDS`。料金の行として出すのは `CHARGE_KINDS` の代引き手数料だけ）。App が使えない種類（`RESERVED_KINDS`）とご注文の状況の料金の行の決め方（`OrderCharges::shownAsCharge`）はこの一覧から作る。核と公式の App のコードが作る行の種類が一覧にあることを `OrderChargeShapeTest` がコードを読んで見張る
- **名入れで見えない文字を断る**: 空白に見える文字（U+3164・U+115F・U+1160・U+FFA0・U+2800）・異体字セレクタ（U+FE00〜FE0F・U+E0100〜E01EF）、結合文字（と空白）だけの名前。前後にある空白に見える文字は Laravel が受け口で先に取り除く（その時は名入れなしになる）
- **Shift_JIS（CP932）で表せない文字は断らない**（作る時の判断）: 「𠮷」「髙」の異体などの本当の名前を断らないため。配送の CSV では核が「〓」に置き換えるので、名入れの欄の説明に「絵文字や一部の旧字体は、送り状では「〓」になることがあります。」を添えた。納品書・管理画面にはそのまま出る
- **決済代行の明細**: 0 円の調整の行（のし「無料」など）は明細から飛ばす（前は 0 円の行があると、明細全体が「ご注文 ◯◯」の 1 行になっていた）
- **数字だけの表書き**（「100」など）の選択肢の値が、配列を広げる時に 0 から振り直されていたのを、鍵をそのまま残す形にした
