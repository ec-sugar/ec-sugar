# 0040 App はページに区画を足せる（動画と地図の App。外の埋め込みは最初から出し、CSP・sandbox・宛先で守る）

状態: **採用**（2026-10-30。動画と地図を貼れるようにする。Instagram の埋め込みは作らない）。ADR 0039 の決めたことの 6（区画の種類はプラグインも足せる）の口を作る。ADR 0020・0025・0034 の続き。**2026-10-30 に 2 の一部・3・6 を置き換えた**（3: 同意を待たずに最初から出す。6: 地図はキーの要らない埋め込み。置き換えた所に、もとの判断を残した）。一部置き換え（→ ADR 0041: 文脈の「店の人は HTML も JavaScript も入れない」を、カスタム区画の整えた HTML に限って許す形に）

## 文脈

- ページは区画を積んで作る（ADR 0039）。区画の種類はテーマと核（`basic_*`）が持ち、App は区画を足せなかった
- お店の人が貼りたいのは、作っているところの動画（YouTube・Vimeo）と、お店や会場の地図（Google マップ）。どちらも外のサイトの枠（iframe）を埋め込むので、開いただけで外の事業者へ IP アドレスなどが送られる。タグの App（ADR 0034）と同じく、同意と外部送信の公表に載せる必要がある
- 守る線は今までどおり: 店の人は HTML も JavaScript も入れない（CONCEPT 7.2。→ HTML は ADR 0041 で一部置き換え: カスタム区画の、保存と描くときに整えた HTML だけ。JavaScript は今も入れない）、テーマは SVG もコードも持ち込まない（ADR 0020）、個人情報の画面には外のものを入れない

## 決めたこと

### 1. App が区画を足す口（核）

- App はマニフェスト（composer.json の `extra.ec-sugar.sections`）に区画の種類を宣言する。中身（`label`・`patterns`・`fields`・`items`・`blocks`・`example`・`wireframe` など）は**テーマの区画と同じ書き方で、核の `SectionSchema` が同じ決まりで確かめる**（欄は核の 7 種類だけ、知らない書き方は登録で断る、見本に店の写真や商品は書けない、ワイヤーの絵は核の語彙だけ）。そのほかに `consent`（同意の種類。任意で、書かなければ要らない。初めは「必ず書く」だったのを 2 の置き換えで外した。必ず書くのはタグの差し込みの `storefront.consent` のほう、ADR 0034）と `embed`（外から埋め込むときの決まり）を書ける
- 種類の名前は `app_` ＋ App の名前（`-` は `_`）か、その後ろに `_` と英小文字・数字（App「google-map」なら `app_google_map`）。ほかの App と重なれば登録で止める。テーマは `app_` で始まる名前を宣言できない（`basic_` と同じく取ってある）。1 つの App は 5 種類まで
- 描くのは App の Blade（パッケージの `resources/views/sections/{種類}.blade.php` か `{種類}/{パターン}.blade.php`）。Blade の名前の場所（`app-{App の名前}`）は核が付ける（App が別の場所を指せない）。テーマは同じ名前の部品（`sections/{種類}…`）を置けば描き直せる
- **店がその App を「使う」にしているときだけ**、テーマの宣言に App の区画を足す（`AppSectionCatalog`）。足すのは決まった並びでないページ（トップと自由なページ）の置ける種類の後ろ。区画を足す欄には App の名前を添えて出る
- **App を止めた店では**: 置けない（保存で断る）・ショップに出さない・編集の画面にも出さない・**値は消さない**。止めている間に並びを保存し直しても公開しても、しまってある並びの同じ位置に戻す（`ThemeContentService::keepAppSections`）。使い直すと元の位置に元の値で出る。App を外した（composer から消した）ときも同じく残す
- 欄の値の確かめを、App の係（`AppSectionHandler::problems`）がもう一段できる（例: 動画の URL の形）。断るだけで値は変えない。保存のときに核が呼び、道筋つきの 422（`sections.3.values.url`）にする
- プラグイン API は 1 のまま（足しただけで、今までの App はそのまま動く）

### 2. 外から埋め込む区画

- `embed` に書くのは、`frame-src`（枠に読み込んでよい宛先。1 つ以上）・`links`（外のサイトで開くリンクの宛先）・`sandbox`・`allow`。宛先は CSP の宛先と同じ形の確かめ（ADR 0034 の `CspSources`。https のホストだけ、道筋で絞れる）。`sandbox` は `allow-scripts`・`allow-same-origin`・`allow-presentation`・`allow-popups`・`allow-popups-to-escape-sandbox` の中からだけ（上の階の画面を動かす・フォームを送る許しは付けられない）、`allow` は `autoplay`・`encrypted-media`・`fullscreen`・`picture-in-picture`・`clipboard-write`・`web-share` の中からだけ（カメラ・マイク・位置・支払いなどは付けられない）
- 埋め込む区画は外部送信の公表（`disclosure`）を必ず持つ（無ければ登録で止める）。係（`sectionHandler`）も必ず渡す。同意の種類（`consent`）は任意（**置き換え**: 初めは 1 つ以上を必ず書かせた。3 の置き換えで外した。書けば、その種類に全部同意したお客さんにだけ区画を出す）
- 埋め込む URL は App の係（`AppSectionHandler::embed`）が欄の値から作り、**核が描く前に宣言の宛先に合うかを確かめる**（合わない枠の URL なら区画ごと出さない、合わないリンクは出さない）。宛先の照らし合わせは、道筋に `.`・`..` の区切りや符号化した点・斜線（`%2e`・`%2f`・`%5c`）のある URL を断る（前方一致の宛先から `../` で外へ出さない。外で開くリンクには CSP が掛からないため）。係は枠ごとに `allow` を絞れる（`Embed::$allow`。宣言の `allow` と重なる言葉だけを使い、宣言より広げられない）。係が失敗してもページは止めない
- 枠（iframe）を作るのは核の部品（`<x-storefront.embed>`）だけ。App の Blade はこの部品を置くだけ（**置き換え**: 初めは押した時に核の JavaScript `embeds.js` が枠を作った。3 の置き換えで外した）
- ~~同意の種類「動画・地図の表示」（`embeds`）を足した~~ → **置き換え（2026-10-30）: 外した**。前に `embeds=1` を持った同意の Cookie は、知らない種類として読み飛ばす。同意の帯と「Cookie の設定」は動画・地図のことを聞かない（区画を置いていない店でも聞いていた件もこれで消えた）

### 3. 埋め込みは最初から出す（2026-10-30 に置き換え）

**置き換え**（2026-10-30、運営の判断。堅牢にしたいのは攻撃への守りで、お客さんに不便をかけたいのではない）: 初めは「同意した人には開いた時から、ほかの人は押した時だけ」にしたが、**同意を待たずに誰にでも最初から枠を出す**形に置き換えた。理由:

- 外の埋め込み（動画・地図の枠）は攻撃の入口ではない。守りは CSP の `frame-src`（区画のある画面に、宣言の宛先だけ）・`sandbox` と `allow`（核の決めた言葉だけ）・宛先の確かめ（係の返した URL を核が確かめ直す）で掛ける。同意の有無で守りの強さは変わらない
- 日本の外部送信規律（電気通信事業法）が求めるのは**公表**で、事前の同意ではない。公表（`disclosure`）は今までどおり必ず書かせ、ショップの「外部送信に関する公表」に載せる
- 押すまで出ない地図・動画は、お客さんにとって不便（地図を見るのにひと手間、JavaScript が無いと出ない）
- タグの App（解析・広告。ADR 0034）の同意の帯は、この置き換えでは変えない（目的が違う）→ 同じ日に で、帯も既定で出さず店の設定で入れる形に置き換えた（ADR 0034 の 4）

今の形:

- ショップの HTML に最初から枠（iframe）を描く（`loading="lazy"`。JavaScript が無い人にも出る）。動画は、店の人が「自動で再生する」を選ばなければ自動で再生しない
- 枠には `sandbox`（宣言の言葉だけ）・`allow`（宣言の言葉の中から、係が絞ったもの）・`referrerpolicy="strict-origin"`（送るのはショップのドメインまで。道筋の値〔署名など〕を外へ渡さない。YouTube の埋め込みは送り元が無いと再生しない）
- 枠の下に「別のタブで開く」（宣言の `links` に合うときだけ）
- **CSP の `frame-src`** は、その応答で出した App の区画の分だけ、宣言の宛先だけを足す。区画の無い画面・App を使わない店・個人情報の画面・プレビューでは足さない
- 編集の画面のプレビューと試し見では、外へは読み込まない（店の写真か無地の箱に「ショップではここに出ます」）
- 同意の種類を書いた区画（今の公式の App には無い）は、同意の帯を出す店（既定は出さない）では、その種類に全部同意したお客さんにだけ出す（ほかの人には区画も枠も CSP の宛先も出さない。押して読み込む形は無い）。帯を出さない店では誰にでも出す
- 公表のページの文は「動画と地図は、そのページを表示したときに読み込む（そのときに情報が送られる）」

もとの判断（2026-10-30 の初め。置き換えた）:

- **同意の帯で受け入れた人**（区画の同意の種類に全部同意）: 開いた時から枠を描く（自動で再生しない URL）
- **受け入れていない人**（決めていない・断った）: 店の写真（区画の写真の欄）か無地の絵に「動画を再生」「地図を表示」のボタンと、送り先の案内。**押すまで外へは何も送らない**（枠も、外のサイトの絵の取り寄せも作らない。YouTube のサムネイルも読まない）。押した人のときだけ、核の JS がその区画の枠だけを作る（動画は押した時に再生が始まる URL）。JS が無い人には「別のタブで開く」のリンク（宣言の `links` に合うときだけ）
- 編集の画面のプレビューと試し見では、同意していても外へは読み込まない（ボタンの形だけ、押しても動かない）
- **CSP の `frame-src`** は、その応答で出した App の区画の分だけ、宣言の宛先だけを足す（押してから読み込めるように、同意の前でも足す。足すだけで、読み込むのは押した時か同意の後）。区画の無い画面・App を使わない店・個人情報の画面・プレビューでは足さない
- 枠には `sandbox`（宣言の言葉だけ）・`allow`（同）・`referrerpolicy="strict-origin"`（送るのはショップのドメインまで。道筋の値〔署名など〕を外へ渡さない。YouTube の埋め込みは送り元が無いと再生しない）

### 4. App が JavaScript を持ち込む場合

- 区画の App は JavaScript を持ち込まない。枠は核の部品が描く（3 の置き換えで、押して読み込む核の JavaScript も無くなった）。見た目も核の CSS（`sections.css` の `sugar-app-section`・`sugar-embed`）で、App は CSS も持ち込まない
- 区画のために JS が要る App は、ADR 0034 の `storefront.scripts`（パッケージの `assets/` の同じオリジンのファイル、審査済みの App だけ）を使う。区画の描画とは別に、ふつうの画面に差し込まれる（同意の帯を出す店では、同意したお客さんにだけ。既定の帯を出さない店では誰にでも。で ADR 0034 の 4 を置き換えた後の形）。SaaS の他社の App は審査した App だけが JS を持てる（ADR 0047 で置き換え。前は「テーマと同じく JS を持てない（ADR 0020）」と書いていた）。開発者モードで決め直すまでこのまま

### 5. 動画の App（`plugin-video`）

- URL から動画の ID を取り出す。受けるのは https の決まった形だけ: YouTube は `www.youtube.com`・`youtube.com`・`m.youtube.com` の `/watch?v=ID`・`/shorts/ID`・`/embed/ID`・`/live/ID`、`youtu.be/ID`、`www.youtube-nocookie.com/embed/ID`（ID は英数字・`_`・`-` の 11 文字）。Vimeo は `vimeo.com/数字`（と限定公開の印）・`player.vimeo.com/video/数字?h=印`。ほかのホスト・`javascript:`・利用者名やポートの付いた URL は断る
- 埋め込む URL は**取り出した ID だけから組み立てる**（貼った URL の残りは使わない）。YouTube はプライバシー強化モード（`https://www.youtube-nocookie.com/embed/ID?rel=0&playsinline=1`）、Vimeo は追跡しない設定（`https://player.vimeo.com/video/ID?dnt=1`）
- パターンは「横いっぱい」「文の幅」。欄は URL・見出し・説明と、選べる設定 4 つ（下）。**再生の前に出す写真の欄は外した**（3 の置き換えで最初から枠を出すので、お客さんに出る場面が無くなった。前に保存した値は、読むときに核が今の宣言に合わせて落とす。`SectionValues::sanitizePage`）
- **作って決めたこと（2026-10-30。自動再生・ミュート・操作の表示を隠す、なども選べるように）**: 店の人が選べる設定を足した。欄は核の選ぶ欄（`choice`）で、値は決まった選択肢だけ（`off`/`on`、操作の表示は `show`/`hide`。選ばなければ「しない」「出す」。見本の値は全部なし）
  - 自動で再生する（YouTube・Vimeo とも `autoplay=1`）・音を消す（YouTube `mute=1`・Vimeo `muted=1`）・操作の表示を出さない（`controls=0`。Vimeo は有料のプランの動画でだけ効く。欄の説明に書いた）・繰り返す（`loop=1`。YouTube は `playlist=同じ ID` も付ける）
  - **自動で再生するなら、音を消すを描くときに付ける**（ブラウザは音ありの自動の再生を止める）。保存した値は変えない（係は値を変えない決まりのまま）。欄の説明に「自動で付く」と書いた
  - 自動で再生するときだけ、枠の `allow` に `autoplay` を付ける（宣言の `allow` には `autoplay` を書いておき、係が `Embed::$allow` で絞る。核は宣言と重なる言葉だけを使う）
  - 自動で再生して操作の表示も出さない組み合わせは**断らない**（背景のように流す使い方を運営が望んだため）。お客さんが止められないことがある（WCAG 2.2.2 一時停止・停止・非表示）ので、欄の説明で「操作の表示は出したままに」「出さないなら 5 秒より短い動画に」と書いた
  - URL は今までどおり、確かめた ID と決まった値だけから組み立てる（店の人の入力の文字は URL に入らない）

### 6. 地図の App（`plugin-google-map`）: キーの要らない埋め込みにした（2026-10-30 に置き換え）

**置き換え**（2026-10-30、運営の判断）: 初めは (c) Maps Embed API（キー）にしたが、**(a) キーの要らない埋め込みに置き換えた**。店の人に Google Cloud でキーを作って制限してもらう手間が重く、「場所を入れるだけで地図が出る」を優先した。(a) が公式の資料に無い形で止まりうることは承知のうえ。もとの判断（(c) にした理由）は下に残す。

- 候補: (a) キーの要らない `https://www.google.com/maps?q=…&output=embed`、(b) Google マップの「地図を埋め込む」で出る `https://www.google.com/maps/embed?pb=…` を貼ってもらう、(c) Maps Embed API（`https://www.google.com/maps/embed/v1/place?key=…&q=…`）
- **今の形（(a)）**: 係が `https://www.google.com/maps?q={場所}&output=embed&hl=ja` を作る。App の設定（API キー）は無い。使う店なら、場所を入れるだけでショップに出る（場所が空なら出さない）
- **宛先**: `frame-src` は `https://www.google.com/maps`（`/` で終わらない＝道筋が `/maps` ちょうどのときだけ。`/maps/embed/…`・`/maps/search/…`・ほかの道筋も、似せたホストも通さない。核の `CspSources::matchesAny` と、CSP の `frame-src` も同じ考え方）。外で開くリンクは今までどおり Maps URLs（`https://www.google.com/maps/search/?api=1&query=…`。公式の形）で、`links` は `https://www.google.com/maps/search/`
- 場所は文字のまま URL の値として符号化して渡す（`rawurlencode`。引用符や空白・`&` で URL の形を壊せない）。地図の URL（`https://…`・`www.…`）を貼られたら文字で入れるよう断る（今までどおり）
- 3 の置き換えで、地図も同意を待たずに最初から枠を出す。`referrerpolicy="strict-origin"` と `sandbox` は今までどおり。外部送信の公表は、送り先 Google LLC・送る情報（IP アドレス、端末とブラウザの情報と Google の Cookie、ショップのドメイン、場所の文字と地図の操作）
- **危うさ**: (a) は Google の公式の資料に無い形で、**予告なく止まる・形が変わる・別の宛先へ回されることがありうる**。止まると、この App を使うすべての店で地図の区画が空の枠か読み込めない表示になる（ページのほかの部分は出る）。別のホスト（例: 同意の確かめの画面）へ回されると、ショップの CSP の `frame-src` に無いので枠の中が出ない
- **止まったら Maps Embed API（(c)）へ戻す**。戻す手順:
  1. `plugins/plugin-google-map/composer.json` の `extra.ec-sugar` に `settings.api_key`（`type: text`・`required: true`・形 `AIza[0-9A-Za-z_-]{35}`・`max: 39`。秘密の項目にはしない＝ショップに出るキー）を戻し、`embed.frame-src` を `https://www.google.com/maps/embed/v1/` に替える
  2. `GoogleMapSections::embed` で `$settings['api_key']` の形を確かめ、`https://www.google.com/maps/embed/v1/place?key={キー}&q={場所}&language=ja&region=JP` を返す（キーが無ければ `null`。入れるべき設定が欠けている間は核が区画も同意の帯も出さない）
  3. README にキーの作り方と制限（「HTTP リファラー」をショップのアドレスに、「API の制限」を Maps Embed API だけに）を戻し、`AppSectionsTest`・`AppSectionManifestTest`・`app-embeds.spec.js` の宛先とキーを戻す（初めの形は、この置き換えのコミットの 1 つ前にそのまま残っている）
  4. 使っている店に、キーを入れるまで地図が出ないことを知らせる
- パターンは「横いっぱい」「地図と案内」。欄は場所・見出し・案内の文

もとの判断（2026-10-30 の初め。置き換えた）:

- **(c) にした**。理由: (a) は Google の公式の資料に無い形で、予告なく止まりうる（店の地図が一斉に消える）。(b) は公式だが、店の人が Google マップで HTML を写して貼る手間があり、`pb` の中身を確かめられない（「住所を入れると地図」にならない）。(c) は公式の資料があり、使う回数の制限なく無料で、場所の文字を入れるだけで地図になる。キーはショップの画面に出る形の API なので、Google Cloud で「HTTP リファラー」をショップのアドレスに、「API の制限」を Maps Embed API だけにしてもらう
- キーは App の設定（`AIza` で始まる 39 文字の形を確かめる）。キーが無ければ区画も同意の帯も出さない
- 未確かめだったこと: (c) の Google Cloud の請求先の登録の要否と、キーの制限の手順（(a) にしたので今は要らない。戻すときに今の公式の資料で確かめる）

## 結果

- 得るもの: 動画と地図を、HTML も JS も入れずに区画として置ける。お客さんは押さずに見られる。核には、ほかの App（レビュー・メールの登録・予約など）も使える「区画を足す口」ができた
- 気をつけること: App の係のコードは核と同じ権限で動く（入れるのは審査した App だけ。ADR 0025 のまま）。外の枠の中身はこちらで管理できない（だから CSP の宛先・sandbox・allow・公表）。開いた人の情報は外の事業者へ送られる（公表に載せる）。地図は公式の資料に無い埋め込みの形なので、止まったら Maps Embed API（キー）へ戻す（6 の手順）
