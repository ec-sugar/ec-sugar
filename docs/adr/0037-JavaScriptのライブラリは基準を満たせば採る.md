# 0037 JavaScript のライブラリは基準を満たせば採る

状態: **採用**（2026-10-29。JavaScript のライブラリをむやみに足すのは危ないが、一切締め出す必要はない。アニメーションは比べたうえで motion を選んだ）

## 文脈

- 管理画面（Vue）とショップ（Blade）は、JavaScript の依存を `vue`・`vue-router` だけにしてきた。アイコンや動きは手で書いていて、足りないものが出るたびに描き足していた
- 依存を足すと、乗っ取られたパッケージや、CSP（読んでよいものを絞る決まり）・Trusted Types（HTML やスクリプトの書き込みを関所に通させる仕組み）とぶつかる書き方が入る道ができる。けれど、全部を締め出すと、作る速さと見た目の質が落ちる
- 危ないのは「無作為に足すこと」で、足すこと自体ではない

## 決めたこと

### 採る基準（すべて満たすもの）

| 見ること | 基準 |
|---|---|
| ライセンス | MIT・ISC・BSD・Apache 2.0 など、AGPL の EC-SUGAR と一緒に配れるもの。独自の条件の付いた無料のライセンス（GSAP など）は採らない |
| 手入れ | 最近 1 年以内に更新がある。止まっているものは採らない |
| 依存の数 | 少ないほど良い。依存の先まで上の基準で見る |
| 守りの仕組みと合うか | `eval`・`new Function` を使わない。CSP の下で動く。Trusted Types を壊さない（HTML の文字の差し込みに頼らない） |
| 読み込み方 | ビルドに入れて自分のサイトから配る。外（CDN）から読まない |
| 版 | 出てから 2 週間以上たった版を、`^` を付けずに固定で入れる。lock ファイルと `npm audit`・`npm audit signatures` を通す（CI も見る） |
| 記録 | [docs/development/dependencies.md](../development/dependencies.md) に、何のために・確かめたこと・入れた日を書く |

- 基準を満たしても、組み込み（CSS・Vue の機能・ブラウザの機能）で足りるなら組み込みを使う
- 入れるのはメンテナーか、メンテナーが許した作業だけ。入れたら一覧に書き、プルリクエストの本文にも書く
- 外すときは一覧から消し、理由を書く

### アニメーション

- よくある動き（フェード・スライド・開け閉め・ページの切り替え）は、CSS と Vue の Transition とブラウザの View Transitions で書く
- 足りない所（ばねの動き・連続した演出・スクロールに合わせた動き）は **Motion**（motion.dev、MIT）を使う。ショップのテーマは素の `motion`、管理画面は `motion-v`
- 比べたもの（2026-10-29）: anime.js v4（依存 0・MIT。次点）、AutoAnimate（一覧の動きだけ）、@vueuse/motion（1 年半更新なし）、GSAP（独自のライセンス）、lottie-web（巨大・`eval` を使う形がある）、popmotion（2022 年で止まっている）
- 見る人が「視差効果を減らす」（`prefers-reduced-motion: reduce`）を選んでいたら、動きを止める（動かさずに最後の形を見せる）

## 結果

- 得るもの: アイコン（Lucide）や動き（Motion）のような、作るのに時間がかかり質の差が出るものを、確かめた道具で手早く入れられる
- 失うもの: 依存が増えるぶん、更新を追う手間と、乗っ取りの道が少し増える（基準・固定の版・署名の確かめ・一覧で狭める）
- 気をつけること: Motion は更新がとても速い（月に数回）。固定した版を、Dependabot（依存の更新を知らせる仕組み）の知らせで 2 週間たってから上げる
