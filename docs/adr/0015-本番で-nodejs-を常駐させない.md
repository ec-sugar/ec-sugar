# 0015 本番で Node.js を常駐させない

状態: 採用（2026-10-27）

## 文脈

管理画面は Vue の SPA ＋ API にした（ADR 0013）。Vue を使うと、SSR（Nuxt など）やフロント用の Node.js サーバーを本番に置く構成に流れやすい。
SUGAR-EC はパッケージとしても配る（CONCEPT）。導入先は一般的なレンタルサーバーや VPS で、PHP は動くが Node.js の常駐プロセスは置けない・置きにくいことが多い。
常駐が 1 つ増えると、監視・再起動・メモリ・更新・攻撃面（npm の依存が本番で動く）も 1 つ増える。

## 決定

- **Node.js はビルドの時だけ使う**（Vite で Vue をビルドし、静的ファイル（HTML / JS / CSS）を作る）。本番で動くのは PHP（Laravel）と、それが配る静的ファイルだけ
- SSR、Node.js の API サーバー、Node.js 製の常駐ワーカー（WebSocket サーバーなど）は入れない。リアルタイム通信が要るときは、Node.js を常駐させない方法（ポーリング、PHP 側の仕組み）から考える
- npm の依存は本番のイメージに入らない（Dockerfile のビルド段で使い捨て）。バージョンは `package-lock.json` で固定し、`npm ci --ignore-scripts` だけで入れる

## 結果

- 得たもの: 導入先の条件が「PHP と PostgreSQL が動く」のままで済む。本番の常駐プロセスと攻撃面が増えない。npm の依存に悪いコードが混ざっても、本番のサーバーでは動かない（影響はビルドと、配った JS に限られる）
- 失ったもの: SSR による初回表示の速さと検索エンジン向けの描画は使えない（管理画面はログインの後ろなので影響は無い。店頭の表示で要るようになったら、PHP 側の描画で考える）
