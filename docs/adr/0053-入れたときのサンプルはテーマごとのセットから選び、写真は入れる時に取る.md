# 0053 入れたときのサンプルはテーマごとのセットから選び、写真は入れる時に Unsplash から取る

状態: **採用**（2026-11-04。セットを選べるようにすることと、写真を配る物に入れずに入れる時に取ることは運営が決めた）。（入れたときのサンプル）の続き

## 文脈

- 入れたときのサンプルは雑貨のお店（自作の絵を同梱）だけで、インストーラーは選べなかった。決めたこと（2026-11-04）: インストーラーの最初にテーマを選べるようにし、それに合わせたサンプルを入れる
- 開発の見本の店（SUGAR SHOP・デモの店・MIDORI 植物店）には、テーマに合った商品と写真がすでにあった。ただし中身は seeder（開発だけ）にあり、写真は手元のフォルダ（git の外）にしかない
- Unsplash の写真は配る物（リポジトリ・イメージ）に入れない（運営の決定）。入れる時に取りに行くのは、本番のサーバーから外への新しい通信になる

## 決定

1. **サンプルはセット**（`App\Core\Shop\Samples`。`SampleSet` の形で、商品・種類とオプション・在庫・カテゴリ・テーマの中身・送料・特商法の見本の文・写真の出どころを持つ）。`zakka`（既定。雑貨・角砂糖・絵を同梱）・`sweets`（お菓子・角砂糖）・`fashion`（布ものと道具・fashion）・`botanica`（植物・botanica）。開発の 3 つの seeder は同じセットを入れるだけにし、中身を二重に持たない
2. **コマンドは `shop:sample <店> [--set=…] [--force] [--photos=…] [--remove]`**。既定は今までと同じ雑貨（今のインストーラーの呼び方を壊さない）。入れ終えたら店のテーマをセットのテーマへ切り替える（`ThemeSelector`。中央の監査ログに残る）。消してもテーマは戻さない
3. **写真は入れる時に Unsplash から取る**。行き先は https の `unsplash.com`・`images.unsplash.com` だけ（リダイレクトの行き先も確かめる）、時間切れ・10 MB・画像の形を確かめ、一時フォルダに置いてから今の画像の処理（作り直し）に通す。**1 枚でも取れなければ、その写真なしで入れて注意を出す（止めない）**。`--photos` で手元のフォルダを使える（開発・ネットの無いサーバー）
4. **1 つの店に入れるのは 1 つのセットだけ**。別のセットへは、先に `--remove`（管理画面のホームの「まとめて消す」と同じ）で消してから。確かめつきで自動で入れ替える形は採らない（消す物の中にお店の書き換えた物が混ざりうるので、消す操作を人が先に選ぶ）

## 作って決めたこと（2026-11-04）

- **印の名前**: 雑貨は前からの形（`listing:mug`・`theme:default`・`legal`）のまま（入れ終えた店の印と合わせる）。ほかのセットはセットの名前を前に付ける（`sweets_listing:jam-apricot`・`fashion_theme:fashion`）。消した後に別のセットを入れても、前のセットの閉じた印と重ならない。DB の印の形の制約は変えていない。今残っているセットは、残っている印の名前から分かる
- **テーマの中身の入れ替え**: 消すとトップを空の最初の並びに戻して公開する（前からの動き）。そのとき戻した後の改訂を印に残し（`cleared`）、次のセットは「お店がその後に触っていない」ときだけ中身を入れる（触っていればお店の物として残す）
- **送料はどのセットも ¥800・¥5,000 以上で無料**: 送料は消しても残す（前からの決まり）ので、セットごとに違うと、入れ替えた後に表記の見本の文と合わなくなる
- **特商法の見本の文**: 新しいセットは、お店が書く所に「（見本です。公開の前に書き換えてください）」を付ける。雑貨は前からの「（サンプル）…を書きます」のまま
- **品番は SAMPLE- で始める**（開発のデモの店の品番も `SAMPLE-LINEN-APRON-…` に変わった）。商品名には「（サンプル）」が付く（開発の見本の店も同じ）
- **出どころの残し方**: 撮った人・ページ・写真の ID か URL を、サンプルの印の snapshot（商品は `credits`、ショップの写真は `credit`）と、商品の説明の終わりの一行（「写真: …（Unsplash）」）に残す。消すと一緒に消える。植物の写真は前の控え（README）に URL しかなく、撮った人は「Unsplash」とだけ出る
- **写真のアップロードの回数**: 1 分の回数（`MediaQuota`）に触れそうなら、書き込みの錠の外で窓が開くまで待つ（`MediaQuota::secondsUntil`。残りの秒は切り捨てで返るので 1 秒足す）。セットの写真はどれも 30 枚の内だが、雑貨を消してすぐお菓子を入れると超えるため
- **取る大きさ**: 長い辺 2,000（ショップの写真の大きいものと同じ）。取り出しの入口に `w=2000` を付けると、リダイレクト先にもそのまま付く（2026-11-04 に本物で確かめた。3 セット 42 枚で 20 MB、1 枚最大 1.1 MB）
- **ShopSamples を役ごとに分けた**（600 行を超えたため）: 断る・写真をどこから読むかを決める `ShopSamples`、中身を入れる `SampleInstaller`、消す `SampleRemover`、写真を取る `SamplePhotos`
- 前の形（印の無い見本の商品）のまま残っている開発の demo の店には入れない（品番の重なりと二重を避ける。作り直すときは店を消してから）
- **インストーラーで選ぶ**（2026-11-04）: 2/5 で「どのテーマで始めますか?」と聞き、答えの `SAMPLES` は `sweets`・`fashion`・`botanica`・`zakka`・`none`。**既定は sweets**（お菓子のお店・角砂糖。見栄えの良いものを既定に。コマンドの既定の zakka とは別に決める）。前の答えのファイルの `yes` は zakka、`no` は none と読み、ファイルは書き直さない。4/5 は最初のショップを作った後に `shop:sample <店> --set=<答え>` を 1 回呼ぶだけ（テーマの切り替えはコマンドがする）。終わりの番号 1 とそのほか（app に届かないなど）は注意と直し方を出して続け、2（引数の誤り）はインストーラーの誤りとして止める。入れ終えた印（`samples_added`）は前からの 1 つのまま（セットを替えても流し直さない）
- **1/5 の Unsplash への道の確かめ**: 写真を取るセットの答えのときだけ見て、届かなくても注意だけ（写真なしで入るため）。1/5 は 2/5 より前なので、まだ答えが無い初めての流しでは `--answers` のファイルの値、それも無ければ 2/5 の既定（新しく入れるなら sweets）として見る。入れ終えたサーバーでは見ない
- 共通の部品（`deploy/lib/common.sh`）に答えの読み替え（`ec_sample_set`）と入れる手順（`ec_add_samples`）を置いた。偽の `ec_dc` で `docker/check-deploy.sh` から確かめるため（install.sh は読み込むとそのまま流れる）

## 結果

- 得たもの: インストーラーの 2/5 でテーマに合ったサンプルを選べる（既定はお菓子のお店）。開発の見本の店とインストールのサンプルが同じ中身になった。写真の権利の物を配る物に入れずに済む
- 失ったもの: 雑貨以外を入れる時はサーバーから Unsplash へ出る（出られないと写真なしになる）。Unsplash の写真が消されると、その写真は入らない（注意が出るだけ）。開発の見本の店の商品名に「（サンプル）」が付き、品番が変わった
