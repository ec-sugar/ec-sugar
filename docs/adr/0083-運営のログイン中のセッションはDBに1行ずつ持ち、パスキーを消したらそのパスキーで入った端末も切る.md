# 0083 運営のログイン中のセッションは DB に 1 行ずつ持ち、パスキーを消したらそのパスキーで入った端末も切る

状態: **採用**（2026-11-06。外からの見直しの「ゼロトラストを実現できているか」への答えで、公開の前にやるものとして「止めたら即座に切る」「いつもと違うログインの知らせ」を選んだ）。ADR 0013（ログインはパスキーだけ）・ADR 0038（パスキーをなくした時）を補う。

## 文脈

- 運営のセッションは、毎リクエストで `EnsureOperatorIsActive` が確かめ直している。止めた運営・絶対期限（12 時間）・ログアウトした番号（`RevokedSessions`）は、次のリクエストで締め出せていた。店の権限も `EnterTenant` が毎回 DB を読むので、変えた次の操作から効く
- 穴は 2 つあった
  1. **パスキーを消しても、そのパスキーで入ったセッションは最長 12 時間生きたまま**。端末を盗まれて、本人が別の端末からそのパスキーを消しても、盗まれた端末の画面は使い続けられる
  2. **ほかの端末のセッションを切る手段が無い**（一覧も無い）。取り消しはキャッシュ（Redis）にだけ覚えていて、Redis が消えると忘れる
- いつもと違う接続元からのログインは、本人へメールで知らせていた。画面には何も出ていなかった

## 決めたこと

1. **ログインごとに中央 DB の表 `operator_sessions` に 1 行**を作る。中身は運営・入ったパスキー・端末の種類（ブラウザと OS だけ。例「Chrome / Mac」）・いつもと違う接続元か・入った時刻・最後に使った時刻・終えた時刻と理由
   - 接続元の住所は置かない（監査ログにある）。UA は種類に丸め、DB の CHECK で文字を縛る（版や細かい印・HTML を置かない）
   - セッションには行の ID だけを置く。セッションの中身はサーバーにあり、お客さんや攻撃者は書き換えられない
2. **毎リクエストで行が生きているかを確かめる**（`EnsureOperatorIsActive`）。行が無い・終えた・ほかの運営の行なら、セッションごと締め出す（監査ログに `ended`）
   - この仕組みの前にログインしていた画面（行が無い）も、ログインし直してもらう。取り込んだ時に 1 度だけ起きる
   - 最後に使った時刻は 1 分に 1 回だけ書く（毎回は書かない）
3. **行を終える時**
   | 時 | 理由 |
   |---|---|
   | ログアウト | `logout`（今までの `RevokedSessions` も残す） |
   | 一覧から 1 つ | `ended_by_self`（今の画面は終えられない。ログアウトで） |
   | 「ほかの端末を全部ログアウトさせる」 | `others`（今の画面は残す） |
   | パスキーを消した | `passkey_removed`（そのパスキーで入った画面だけ。消した本人の今の画面は残す） |
   | 運営を止めた（画面・コマンド） | `disabled`（全部） |
   | 絶対期限を過ぎた | `expired` |
4. **一覧と終える操作は本人の分だけ**。直前の再確認は求めない。守りの操作だから（盗んだセッションで本人を締め出されても、本人はパスキーで入り直してその端末を終えられる）。ほかの運営の行は見つからない扱い（404）
5. **いつもと違う接続元**（過去 90 日に無い回線。決め方のまま）から入った行に印を付ける。今の画面でない印つきの端末がログイン中なら、ホームに知らせを出し、そこからログアウトさせられる。入った本人の画面には出さない（出先から自分で入っただけ）

## 選ばなかったもの

- **セッションの番号そのものを DB に置く**: 番号が漏れればセッションを名乗れる。ハッシュにしても、Laravel はログインの時に番号を作り直すので追いにくい。行の ID をセッションの中に置く方が単純
- **パスキーを消したら全部の端末を切る**: 本人の今の画面まで切ると、消した後の確かめ（ほかのパスキーが使えるか）ができない。消したパスキーで入った画面だけを切る
- **端末の状態（OS の更新・管理された端末か）を見る**: 運営が少ない今は手間に見合わない。パスキーが端末に結びつくので、盗まれた時の切り方を先に作った

## 結果

- 端末をなくした・盗まれた時の手順は「別の端末からそのパスキーを消す」だけで、その端末の画面も次の操作で締め出される
- Redis が消えても、終えたセッションは締め出したまま
- 毎リクエストに中央 DB の主キーの読みが 1 回増える
