# 0064 送料は「配送の方法」ごとの都道府県の表で決め、方法の違う品は分けて送る

状態: **採用**（2026-11-05。送料の細かい設定を作ることは運営が選んだ。形は作る時に決めた）。ADR 0054（クーポン: 送料無料のクーポン・「◯円以上で無料」は値引きの後）・0055（贈り物: いちばん高い送料で取り、受け取りの住所で差額を返金）・0049（定期便: 送料も約束）の上に置く

## 要点（先に）

1. 送料の表は**配送の方法**（「通常便」「クール便」など。10 まで）ごとに、**47 都道府県の額**と「**◯円以上で無料**」を持つ。入力は地域（北海道・東北・関東・信越・北陸・東海・近畿・中国・四国・九州・沖縄）でまとめて入れ、県ごとに上書きできる。保存は県ごと
2. 商品は**使う配送の方法を 1 つ**（空ならいちばん上の方法）と「**送料無料の商品**」の印を持つ
3. 方法の違う商品が 1 つのカートにあれば、**分けて送り、方法ごとに送料**を取る（断らない）。同じ方法の便に送料無料の商品があれば、その便は送料無料
4. カートでは**目安**（いちばん安い地域〜高い地域）。注文の入力で送り先の都道府県が決まった後の確かめの画面から**確定の額**。確かめの画面の指紋に方法ごとの額を入れる
5. 今の設定（全国一律・◯円以上で無料）は、**全国同じ額の「通常便」1 つ**に移行で写す
6. 贈り物はいちばん高い額で取り、受け取りの住所で決まる額との**差額を返金**する（返金の目的 `shipping`、1 注文 1 回）

## 文脈

- 今の送料は全国一律と「◯円以上で無料」だけ。北海道・沖縄・離島で額が違う、冷やして送る品がある店は乗り換えられない（2026-11-05。乗り換えのいちばんの壁）
- 贈り物（ADR 0055 の 7）は「地域別の送料が入ったら、受け取りの住所で決まる送料との差額を受け取りの時に返金する」と決めてある
- 定期便（ADR 0049 の 4）は送料の決まり（額と無料の線）を約束として契約に持つ

## 決定

### 1. 送料の表

- 配送の方法: 名前（30 文字まで、店の中で重ならない）・並び・「この金額以上で無料」（1〜¥10,000,000、空なら無料にしない）。1 つ以上 10 まで。いちばん上の方法が、方法を選んでいない商品の方法（既定）
- 額: 方法 × 47 都道府県、0〜¥100,000 の整数（円・税込み）。DB の制約でも範囲と都道府県の名前を守る。保存は表をまとめて置き換える（47 県がそろわない保存は断る）
- **離島の加算は今回は持たない**。郵便番号から離島を確実に決める表が手元に無く（外のサービスに頼ると注文が止まる）、運送会社の中継料も店ごとに違う。要る店は注文の案内（届く目安）に「離島は別にご連絡します」と書く。後で郵便番号の範囲で足せる形（方法ごとの加算の表）にしておく
- 方法を消すと、その方法の商品はいちばん上の方法になる（商品の列は空に戻す）。注文の行と受渡には名前を写してあるので、過去の注文は変わらない

### 2. 商品

- `listings.shipping_method_id`（空ならいちばん上の方法）と `listings.free_shipping`（送料無料の商品）。商品の編集と同じバージョンの確かめとイベント（`listing.updated`）で変える。変えると定期便の約束の見直し（ListingPriceChanged）も走る
- 「使える方法」を複数持つ形（お客さんが便を選ぶ）は持たない。日本の店では「この品はクール便」と品で決まることがほとんどで、選ばせると手間が増える

### 3. 方法の違う品・送料無料の品

- **分けて送り、方法ごとに送料**（日本の店でよくある「常温と冷凍の品は別の便で、送料は 2 つ分」）。断ると、買う人がカートを 2 回に分ける手間になる。受渡（Fulfillment）も拠点 × 方法で分け、受渡に方法の名前を写す（発送の画面・配送の CSV で便が分かる）
- 「◯円以上で無料」は**方法ごとに、その便の品の値引きの後の小計**で決める（ADR 0054 の 4 を方法ごとに）。クーポンの値引きは対象の品へ金額の割合で割り振ってから便ごとに足す（ADR 0054 の 7 と同じ割り振り）
- **同じ便に送料無料の商品があれば、その便は送料無料**（同梱の品も無料。「送料無料の品と一緒なら全部無料」は日本の店でよくある形で、店にもお客さんにも分かりやすい）。別の便には効かない
- 送料無料のクーポン（ADR 0054）は、すべての便の送料を無料にする

### 4. カート・確かめの画面・確定

- カートは住所を知らないので**目安**: 便ごとのいちばん安い地域〜いちばん高い地域の合計（「¥800〜¥1,500」）と、合計も幅で。全国同じ額なら今までどおり 1 つの額。ほかの案（カートで都道府県を選ばせる）は、手間を増やすので採らない
- 注文の入力で送り先が決まると、確かめの画面・確定はその都道府県の額。贈り物はいちばん高い額
- 確かめの画面の指紋（`CheckoutSummary::fingerprintOf`）に、便ごとの方法と額を入れる。確かめた後に表・商品の方法が変われば確定しない（「内容が変わりました」）
- 便が 2 つ以上・店に方法が 2 つ以上ある時は、送料の行の名前を「送料（クール便）」にし、確かめの画面・ご注文の状況・メールで方法と額が分かるようにする

### 5. 移行

- 今の `shop_settings.shipping_fee`・`free_shipping_over` を、全国同じ額の「通常便」1 つに写す（行が無い店は 0 円・無料の線なし）。古い列は残すが読まない（戻せるように。次に触る時に消す）
- 運営の近道 `ShopSettingsService::setShipping`（全国一律にする）は残し、いちばん上の方法を全国同じ額にする（入れたときのサンプル・テスト）

### 6. 贈り物の差額（ADR 0055 の 7）

- 注文の時に、便ごとに「どう決めたか（都道府県の額・いちばん高い額・無料の線・送料無料の品・クーポン）」と額を `order_shipping` に残す。いちばん高い額で取った便は、**その時の 47 県の額を写して**持つ（受け取りまでに店が表を変えても、注文の時の表で差額を決める）
- 受け取る人が送り先を入れた時（同じトランザクション）に、写した表で差額を決めて記録し（`order.shipping_settled`。都道府県は残さない）、確定の後にキューの仕事で決済代行へ返金を頼む。返金は今の返金の記録（`refunds`）に目的 `shipping` で残し、成功してから台帳に返金を書く（ADR 0027 の流れ）
- 差額が 0 なら何もしない。返金は受け取った額まで（クーポンで払いが小さい時）。1 注文に 1 回（DB の一意の索引）。0 円の注文（払いが無い）は返金しない
- 返金がはっきり断られたら失敗として残し（注文の画面の返金の一覧と、ホームのやること）、自動では頼み直さない。答えが分からない時は、返金の見回り（`RefundReconciler`）が同じ冪等キーで頼み直す
- **注文の取消の返金は、送料の差額の返金を引いた額**。差額の返金が途中（答え待ち・止めた）の間は、取消を断る（二重に返さない）

### 7. 定期便（ADR 0049 の 4）

- 約束の送料は、申し込みの時の**送り先の都道府県と商品の方法**で決めた（額・無料の線）。店が表や商品の方法を変えたら、今の値段の変更と同じ知らせの流れ（その契約の都道府県で額を比べる）
- お客さんが届け先を変えて都道府県が変わったら、その時の表で約束の送料を決め直す（お客さんが選んだ変更なので、知らせを待たない）

### 8. 上限と守り

- 方法 10・名前 30 文字（改行と制御文字を断る）・額 0〜¥100,000・無料の線 1〜¥10,000,000。負の額・小数・文字は断る。DB の制約が 2 枚目
- 表を変えるのは「運用」以上の権限（ほかの店の設定と同じ）。表の変更はイベント（`shop.shipping_methods_updated`。変わった方法の ID と名前・額は入れる。個人情報は無い）と中央の監査ログに残す
- 送料はいつもサーバーで決める。カートやフォームから送られた額・方法を信じない

## 結果

- 得たもの: 地域ごとの送料・クール便・送料無料の商品を、乗り換えてきた店がそのまま持てる。贈り物の送料の取りすぎを返せる
- 失ったもの: カートでは送料が幅になる（送り先を入れるまで確定しない）。離島の加算は無い。1 つの品に複数の方法を選ばせられない

## 作って決めたこと（2026-11-05）

- API は `GET`・`PUT /api/tenants/{店}/shipping-methods`（表をまとめて置き換え）。前の `PUT …/shop-settings/shipping`（全国一律）は外した（開いたままの古い画面が地域の額を全国一律で上書きしないように）。店の設定の答えからも `shipping` を外した
- 同じ表の保存は記録を残さない（イベント・定期便の見直しを出さない）。中央の監査ログには保存ごとに 1 行（`operator.shipping_changed`。方法の数だけ）
- 方法の名前の入れ替え（A と B を取り替える）は、残す方法の名前をいったん ID にしてから付け直す（一意の制約に当たらないように）
- 送料の行の名前は、店に方法が 2 つ以上か便が 2 つ以上のときだけ「送料（クール便）」。方法が 1 つの店は今までどおり「送料」
- カートの目安のときは合計も幅（「¥4,800〜¥6,000」）。送料無料のクーポンを入れているときは幅を出さず「無料（クーポン）」
- 返す額が残っていない取消（送料の差額の返金が払いの全部だった）は、返金を頼まずに取り消す
- 送料の差額の返金がはっきり断られたら、自動では頼み直さない（店のホームのやることに出す。注文を取り消すと返せていない差額も含めて返る）。答えが分からない返金は返金の見回りが続きから
- 定期便の 1 回目の注文（カートを通さない注文）の送料も同じ表（商品の方法と届け先の都道府県）から決める
- 受渡に写す方法の名前は、方法が 1 つの店でも写す（発送の画面で便が分かる）

## 作って決めたこと（2026-11-05、PR 89 の見直し）

- **返金の記録を作る前に止まった差額を拾い直す**: 受け取りの後のキューの仕事が届かない・支払いの準備（`prepareCancel`）で止まると、差額は決まったのに返金の記録が無いまま残っていた。仕事は「今は頼めない・答えが分からない」（`waiting`）なら例外で落ちてキューにやり直させ、返金の見回り（`storefront:reconcile-refunds`）も「差額が決まり（`settled_fee` が入り `fee > settled_fee`）、差額の返金の記録が 1 つも無く、払われて閉じていない注文」を受け取りの 15 分後（`ShippingDifferenceRefunds::STRANDED_AFTER_MINUTES`。仕事のやり直しの間より長く）から古い順に拾い直す。仕事と見回りが同時に拾っても、記録はロックの中で前の記録を返す（`openForShipping`）と部分の一意の索引で 1 つ、冪等キーも同じなので返金は 1 回。**断られた記録のある注文は拾わない**（自動では頼み直さない）。別のアカウントで受けた支払いのように頼めないままの差額は、見回りのたびに次の回へ回る（ログに警告。店のホームには出ない。残り）
- **断られた差額は、店の人が注文の画面の「差額をもう一度返金する」で頼み直す**（`POST …/transactions/{id}/shipping-refund/retry`。お金の段階・パスキーの直前の再確認・中央の監査ログ〔立ち入りの記録〕）。押すと、断られて片付けていない差額の返金を **Stripe の答え（`failed` と断りの符号）のまま残して片付けの印（`resolution = retried`）だけを付け**、新しい返金の記録を作って頼む（同じトランザクション。印と記録の片方だけにならない）。一意の索引（`refunds_one_shipping`、`status <> 'failed'` の行だけを数える）はそのままで、生きた差額の返金は 1 注文に 1 つ。断られた行の状態を書き換えないのは、決済代行の答えを記録として残すため（`refunds_resolution` の制約に `retried` は「失敗した差額の返金だけ」を足した）。新しい記録の冪等キーは断られた数の続きの番号（`refund-shipping-{注文}-2`）。また断られたら新しい記録が失敗で残り、もう一度頼み直せる。途中・済んだ差額の返金がある・注文を取り消した時は断る（409）。発送の後でも頼み直せる
- **店のホームのやること**: 断られた差額は、片付けの印の無いもので、ほかの差額の返金が途中・済んでおらず、注文が閉じていない（取り消していない）ものだけを出す。取り消した注文は取消の返金が返せていない差額も含めて返すので出さない（前は取り消した後も出たままだった）
- **郵便番号と都道府県を照らす**: 送料は都道府県で決まるので、注文の入力（買う人・送り先）と贈り物の受け取りの住所（と、同じ確かめを使う会員の届け先）で、郵便番号の上 3 桁から引いた都道府県と選んだ都道府県が合わなければ「郵便番号と都道府県が合いません」で断る。郵便番号から住所を入れる仕組みは外のサービス（zipcloud）なので、照らすのには使わず、**上 3 桁 → 都道府県の手元の表**（`App\Storefront\Postal\PostalPrefectures`）を持つ。出どころは日本郵便の郵便番号データ（住所の `utf_ken_all.csv` 2026-10-23 版と事業所の個別番号 `jigyosyo.csv` 2026-10-27 版。2026-11-05 に取って上 3 桁ごとの都道府県を集めた。日本郵便は著作権を主張していない）。2 県にまたがる上 3 桁（県境の町と事業所の個別番号。22 個）はどちらも通す。**表に無い上 3 桁（まだ使われていない・新しく付いた番号）は照らせないので通す**: 断ると、表を作り直すまで正しい住所の注文が止まる。安い県を選ぶ悪用は、使われている番号ではどれも照らせる。セッション・定期便の届け先から入力を戻す時（`CheckoutInput::fromArray`）は照らさない（入れた時に照らし済み、前に保存した届け先で定期便の回を止めない）。表は日本郵便のデータの新しい版で年に数回作り直す
- **確定は、作った注文の合計が確かめの画面の合計と同じかを照らす**（守りの 2 枚目）。指紋が合っても明細の組み立てが違えば、ログ（`Log::error`）に残して確定しない
