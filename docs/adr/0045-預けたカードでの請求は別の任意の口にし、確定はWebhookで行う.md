# 0045 預けたカードでの請求は別の任意の口にし、確定は Webhook で行う

状態: **採用**（2026-10-31。4 の 3 つは運営が選択肢で決めた）。定期便の土台。ADR 0019（Stripe Checkout・確定は Webhook）・0022（SaaS の店は Stripe Connect の直接の支払い）・0026（決済は核の口を通す）・0044（お客さんの台帳）の上に置く

## 要点（先に）

1. 預けたカードで請求する口は、今の `PaymentDriver` とは**別の任意の口**（`StoredPaymentDriver`）にする。持たない決済代行の店では、定期便を使えない（画面で出さない）
2. カードを預ける先（Stripe の Customer）の ID は、核の表でなく**決済の部品の表**に、お客さん × 決済代行 × アカウントの組で置く。カードの番号は今どおり触れない
3. 預けるのは**最初の支払いのとき**（支払いの画面で「次回からこのカードで」を付ける。手続きは 1 回）。カードの変更はマイページから
4. 毎回の請求の**確定は Webhook**（ADR 0019 のまま）。同じ回を 2 回請求しないよう、冪等キーは回の ID
5. カードの本人確認（3-D セキュア）を求められたら、お客さんにメールで知らせ、マイページから確かめてもらう
6. カードが通らなかったら 3 回試して止める（解約しない）、本人確認は 7 日待つ、カードはブランド・末尾 4 桁・期限で見せる（運営の判断）

## 文脈

- 定期便は、お客さんがいない時（夜中の定期の処理）に、前に預けたカードで請求する。今の決済の口は、お客さんがその場で払う支払いの画面（Checkout）と返金だけ（ADR 0026）
- 日本のカードは、お客さんがいない時の請求でも、カード会社が本人確認を求めることがある
- SaaS の店は Stripe Connect の直接の支払い（ADR 0022）なので、Stripe の Customer は店の連結アカウントの中に作る。店の鍵を貼る形から接続する形へ移ると、預けたカードは前のアカウントに残り、使えなくなる
- ADR の見直し（2026-10-31）で、Customer の ID を核の表（ADR 0044 の `customer_accounts`）に置く案は、ADR 0026「核は決済代行を知らない」に反すると分かった

## 決めたこと

### 1. 口

- `App\Core\Payment\Contracts\StoredPaymentDriver`（任意）:
  - `saveOnCheckout(...)`: 支払いの画面を開くときに「カードを預ける」を付ける（Stripe なら `setup_future_usage=off_session` と Customer）
  - `openCardUpdate(...)`: カードを替える画面（Stripe なら Checkout の setup のモード）
  - `chargeStored(credentials, storedMethod, amount, currency, idempotencyKey, transactionRef): StoredChargeResult`（お客さんのいない請求。状態は succeeded・processing・requires_action・failed に正規化。失敗の理由はカード会社の符号だけ）
  - `detachStored(...)`: 解約・退会で預けたカードを外す
- 決済代行が持つかどうかは、ドライバがこの口を実装しているかで決まる。核の定期便は、口が無ければ「この店では定期便を使えません」

### 2. 置き場

- 店の DB に `stored_payment_methods`（決済の部品の表）: お客さんの台帳の ID（ADR 0044）・決済代行の名前・アカウント（Stripe の連結アカウント。店の鍵なら空）・Customer の ID・カードの ID（`pm_`）・状態（使える・登録し直しが要る・外した）・作った時刻
- 同じお客さんでも、アカウントが替われば別の行。今のアカウントの行だけを使う。アカウントを替えた店では、預けたカードは「登録し直しが要る」にして、定期便を止め、お客さんに知らせる

### 3. 請求と確定

- 回の日に、定期便が子の取引を作り（ADR の見直しで「子は合意から始める」）、`chargeStored` を呼ぶ。冪等キーは回の ID（同じ回は何度呼んでも 1 回の請求）
- 確定は Webhook（`payment_intent.succeeded`・`payment_intent.payment_failed`）。同期の答えは「途中」の記録に使うだけで、台帳には Webhook で書く（今の支払いの画面と同じ）
- 本人確認を求められたら（`requires_action`）、その回は「お客さんの確かめ待ち」。お客さんにメールで知らせ、マイページの「お支払いの確認」から Stripe の確認の画面へ。済めば Webhook で確定して発送へ

### 4. 決めたこと（2026-10-31）

- **カードが通らなかった時**（残高不足など）: 1・3・5 日後に自動で 3 回試し直し、毎回お客さんにメール。全部だめなら定期便を「止める」（自動で解約しない。お客さんがカードを替えると再開）。店にも知らせる
- **本人確認の待ちの期限**: 7 日（待つ間は発送しない）。過ぎたらその回は取り消し（在庫を戻す）、定期便は続ける
- **カードの見せ方**: ブランド・末尾 4 桁・期限を持って、マイページと管理画面に「Visa •••• 4242（2028 年 12 月まで）」と出す（カードの番号ではないので PCI DSS〔カードの業界の守りの基準〕で持ってよい値。暗号化はしない）。表 `stored_payment_methods` にブランド・末尾 4 桁・期限の年と月の列を足す。期限の 1 か月前にお客さんへ知らせる

## 作って決めたこと（2026-11-01）

- **預ける先は別の表** `stored_payment_customers`（お客さんの台帳 × 決済代行 × アカウントで 1 つ、一意の制約）。2 では「カードの行に Customer の ID」としたが、カードを預ける前（1 回目の支払いの画面を開く時）に Customer が要るので分けた。カードの行（`stored_payment_methods`）にも Customer の ID を写す
- 口は `StoredPaymentDriver` の `createCustomer`・`openCheckoutSavingCard`・`savedCardOf`・`chargeStored`・`detachStored`（カードを替える画面 `openCardUpdate` はマイページの区切りで足す）。Stripe の実装は `StripeStored`、支払いの画面は Customer に付けて `setup_future_usage=off_session`
- Customer に渡すのは台帳の ID と店の名前の札だけ（メールなどは渡さない）。冪等キーは「お客さん × アカウント」
- 1 回目の支払いの記録（`payment_attempts.saves_card_for`）に「預けるお客さん」を残し、払われた知らせの後で、Stripe の答えの Customer がそのお客さんの預ける先と同じときだけカードを記録する（`payment.card_stored`。中身はカードの行の ID と決済代行だけ）。記録に失敗しても支払いの確定は変えない
- お客さんのいない請求は、使える・今のアカウントのカード・1 円以上のときだけ。カードの断りは状態 failed と断りの符号、本人確認は requires_action と支払いの ID。答えが分からなければ例外（同じ冪等キーでやり直す）。確定と台帳は Webhook（区切り 3）
- 外す（`payment.card_detached`）は、今のアカウントのカードなら Stripe でも外す

### 見直しで直したこと（2026-11-01）

- **アカウントの見分け**: テストと本番を必ず分ける（`test:own`・`live:acct_…` の形）。店の鍵をテストから本番へ替えると、テストの預け先とカードは使わない（新しい預け先を作る）。同じモードで別の Stripe アカウントの鍵へ貼り替えたときは、請求で「カードか預け先が無い」と分かった時に登録し直しの印（`needs_update`）を付ける
- **請求の答えは 6 つ**（`StoredCharge`）: succeeded・processing・requires_action（Stripe は本人確認が要るとき 402・`authentication_required`・状態 requires_payment_method で返すので、符号で読む）・failed（カードの断り。カードか預け先が無い `resource_missing` は登録し直しの印）・unknown（通信の失敗・429・5xx・読めない答え・知らない状態）・rejected（鍵の失効や連結の取り消し、同じ冪等キーで違う中身。お客さんの失敗に数えず人に知らせる）。例外を外へ出さない
- **冪等キーは 24 時間ほどで消える**（Stripe）。区切り 3 では、請求の前に「回 × 何回目」の行と冪等キーを記録し、試し直しは回数ごとに別のキー、unknown のやり直しは 24 時間のうちに同じキーで（それを過ぎたら Stripe に問い合わせてから）
- **預けるのは、その注文のお客さんの台帳で、会員で、止めておらず、まとめられていないときだけ**。確かめは店の公開・払える注文の確かめと一緒に先に行い、預け先はその後で作る。請求も、渡した契約のお客さんとカードの持ち主が同じときだけ
- **預ける画面とふつうの画面を混ぜない**（支払いの記録と予約の両方に `saves_card_for`）
- 預け先の記録は連鎖のロックとイベント（`payment.customer_prepared`）。知らせで記録するときは、画面を作った時のアカウントと今のアカウントが同じときだけ、外したカード・ほかのお客さんの行は上書きしない。外すときに Stripe でもう外れていれば済みとして扱う
- 記録に失敗した預けたカードは、定期便の請求の前に 1 回目の支払いから拾い直す（`StoredPayments::recover`、2026-11-01 区切り 3）。unknown の 24 時間を過ぎた請求は聞き直さず人が確かめる（Stripe への問い合わせで確かめる形は残りの作業）。請求してよいか（開いた・合意の段・払われていない注文、閉じた記録の番号は使わない）は核がロックの中で決める。後で断られた請求は `payment_intent.payment_failed` で記録を failed にする（Stripe に登録する知らせの種類に足した。ADR 0049 の見直し）

## 採らない案

- **今の `PaymentDriver` に足す**: 預けたカードを持たない決済代行（コンビニ払いなど）にも実装を強いる
- **Stripe Billing（Stripe の定期の仕組み）に任せる**: 運営が「EC-SUGAR が回を管理」を選んだ（2026-10-31）。台帳が決済代行に依存しない（ADR 0019）
- **Customer の ID を核の表に置く**: ADR 0026 に反し、アカウントの切り替えで壊れる

## 結果

- 定期便を、核を決済代行から切り離したまま作れる。2 つ目の決済代行でも、口を実装すれば定期便が使える
- 表が 1 つ増える。アカウントを替えた店では、お客さんにカードの登録し直しをお願いすることになる
- **カードを替える画面**（2026-11-01 の後半）: 口に `openCardSetup`・`savedCardOfSetup` を足した（ADR の `openCardUpdate` に当たる）。Stripe は Checkout の setup のモードで、預け先に付け、metadata は記録の ID と店だけ。知らせ（`checkout.session.completed` の setup）でカードを記録し、本人確認はこの画面で済む。新しいカードはいちばん新しい使えるカードとして請求に使う（前のカードは外さない。外すのは残りの作業）
- **開いたままの請求の取り消しと、カードを外す**（2026-11-03 の残りの守り）:
  - 口に `cancelStoredCharge` を足した（Stripe は先に今の状態を問い合わせ、払われた・処理中なら取り消さない）。核の `StoredPayments::releaseOpenCharges` が、開いたままの請求を決済代行で取り消して記録を failed にする（`payment.stored_charge_cancelled`）。払われていた・処理中・答えの分からない請求（仮の参照のまま）・作った時と違うアカウント・問い合わせられない時は取り消さず、注文も取り消さない（後でもう一度。答えの分からない請求は人が確かめる）
  - 新しい番号で請求する前に、前の番号の開いたままの請求を取り消す（取り消せなければ今は請求しない。お客さんの断りに数えない）。カードを替えた後の請求し直しで、前の本人確認の画面から後で払われて二重にならないように
  - 払われていない注文の取消（`SaleOrderService` の払われていない側。管理画面の取消・回の処理・見回りのどれも）は、先に預けたカードの開いたままの請求を取り消す。核の見回り（`storefront:expire-unpaid-orders`）は、14 日を過ぎても払われない預けたカードの注文も同じ道で片付ける（定期便の App を止めた店など）
  - カードを外す（`DetachStoredCards`、裏の仕事で送り直しつき）: 退会した時（核が `CustomerLeft` を聞く）・新しいカードを記録した時（前のカード）・定期便が全部解約済みで届ける回も終わった時（プラグインの毎時の処理）。作った時と違うアカウントのカードは今の鍵で外せないので、記録だけ外したにする
- **見直しで直したこと**（2026-11-03、見直しの重 1・中 4。軽 6 は残りの作業）:
  - 支払いの ID の無い、はっきりした断り（失敗・受け付けなかった）の記録は失敗にする（`payment.stored_charge_refused`。開いたまま残すと、次の番号の請求と注文の取消が止まり続けた）。同じ番号で頼み直す時は、その記録を開き直す（`payment.stored_charge_restarted`。決済代行に支払いは作られていない）
  - 請求の取り消しは、その請求を作ったアカウントの鍵で（`stripeFor`）
  - 払われていない注文の取消は、入口で開いたままの請求を取り消し（取り消せなければ断る）、ロックの中でも開いた記録があれば断る（取り消しの確かめの後に始まった請求のある注文を取り消さない）。管理画面の取消も同じ道
  - カードを外す仕事は、出した時に決めたカードの ID だけを外す（送り直しを待つ間に預けた新しいカードを外さない）

- **抽選販売も同じ口で請求する**（2026-11-06、ADR 0080）: App「抽選販売」は申し込みの時にカードを預け（カードを替える画面と同じ setup のモード）、当選の注文を `chargeTransaction` で請求する。カードを外す道が 2 つの App にまたがるので、使い終わったカードを外す前にほかの App がまだ使うかを聞く口（`StoredCardHolder`・`StoredPayments::heldByApps`）を足し、定期便の毎時の処理もそれを聞く（定期便を全部解約したお客さんの、抽選の結果を待つカードを外さない）。退会では聞かずに外す
- **カードの指紋**（2026-11-06 の見直し、ADR 0080）: 預けたカードの行に Stripe の `card.fingerprint`（同じアカウントの中で同じカードなら同じ値。番号ではない）を残す（`stored_payment_methods.fingerprint`、`SavedCard::$fingerprint`）。前に預けたカードは空のまま。答えの分からないまま 23 時間を過ぎた請求を、店の人が Stripe で確かめた後に閉じる口 `StoredPayments::abandonUnknownCharges`（`payment.stored_charge_abandoned`）も足した
