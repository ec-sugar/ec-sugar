# 0048 返品と一部返金は、取引に返金の行を足して記録する

状態: **採用**（2026-11-01。運営が選択肢で決めた: 返金は行と数を選ぶ＋金額だけの返金も・返品の在庫は行ごとに選ぶ〔既定は戻さない〕・作るのは止めた返金の片付け〔〕から、返品と一部返金は会員と定期便の後）。（一部返金の仕訳・止めた返金の片付けを寄せる）。ADR 0011（取引と仕訳）・0024（お金の権限）・0027（返金の記録）・0036（種類とオプション）の上に置く

## 要点（先に）

1. 今できる返金は、発送の前の取消（全額）と、返金が要る支払いだけ。画面の文は「発送した注文は返品・返金で扱います」と約束しているのに、その形が無い
2. **返金は、取引を開き直さず、同じ取引に「返金の行」を足して記録する**（どの行の何個を・いくら・税率ごとに）。台帳には返金の仕訳を、決済代行の返金が成功してから書く（ADR 0027 の流れのまま）
3. 返金の操作はお金の段階と直前の確かめ（ADR 0024）。返金の合計は、受け取った額を越えない（DB とサービスの両方で守る）
4. 止めた返金（額が違う・Stripe の画面でした返金）は、同じ画面で片付ける

## 決めたこと

### 1. 返金の単位

- **行と数を選ぶ**（金額は行の値段 × 数で出し、送料・オプションの料金は返すかを選ぶ）。店の都合の値引きや見舞いの返金のために「金額だけの返金」も 1 行で足せる（理由を書く）
- 税率ごとに分けて仕訳を立てる（ADR 0011 の丸めの決まり。オプションは親の行と同じ税率〔ADR 0036〕）

### 2. 返品の在庫

- 返金の時に、行ごとに「在庫に戻す」を選ぶ（既定は戻さない。傷んだ品・食品は戻せない）。戻す時は種類（ADR 0036）の在庫に、記録つきで

### 3. 閉じた取引

- 完了した取引にも返金の行を足せる（取引の状態は「完了」のまま、返金の合計で「一部返金」「全額返金」と見せる）
- 取り消した注文の返金が後から失敗した時（今はアプリの中でやり直せない）: 同じ画面の「返金をやり直す」で、新しい冪等キーで頼み直す

### 4. 止めた返金の片付け

- 額が違って止めた返金・Stripe の画面でした返金（ADR 0027 の追記）は、店の人が Stripe で確かめた後に、「この額で返金として記録する」（台帳に返金の仕訳、返金の行も足す）か「返金は無かった」を選ぶ。理由を残し、イベントにする

## 採らない案

- **取引を開き直す**: 完了した取引の状態を戻すと、発送・在庫・売上の数（ADR 0042）がぶれる
- **返金ごとに別の取引を作る**: 元の注文と返金が離れ、一部返金の合計の守り（受け取った額を越えない）が取引をまたぐ

## 結果

- 返品・一部返金・返金のやり直し・止めた返金の片付けが、注文の画面の 1 か所に集まる
- 台帳の「受け取ったまま」が、確かめた返金で正しく減る。運営全体の売上（ADR 0042）は返金を引いた額に直す

## 作って決めたこと（2026-11-05）

### 形

- **返金の 1 回（`order_returns`）と返金の行（`refund_lines`）**。どちらも追記だけ（直す・消すを DB が断る）。1 回は理由（決まった値 `ReturnReason`。自由な文は持たない）・合計・税率ごとの返す額と消費税（`taxes`）・誰が（actor）。行は種類（商品 `item`・オプション `addon`・送料 `shipping`・金額だけ `amount`）・明細の位置・数・額・税率・在庫に戻したか
- お金の動きは今までの返金の記録（`refunds`）に目的 `return` と `return_id` を足して追う。1 回に生きた返金は 1 つ（DB の部分の一意の索引）。断られたら、同じ 1 回に新しい返金の記録を足して頼み直す（冪等キーは `refund-return-<1 回の ID>` と続きの番号）。取引の状態は変えない
- **返し方（`refunds.channel`）**: `provider`（Stripe に頼む。ADR 0027 の 3 段のまま）・`outside`（店が外で返した記録だけ。銀行振込・代金引換・現金など。その場で済みにして帳簿まで書く。台帳の返金の仕訳は店から直に返した向き〔`PaymentRoute::Direct`〕）。外で返した記録は決済代行の支払いを持たないことがあるので、`attempt_id`・`payment_ref` は `provider` の時だけ必須にした。銀行振込・代金引換（並行のブランチ）の「外での返金」もこの形に乗せられる
- 返せるのは**発送した注文（受渡・受取確認・精算の段。開いている・済んだ）**だけ。発送の前は今までの取消（全額）。発送の後は取消できないので、取消と返品が重ならない
- 止めた返金（額が違う・まだ確かめていない Stripe の画面の返金）と、途中の取消・送料の差額・**返品の返金**がある間は、新しい返品を断る（先に片付けてもらう。二重に返さない）。途中（答え待ち・手続き中・止めた）の返品の返金は 1 注文に 1 つで、DB の部分の一意の索引 `refunds_one_active_return` も守る（同じ支払い・同じ額の返金が 2 つ途中にあると知らせを取り違えうる。同時の 2 人の「金額だけ」も 2 人目は断られる）。送料の差額の返金も、途中の返品の返金があれば待つ（見回りが後で拾う）
- 0 円の品だけを返す（在庫に戻す）返品は、返金 0 円の記録として受ける（返金の記録は作らず、決済代行にも触れない）
- 理由 `resale`（2026-11-05、ADR 0069 の「リセール」）: App「デジタルチケット」の公式の定価リセールで売れた 1 枚の額から手数料を引いた額を、元の人へ金額だけの返金として返す時に App が付ける。店の人は選ばない（`choosable` の外。`external` と同じ）。画面の言葉は「チケットのリセール（手数料を引いた額）」

### 額の決め方

- 商品の行の返す額は「明細の額 − 値引きの割り振り（`coupon_redemptions.allocations`）− 使ったポイントの割り振り（`order_points.allocations`）」の実の額を、数で割った**累計の差**（`floor(実の額 × 返した累計 ÷ 数) − floor(実の額 × 前の累計 ÷ 数)`）。何回に分けても、全部返すと実の額にちょうど届く
- 割り振りの記録の無い調整の行（定期便の値引きなど）があれば、その率の明細の合計から送料の分を引いた額を、商品とオプションの行に割合で配り直す（記録がそろっていれば結果は同じ）
- オプションの料金は「その品のオプションの料金も返す」を選んだ時だけ、返す数の分を同じ決め方で（親の率）。送料は「送料も返す」で、まだ返していない分の全部（ポイントの割り振りと贈り物の送料の差額の返金を引く）
- 金額だけの返金は、**税率ごとのまだ返していない額の割合で配る**（店の人に率を選ばせない）
- 返せる数は発送した数 − 返した数（受渡の発送済み・済みの行から）

### 税率ごとの仕訳

- 消費税は**「返す前の残りの額の税 − 返した後の残りの額の税」**（率ごとに 1 回だけ丸める ADR 0063 のまま。全部返すと税の合計が注文の税にちょうど戻る）
- 返金が成功したら（外で返した記録はその場で）、台帳に返金の仕訳（お金の動き）と、**税率ごとの調整の仕訳**（`adjustment`。payer +返した額 / payee −（返した額 − 税）/ tax −税、reference は `return-rate-<率>`）を書く。全部返すと、取引のすべての口座が 0 に戻る。調整は請求の残りを越えない（`LedgerService::recordReturnAdjustment` が断る）。1 円の返金では税が返した額と同じ 1 円になることがあり、その時は payee の行を書かない（作っている途中に、1 円と残りに分けて返すテストで見つけた。前は 0 円の明細になって仕訳が書けなかった）
- Stripe の画面でした返金を店の人が確かめて記録した時（止めた返金の片付け）も、**発送の後（返品できる段）なら**、金額だけの返金の行（理由 `external`）を足して同じ調整の仕訳を書く。**発送の前は今までどおり返金の仕訳だけ**（後で取り消すと、取消が請求と税を全部打ち消すので、調整を書くと口座が 0 に戻らない。見直しの中 1）
- 額が違って止めた返品の返金（held）を、店の人が Stripe で確かめた額で「記録」した時は、確かめた額と返金の行の合計の差を金額だけの行でそろえる（多ければまだ返していない額の割合で足し、少なければこの 1 回の率ごとの額の割合で負の行を足す。負を許すのは金額だけの行だけ）。その後はふつうの返品と同じく、台帳・ポイント・`RefundSettled`（返金の 1 回と行つき）。イベント `order.return_corrected`。返品の 1 回の `amount`・`taxes` は頼んだ時の値のまま残り、台帳の調整の税は行から出し直す。「無かった」とした返品の返金は、断られた返金と同じく頼み直す（新しい冪等キー）か外で返した記録にできる（見直しの中 2）
- 決めきれなかったこと: 贈り物の送料の差額の返金（ADR 0064）は、今も返金の仕訳だけで調整の仕訳を書いていない（payer の口座に差額が残る）。返品の行の残りの計算では送料の率の「返した額」に数えている。次に送料の差額を触る時に、同じ調整の仕訳に寄せる

### 返金の合計は受け取った額を越えない（サービスと DB）

- サービス: 返せる額 = 台帳の支払いの仕訳の合計 − 途中・止めた・済んだ返金 − 断られた・「無かった」とした、まだ頼み直していない返品の返金（`ReturnSettlement::available`）。返金の 1 回はロックの中で作り直し、確かめの画面の合計と違えば断る（`expected_total`。実行の時は必須）。頼み直しも余りを確かめ、足りなければ 409 の文で断る
- DB: 返金の記録を足す・額や状態を変える時に、トリガー `sugar_refunds_within_received` が取引の行を錠で取ってから「台帳の支払いの合計 ≥ 途中・止めた・済んだ返金の合計」を確かめる（返金が要る支払いと、それに当たる外の返金、まだ確かめていない外の返金は数えない）。返金の行もトリガー `sugar_refund_lines_within_line` が明細の数と額を越えさせない
- 送料の差額の返金・取消の返金・止めた返金の片付けの額も、同じ「まだ返せる余り」（`ReturnSettlement::room`）までに抑える
- 返品の送料の計算と率ごとの残りの額では、断られてまだ片付けていない送料の差額の返金も引く（店の人が頼み直せるので、返品の送料で返すと二重になる）

### 知らせの当て方（見直しの中 3）

- 決済代行へ返金を頼む時に、こちらの返金の記録の ID を返金のメタデータ（`ec_sugar_refund`）に載せる。知らせは、決済代行の返金の ID → このメタデータの ID（支払いの ID が分かればそれも合う時だけ）→ 今までの「同じ支払い・同じ額の答え待ち」の順で当てる
- 気をつけること: 冪等キーが同じでも頼む中身が変わると Stripe は頼み直しを断る（idempotency_error）。この変更を入れた時に答え待ちのまま残っている返金を見回りが頼み直すと、断られた（failed）として残る。入れる時は答え待ちの返金が無いことを確かめる

### 在庫

- 「在庫に戻す」を選んだ商品の行だけ、種類 × 拠点の在庫に入庫し、イベント `inventory.returned`（取引・種類・拠点・数・後の数）を残す。返金の 1 回を作る時（ロックの中）に戻す（品は返ってきている。お金が断られても在庫はそのまま）。発送して完了の前なら、押さえた数はそのままで完了の時に出庫される
- 個体の在庫（買取）の行は戻せない（断る）

### ポイント（ADR 0068 の「一部の返金は手で直す」を置き換え）

- 金額だけの返金でも同じ（画面の欄にも一言）。一部の返金が確かになるたびに、返した額の累計 ÷ 割合の元（受け取った額 − 送料の差額の返金）の割合まで、**使った分を戻し（release、cause = `partial`）、付けた分を取り消す（revoke、cause = `partial`。残高まで、足りない分は shortfall）**。割合に合わせるので何度呼んでも同じ
- 全額を返した時は今までの全額の取り消し（release は cause なし、revoke は cause = refund）で、先に割合で動かした分を引いた残り。1 回で全部返せば、行も今の全額の返金とまったく同じ
- まだ付けていない注文（受渡が残る）は戻すだけで、全部発送して付けた時に割合まで取り消す（`SaleOrderService::ship`）
- DB: 注文ごとの戻しの合計は使った数まで、取り消しの合計は付けた数まで（トリガー `sugar_point_entries_within_order`）。`partial` の行は一意の索引の外（何度でも）
- 贈り物の送料の差額のポイントでの戻し（`creditShipping`）は、一部の返金の戻し（`partial`）の後でも消えない（戻したかの判断を cause で分け、使った数のうちまだ戻していない分まで）

### 知らせ

- 返金が確かになったら核のイベント `RefundSettled`（取引・返金・目的・額・全額か・返金の 1 回・返金の行〔種類・明細の位置・数・額〕）を、書き込みが終わってから出す。取消・送料の差額の返金も目的つきで出す。個人情報は入れない。デジタルのチケットの App などはこれを聞いて、返した品に結びつくものを止める
- お客さんへの返金のメール（`order_refunded`。返品・一部返金だけ）: 返した額と、Stripe で返した時はカードへの戻りに数日かかる旨、外で返した時は「お店からのご案内を」。明細の住所・電話は載せない。返金ごとに 1 回（`sent_mails.refund_id`）
- 記録（イベント）: `order.return_recorded`（1 回・理由・額・返し方・税率ごとの額・行）、`payment.refund_requested`・`payment.refund_recorded`（今までどおり）、`inventory.returned`

### 並行の枝と合わせること

- この移行は `sent_mails_kind` と `refunds_*` の制約を作り直している。銀行振込・代金引換など並行の枝も同じ制約に値を足すので、取り込みの時に値の和をとった移行を足して合わせる。移行の down は、返品の記録か取消・返品の返金のやり直しの記録があれば戻さない

### 管理画面

- 注文の 1 件の画面の「返品・返金」: 商品ごとに返す数・在庫に戻す・オプションの料金も、送料も、金額だけ、理由、返し方 → 「返す額を確かめる」（行・税率ごとの額と消費税・合計）→ 実行（お金の段階・直前のパスキーの再確認）。返金の履歴（日時・内容・理由・状態・誰が・額）は閲覧の人にも見える
- 断られた返品の返金と、取り消した注文の後から断られた取消の返金は、「返金の記録」の「返金をやり直す」で頼み直す（Stripe で。返品は外で返した記録にもできる）。店のホームの「確かめが要る返金」にも出し、頼み直したら消える
- 注文の一覧と 1 件の画面に「一部返金」「全額返金」の札（返品か記録した外の返金があって、取引が閉じていない時。全額は返した額が注文の合計に届いた時）
- ホームの売上と運営全体の売上（ADR 0042）は、済んだ返品・一部返金・記録した外の返金・送料の差額の返金を注文の額から引く（注文は数に残す）。売上の集計（ADR 0060）の売上はもともと返金の仕訳を引くので変えない。商品別は、返金が済んだ返品の数と、その割合の額（行の額 × 返した数 ÷ 数）を引く。使ったポイントの数からは一部の返金で戻した分も引く

## 作って決めたこと（2026-11-06 金額だけの返金の後の返品）

通しの確かめで、金額だけの一部返金（お詫びなど）の後に、同じ注文の品を在庫に戻す返品ができないと分かった（品の返す額が明細の実の額のまま決まり、残りを越えて「まだ返していない額を越えて返金できません」で断られた。外で返した記録でも同じ）。運営が直し方を決めた（11-06）: 返す額を残りまでに下げられる形。

- **品の返す額**（商品・オプション・送料の行の合計）の**既定は「品の額と返せる残りの小さい方」**。店の人は 0 から既定までに下げられる（`ReturnRequest::goodsAmount`、管理画面の入力 `goods_amount`。空なら既定）。上げることはできない（品の額より多く返すときは、今までどおり「金額だけの返金」を足す。返金の行の額は明細の額を越えない〔DB のトリガー〕ので、上げる分は金額だけの行になる）
- **上限（＝既定）**は次の小さい方（`ReturnPlanner::fit`）:
  - 税率ごとに「選んだ品のその率の額」と「その率のまだ返していない額（`remainingByRate`）」の小さい方の合計。率ごとに抑えるのは、全体の残りの中でも率の残りを越えると税率ごとの調整（「返す前の残りの税 − 返した後の残りの税」）が書けないため（金額だけの返金は率ごとの残りの割合で配られるので、2 つの率の注文では全体の残りより率の残りが先に尽きる）
  - 返せる額（`ReturnSettlement::available`。受け取った額 − 途中・止めた・済んだ返金 − 断られて頼み直していない返品の返金）
  - 決済代行（Stripe）で返す時は、決済代行で受け取ってまだ返していない額（`room − ギフトカードでの受け取り`。ADR 0076）。ギフトカードで払われた分は Stripe では返せないので、Stripe で返す既定は Stripe の分までに下がる。残りは外で返した記録とギフトカードの戻し（今までどおり）。実行の時の `OVER_PROVIDER` の守りはそのまま（金額だけの返金と合わせて越えた時）
- **下げた額の配り方**は金額だけの返金と同じ `ReturnSettlement::split`（端数は大きい順）: まず率ごとの上限の割合で率に配り、率の中は行の額（明細から決めた額）の割合で行に配る。どの行も明細から決めた額を越えず、どの率も残りを越えない。品の行に記録する額は下げた額（返した数は数えるので、次に同じ行を返す時の額は今までどおり数の累計の差で決まる）
- **0 円**: 品だけ受け取って在庫に戻す記録（今の「0 円の品だけを返す」と同じ道）。返品の記録（`order_returns`。額 0）・返金の行（品は額 0、0 円のオプション・送料の行は残さない）・在庫の戻し（`inventory.returned`）・イベント（`order.return_recorded`）だけを、連鎖のロックの中で同じトランザクションに残す。決済代行に頼まず、返金の記録（`refunds`）も台帳の仕訳も作らない。DB の制約（`order_returns.amount >= 0`・品の行の `amount >= 0`）はもともと 0 を許すので、移行は足していない
- 入力は 0 以上の整数（負は入力の検査で 422、核でも断る）・上限を越える額は見せてよい文（`ReturnPlanner::GOODS_OVER`。上限の額つき）で断る。実行はロックの中で作り直し、確かめの画面の合計と照らす（同時に 2 人が押すと、2 人目は途中の返金で断られ、押し直しても既定が残りに変わっていれば `CHANGED` で確かめ直してもらう）
- 確かめの画面の中身に `goods`（`full` 品の額・`limit` 上限＝既定・`amount` 今回の品の返す額）を足した。管理画面は「品の返す額（円）」の欄（空なら既定）と、確かめた後に品の額と上限を出す
- ついでに直したこと: 返品の画面の「Stripe で返金する」の出し分け（`OrderReturns::options` の `provider`）と、決済代行で返す下ごしらえ（`prepare`）が、店が受け取る支払い（銀行振込・代金引換。`payment_attempts.kind = direct`、ADR 0074）も決済代行の支払いに数えていた。銀行振込の注文で「Stripe で返金する」が既定に出て、押すと「Stripe の支払いが見つからない」で断られた。`kind <> direct` だけを数えるようにした（その時は `NO_PROVIDER` の文で断り、画面は「外で返した（記録だけ）」が既定になる）
