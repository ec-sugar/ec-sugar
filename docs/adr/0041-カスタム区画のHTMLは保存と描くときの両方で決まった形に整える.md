# 0041 カスタム区画の HTML は保存と描くときの両方で決まった形に整える

状態: **採用**（2026-10-30。HTML を書けるカスタム区画が欲しい → 「自由な HTML」と「見たまま書ける文」の 2 つとも作る）。ADR 0039（ページは区画を積んで作る）の核の区画に足すもの。

## 文脈

- ページは区画を積んで作る（ADR 0039）。区画の中身は欄（文・写真・リンク・商品など）で、描くのはテーマか核の部品。決まった形に入らないもの（2 列の説明・細かい表・自分で組んだ案内）は作れない
- 求めたこと: HTML を書ける場所。HTML の分かる人は自分で形を作り、分からない人もボタンで整えたい
- CONCEPT 7.2 の「管理画面からコードを入れない」: 店の人が書いたものがショップで**動くコード**になってはいけない。HTML は形の情報だが、`<script>`・`on…` の属性・`javascript:` のリンク・`iframe`・`form` などを通すと、店のスタッフの書いたもの（乗っ取られたアカウントを含む）がお客さんのブラウザで動き、カードや住所の入力を盗む道になる
- ショップの CSP（`script-src 'self'`・`style-src 'self'`・Trusted Types）があるので、インラインのスクリプトはもともと動かない。けれど CSP だけに頼ると、`form` で偽の入力の欄を作る・`base` や `meta` で行き先を変える・`style` や好きな class で画面を覆う、は止まらない

## 決めたこと

1. **核の区画を 2 つ**: `basic_html`「自由な HTML」（等幅の欄に HTML をそのまま）と `basic_richtext`「見たまま書ける文」（道具の帯で整える）。保存する形はどちらも同じ HTML で、同じ整え方を通す。パターンは「文の幅」「横いっぱい」。公式テーマ 4 つのトップと自由なページに置ける
2. **整えるのはサーバー、保存するときと描くときの両方**: 保存のときに整えた形をしまい、描くとき（ショップ・下書きのプレビュー・試し見）にもう 1 度同じ決まりで整える。決まりを後で狭めたとき・DB を直に書き換えられたときにも、保存済みの値から危ないものが出ない
3. **整え方は実績のある部品**（symfony/html-sanitizer）。自分で正規表現で HTML を整えない。核が持つのは「残す表」（要素・属性・class）と属性の値の決まりと、解析した木の下見（入れ子の深さ・写真の要素ごとの除去・外したものの一覧）だけ
4. **残すのは決まった形だけ**（許した物だけを書き出す。消す物を数え上げる形にしない）:
   - 要素: 見出し（h2〜h6）・段落・改行・区切り線・div/span・文字の飾り・リスト・表・引用・写真（figure）・リンク・details/summary。h1 と section などの入れ物はタグだけ外す。ほかは中身ごと消す
   - 属性: 表に挙げたものだけ（リンクの href と title、写真の src と alt と大きさ、表の colspan など）。`on…`・`style`・`id`・`data-…` は外す
   - リンク: 店の中の道筋か https（区画のリンクの欄と同じ決まり）。いつも `rel="noopener noreferrer"`
   - 写真: 店の写真の置き場の道筋だけ（外の URL は要素ごと外す。お客さんの来訪を外へ知らせない・CSP の img-src とそろえる）
   - 見た目: 核が決めた class（2 列・3 列・中央・ボタンの形・注記の箱など 12 個）だけ。見た目は核の CSS がテーマの変数で付ける。位置を固定する class は作らない（画面を覆わせない）
5. **大きさの上限**: 打った HTML は 2 万字、入れ子は 20 段。越えたら保存で断り、描くときは何も出さない。壊れた文字・制御文字も断る
6. **テーマは HTML の欄を宣言できない**（今は核の 2 つの区画だけ）。テーマに渡すのは整えた後の `HtmlString` だけで、テーマは `{{ }}` で出す。テーマに広げるときは、テーマ API の約束として決めてから
7. **CSP は緩めない**（ショップも管理画面も）。整えた後の HTML も CSP と Trusted Types の下で描く（二重の守り）
8. **スクリプトを動かしたい人へ**: 管理画面では入れられない。開発者モードか App（ADR 0034 の決まった形の差し込み）で。欄の説明にそう書く
9. **見たまま書ける文の部品は自前**（JavaScript のライブラリを入れない）: Tiptap などのよくある部品は、初めの HTML を読むときに DOMParser（Trusted Types の口）を使い、管理画面の Trusted Types と合わない。自前の部品は、サーバーが返す整えた木から要素を 1 つずつ作り、書き出すときは DOM をたどって残す要素と属性だけを HTML にする。整えるのはサーバーなので、部品は道具であって守りではない

## 結果

- 得るもの: 決まった区画に無い形を、店の人が自分で作れる。HTML の分かる人と分からない人の両方に道がある。守りは「サーバーで 2 回・許した物だけ・CSP」の 3 重
- 失うもの: 書いた HTML の一部が黙って外れる（外したものは管理画面の欄の下に並べ、整えた形を見せる）。好きな見た目（style・自分の class）は使えない。埋め込み（動画・地図）は App の区画で
- 気をつけること: symfony/html-sanitizer の更新を追う（Dependabot）。表に足すときは、足した物がスクリプト・読み込み・画面を覆うことにつながらないかを脅威モデルで見る。class の名前は消さない・変えない（保存済みの HTML の見た目が変わる）

## 作って決めたこと（2026-10-30）

- **形**: 欄の種類 `html`・`richtext`（上限 2 万字。`FieldType`）。区画の値は整えた HTML の文字列で、ページの並びの今の形のまま（DB の形は変えない）。読むとき（`sanitizePage`）は文字列と大きさだけを見て、整えるのは描く前の `SectionResolver`（`SectionHtml::render`）。読むたびに整え直すと、管理画面に返す値の形が毎回変わるため
- **保存したものはもう 1 度整えても変わらない**: 整えると `+` `=` `@` などが文字の参照（`&#43;`）になって長くなるので、描くときの上限は打つときの 4 倍（8 万字）。整えた形をもう 1 度整えても同じで、知らせも出ない（テストで見る）
- **大きさは整えた後の形で見て、保存・確かめ・描くときで同じ決まりにする**（見直しで直した）: 前は保存で打った字数（2 万字）だけを見て、描くときは整えた形の 8 万字で見ていた。整えると `"` は `&#34;`、全角の `＜` は `&#xFF1C;` と 5〜8 倍になるので、`"` を 2 万字打つと保存は通り、しまう形は 10 万字になって**ショップで黙って消えていた**。また、しまった形（2 万字を越える）を管理画面がそのまま送り返すと、何も変えていないのに保存で断られた。今は `SectionHtml::clean` の 1 か所で 3 つを見る: (1) 解析の前の歯止め（渡された字数が 8 万字まで）、(2) 字数（整えた後の形で、文字の参照を 1 字と数えて 2 万字まで。しまった形を送り返しても数が変わらない。核が足す `rel` と `<br>` を `<br />` と書く分は数に入る）、(3) しまう形の長さ（8 万字まで。越えたら「ショップに出す形にすると 80000 字を越えます（今は N 字）」と、長くなる記号を挙げて断る）。描くとき（`render`）と確かめの API も同じ既定の上限を使うので、保存で通ったものは必ず描ける。描くときに何も出さないのは、DB を直に書き換えた・決まりを後で狭めたときだけ
- **pre の先頭の改行**: HTML の決まりで `<pre>` の開きタグのすぐ後の改行 1 つは読むときに捨てられるので、中身が改行で始まる pre は整えるたびに改行が 1 つずつ減っていた（保存と描くときで形が違った）。整えた後の形で `<pre …>` のすぐ後が改行なら 1 つ足す（ブラウザが HTML を書き出すときと同じ）。整えた後の形では文の中の `<` は `&lt;`、属性の値の中の `>` は `&gt;` なので、この置き換えが本物のタグにだけ掛かる。整えるのは冪等（何度整えても同じ）になった
- **HTML の中の写真も「使っている写真」**: 写真の画面の「使っている所」（`ShopMediaService::usageMap`）は、値の文字列まるごとが ID の形のものだけを拾っていたので、HTML の中の `<img src="/media/shop/{ID}/large">` で使っている写真を消せてしまった（ショップで写真が欠ける）。今は値の中の `/media/shop/{ID}` の道筋も拾う（欄の種類を見ずに拾う。文の欄に道筋を書いただけでも消せなくなるが、消せないほうに倒れるだけ）。保存のとき（`ThemeContentService` の下書きの書き込み）も、HTML の中の写真がこの店の置き場にあるかを、ほかの写真の欄と同じロック（`EventStore::lock()` の後で写真の行を `lockForUpdate`）の中で確かめ、**無い写真（ほかの店の ID・消した写真）は断る**（欄の道筋 `sections.N.values.html` で「写真を選び直すか、その写真を消してください」）。黙って外すと、保存した後にショップで写真が消えたことに気づけないため、外さずに断るほうを選んだ。テーマを替えて自由なページを写すときも、HTML の中の写真を押さえる
- **求める PHP を 8.4.1 以上に**: `Dom\HTMLDocument`（PHP 8.4 から）と symfony/html-sanitizer（PHP 8.4.1 以上）を使うので、composer.json の `php` を `^8.3` から `^8.4.1` にした（ADR 0002 の追記）。開発機・本番のイメージ・CI は 8.5
- **部品の中の作り**: symfony の部品は、知らない要素を既定で中身ごと消す。`<head>` の要素（`style`・`meta`・`link`・`title`）は本文の設定から外す作りなので、既定を「タグだけ外す」にすると `style` の中の文が文字で出る。既定は「中身ごと消す」のまま、害の無い入れ物だけを「タグだけ外す」に並べた。写真の src を外すのは属性の決まりの口では属性だけになるので、解析器を差し替える口（`ParserInterface`）で、整える前に木を下見して要素ごと外す（同じ下見で入れ子の深さを数え、外したものを一覧にする。深い木を部品の再帰に渡さない）。部品が持つ URL の決まり（スキーム・前後の空白・`//`）も、核の決まりと一緒に掛かる
- **管理画面の確かめの API**: `POST /api/tenants/{店}/section-html`（閲覧の段階から。何も書かない）。整えた HTML・外したもの・編集の箱を組む木を返す。自由な HTML の欄は打って 0.6 秒で呼び、外すものを欄の下に並べる
- **見たまま書ける文の太字と斜体**: ブラウザの編集の命令（execCommand の bold）は、見出しの中などで `style` の属性を足して管理画面の CSP の違反になる（ブラウザのテストの見張りで見つけた）。太字と斜体は要素（strong・em）で包む・外す形にした。見出し・リスト・引用は命令のまま（違反は出ていない）
- **ADR の番号**: ほかの作業場所が 0040（App はページに区画を足せる）を使っているので 0041
