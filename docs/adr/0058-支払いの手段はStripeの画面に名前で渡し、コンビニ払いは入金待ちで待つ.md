# 0058 支払いの手段は Stripe の画面に名前で渡し、コンビニ払いは「入金待ち」で待つ

状態: **採用**（2026-11-05。支払いの手段を増やすことは運営が選んだ。Stripe の中で足せるものから作り、代引き・銀行振込は形だけ書く、までが指示。細部は作りながら決め、下の「作って決めたこと」に書いた）。ADR 0019（Stripe Checkout）・0022（Connect）・0026（決済の口）・0054（クーポン）・0055（贈り物）の上に足す。置き換えるものは無い

## 文脈

- 今の支払いの画面はカードだけ（`payment_method_types: ['card']`。で「後で払う手段は、払われる途中に期限切れの片付けが取り消してしまうので、受ける仕組みを作るまで使わない」と決めていた）
- 日本のショップでは、カードを持たない・使いたくないお客さんのためにコンビニ払いと PayPay が求められる。Apple Pay・Google Pay はスマホでの購入の手間を減らす
- Stripe の公開の文書で確かめたこと（2026-11-05 に読んだ。URL は下の「確かめた文書」）:
  - **コンビニ払い**（`konbini`）: 日本の Stripe アカウント・JPY だけ。1 回 120 円〜300,000 円。**支払いの確定が遅れる手段**（お客さんは払込票の番号でファミリーマート・ローソン・ミニストップ・セイコーマートで現金で払う）。Checkout の画面は払込票を出した所で終わり（`checkout.session.completed` の `payment_status` は `unpaid`）、お客さんは `success_url` ではなく Stripe の払込票の画面（`hosted_voucher_url`）へ送られる。払われると `checkout.session.async_payment_succeeded`、期限切れ・失敗で `checkout.session.async_payment_failed`。期限は `payment_method_options.konbini.expires_after_days`（1〜60 日、既定 3 日）で、確定した日から数えた日の 23:59:59（日本時間）。期限の後もしばらくはレジで払い終えられる（バッファーがある）。払う途中でなければ PaymentIntent を取り消せる。定期の請求（`setup_future_usage`）には使えない。返金はお客さんの銀行口座へ（Stripe がお客さんにメールで口座を尋ね、45 日答えが無ければ失敗）。チャージバックは無い。Connect では連結アカウントでも有効にする（ダイレクトの支払い）
  - **PayPay**（`paypay`）: 日本・JPY だけ。1 回 50 円〜1,000,000 円。**その場で確定する**手段（PayPay のアプリで承認して戻る）。定期の請求には使えない。返金は 365 日以内・その場で済む。**アカウントの種類は「Merchant」だけで、Platform・Connect は使えない**と書かれている
  - **Apple Pay・Google Pay**: Stripe が用意する支払いの画面（Checkout）では、**カード（`card`）の中で**出る。ダッシュボードの「決済手段」で有効にすれば、追加の実装もドメインの登録も要らない（ドメインの登録は埋め込みの画面のときだけ）
  - Stripe は `payment_method_types` を渡さず、ダッシュボードの設定で手段を決める形（動的な決済手段）を勧めている。渡せば、ダッシュボードの設定をその画面だけ上書きする

## 決定

1. **店は「設定 › お支払い › 使う支払いの手段」で、カードのほかにコンビニ払いと PayPay を選ぶ**。カードはいつも使う（定期便・0 円でない注文の受け皿）。Apple Pay・Google Pay はカードの中なので、こちらでは選ばず、Stripe のダッシュボードで有効にする。選んだ手段は **Stripe のダッシュボードでも有効にする**必要があることを、画面とヘルプに書く。選ぶのはお金の権限の人で、パスキーの再確認の後（鍵と同じ）
2. **Checkout へは `payment_method_types` で名前を渡す**（支払い方法の設定〔payment method configuration〕は使わない）。理由: 核が扱い方を知っている手段だけを出すため。ダッシュボードの設定に任せると、店がダッシュボードで足した後払いの手段（銀行振込〔`customer_balance`〕など）が、入金待ちの扱いの無いまま注文に出てしまい、今の期限切れの片付けがその注文を取り消してしまう（心配と同じ）。代わりに、ダッシュボードとこちらの両方で有効にする手間が店に残る（片方だけだと Stripe が画面を作らず、お客さんが支払いに進めない）。その注文の額で使えない手段（コンビニ払いの 120 円未満・30 万円超など）は出さない。カードを預ける支払い（定期便の 1 回目）はカードだけ。Stripe へ接続した店（Connect）には PayPay を出さない
3. **後から払う手段（今はコンビニ払いだけ）は「入金待ち」**: `checkout.session.completed` が `unpaid` で届いたら、支払いの記録を `awaiting` にし、払いの期限（Stripe の払込票の期限）と払込票の画面を記録する。注文は合意の段のまま（ショップでも管理画面でも「入金待ち」）、**在庫は押さえたまま、クーポンの数も押さえたまま**。お客さんへ「入金をお待ちしています」の知らせを送る（払い方そのものは Stripe の払込票の画面。メールにはその画面へのリンクと期限）
   - `checkout.session.async_payment_succeeded` で確定する（今のカードと同じ道。金額・通貨・取引の照合も同じ）
   - `checkout.session.async_payment_failed` で、支払いを `failed` にし、注文を取り消して在庫とクーポンの数を戻す（今の「払われないまま期限が過ぎた注文」の取り消しと同じ道）。お客さんへ「お支払いの期限が過ぎたため、ご注文を取り消しました」を送る
   - 知らせが届かなかったときの受け皿は今の見回り（`storefront:expire-unpaid-orders`）。入金待ちは、払いの期限の後に猶予（既定 24 時間。`payment.awaiting_grace_hours`）を待ってから Stripe に問い合わせ、払われていれば確定、まだ払える（払込票が生きている）なら**先に Stripe で払込票を取り消してから**注文を取り消す。お店で払っている途中で取り消せなければ次の回へ。支払いの画面は終わったが入金待ちの知らせが届いていない注文は、問い合わせで入金待ちにして待つ（取り消さない）
   - 入金待ちの注文で「お支払いへ進む」を押しても、新しい支払いの画面は作らず、払込票の画面へ送る（二重に払われないように）
4. **二重に払われた・取り消した後に払われた**ときは、今の「返金が要る支払い」（`stray_payments`、`duplicate`・`late`）に載せる。店の人が注文の画面から返金する。コンビニ払いの返金は、お客さんの口座を Stripe が尋ねるので保留（`pending`）が長く続くことがある（ADR 0027 の保留の扱いのまま）。店の人の取り消し（注文の画面の「注文を取り消す」）は、入金待ちなら先に Stripe で払込票を取り消し、払われていた・お店で払っている途中なら断る
5. **組み合わせ**
   - **0 円の注文**: 支払いの画面を作らないので、手段は関わらない（ADR 0054 のまま）
   - **定期便**: 1 回目もカードだけ（コンビニ払いと PayPay はカードを預けられない。Stripe の決まり）。2 回目からは預けたカード（ADR 0045）
   - **贈り物**: 受け取りのリンクは、払いが確かになった時（`PaymentConfirmed`）に作る今の決まりのまま。入金待ちの間は「お支払いの確認待ち」で、リンクは出さない。贈り物の期限は払いが確かになってから数える（ADR 0055 のまま）
   - **クーポン**: 入金待ちの間は数を押さえたまま。払われずに取り消した注文は戻す（ADR 0054 の 6）
6. **お客さんと店の人に払った手段を見せる**: 支払いの記録に、出した手段（`methods`）と払われた手段（`method`。カード・Apple Pay・Google Pay・コンビニ払い・PayPay）を残す。手段は、いくつかの手段を出した画面のときだけ Stripe に問い合わせて決める（カードだけの画面はカード。今までの頼み方と知らせの記録の形を変えない）。ご注文の状況・注文の知らせのメール・管理画面の注文に出す
7. **代引き・銀行振込（決済代行を使わない手段）は今回は作らない**。作るときの形だけ決めておく（2026-11-05 に ADR 0074 で作った。決済の口のドライバでなく、注文の流れ〔`Core\Order\Services\DirectPayments`〕と支払いの記録の `provider = direct` にした）:
   - 核の決済の口（ADR 0026）の 2 つ目のドライバ「店で受け取る」として足し、Stripe の画面を通さない。注文は「入金待ち」（銀行振込）か「発送待ち・代金は届けた時」（代引き）で確定し、**入金の確認は店の人が管理画面で押す**（台帳へは人の操作として `recordPayment`。経路は店が直接受け取る形）
   - 銀行振込の期限・期限での取り消しは、この ADR の入金待ちと同じ見回りに載せる。振込先の口座は店の設定（個人情報ではないが、書き換えは監査に残す）
   - 代引きは手数料の行（調整の行）を足し、運送会社の代金引換の結果を店の人が記録する。受け取り拒否は取消（在庫を戻す）
   - 返金は決済代行を通らないので、記録だけ（店の人が自分で振り込み、「返金した」を押す）

## 結果

- 得たもの: カードを持たないお客さん（コンビニ払い）と、スマホで素早く払いたいお客さん（PayPay・Apple Pay・Google Pay）に売れる。後から払う手段を「入金待ち」として核が扱えるので、銀行振込などを足す道ができた
- 失ったもの・気をつけること: 店は手段をダッシュボードとこちらの両方で有効にする（片方だと支払いに進めない）。コンビニ払いの注文は、払われるまで（既定 3 日、最大 30 日）在庫を押さえる。コンビニ払いの返金はお客さんの口座の入力を待つ（すぐ終わらない）。いくつかの手段を出した店では、払われた知らせのたびに Stripe へ問い合わせが 1 回増える（手段を知るため。届かなくても確定は止めない）

## 作って決めたこと（2026-11-05 App「デジタルチケット」）

- 受渡に digital のある注文（チケット）にも、後から払う手段（コンビニ払い）を出さない（お届け日を選んだ注文と同じ扱い。`PaymentService::noDeferredPayment`）。終演の後に払いが届いてチケットが出る、を作らない。カードと PayPay は出す（ADR 0069）

## 作って決めたこと（2026-11-05）

- **設定の表は支払いの文脈に置く**（`payment_method_settings`、店に 1 行）。店の設定（`shop_settings`）に足さず、支払いの文脈（`Core\Payment`）の中で読む・変える（`PaymentMethodSettings`）。変えたら `payment.methods_updated`（値だけ）。同じ値の保存は記録を残さない
- **コンビニ払いの期限は 1〜30 日**（Stripe は 60 日まで受ける。長く在庫を押さえないよう 30 日まで）。既定は Stripe と同じ 3 日
- **頼む中身に手段を入れる**: 支払いの画面の予約（`checkout_plans.methods`）に「card,konbini:3,paypay」の形で記録し、答えが届かなかったやり直しも同じ中身で頼む（途中で店が設定を変えても、同じ冪等キーで違う中身を送らない）。記録（`payment_attempts.methods`）にも同じ値
- **払込票の画面の URL は店の鍵で暗号化して置く**（`payment_attempts.instructions_url`。持つ人は払い方を見られるため）。出すのは注文を見てよい人の画面（ご注文の状況・注文を受け付けた画面からの「お支払いへ進む」）とお客さんへのメールだけ。管理画面には返さない。Stripe の https の画面（`*.stripe.com`）だけを受ける
- **期限は Stripe の答え**（`next_action.konbini_display_details.expires_at`）。問い合わせられなかったときは Stripe と同じ数え方（日本時間で今日から設定の日数の後の 23:59:59）で決める（入金待ちの知らせ自体は止めない）
- **入金待ちの知らせは、出した手段に後払いが含まれる画面だけで扱う**。カードだけの画面に `unpaid` の終わりが届いても扱わない（起きないはず。今までの「扱わない」と同じ）
- **払われなかった知らせで取り消すのは、ほかに払える画面・入金待ち・作りかけの画面が無いときだけ**（あれば、それぞれの期限で片付く）
- **取り消した注文の払込票の知らせ**（取り消しと払込票が出たのがすれ違った）は、Stripe でも払込票を取り消す（できなければログに残し、払われたら返金の道）
- **見回りの順番**: 入金待ちは払いの期限と猶予の前なら Stripe に問い合わせず「待つ」と数える（5 分ごとに全部を問い合わせない）
- **知らせの順の入れ替わり**: 払われた知らせの後に届いた「払込票が出た」は `already_paid`、払われた・閉じた支払いへの「払われなかった」は扱わない（`ignored`）。同じ知らせの二度目は今までどおり `seen`
- **Stripe のダッシュボードで選ぶ通知に `checkout.session.async_payment_failed` を足した**（設定 › お支払いの手順の一覧）。前から入れている店は足す必要がある（足さなくても、見回りが期限と猶予の後に片付ける）。Stripe へ接続した店の知らせは運営の Connect の送り先で受けるので、**運営の送り先にも同じ通知を足す**（運営の作業）
- 「お支払いの方法と時期」（特商法の最終確認）: カードだけの店は今までの文のまま。手段がいくつかあれば「クレジットカード・コンビニ払い・PayPay（次の決済代行の画面でお選びいただけます）」、コンビニ払いがあれば「コンビニ払いは、ご注文から ◯ 日後の 23:59 までにお店でお支払いください（期限までにお支払いがないときは、ご注文を取り消します）」
- **お届け日を選んだ注文には、コンビニ払い（後から払う手段）を出さない**（2026-11-05、PR 89 の見直し。ADR 0059 と組み）。払いの期限（既定 3 日、30 日まで）まで発送を待つので、選んだ日に届かない注文ができてしまう。時間帯だけの指定は日を約束しないので出す。支払いの画面へ渡す手段は、確定した注文の受渡に希望日があるかでサーバーが決める（`PaymentMethodSettings::forCheckout` の `$datedDelivery`）。確かめの画面の「お支払いの方法」も同じ決め方で、店がコンビニ払いを使っていて外したときは「お届け日をご指定のご注文は、コンビニ払いをお選びいただけません」を添える
- **確かめの画面の指紋に、出す支払いの手段の並び（`card,konbini:3` の形）を入れる**（同じ見直し）。確かめた後に店が手段を変えたら、特商法の最終確認で見せた「支払いの方法と時期」と違う注文になるので確定しない

## Stripe の API の版の変わり目で決めたこと（2026-11-05）

- Stripe の API の版 2026-09-30 から、支払いの画面（Checkout Session）に `payment_method_types` を渡せなくなった（本番のテストの鍵で 400 `invalid_request_error`、手元と CI は偽の Stripe なので気づけなかった）。出す手段は**ダッシュボードで有効にしたもの**になり、注文ごとに出さない手段を `excluded_payment_method_types` で外す
- 外すのは、核が扱える手段（`card`・`konbini`・`paypay`）のうちこの注文で出さないものと、日本の店のダッシュボードで足せるが核が扱えない手段（`customer_balance`〔Stripe の銀行振込〕・`alipay`・`wechat_pay`）。一覧は `CheckoutMethods::EXCLUDABLE`。Apple Pay・Google Pay・Link はカードの中で、外す一覧に入れると Stripe が断るので入れない
- 店の設定でコンビニ払い・PayPay を使うにしても、Stripe のダッシュボードで有効でなければ画面に出ないだけ（前は Stripe が支払いの画面ごと断った）
- カードを替える画面（setup のモード）もカードのほかを外す。預けたカードでのお客さんのいない請求（PaymentIntent）は `automatic_payment_methods`（画面の移動の要る手段は使わない `allow_redirects = never`）
- Stripe に断られた時は、断りの理由の文と欄の名前（`message`・`param`）もログに残す（こちらは個人情報・鍵を Stripe に渡していないので、Stripe の文にも含まれない）
- 残る危険: ダッシュボードで新しく足せるようになった手段（この一覧に無いもの）は、店が有効にすると支払いの画面に出る。払われた手段は「そのほかの方法」として受け、入金待ちの形が違う手段は扱えないので、使わないよう店に案内する（ヘルプ）

## 作って決めたこと（2026-11-12、リリース 1.0 の R6）

- 払われた知らせ（`checkout.session.completed`・`async_payment_succeeded` の paid）で注文を確定した後、DB のロックの外で、同じ注文に残っているほかの支払いの画面を閉じ（`expire`）、入金待ちの払込票を取り消す（`PaymentService::closeLeftoversOfPaid`）。払込票が出た知らせを先に受けた後に、入金待ちになる前に作った別の画面でカードで払われると、払込票が使えるまま残るため（見直しの残り）
- 閉じたものは記録も閉じる（画面は `expired`、払込票は `failed`。イベント `payment.leftover_closed`）。もう払われていた・お店で払っている途中（取り消せない）ものは触らず、届いたら二重の支払いとして返金の道に乗る
- Stripe に届かない・取り消せなかった分は、`storefront:expire-unpaid-orders`（5 分ごと）が払われた注文の残りとして見回り、もう一度閉じる（作ってから 61 日まで）。払われていない注文の払込票はこの見回りでは触らない（払いの期限まで待つ）
