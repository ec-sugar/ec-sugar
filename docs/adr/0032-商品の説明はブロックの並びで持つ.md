# 0032 商品の説明はブロックの並びで持つ

状態: **採用**（実装済み。2026-10-29〜30 に作って main へ入れた。運営が決めた記録は残っていないので、2026-10-31 の見直しで、開いたままの「決めてほしいこと」に今のコードの形を書いた）。ADR 0018（店頭は Blade とテーマ）・ADR 0028（テーマは区画を宣言し、核は汎用の値と写真を持つ）・ADR 0010（平文の個人情報を足さない）に関わる

## 文脈

- 商品の説明は 1 つの素の文字（`listings.description`、5,000 字まで）だけで、見出し・箇条書き・写真・表を入れられない（2026-10-29。商品の説明の欄が物足りない）
- よくある作りは「リッチテキスト（HTML）をそのまま保存して出す」だが、店の人の入力から XSS の道ができる（よくある設置型の EC の管理画面の XSS と同じ形）。HTML を消毒して出す形も、消毒の漏れがそのまま穴になる
- 素材・サイズ・原産国のような「項目と値の組」と、一覧に出す短い説明も欲しい
- バリエーション（色・サイズごとの在庫）とオプションは別の仕事にする（核の在庫と価格の形に関わるため）

## 決定

### 1. 説明は「決まった種類のブロックの並び」（JSON）で持ち、HTML を保存しない

- 店の DB の `listings` に 3 つの列を足す: `description_blocks`（jsonb、ブロックの並び）・`specs`（jsonb、仕様の表）・`summary`（1 行の短い説明）
- ブロックの種類は核が決めた 6 つだけ。知らない種類・知らない項目は断る

  | 種類 | 中身 |
  |---|---|
  | `paragraph` 段落 | `text`（改行あり） |
  | `heading` 見出し | `level`（2 = 大・3 = 小。2 段まで）、`text`（1 行） |
  | `list` 箇条書き | `style`（`bullet` 点・`number` 番号）、`items`（1 行ずつ） |
  | `image` 写真 | `media_id`（**同じ店の「ショップの写真」の ID**）、`caption`（1 行・任意） |
  | `table` 表 | `header`（1 行目を見出しにするか）、`caption`（任意）、`rows`（文字の並びの並び。行ごとの列の数はそろえる） |
  | `note` 注意書き | `tone`（`info` お知らせ・`warning` ご注意）、`text`（改行あり） |

- 文はどれも**素の文字**。HTML のタグは書き換えも取り除きもせず、文字のまま保存し、描くときに必ずエスケープする。壊れた UTF-8・制御文字（C0・DEL・C1。複数行の文だけ改行とタブを通す）・文字の向きを変える印（U+202A〜202E・U+2066〜2069）は断る
- 形を確かめるのは核の 1 か所（`App\Core\Listing\Description\ProductDescription`）。保存のときは違う所を道筋（`description_blocks.3.text` など）つきで断り、読むときは形の崩れたブロック（知らない種類など）を捨てる（DB を直に書かれてもショップを壊さない）
- ただし**文の中の断る文字（壊れた UTF-8・制御文字・向きを変える印）と長すぎる文は、読むときは「その文字だけ外す・切り詰める」でブロックを残す**（Windows や Office から貼った前の説明が、移行の後にショップや管理画面から消えないように。見直しで足した）。管理画面の詳細は、外して見せているときに `description_repaired` で知らせる

### 2. 上限

| もの | 上限 | 理由 |
|---|---|---|
| ブロックの数 | 100 | 長い説明でも 30〜50 個ほど。DB の検査でも守る |
| 段落・注意書きの文 | 5,000 字 | 今の説明の上限と同じ（今の説明をそのまま 1 つの段落に写せる） |
| 文の合計 | 50,000 字 | 100 × 5,000 の 50 万字を 1 ページに出させない（ページの重さと保存の大きさ） |
| 見出し | 200 字 | 商品名と同じ |
| 箇条書き | 50 行・1 行 500 字 | |
| 表 | 20 行 × 6 列・1 ます 200 字 | スマホで読める幅。大きな表は分ける |
| 写真のブロック | 30 個 | ページの重さ。ショップの写真は 1 店 100 枚まで |
| 写真・表の説明 | 200 字 | 写真の代わりの文字と同じ |
| 仕様の表 | 30 行・項目 50 字・値 500 字（値は改行あり） | DB の検査でも守る |
| 短い説明 | 200 字・1 行 | 一覧のカードで 2 行ほど。DB の検査でも守る |
| 列の大きさ（DB） | ブロック・仕様の表とも 512KB | 個数の上限の中でも巨大な値で重くさせない（アプリの上限の合計より余裕を持たせる） |

### 3. 書き込みは今の商品の更新と同じ道

- `ListingService` だけが書く（`EventStore::lock()` → 商品の行のロック → バージョンの確かめ → 写真の行のロック、イベントは同じトランザクション。開発の規約の書き込みの決まり）。同時の保存は今までどおりバージョン（楽観ロック）で後から来た方を断る（409）
- 記録（`listing.updated`）には説明の中身を残さず「変わった」だけ（長文で、店の人の文を記録に増やさない）。項目の順だけ違う同じ中身（jsonb は項目の順を変えて返す）は変えたことにしない
- **写真は同じ店の「ショップの写真」にあるものだけ**。写真の行を `FOR UPDATE` で押さえてから指す（消す側の `ShopMediaService::remove` も先に `EventStore::lock()` を取るので順番になる）。ほかの店の写真の ID は、その店の DB に無いので「無い」として断る。説明に使っている写真は、ショップの写真から消せない（`usageMap` に `listing:商品の ID` を足す。ゴミ箱の商品は数えない）。消すときは 1 枚分だけを `description_blocks @> '[{"type":"image","media_id":"…"}]'` と GIN の索引（`jsonb_path_ops`）で調べ、全部の説明を回さない。商品の画面の写真の選び方は、使っている所を数えずに一覧を読む（`?usage=none`）

### 4. 前の説明の列は残し、両方向に写す（二段の移行）

- 移行（`2026_10_29_000700`）は今の `description` を 1 つの段落に写す（改行をそろえ、制御文字と向きを変える印を外し、前後の空白を除く。空なら空の並び。まだブロックの無い行だけなので、流し直しても同じ）。`description` はすぐ消さない
- 今のアプリはブロックと一緒に、ブロックの文をつないだもの（5,000 字まで）を `description` に書く。前のバージョンのアプリへ戻したとき、その文が説明として出る。検索エンジン向けの説明の元にもなる
- 前のバージョンのアプリは `description` だけを書くので、**ブロックが変わらずに `description` だけが変わったら、DB のトリガーがブロックを 1 つの段落に写し直す**（前のバージョンで説明を直しても、新しいバージョンに戻ったときに古いブロックが出ない。ただし見出しや写真は段落 1 つになる）
- 前の形（`description` だけ）を送ってきたとき（デプロイの前から開いたままの古い管理画面など）、今の写しと同じなら変えたことにしない（1 段落に作り直して構造をつぶさない）。今の管理画面は、読んだときから変えた説明の項目だけを送る
- **前のバージョンへ戻すときは、イメージだけを差し替え、移行の down は流さない**。前のアプリは `description` だけを読むので、この形のまま動く。down はブロックの構造・仕様の表・短い説明を消す（残るのは写しの文だけ）。down を流すのは、作った直後に取り消すときだけ
- `description` を消すのは、前のバージョンへ戻す必要がなくなってから（別の移行で）

### 5. 表示はテーマ、描き方は核の部品

- ショップには `ProductView::$blocks`（`list<DescriptionBlock>`。写真はショップの写真にあるものだけを `ShopPhoto` に解いて渡す）・`$specs`・`ListingCard::$summary` を渡す（テーマ API 2 の付け足し。今のテーマはそのまま動くのでバージョンは上げない）
- 描くのは**核の Blade の部品** `<x-storefront::description-blocks>` と `<x-storefront::product-specs>`。決まった要素（`p`・`h3`/`h4`・`ul`/`ol`・`figure`・`table`・`aside`・`dl`）に、`{{ }}` だけで文を出す。部品は class を持たず、テーマは印（`[data-blocks]`・`[data-block=…]`・`[data-tone=…]`・`[data-specs]`）から自分の CSS で見た目を決める。公式テーマの 4 つはこの部品を使う（`ThemeTest` が見張る）
- 一覧・トップ・カートのカードは、カードに要る列だけを読む（説明のブロックと仕様の表を運ばない）。詳細の説明の素の文（検索エンジン向け）は、読んだブロックからつなぐ
- テーマが自分で描くこともできる（`DescriptionBlock` を読むだけ）が、そのときもエスケープしない出力は使えない（`ThemeTest`）

### 6. 管理画面

- 商品の画面の「基本の情報」に、短い説明の欄・説明のエディタ（ブロックを足す・上下に動かす・消す。キーボードはボタンと Alt + ↑ / ↓）・仕様の表の欄を置き、1 つの「保存する」でバージョンと一緒に送る
- 写真のブロックは、テーマの中身の写真の欄と同じ選び方（ショップの写真から選ぶ・その場で上げる）

## 結果

- 得たもの: 見出し・箇条書き・写真・表・注意書きで説明を組み立てられる。店の人の入力から HTML が出る道が無い（保存も表示も文字だけ）。見た目はテーマごとにそろう。前のバージョンへ戻しても説明が出る
- 失ったもの・気をつけること: 太字・リンク・文の中の色など、段落の中の飾りは無い（要るなら種類を足す。リンクは区画のリンクと同じ確かめにする）。前のバージョンで説明を直すと、見出しや写真が段落 1 つにまとまる。`description` の列をいつ消すか決める

## 決めてほしかったこと（2026-10-31 に今のコードの形を書いた）

1. ブロックの 6 種類と上限（上の 2）でよいか → 今の形: 6 種類と上の 2 の上限のまま（`ProductDescription` の定数と DB の検査）
2. 段落の中の太字・リンクを、今は入れない（入れるなら次の区切りで、決まった印の形で）でよいか → 今の形: 入れていない（どの文も素の文字だけ）
3. テーマ API のバージョンは上げず、2 の付け足しとしてよいか（今のテーマはそのまま動く）→ 今の形: 上げていない（公式テーマ 4 つの theme.json は `theme_api: 2` のまま）
