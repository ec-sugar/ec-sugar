# 0055 贈り物は、住所を受け取る人が入れ、期限で自動で返金する

状態: **採用**（2026-11-04。形と 3 つの決めごとは運営が決めた。同じ日に区切り 1・2 を作った）。

## 文脈

- 作るもの（2026-11-04）: 送り先の住所を入れずに贈り物を買え、払った後に共有のリンクを送ると、受け取る人が住所を入れて受け取れる App を作る
- 今の注文は、確定の時に送り先が決まっている前提（`PlaceOrder` が受渡〔Fulfillment〕に送り先を暗号化して入れる）
- 運営の決定（2026-11-04）: 期限までに住所が入らなければ**自動で返金**／送料は**買う時にいちばん高い送料で取る**／受け取る人には**値段を見せず、メッセージを付けられる**

## 決定

1. **核は「送り先が未定の受渡」を持ち、贈り物の画面は App**（`plugin-gift`。ADR 0050 の定期便と同じ分け方: 核は口と表の移行、App は画面と設定）
   - 核: 受渡に「送り先を待つ」の状態。送り先の無い受渡は発送にできない（発送の画面・配送の CSV に出さない）。送り先を後から入れるサービス（イベントを同じトランザクションで残す）
   - App: 注文の入力の「贈り物として送る」・受け取りのリンク・受け取りの画面・期限の処理・設定
2. **買う人**: 注文の入力で「贈り物として送る（住所はお相手が入れます）」を選ぶと、送り先の欄の代わりに、差出人の表示名（既定は自分の名前）とメッセージ（文だけ。500 文字まで。暗号化して持つ）を入れる。会員でもゲストでも使える
3. **受け取りのリンク**: 払いが確かになった時（Webhook）に作る。完了の画面と買う人へのメールに出し、LINE などで送れる「写す」「共有」のボタン。token は推測されない 32 バイト、DB には sha256 だけ。買う人はマイページ（ゲストはご注文の確認）から、リンクを作り直せる（前のリンクは使えなくなる）・受け取られる前なら取り消せる（返金）
4. **受け取る人の画面**（`/gifts/{token}`）: ショップの見た目で、差出人の表示名・メッセージ・商品の名前と写真と数だけを出す（**値段・買う人のメールや住所は出さない**）。名前・郵便番号・住所・電話を入れて確定すると、受渡の送り先になる（暗号化）。確定の後は同じリンクで「受け取り済み・発送済み（送り状番号）」だけを出し、住所は直せない（直すのは店へ問い合わせ）。`noindex`・`Referrer-Policy: no-referrer`・回数の上限
5. **買う人へ知らせる**: 受け取られた（住所は知らせない）・発送した・期限の 3 日前・期限で返金した
6. **期限**: 店が決める（既定 14 日、払いが確かになってから数える）。期限を過ぎても住所が無い注文は、毎日の処理で**取り消して全額を返金**し、在庫を戻す（今の取消と返金のサービスを通す）
7. **送料**: 買う時に、選べる送り先の中でいちばん高い送料を取る（今は全国一律なので、その額）。地域別の送料が入ったら、受け取りの住所で決まる送料との差額を受け取りの時に返金する（ADR 0054 の値引きではなく返金で）
8. **値段を出さない**: 贈り物の注文は、納品書と発送の知らせで値段を出さない。領収書は買う人にだけ
9. **店の人**: 注文の画面に「贈り物・受け取り待ち（期限 ◯日）」。受け取られれば送り先が見える。店の人も代わりに取り消し（返金）できる

## 区切り

1. 核の口（送り先を待つ受渡・後から入れる・発送できない守り）と、App の注文の入力・リンク・受け取りの画面
2. 知らせのメール・期限と自動の返金・作り直しと取り消し・管理画面の表示

## 結果

- 得たもの: 住所を知らない相手にも贈れる（SNS のつながりなど）。受け取る人の住所は買う人に渡らない
- 失ったもの: 受け取りを待つ間、在庫を押さえ続ける（期限で戻る）。リンクを知った人は誰でも受け取れる（リンクの扱いは買う人に任せる。作り直しで止められる）

## 作って決めたこと

### 区切り 1（注文の入力〜受け取りの画面）

- **核の口は `GiftHandler`（`App\Core\Plugin\Contracts`）を `PluginDefinition` の `gift` に渡す形**。店で使っている App のうち 1 つだけ（登録簿が 2 つ目を断る）。核の `App\Core\Order\Gifts` が「使っているか」を見て、注文の入力に「贈り物として送る」を出す（核の部品 `gift-fields`）。使っていない店では欄を出さず、送られてきても断り、確定の時にも確かめる
- **贈り物の注文の印は、注文の確定と同じトランザクションのイベント `order.gift_placed`**（中身は空）。核の表に列を足さず、App を使うのをやめた後も「値段を出さない」の印が残る（`OrderView::$hidePrices`。発送の知らせのメールで値段を出さない。納品書は別の作業でこの印を読む）
- 差出人の表示名（50 文字・1 行。空ならご依頼主のお名前）とメッセージ（500 文字・改行だけ可）は、核の `GiftNote` が改行のほかの制御文字と向きの印を断り、App の表に店の鍵で暗号化して置く。注文の入力の確かめ（`CheckoutInput`）と `GiftNote` の二重
- **受け取りのリンクの token は 32 バイトの乱数**。DB には引くための sha256 と、**買う人にリンクを出し直すための token を店の鍵で暗号化したもの**を置く（メール・ご注文の状況・買う人の画面で何度でも出すため。DB の dump だけでは受け取れない）。指示は「DB には sha256 だけ」だったが、出し直せないと完了の画面とメールの両方に出せないので、この形にした
- 払いが確かになった時（`PaymentConfirmed`。0 円の注文は確定の直後）に、**核が注文の知らせのメールより先に** App にリンクを作らせる（`Gifts::paid` → `SendOrderMail`。知らせのメールにリンクが必ず載る）。作れなかった時もメールは送る
- **注文を受け付けた画面には受け取りのリンクそのものを出さない**。この画面は App のタグ（解析・広告。画面の中身を読むものもある）を差し込む画面なので、リンク（持つ人は誰でも受け取れる）を渡さない。代わりに、このセッションで今買った注文だけが開ける App の画面（`/p/gift/orders/{注文}`。タグを差し込まない）への入口を出し、そこで「写す」「LINE で送る」。メールとご注文の状況（タグを差し込まない画面）にはリンクを出す
- 買う人の画面を開けるのは、このセッションで今買った注文（核の `LastOrder`）・メールとご注文の状況の署名つきリンク（30 日。開いた後はこのセッションで覚える）・注文した会員だけ。ほかは見つからないと同じ 404
- 受け取る人の画面は `/p/gift/{token}`（ADR 0025 の App の経路の決まり）。入れる → 確かめる（入れた送り先はセッションにだけ）→ 確定で受渡の送り先に。受け取りは、受け取り待ち・期限の前・注文が開いている・**取消の返金の記録が無い**時だけ（返金の通信の途中に受け取らせない）
- 送り先の入力は核の部品 `address-fields`（会員の届け先と同じ）に郵便番号から住所の印を足して使う
- 送料は今は全国一律なので、いつもの送料のまま（決定 7 の「いちばん高い送料」と同じ額）

### 区切り 2（知らせ・期限と自動の返金・取り消し・管理画面）

- **期限の処理は毎時の `gifts:run`**（使う店だけ。定期便と同じ形）。期限の 3 日前の知らせは 1 回だけ（`reminded_at`。連鎖のロックとイベント `gift.reminded`）。期限が 3 日より短い店（設定で 1〜3 日）では、リンクができた時にもう 3 日を切っているので知らせない
- **取り消しと返金は 3 段**（`GiftCancellation`）: ① 連鎖のロック → 贈り物の行のロックの中で「取り消しの途中（cancelling）」にする（同時に 2 つ走っても、抜けるのは 1 つ。この間は受け取れない）② ロックの外で核の `SaleOrderService::cancel`（返金と在庫の戻し）③ 答えを書く。**返金できなかった（断られた・答えが分からない・額が違って止めた）時は「止めた（stopped）」にして、自動では返金し直さない**。店の人が注文の画面で「注文を取り消す」を押し直すと、核が同じ冪等キーで続きから進め、毎時の処理が贈り物を「取り消した」に合わせる。取り消しの途中のまま 1 時間を過ぎたもの（処理が落ちた）も「止めた」にする
- **店の人の取り消し（返金）は、注文の画面の「注文を取り消す」**（お金の権限・直前の再確認）。App の画面（ADR 0051）の操作は運用の段階から押せるので、お金を動かす操作を置かない（権限を飛び越えないため）。App の画面は一覧と 1 件（注文の画面へのリンク）だけ、ホームの「やること」に返金が止まった贈り物
- 買う人の取り消しは、受け取られる前（受け取り待ち）だけ。受け取られた後は店へ問い合わせ（店の人は発送の前なら注文の画面で取り消せる）
- 買う人への知らせは 受け取られた（送り先は書かない）・期限の 3 日前（受け取りのリンクを添える）・期限で返金した・取り消した。発送の知らせは核の注文の知らせのまま（値段を出さない）。キューに載せるのは贈り物の ID と種類だけ
- 管理画面の注文の画面に「贈り物・受け取り待ち（期限 ◯）」などの印。送り先を待つ受渡は発送の操作に数えない（`awaiting_address`）

### PR 86 の束に合わせた時（2026-11-05）

- **ご注文の状況（テーマの order の画面）への入口は、束の App のご注文のリンクの口（`OrderLinkProvider`・部品 `order-links`）にまとめた**（新しい口は作らない）。贈り物の App が「贈り物のリンク・取り消し」（受け取った後は「贈り物の様子」）を、署名と期限（30 日）をつけた買う人の画面への道筋で返す。テーマの order の画面からは `gift-share` の部品を外した（受け取りのリンクそのものはご注文の状況に出さず、買う人の画面で出す）。`OrderView` の `gift`・`hidePrices` は残す（注文の知らせのメールと、納品書の値段を出さない印）
- **App を使うのをやめても、受け取り待ちの贈り物の期限の処理（3 日前の知らせと期限での自動の返金）は続ける**（お金を宙に浮かせないため）。核の `PluginTenants::each` に「使うのをやめた店でも片付ける仕事が残っているか」（`$leftover`）を足し、`gifts:run` は払いの確認待ち・受け取り待ち・取り消しの途中の贈り物が残る店も回る。受け取りの画面と買う人の画面は止まる（App の経路は使う店だけ）ので、知らせのメールには開かないリンクを載せない。片付けが済めば、その店はもう回らない
- 贈り物の注文にもクーポンは効く（ADR 0054 の 9）。値引きの行と、送り先の無い受渡は両方そのまま

### 送料の細かい設定が入った時（2026-11-05、ADR 0064）

- **決定 7 の差額の返金を作った**: 買う時は便ごとにいちばん高い都道府県の額で取り、その時の 47 県の額を `order_shipping` に写す。受け取りの確定（同じトランザクション）で受け取る人の都道府県の額との差額を決め（`order.shipping_settled`。都道府県は残さない）、確定の後にキューの仕事（`RefundShippingDifference`）で返金する。返金の目的は `shipping`（1 注文 1 回、受け取った額まで）。差額 0 なら何もしない
- 差額の返金が断られても受け取りは戻さない（受け取る人の手間を増やさない）。返金は失敗として残り、店のホームのやることに出る。店の人が注文を取り消すと、返せていない差額も含めて返る
