# 0105 入られた後の書き換えは、中で毎分照らして署名した様子を出し、外の見張りが店頭と一緒に確かめる

状態: **採用**（2026-11-13。入られてプログラムを書き換えられたことに気づける仕組みが無かった → 3 つとも 1.0 の前に。ソースコードを配るので、入れた人が誰でもこの守りを使えるようにする）。R11（破られる前提の守り）。ADR 0006（読み取り専用のイメージ）・ADR 0099（配る道の署名）・ADR 0043（壊れたら知らせる）・ADR 0103（おかしな動きの知らせ）の上に置く

## 文脈

- 今の守りは「書き換えさせない」（根が読み取り専用・root でない・cap_drop ALL・管理画面からコードを入れない）と「入れる時に確かめる」（署名したタグと cosign の keyless の署名。公開版の形だけ）。**入られた後に書き換えられたことに気づく仕組みが無い**
  - 更新の後に VM の root を取られて、イメージ・compose・Caddyfile・unit・運用の道具を差し替えられても、何も照らさない
  - 見張り（`ec-sugar watch`・毎日の検証）は同じ機械の中にいるので、root を取られると黙らされる
  - EC でいちばん現実にある攻撃は店頭へのスクリプトの差し込み（支払いの前に偽の画面へ飛ばす・入力を抜く）。外から店頭を照らすものが無い
- **配る製品の守りにする**。私たちの本番（Plesk のサーバー・Slack）に頼る作りにしない。入れた人なら誰でも、ふつうの道具だけで同じ守りを使える
- 中の照らしは、root を取られれば偽れる。偽れないのは「外から見える店頭」だけ。だから中の照らし・外の見張り・お互いの生存の確かめを重ねる

## 決めたこと

1. **中で照らす（`ec-sugar integrity`、毎分の systemd の timer）**
   - 入れる・更新・ロールバックが終わった時と、compose や入口の設定を書く運用のコマンド（`admin-ips`・`shops`・`firewall` など）の後に、**あるべき姿**を root だけが読める `/srv/ec-sugar/trust/integrity/expected` に控える: 動くはずのサービスと各々のイメージ ID、compose と入口の設定（Caddyfile・nginx の雛形）・systemd の unit・運用の道具（`/usr/local/bin/ec-sugar` と lib）の sha256。控えるたびに **世代**（`generation`）を 1 つ上げる
   - 毎分、動いているコンテナ（compose の外の、許していないコンテナも）・イメージ ID・ファイルの hash を控えと照らす。違えば困りごとの名前（`image:app`・`file:compose`・`container:extra` など。値や秘密は出さない）を出す
   - 違えば、今の知らせの道（運営の様子の要対応とオーナーへのメール。ADR 0043）にも載せる。ただしアプリ自身が書き換えられていれば黙るので、頼りは外の見張り
2. **署名した様子を出す**
   - 毎分、`integrity.json` を書いて **Ed25519** で署名する。鍵は入れた時に作り、root だけが読める（`/srv/ec-sugar/trust/integrity/key`。アプリのコンテナには差し込まない。PHP が乗っ取られても署名できない）。公開の鍵は `sudo ec-sugar integrity key` で出す
   - nginx が、どのホストでも `/.well-known/ec-sugar/integrity.json` と `integrity.json.sig`（`integrity.json` のバイト列そのものへの署名を base64 で）を、読み取り専用で差し込んだ置き場からそのまま返す（PHP を通さない）
   - 形（`format: 1`）:
     ```json
     {"format":1,"server":"<入れた時に作る識別子>","generation":12,"checked_at":"2026-11-13T05:00:00Z","ok":true,"problems":[]}
     ```
     コミットやバージョンは載せない（公開の URL で版を教えて、知られた穴を狙わせない）。
     更新などの運用のコマンドが錠を取っている間は照らさず、`"busy":true` を足して署名だけ新しくする（照らすと入れ替えの途中を誤報にする）。外の見張りは busy が 30 分続いたら知らせる
3. **外の見張り（`ec-sugar-sentinel`）を配る**
   - 1 つのファイルの台本（bash・curl・openssl 3・python3）。**使う人が自分の別の機械**（安い VPS・手元の Mac・家の別の PC）に置き、cron・systemd・launchd で数分ごとに流す。知らせは Slack 形式の Webhook か、任意のコマンド（メールなど）
   - **様子の確かめ**: 署名が公開の鍵で通る・`checked_at` が 5 分以内・`ok` が真・`server` が同じ。違えばすぐ知らせる（取れないのは 2 回続いたら）。`generation` が上がったら「あるべき姿が変わった（更新か設定の変更）。心当たりが無ければ調べる」を 1 回だけ知らせる
   - **店頭の確かめ**: 決めたページ（トップ・商品・カート）を開き、指紋を取る。指紋に入れるのは、CSP の見出し・`<script src>` の宛先・同じ出どころのスクリプトの中身の sha256・インラインのスクリプトの hash・`<form action>`・`<iframe src>`・`meta refresh`。店の人が直す文や写真は入れない（誤報にしない）。控えの指紋と違えば、違う所を並べて知らせる。控えは `ec-sugar-sentinel accept` で取り直す（更新の後に）
   - 1.0 の公開版の形では、公開用の CI が版ごとの「店頭の指紋のもと」（自前のスクリプトの hash と、同梱の App が使う外の宛先の一覧）を署名して出し、見張りはそれと照らす（更新のたびに accept しなくてよい形）。公開用の CI を作る時（R4）に足す。それまでは控えの形
4. **お互いの生存を確かめる**
   - 外の見張りが黙らされたら、中が気づく: nginx が `integrity.json` を取りに来た時刻だけを別の記録に書き、中の照らしが「30 分来ていない」を困りごとにする（一度でも来たことがある時だけ。見張りを置いていない人に誤報を出さない）
   - 中が黙らされたら、外が気づく: `checked_at` が古い・取れない

## 採らなかった案

- **私たちが外の見張りをホストする**: 配った後の人が私たちに頼ることになる。私たちの見張りが止まると全員が止まる。後で「見張りの代行」を出すことはできるが、まず誰でも自分で置ける形
- **中から外へ便りを送る（push）**: 受け口のサーバーを持たない人が使えない。取りに行く形（pull）なら、外の見張りは家の中の PC でもよい
- **AIDE などのホストのファイルの見張りを入れる**: root を取られれば同じく偽れる。照らす対象がはっきりしている（イメージ・compose・設定・道具）ので、自前の短い照らしで足りる
- **TPM・measured boot での遠隔の証明**: KVM の仮の TPM はホストの手の中で、VPS の多くでは使えない。配る製品の前提にできない
- **様子にコミットや版を載せる**: 照らしは便利になるが、公開の URL で版を教えることになる

## 結果

- VM の root を取られて道具やイメージを差し替えられても、雑な手口なら 1 分ほどで中が気づき、中を黙らされても外が 5 分ほどで気づく
- root を取って署名の鍵まで使う相手には、中の照らしと様子は偽れる。その時も、店頭への差し込み（お客さんに害が出る形）は外の見張りが見る
- 使う人の手間: 別の機械に台本を 1 つ置き、公開の鍵と Webhook を設定する。更新の後に `accept`（1.0 の公開版の形では要らなくする）
- 残り: 外の見張りの機械そのものを取られた時、店頭の正しい指紋をどこから得るか（公開版の形で、署名した指紋のもとで解く）

## 作って決めたこと（2026-11-13 中で照らす）

決めたことの 1・2・4 の中の側を、`deploy/`（`ec-sugar integrity`・`deploy/lib/common.sh` の `ec_integrity_…`・`ec-sugar-integrity.timer`）と compose・nginx だけで作った。使い方は docs/install.md の「中の照らし」。

- **様子の形**は 2 のまま（`format`・`server`・`generation`・`checked_at`〔UTC・小数なし・Z〕・`ok`・`problems`、busy の時だけ `busy`）。決めていなかった所:
  - `integrity.json` は**末尾に改行を付けない**（外の見張りがコマンドの置き換え `$(…)` で読んでも、署名したバイト列が変わらない）。`integrity.json.sig` は署名の 64 バイトを base64 の 1 行で、これも改行なし
  - busy の時は照らさず、**前の結果の `ok` と `problems` のまま**（無ければ ok）に `"busy":true` を足して `checked_at` と署名だけ新しくする
  - 困りごとの名前は `image:<サービス>`・`service:missing:<サービス>`・`container:extra`・`file:<短い名前>` のほかに、`docker:unreachable`（Docker に聞けない）と `expected:missing`（控えが無い・壊れた）。短い名前は小文字の英数字と `._-` だけ（`compose`・`compose-tunnel`・`caddy-caddyfile`・`nginx-prod.conf`・`unit-ec-sugar.service`・`unit-ec-sugar-backup.timer.d-10-timezone.conf`・`tool-ec-sugar`・`tool-common.sh`・`trust-signers`・`tunnel-config` など）。並びは名前の順で 20 個まで
  - 2 つのファイルは別々の要求なので、毎分の書き換えが外の見張りの 2 つの取得の間に入ると、JSON と署名が合わないことがある（1 分に 1 回、数十ミリ秒の間）。**外の見張りは、署名が通らない時は 2 つとも 1 回だけ取り直してから知らせる**（見張りの側）
- **あるべき姿の「動くはずのサービス」**は、compose の設定を解かずに、compose が作ったコンテナ（プロジェクト `ec-sugar`・一度きりでないもの。止まっているものも入れる）のサービスとイメージ ID（コンテナの `.Image`）から取る。後ろに置く形の caddy（0 個）・ステージングの mailpit も、そのまま形ごとに合う。照らしでは、動いているコンテナを数と ID で比べる: 控えに無いサービスの名札・同じサービスが控えより多い・compose の外のものは `container:extra`（答えの `INTEGRITY_ALLOW_CONTAINERS` の名前か `*` の形は数えない）。一度きりのコンテナ（マイグレーションなど）は、同じサービスの控えのイメージなら数えず、違えば `image:<サービス>`
- **控え直す時**（`deploy/ec-sugar` の書くコマンドを全部読んで決めた）:
  - いつも（確かめたコミットから作り直した後）: `install.sh` の終わり、`install-units`（更新の後もここを通る。この仕組みの前のバージョンからの更新でも、新しい道具の `install-units` が控える）、`rollback` の後、手の `ec-sugar integrity record`
  - 最後の照らしで違いが出ていなかった時だけ（違いを黙って「あるべき姿」にしない）: `admin-ips`・`shops`（替えた・前の形へ戻した）・`trust add`・`trust remove`・`restore`。違いが出ていたら注意を出して控えない（調べてから `record`）
  - 中身が前の控えと同じなら書かず、**世代を上げない**（外の見張りに要らない「変わった」を出さない）。開発の形（`CHANNEL=source`）は compose を作業場所から読むので、作業場所に手で変えた所があれば控えない
  - 更新の自動のロールバック・途中で止まった時のそろえ直しは、前のバージョン（控えたまま）に戻るだけなので控え直さない
  - `firewall` は iptables だけを書き、照らすもの（compose・入口の設定・unit・道具）を書かないので控え直さない（1 の例に挙げていたが、作ってみると要らなかった）。`start`（起動のたびに web を作り直す）もイメージが同じなので控え直さない
- **外の見張りが来た時刻**は、nginx の `access_log` を**ホストへ書かせない**。web の中の tmpfs（`/var/log/ec-sugar-integrity/`、uid 101・noexec）に、2 つの場所の 200 の時だけ時刻を 1 行書き、照らしが毎分 `docker exec` で記録の時刻（`stat -c %Y`）を読んで空にし、root の置き場の `last_fetch` に残す（web に書ける差し込みを足さない。web を作り直すと記録は消えるが、`last_fetch` は残る）。2 つの場所は接続元ごとに毎秒 2 回（まとめて 20 回）までにし、記録を膨らませない
- **外の見張りの不在は様子（JSON）に載せない**。来ていないことを JSON に書くと、止まっていた見張りが戻った時に、それを読んで誤報にする。中の知らせ（運営の様子の要対応 `sentinel_silent` とメール）だけにする。一度も来ていない間は何も出さない
- **運営の様子へ渡すのは変わった時だけ**（照らしの結果の語と名前・外の見張りの seen と silent が変わった時。毎分 `operations:host-report` を呼ぶと、証明書の確かめも毎分になる）。毎晩などのほかの報告にも、state の最後の結果を載せる（報告は丸ごと置き換えなので）。渡せなかった時（app が動いていない）は 10 分おきに渡し直す。前のバージョンのアプリに断られたら、`--integrity…`・`--sentinel…` を外して渡し直す（`--tunnel` を知るアプリには `--tunnel` を残す）。アプリの側は、違いの名前を 1 行ずつ（kind `integrity`、name に名前）置き、名前ごとに要対応 `integrity_mismatch` を出す（別の違いが出たらまた知らせる）。古さはアプリでは見ない（中が黙らされたことは外の見張りが `checked_at` で見る）
- **鍵**は `ec_integrity_ensure` が無ければ作る（入れた時の `record`・最初の `check`・`key`）。入れ替えたい時は鍵を消して `check` を流す（識別子は変えない）
- **照らさないもの**（残り）: コンテナの設定（特権・差し込み・コマンド）。同じイメージで設定だけを替えたコンテナは、数が控えと同じなら気づけない。env の値（`.env.production`）。誰が取りに来ても「外の見張りが来た」に数える（黙らせた見張りの代わりに攻め手が取りに来れば、不在に気づけない）

## 作って決めたこと（外の見張り。2026-11-13）

`deploy/sentinel/ec-sugar-sentinel`（1 つのファイル。bash は道具を探して python3 の本体を流すだけ）。使い方は docs/install.md の「外の見張りを置く」。上の 3 から変えた所・決めきった所:

- **店頭の指紋の中身**: 上に書いたものに加えて、答えの見出しの `Refresh`・`Link`・`Content-Type`、`<link rel=modulepreload>`・`preload as=script`（読み込むスクリプト）・`formaction`・`object`・`embed`・`base`・すべての `meta http-equiv`（CSP も）・`on…` のイベントの属性と `javascript:` の URL の数・3xx の転送先・核の Trusted Types の関所に渡す宛先（`data-sugar-script-src`）も入れる。どれもスクリプトの差し込みかフォームの横取りに使える所で、店の人が直す値ではない。設定の `LINKS_PAGE` のページ（カートなど）だけは、外の出どころへの `<a href>` の出どころも入れる（偽の支払いの画面への誘いに気づく。ほかのページは店の人が外へのリンクを足すので入れない）
- **要素は生の HTML から拾う**（2026-11-13 の見直し）: python3 の HTMLParser は、`<!-->`・`<!--->`・`<![CDATA[` の後ろ（3.9 では `--!>` の後ろも）を注釈の中と読むが、ブラウザでは要素が生きる（`<!--><meta http-equiv="refresh" …>-->` は CSP にも掛からずお客さんを飛ばす）。そこで指紋の要素は、注釈・CDATA・スクリプトの中も含めて `<` で始まる開始の札を全部拾い（生の走査）、HTMLParser で解いた結果に無い要素が生の HTML にあれば「隠した要素があります」をすぐ知らせる。ブラウザの解き方を真似るのでなく「解く部品に見えない所に要素がある」こと自体を困りごとにする（店頭のテンプレートには HTML の注釈もインラインの JavaScript も無く、JSON-LD は `<` を `\u003C` で書くので、ふつうのページでは出ない。本物の店頭で 2 回取って出ないことを確かめた）
- **UTF-8 でないページは困りごと**: `Content-Type` の charset・BOM・`meta charset`（`http-equiv` の content-type も）のどれかが UTF-8 でない、どれも名乗っていない、UTF-8 として読めない、のどれでも。見張りとブラウザで HTML の読み方が変わると、指紋を取った HTML とお客さんの見る HTML がずれるため
- **誤報にしないためにそろえるもの**（今の店頭の Blade と本物の店頭で、2 回取って同じになることを確かめた）: JSON-LD は**中身を入れず数だけ**（商品の名前・値段・在庫の有無が入る。実行されないデータで CSP にも掛からない）。ほかの type のインラインのスクリプトは中身の sha256。`iframe` は宛先の**出どころと sandbox だけ**（動画・地図の ID は店の人が直す値）。同じ出どころのフォームの送り先は道筋だけで、ULID・数字・長い合い札の区切りは `{id}` にそろえる（外の出どころは URL を全部）。CSP の `'nonce-…'` はそろえる。CSRF のトークン・ページの鍵（`data-sugar-page-key`）は属性で、指紋に入れる要素に無いので見ない。文・写真・リンク・CSS は見ない
- **同じ出どころのスクリプトだけ中身を取る**（1 ページ 40 まで・1 つ 4 MB まで）。外の出どころは宛先だけ（取りに行くと見張りが外のサービスを叩くことになる。外の宛先が増えれば宛先の変化で気づく）
- **様子の結果は、ページを見る前に知らせる**（遅いページの答えで、様子の困りごとの知らせを遅らせられないように）。1 回の確かめ全体に時間の上限（`TIME_LIMIT`、既定 120 秒。1 つの取得は 30 秒まで）を置き、越えたら「時間の上限を越えました」をすぐ知らせ、見られなかったページは次の回に。錠が取れない（前の回が終わらない）のが 15 分続いたら 1 回知らせて 1 で終わる（状態は前の回が書くので、別のファイルに残す）
- **User-Agent は既定でふつうのブラウザの形**（設定 `USER_AGENT` で替える）。入られたサーバーは見張りにだけきれいな答えを返せる（接続元・User-Agent・時刻で見分ける）。名乗らないのはその手間を増やすためで、接続元で見分ける手口は残る。ページを別の接続元から取る案（別の回線・別の VPS にもう 1 つ見張り）は install.md に書いた
- **見張りの合い言葉**: 設定 `SENTINEL_TOKEN_FILE`（本番の `sudo ec-sugar integrity token` が出す 32 桁の 16 進。0600 の本人のファイル）があれば、様子の 2 つの取得にだけ見出し `X-EC-Sugar-Sentinel` で付ける（中の「見張りが来ていない」を、見張りのほかの取得で消されないため）。ページの取得には付けない（見張りと見分けさせない）。値は記録・状態・知らせ・curl の引数に出さず、curl へ設定として標準入力で渡す
- **`problems` は種類だけ**（`image`・`service`・`container`・`config`・`code`・`file`・`docker`・`expected`・`lock`。本番の側の約束）。知らせにはそのまま並べ、細かい名前はサーバーの `sudo ec-sugar status` で見ると案内する。知らない種類も形（英数字と `:_./-`）が合えば並べる
- Slack の Webhook には `unfurl_links:false`・`unfurl_media:false` を付ける（知らせの中の偽の宛先を Slack に開かせない）
- **署名が通らない時は 1 秒置いて様子と署名を取り直し**、それでも通らなければ知らせる。2 つは別々の要求なので、サーバーが毎分書き換える間に取ると組が合わないことがあるため
- 世代が**下がった**時も 1 回だけ知らせる（バックアップから戻した・入れ直した時のほかは、古い様子の出し直しを疑う）。`problems` の中身や店頭の違いの中身が変わったら、続いている困りごとでももう一度知らせる（「中身が変わった」）
- busy の 30 分は、見張りが busy を最初に見た時から数える（サーバーの時刻を信じない）
- 知らせを送れなかった時は、知らせた印と世代を前のままにして、次の回に送り直す
- **`accept` は、署名が通らない・形が違う時は止まる**。`ok: false`（busy の途中でも）・様子が古いか先・隠れた要素・UTF-8 でないページの時も断り、`--force` で越える。通った時は店頭の基準と一緒に `server` と世代も記録し直す（入れ直した後の `server` の違いもこれで解く）。前の基準との違いを並べて見せ、人が見てから取る
- 取る時の決まり: https だけ（http は設定の `ALLOW_HTTP=yes`。テストだけ）・転送を追わない・`~/.curlrc` を読まない・圧縮を頼まない・時間 30 秒・大きさは様子 64 KB・署名 4 KB・ページ 2 MB。長さを名乗らずに流し続ける答えも上限で読むのをやめる。設定はシェルとして読まず（key=value を python3 で解く）、知らない名前は断る。Webhook のファイルは本人の 0600 だけ、URL は curl へ標準入力で渡す。状態の保存先は本人の持ち物で、ほかの人が書けないこと
- 終わりの値は 0（困りごと無し）・1（困りごとがある・送れなかった）・2（使い方か設定の誤り）
- テストは `docker/check-sentinel.sh`（開発用の CI の image の段と、公開用の CI の scripts の段）。macOS の bash 3.2 と python3 3.9 でも流して通ることを確かめた
