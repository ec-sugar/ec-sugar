# 0024 運営はオーナーとスタッフ、スタッフは店ごとに閲覧・運用・お金

状態: 採用（2026-10-28）。ADR 0014（運営はどのテナントにも立ち入れる）の「失ったもの」を塞ぐ。

## 文脈

運営は誰でも、どの店にも入り、どの操作（返金・Stripe の鍵・テーマの切り替え）もできた。運営のアカウント 1 つが乗っ取られると全店に届く。ゼロトラストの見直し（2026-10-28）で、いちばん危ない穴とした。よくある EC の管理画面には「メンバー管理・権限管理・ログイン履歴」がある。

## 決定

- **運営の役割は 2 つ**: オーナー（全店・全操作・メンバーの追加と権限の変更）とスタッフ（与えられた店だけ）。オーナーは少なくとも 1 人残す（最後の有効なオーナーは外せない・止められない）。いた運営はオーナーにする（これまでどおり）
- **スタッフは店ごとに 3 段階**: 閲覧（読むだけ）／運用（商品・在庫・カテゴリ・店の設定・発送と完了・個人情報の表示）／お金（取消と返金・返金が要る支払い・Stripe の鍵とつなぐ）。上の段階は下を含む
- **守るのはサーバー**: 店の API の段階は、読む（GET）は閲覧・変える（それ以外）は運用を既定とし、お金と個人情報の表示は経路に明示の印（`tenant-level:money` など）を付ける。お金の経路に印があることをテストで機械的に確かめる。与えられていない店は 404（あるかどうかも見せない）、段階が足りなければ 403。どちらも監査ログに残す
- **変えるのは管理画面（オーナーだけ、直前の再確認、監査ログ）とコマンド**（`operator role` / `operator grant`）

## 結果

- 得たもの: スタッフのアカウントが乗っ取られても、届くのは与えた店と段階まで。お金を動かせる人を絞れる
- 失ったもの・気をつけること: オーナーのアカウントは今までどおり全店に届く（オーナーを少なく保つ。二人承認は ）。店の数が増えると権限の付け外しの手間が増える（店のグループは後で）

## 作って決めたこと

- 2026-11-11: 店の名前を変える（設定 › 基本）は、店の段階でなく**オーナーだけ・直前の再確認**（メンバーと権限・サンプルの片付けと同じ）。名前は中央の店の行にあり、メールの差出人の名前と件名に出るので、乗っ取ったセッションやスタッフに装いの名前へ替えさせない。お金の段階のスタッフも 403。変えたことは中央の監査ログ（`tenant.renamed`）と店の記録（`shop.renamed`）に、誰が・どの店かだけを残す
