# 0094 プライバシーポリシーは店の設定の本文で持ち、ショップの /privacy に出す

状態: **採用**（2026-11-11 2 つ目。形は既定で、中身は今のコードから決めた）。迷ったところは安全で単純な既定を置き、末尾の「確かめたいこと」に挙げた。
ADR 0018（ショップ）・0028（核は店の事実を持つ）・0032（説明のブロック）・0034（外部送信の公表）・0039（自由なページ）・0093（互換の約束）の上に置く。置き換えるものは無い

## 文脈

- 特商法の表記は店の設定（`ShopSettings.legal`、暗号化）とテーマの画面 `legal` で出していた。プライバシーポリシーは欄もショップのページも無く、お店の人向けの案内は「自由なページで作ってメニューに載せる」だった。App「LINE 連携」のヘルプは「ショップのプライバシーポリシーに書き足す」と、有る前提で書いていた
- 外部送信の公表（ADR 0034 の 5）は核が `/legal/external` に出し、フッターの `<x-storefront.app-links>` から辿れる。プライバシーポリシーとは別のページ
- 個人情報保護法では利用目的の公表などが求められ、どの店にも要るものなので、ADR 0028 の 1（核は店の事実だけを持つ）の「店の事実」に入る

## 決めたこと

1. **本文は店の設定の 1 つの文の欄**（`shop_settings.privacy_policy`）。20,000 字まで。改行は `\n`、タブは空白にそろえ、ほかの制御文字は断る。空（null・空白だけ）は外す。問い合わせ先に店主の名前・住所が入りうるので、特商法の表記と同じく**店の鍵で暗号化**し、DB の制約で平文を断る。変えるのは `ShopSettingsService::setPrivacyPolicy` だけで、`EventStore::lock()` → 行のロック → 記録 `shop.privacy_updated`（`{chars}` 文字の数だけ。中身は入れない）を同じトランザクションで
2. **管理画面は「設定 › ショップ › プライバシーポリシー」**（`/tenants/{店}/settings/privacy`。特商法の画面と同じ型）。API は `GET …/shop-settings` の `privacy_policy` と `PUT …/shop-settings/privacy-policy`（`{body}`）。権限はほかの店の設定と同じ: 読むのは閲覧、変えるのは運用（閲覧は 403）
3. **書き方は Markdown の小さな一部だけ**: 空の行で段落、`# `・`## ` は大きい見出し、`### ` は小さい見出し、`- `・`* `・`・` は箇条書き。番号つきの並びは作らない（途中で段落が挟まると番号が 1 から振り直されるので、書いた番号を文のまま出す）。リンク・太字・HTML は読まない。読んだ結果は商品の説明と同じ `DescriptionBlock` にして、核の部品 `<x-storefront::description-blocks>` で描く（お知らせ・ブログの記事と同じ描き方。どの文も `{{ }}`）。保存するのは書いたままの文で、読み方は描くときに核が決める（後で読める記法を足しても保存し直さなくてよい）
4. **ショップは `/privacy`**（`storefront.privacy`）。本文が無い店では**「見つかりません」（404）**。特商法の表記の「準備中」と違い、法律で常に見せる決まった項目の表ではないので、空のページを出さない（フッターのリンクも出さない）。準備中のショップでは**関所の内側**（まだお客さんの情報を受けない。特商法の表記と違い、外に出す理由が無い）。画面の種類は**ふつうの画面**（`StorefrontView::PAGE_KINDS` に `privacy` を足した。店の人の文だけで、お客さんの情報は入らない。App のタグは差し込む）。検索に載せ、本文がある店ではサイトマップに入れる
5. **描くのはテーマの任意の画面 `privacy`**、無ければ核の既定の画面 `storefront.privacy`（テーマの外枠の中に題と本文。外へ送る App を使う店では、外部送信に関する公表のページへの一言を添える）。テーマに渡すのは `$privacy`（`PrivacyPolicyView`: `title`・`url`・`blocks`）と、すべての画面の `$shop->privacyUrl`（本文がある店だけ `/privacy`、無ければ null）。**テーマ API の付け足し**（任意の画面と、新しく渡す値）なので番号は 2 のまま（ADR 0093 の 3）
6. **フッターのリンク**は 4 つの公式テーマで、特商法の表記のリンクの隣、`<x-storefront.app-links>`（外部送信について・Cookie の設定）の**前**に置く（法律の案内 2 つ → 送信の公表の順。公表のリンクは今までどおり要るときだけ出る）。kinari の下の段（©の横）の特商法のリンクには足さない（同じ画面の上の案内に出る）
7. **`privacy` は自由なページの予約語**（`ShopPage::RESERVED_SLUGS` と DB の制約 `shop_pages_slug_not_reserved`。App のショップのページの頭にも使えない〔`PluginRoutes::reservedPrefixes`〕）。前の案内どおりに `privacy` のページを作っていた店のために、制約を作り直すマイグレーションが、そのページを `privacy-page`（使われていれば `privacy-page-2` …）に替え、ゴミ箱でなければ `/pages/privacy` から 301 の転送（`source` auto）を足す。記録には残さない（店の人の操作ではない。前のデータの移行と同じ扱い）
8. **書き始めの手助け**: 管理画面の「ひな形を入れる」（本文が空のときだけ）。見出しの骨組みだけ（取得する情報・使う目的・第三者への提供・外部への送信〔解析・広告のタグなど〕・安全管理のための措置・開示などのお求め・お問い合わせ先・改定）と【】の空欄。決まった言い回しは入れず、画面とヘルプに「ひな形は見出しの骨組みで、法律の助言ではありません。内容はお店で確かめてください」と出す
9. App「LINE 連携」のヘルプと README は「設定 › プライバシーポリシーに書き足す」に合わせた（マニフェストの説明の文は「ショップのプライバシーポリシーに書き足す」のままで食い違わないので変えていない。変えると composer.lock の写しも直すことになる）

## 結果

- 得たもの: どの店もコードなしでプライバシーポリシーを出せ、テーマは何もしなくても描ける。描き方が商品の説明・お知らせと同じ核の部品なので、XSS の守りが 1 か所
- 失ったもの・気をつけること: 書き方が決まった小さな記法だけ（表・リンク・太字は使えない）。前に `privacy` の自由なページを作っていた店は URL が `privacy-page` に変わる（転送はする）。改定日は本文に書いてもらう（列では持たない）

## 確かめたいこと（既定で進めた。違えば直す）

1. 本文が空のときの `/privacy`: **404**（既定）か、特商法と同じく「準備中」と出すか
2. 準備中のショップで `/privacy` を**関所の内側**に置いた（既定）。決済代行の審査などで公開の前に見せたいなら、特商法の表記と同じく関所の外の一覧に足す
3. 上限 20,000 字（既定）で足りるか
4. 記法: 表・リンクが要るか（要るなら説明のブロックの表と、同じショップの中の道筋か https だけのリンクを足す）
