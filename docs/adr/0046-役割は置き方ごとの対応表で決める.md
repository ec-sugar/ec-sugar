# 0046 役割は置き方ごとの対応表で決める（自分で持つ形と SaaS）

状態: **採用**（2026-10-31。4 つの分かれ道は運営が選択肢で決めた: 自分で持つ形は運営＝店の人・SaaS の店の人は同じ管理画面で自分の店だけ・立ち入りは記録して店に知らせる・知らせは種類で分ける）。ADR 0013・0024（運営とオーナー・スタッフ）・0023（店の人とお客さん）・0038（パスキーをなくした時）・0042・0043（運営全体の画面と知らせ）・0044（お客さん）の読み替えをそろえる

## 要点（先に）

ADR ごとに「運営」「オーナー」「店の人」が誰を指すかがぶれていた（ADR の見直し 2026-10-31）。置き方ごとに 1 枚の表にする。

| 役割 | 自分で持つ形（パッケージ） | SaaS |
|---|---|---|
| 運営（管理画面の運営。オーナーとスタッフ、ADR 0024） | 店の持ち主とその会社・制作会社 | 私たち（EC-SUGAR を提供する側） |
| 店の人（ADR 0023） | 運営と同じ人（別のログインを作らない） | 契約した店の店主とスタッフ（店ごとのログイン） |
| お客さん（ADR 0044） | ショップで買う人 | 同じ |

## 決めたこと

### 1. 入る画面と触れるもの

| | 自分で持つ形の運営 | SaaS の私たち（運営） | SaaS の店の人 |
|---|---|---|---|
| 入る画面 | 管理画面（全部） | 管理画面（全部） | 同じ管理画面に、店の人の入口から入り、自分の店だけ |
| 運営全体の画面・知らせ（ADR 0042・0043） | 見る | 見る | 見ない |
| 自分の店のお金・個人情報・App・テーマ | 段階（ADR 0024）のとおり | 立ち入りの決まり（3）のとおり | 店の人の段階のとおり（ADR 0024 と同じ 閲覧・運用・お金） |
| サーバー（`ec-sugar`） | 入れる | 入れる | 入れない |

### 2. パスキーをなくした時に誰が戻すか（ADR 0038 の 6）

- 自分で持つ形: 本人（回復用のコード・メールの 24 時間待ち）か、サーバーに入れる人
- SaaS の店の人: 本人か、その店のほかのオーナー。だめなら私たちが本人の確かめ（契約の情報）をしてから登録のリンクを出す

### 3. SaaS で私たちが店の中に立ち入る時

- 店の許可は要らないが、立ち入りは必ず記録（ADR 0014 の入口）し、店のオーナーに知らせる（メールとホーム）。個人情報の閲覧とお金の操作は、今の段階と操作の直前の確かめのまま

### 4. 知らせの宛先

- 仕組みの壊れ（エラー・証明書・空き容量・更新。ADR 0043）は運営へ。店の困りごと（確かめが要る返金・止まった支払い）は運営と、その店の店の人のオーナーへ

## 採らない案

- **自分で持つ形でも店の人のログインを別に作る**: 同じ人が 2 つのアカウントを持つことになり、守る入口が増えるだけ
- **SaaS の店の人に別の簡単な画面を作る**: 同じ画面を 2 つ育てることになる。見せる範囲は API の権限で絞る（今の段階の仕組みを使う）

## 結果

- ADR 0022（「パッケージ版は運営がいない」）・0038（SaaS の戻し方）・0042・0043（オーナー）の読み替えが 1 か所で決まる
- SaaS の店の人のログインは、運営と同じ管理画面に入口と範囲を足す形で作る
