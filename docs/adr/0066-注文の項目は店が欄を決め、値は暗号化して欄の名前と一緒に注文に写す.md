# 0066 注文の項目は店が欄を決め、値は暗号化して欄の名前と一緒に注文に写す

状態: **採用**（2026-11-05。注文に関わるので核の機能）。

## 文脈

- 日本のネットの店では、注文の入力で店ごとに聞きたいことがある（のしの有無・表書き・用途・ご要望・名入れの文字など）。今の注文の入力は、ご依頼主・送り先・贈り物・お届け日時・お知らせのメールだけで、店が欄を足せない
- 答えは自由な文になりうるので、名前・住所・事情などの個人情報を含みうる（ADR 0010 の「平文の個人情報を新しい列やイベントに入れない」）
- 店は欄を後から変える（名前を直す・必須にする・消す）。過去の注文の答えは、その時の欄の意味で読めないと困る。確かめの画面を見せた後に欄の決まりが変わると、見せた内容と確定する注文が食い違う（ADR 0059 のお届け日時と同じ問題）

## 決定

1. **欄の決まりは店の DB の表 `order_fields`**。店の人が管理画面の「設定 › 注文の項目」で作る。種類は 1 行の文（200 文字まで）・複数行の文（1,000 文字まで）・選ぶ（選択肢は 20 個まで、各 40 文字）・チェック（はい／いいえ）。名前（40 文字）・説明（100 文字）・必須・並び・使う／使わない。**同時に使う欄は 10 個まで**（連鎖のロックの中で数え、DB のトリガーでも守る）
2. **注文の入力には、使う欄を核の部品 `<x-storefront::order-fields>` で出す**（4 つのテーマに置く。テーマ API の「注文の項目」）。サーバーが確かめる（必須・長さ・選択肢の中か）。確かめの画面に入れた値を出す（`<x-storefront::order-fields-summary>`）。**確かめの画面の指紋に、欄の決まりと値の要約（ハッシュ）を入れ**、確かめの後に欄の決まりが変わったら確定しない（入力の画面で確かめ直してもらう）
3. **値は注文ごとに `order_field_values`**（取引の ID・欄の ID・**その時の欄の名前・説明・種類の写し**・並び・値）。値は自由な文で個人情報を含みうるので、**ADR 0010 の列の暗号化で持つ**（選ぶ・チェックも同じ扱い）。注文のイベント `order.fields_recorded` には欄の ID だけを入れ、値は入れない。注文の確定と同じトランザクション（連鎖のロックの中）
4. **欄を消す**: 一度も注文に使われていなければ消せる。使われていれば「使わない」にだけできる（DB の外部キーでも消すのを拒む）。過去の注文の表示は値に写した名前と種類から
5. **見せる所**（2026-11-05 の見直しで変えた）: 選ぶ・チェックの答えは、確かめの画面・ご注文の確認のメール・ご注文の状況とマイページの注文・管理画面の注文の 1 件の画面に出す。**1 行・複数行の文の答えは、確かめの画面（入れた本人のセッション）と管理画面の個人情報の入口だけ**。メール・ご注文の状況・マイページには中身を出さず、文の答えのある注文に「ご要望などの文のお答えはお店に届いています」の一言だけ。理由: 注文はメールの完全一致でつなぐので、打ち間違えたメールの持ち主にメールとマイページで他人の文が見える。またコンビニ払いの入金待ちのメール（ADR 0058）はお金を払わずに送れるので、好きな文を他人のメールへ店の名前で届ける口になる。配送の CSV と納品書（`plugin-shipping-csv`・`plugin-order-print`）は今回は入れない（次の候補）
6. **贈り物の注文でも買う人に聞く**（のし・用途は贈り物でこそ要る。届く日と違い、受け取る人しだいで変わらない）。**定期便の申し込み・カートを通さない申し込み（`PlaceSingleOrder`）では今回は出さない**: 定期便は回ごとに注文を作り、回の注文は人の入力を通らない（ADR 0049）。1 回目だけ聞くと回ごとの答えが食い違い、毎回同じ答えを写すなら定期便の側の約束（申し込みの時の値の持ち方・変え方）を決める必要がある。申し込みの画面は App の画面（ADR 0050）で、核の注文の入力とは別の流れでもある
7. **管理画面の権限は今の設定の画面の決まりに合わせる**（ADR 0024）: 読むのは閲覧から、足す・直す・消す・並べ替えるは運用から。店の人の作る・直す・消す・並べ替えは、店の記録（`order_field.*`。actor つき）と中央の監査ログ（`operator.order_field_changed`）に残す

## 結果

- 得たもの: 店が注文の入力に聞きたいことを足せ、答えは注文の時の名前で残る。改ざんした値・確かめの後に変わった決まりで確定しない。DB の dump が漏れても答えは暗号文
- 失ったもの: 答えで注文を探す・並べ替える・数えることはできない（暗号化した列）。答えを確定の後に直す画面は無い（店が連絡を受けて、別に控える）。定期便の回には付かない

## 作って決めたこと

- **管理画面の注文の 1 件の画面では、選ぶ・チェックの答えだけを閲覧の段階から見せ、1 行・複数行の文の答えは「個人情報」の入口（運用から・見た記録が中央の監査ログに残る）でだけ返す**（作る時の判断）。決定 7 の「値を見られるのは注文を見られる人」を、名入れの文字（ADR 0036 のオプションの入れた文字）と同じ扱いに合わせた。選ぶ・チェックは店の決めた選択肢なので個人情報にならず、文は名前や事情が書かれうるため
- **お客さんの値の形は 2 段で確かめる**: 注文の入力の形（`CheckoutInput`）は「欄の ID（ULID）=> 文字」だけを残して数を上限（50）で切り、中身は核の `OrderFields::check` が店の今の決まりで確かめる。誤りの欄の名前は `fields.<欄の ID>`（入力の画面の欄の下に出る）
- **文の決まりは贈り物のメッセージと同じ**（`GiftNote`）: 改行を `\n` にそろえて前後の空白を取り、長さは見える文字で数える。制御文字と文の向きの印は断る。1 行の文は改行を断る。選ぶは選択肢と完全に同じ文だけ
- **空の任意の欄は値を残さない**（確かめの画面にも出さない）。チェックは「いいえ」も答えとして残す（「のし: いいえ」を店が確かめられる）。必須のチェックは「チェックを入れないと注文できない」（注意事項への同意などに使う）
- **欄の無い店の指紋は前と同じ形**（要約が空なら足さない）。欄の名前・説明・選択肢を変えた・欄を足した・消したも、決まりの要約が変わるので確定しない。**要約の中の欄は ID の順**に並べる（確かめの後に並べ替えただけなら答えの意味は変わらないので止めない）。**説明も要約に入れ、値にも写す**（同意のチェックに使った時、どの文に同意したかを示せる）
- **欄は全部で 50 個まで**（使わない欄も含む。ホストする時の上限）。値は追記専用（DB のトリガーで UPDATE・DELETE・TRUNCATE を断る。記録の表・台帳と同じ形。店を消す時は DB ごと消すのでぶつからない）
- **並び（position）は 0〜1000**（DB の制約）。足す時に最後の次が 1000 を超えるなら、今の並びの順のまま 0 から詰め直してから足す（足して消すを繰り返しても 500 にしない）
- 管理画面の入力の形は FormRequest（`OrderFieldRequest`・`OrderFieldOrderRequest`）。規則は核の `OrderFields::rules` と同じもので、核でも確かめ直す。何も変えない保存・並べ替えは、店の記録にも中央の監査ログにも残さない
- 文の決まり（`GiftNote::UNSAFE`。贈り物のメッセージと共通）に、行と段落の区切り（U+2028・U+2029）と幅の無い文字（U+200B・U+200C・U+FEFF）を足した。絵文字をつなぐ U+200D（家族・肌の色の組み合わせ）は、贈り物のメッセージで使われるので通す（商品レビューの決まりと同じ。2026-11-05）
- メールは「ご注文の確認」（`order_paid`・`order_awaiting_payment`）にだけ選ぶ・チェックの答えと一言を載せ、発送の知らせには何も載せない
