# 0091 サービス（役務）はふだんのカートで売り、受渡は in_person で店の人が提供済みにする

状態: **採用**（2026-11-10。作ることは運営が決めた〔公式の店で設置代行とカスタマイズを売る。オプションも付けられること〕。形は作る時に決めた）。
ADR 0025（App）・0036（商品のオプション）・0056（予約の役務の受渡 `deliverInPerson`）・0084（送らない品 `digital`）の上に足す。置き換えるものは無い

## 要点（先に）

1. App「サービスの販売」（`plugins/plugin-services`、名前 `services`、目的 `selling`）が商品の扱い「サービス」（`service_item`）を足す。**ふだんのカートと注文の流れで買え、オプション（ADR 0036）もそのまま使える**
2. 核の商品の種類に**役務の印**（`ListingKindDefinition::$inPerson`、`ListingKinds::inPerson()`）を足した。役務は送らない品（ADR 0084）と同じく、送料・送り先・在庫を使わず、1 回の注文で 1 点まで（`ListingKinds::digital()` は役務も送らない品と答える）。**受渡は `digital` でなく `in_person` の 1 つ**
3. **役務はほかの扱いの品と同じ注文に入れない**。カート（`CartService`）は混ざった時に役務の行を止めて知らせ（`CartService::SERVICES_MIXED`）、止まった行のあるカートは確定に進めない。確定（`PlaceOrder`）でも二重の守りとして断る
4. 作業を終えたら、店の人が管理画面の注文の**「提供済みにする」**（`POST …/transactions/{注文}/deliver-service`、運用の段階）を押す。核の `SaleOrderService::deliverService` が「役務の種類の商品だけの注文」（`isServiceOrder`）と支払いが済んでいることを確かめ、`deliverInPerson`（ADR 0056）で受渡 → 受取確認 → 精算まで進める。発送の知らせのメールは出さない

## 文脈

- 公式の店（official.ec-sugar.jp）で、設置代行（本体の値段＋オプション）とカスタマイズを売る（2026-11-10。オプションも付けられること）。物を送らないので、送料・送り先・在庫は要らない
- 核にはもう役務の受渡（`in_person`）と、それを済ませる `deliverInPerson` がある（予約の App）。ただし予約は App の 1 品の注文の画面で売り、枠の状態と一緒に App が済ませる
- 送らない品（`digital`）は払いが確かになった時に App が渡し終える。役務は作業が要るので、払っただけでは済まない

## 決定

- 種類の印は `inPerson`（`stockless: true` と一緒に登録する）。カタログは行に `digital`（送らない）と `inPerson` を付け、カートと確定は `digital` の行を送料の便・在庫から外す今の決まりをそのまま使う
- 確定（`PlaceOrder::drafts`）は送らない品の行の位置ごとに役務かを持ち、役務の行は `in_person` の受渡 1 つにまとめる（送り先も拠点も無い）
- 混ぜない理由: `deliverInPerson` は「役務の受渡だけの注文」を済ませる作り。物と一緒の注文で役務の受渡だけを済ませると、段の進み方（発送 → 受渡）と食い違う。売る側の使い方（設置の代行とマグを一緒に買う）も考えにくい
- 「提供済みにする」は予約の品の役務の注文では断る（予約は枠の状態を App が持つので、核のボタンで済ませると枠と食い違う）。見分けは注文の商品の行の種類が全部 `inPerson` か
- 支払い: 送らない品と同じく、コンビニ払いと代金引換は出さない（今の `hasDigital` の決まりと ADR 0084 の代金引換の決まり）。銀行振込は使える（入金を確かめてから「提供済みにする」）

## 作って決めたこと

- 種類の名前は `service_item`（CONCEPT 6.3 の「仕事」の `service` と重ねない）
- 払う前に「提供済みにする」を送ると「支払いの前は提供済みにできません」で断る（予約の「来店済み」の文を出さない）
- 混ざったカートでは役務の行だけを止める（ほかの品は買える形のまま。ただし止まった行のあるカートは今の決まりで確定に進めないので、お客さんは役務を外すか、別に注文する）

## 結果

- 公式の店で、設置代行（オプションつき）をカートから売れる。ほかの店も、作業・講座の申し込み・修理の受付など、物を送らない役務を同じ形で売れる
- 残り: 役務の注文の知らせのメールは、ふつうの注文と同じ文（「発送」の言葉は出ないが、役務向けの案内は無い）。作業の日程の調整はメールで店とお客さんが行う
