# 0003 テナントごとに DB を分割する

状態: 採用（2026-10-26）

## 文脈

マルチテナントの分離方式は「単一 DB に tenant_id」「スキーマ分割」「DB 分割」がある。
単一 DB は実装が単純だが、SQL インジェクションや認可バグ一つで全テナントの顧客情報が抜ける。
本製品は決済と本人確認書類を扱う。

## 決定

中央 DB（Tenant・ドメイン・契約・管理者・接続情報）＋ テナントごとの DB。
実装は stancl/tenancy の PostgreSQLDatabaseManager。
出品者（Seller）はテナント DB の中に複数持てるので、マーケットモードでも DB をまたぐ検索は生じない。

## 結果

- 得たもの: 攻撃・漏洩時の被害が 1 テナントに閉じる。データの持ち出しが dump 一つで済む（SaaS → パッケージの移行がそのまま成立）。バックアップ・復元・削除がテナント単位
- 失ったもの: マイグレーションがテナント数だけ走る。キュー・スケジューラ・検索は必ずテナント文脈を持つ必要がある。テナント横断の集計は中央 DB への集約イベントで行う
- 急所: 中央 DB にテナント DB の接続情報が集まる。テナントごとに DB ユーザーを分け権限を最小にし、接続情報は暗号化して保管する（→ ADR 0009 で済: テナントごとの専用ロール〔最小権限〕、テナント DB のパスワードは APP_KEY で暗号化して中央に保存）
