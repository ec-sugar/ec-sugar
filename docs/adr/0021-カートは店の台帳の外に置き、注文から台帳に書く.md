# 0021 カートは店の台帳の外に置き、注文から台帳に書く

状態: 採用（2026-10-27）。ADR 0012（書き込みは EventStore::lock() を先に取る）の例外を 1 つ足す。一部置き換え（→ ADR 0036: カートの行にオプションの入れた文字〔名入れ〕を、店の鍵で暗号化して持つ）

## 文脈

店頭のカートを作る。お客さんの立場で考えて決めた。

- お客さんはスマホで見て入れ、数日迷ってから買うことが多い。カートは**テナント DB に 30 日保つ**（推測できない合い言葉の Cookie で紐付け、DB には合い言葉の SHA-256 だけを置く）
- カートの操作は**最初から JavaScript で滑らかに**（ページを移らずに入れる）。ただし JS が無くてもフォームで動くようにする。JS はテーマではなく核の部品（ADR 0020）

今の決まりでは、テナント DB への書き込みはすべて、店全体で 1 本の記録の鎖のロック（`EventStore::lock()`）を取り、変更をイベントとして残す。これをカートにも当てはめると:

- 「カートに入れる」のたびに、店全体の書き込みが 1 本の列に並ぶ。人が集まると、注文・在庫・お金の処理まで待たされる
- 記録（監査・帳票・AI の評価データの源泉）が、ほとんど買われないかごの出し入れで埋まる

## 決定

- **カートは「取引の前の下書き」として、記録の鎖のロックとイベントの外に置く**。同時の操作は、そのカートの行のロック（`SELECT … FOR UPDATE`）で守る。ほかのお客さんを待たせない
- **注文の確定からは今の決まりどおり**: `EventStore::lock()` を取り、在庫を確保し、取引をイベントとして残す。カートの中身は確定のときにサーバーの商品から計算し直す（カートに入れた時の価格や在庫を信じない）
- カートには個人情報を入れない（商品と数だけ）。古いカート（最後の操作から 30 日）は定期的に消す（→ ADR 0036 で一部置き換え: 名入れの文字は人の名前になりうるので、個人情報として店の鍵で暗号化して `cart_lines.addons` に持つ）
- 「カートに入れた」ことの分析用の記録は、要るときに別の軽い記録として足す（今は作らない）

## 結果

- 得たもの: かごの出し入れが店全体の書き込みを待たせない。記録が注文・在庫・お金の出来事に絞られる
- 失ったもの: カートの変更の履歴は残らない（必要になれば別の記録を足す）。「書き込みは必ずロックとイベント」の決まりに例外が 1 つ増える（決まりの文書に明記する）
