# 0061 検索と共有の見え方（SEO）は核が決め、テーマは `<head>` に部品を置くだけにする

状態: **採用**（2026-11-05。SEO を「需要の多いものから順に」の 1 番目にすることは運営が決めた。核に置くか・決まりの中身は作る時に決めた）。

## 文脈

- 検索（Google など）と共有（LINE・X・Facebook）での見え方は、どの店にも要る基本。よその EC の App のストアには似た App が 20 本ほどある（題・説明・OGP・構造化データ・サイトマップ・転送）
- 今は、4 つのテーマの `layout` が `<title>` と `<meta name="description">` を自分で出し、商品の画面だけが `@section('description')` と canonical を持つ。カテゴリ・自由なページ・トップの説明は「◯◯のオンラインストアです。」の決まった文。OGP・構造化データ・サイトマップは無く、`public/robots.txt` はどのホストにも「全部いい」を返している（管理画面のホストも、準備中のショップも）
- 商品の URL は ID（ULID）で、作った後に変わらない。カテゴリ（`/categories/{slug}`）と自由なページ（`/pages/{slug}`）は slug を店の人が変えられる
- 乗り換えてくる店は前のショップの URL（`/item/123` など）を検索に載せている。乗り換えると、その URL が「見つかりません」になり、検索の順位とリンクを失う
- App「商品フィード」の README は「商品の画面の JSON-LD は核の仕事」と書いている。App「商品レビュー」は平均の星と件数を、商品の画面の並び（`ProductPanel` の `rating`）で渡している

## 決定

1. **核に置く**（App にしない）。どの店にも要り、`<head>` のすべての画面に関わる。App にすると、App に `<head>` の中へ文を書かせる口（すべての画面への差し込み）が要り、守る所が増える。テーマは `<head>` に核の部品 `<x-storefront::seo>` を 1 行置くだけ（題・説明・canonical・robots・OGP・X のカード・JSON-LD を部品が出す）。テーマごとに写しを持たない
2. **題の付け方**: `「ページの題 | 店の名前」`（区切りは半角の縦線）。トップは店が入れた題、無ければ店の名前だけ。ページの題は、店が入れた「検索の結果に出す題」、無ければ商品名・カテゴリの名前・ページの題。店が入れた題にも店の名前を付ける（どの店の物かを検索の結果で分かるように）。検索に載せない画面（カート・注文など）はテーマの題のまま
3. **説明（description）**: 店が入れた「検索の結果に出す説明」、無ければ自動で作る。商品は短い説明か説明の文の頭、カテゴリは「店の名前の カテゴリ の商品の一覧です。」、自由なページとそのほかはトップの説明、無ければ「店の名前のオンラインストアです。」。自動の説明は 120 文字で切る。目安（画面に出す）: 題は 30 文字、説明は 120 文字。上限（サーバーと DB）: 題 70 文字・説明 200 文字、改行と制御文字は断る
4. **共有の見え方（OGP・X のカード）**: `og:site_name`・`og:title`（店の名前を付けない題）・`og:description`・`og:url`（canonical と同じ）・`og:type`（商品は `product`、ほかは `website`）・`og:locale`（`ja_JP`）・`og:image`（商品は 1 枚目の写真の大きい方、無ければ店の「共有の既定の写真」〔設定 › SEO。ショップの写真から選ぶ〕）。X は `twitter:card`（写真があれば `summary_large_image`）。URL はすべて絶対の URL
5. **構造化データ（JSON-LD）**: 商品の画面に `Product`（名前・説明・写真・品番〔種類が 1 つの時〕・`Offer`〔価格・通貨・在庫・URL〕。種類で価格が違えば `AggregateOffer` の最安と最高・種類の数）、App が平均の星を渡していれば `AggregateRating`（今の口 `ProductPanel::rating` を使い、新しい口は足さない）。カテゴリと商品の画面に `BreadcrumbList`、トップに `OnlineStore`（名前・URL・共有の写真）。JSON は `<` `>` `&` `'` `"` を `\uXXXX` にして書く（`</script>` を壊さない）。`<script type="application/ld+json">` は実行されないデータの塊なので CSP の `script-src 'self'` のままでよい。この 1 つの塊は PHP（`SeoMeta::jsonLd()`）が作り、Blade の部品にはスクリプトの要素を書かない
6. **検索に載せる画面は決めた一覧だけ**（書き忘れは載せない側に倒れる）: トップ・商品・すべての商品とカテゴリの一覧・自由なページ・特商法の表記。ほか（カート・注文の入力と確認・ご注文・マイページ・同意・外部送信の公表・App の画面・プレビュー・エラー・**検索の結果**）は `noindex`。**準備中のショップはすべて** `noindex`
7. **canonical**: 商品は商品の URL、一覧は並び替え（`sort`）と検索（`q`）を外した URL（2 ページ目からは `?page=N` を残す。ページごとに別の中身なので）、自由なページはその URL、トップはトップ
8. **サイトマップ** `/sitemap.xml`: 開いているショップだけ（準備中は 404）。トップ・すべての商品・カテゴリ・公開中の商品（`lastmod` 付き）・公開した自由なページ・特商法の表記。5 万件まで（1 つのファイルの上限）
9. **robots.txt は店ごとに核が返す**（`public/robots.txt` は外す）。開いている店は、カート・注文・マイページ・パスワード・同意・プレビュー・App の公開の経路（`/p/`）・郵便番号を止め、サイトマップの場所を書く。準備中の店と管理画面のホストは全部を止める
10. **301 の転送**: 店が「古い URL → 新しい URL」を足せる（乗り換えの店のため。設定 › SEO）。守り:
    - **転送するのは、その URL が「見つかりません」になる時だけ**（今ある画面を上書きしない。店の画面より転送が先に効くと、ショップの画面を乗っ取れる）。GET と HEAD だけ
    - 行き先は**同じショップの中の道筋だけ**（`/` で始まり、`//` と `/\` で始まらない、英数字と記号だけ。スキームとホストを持てない。開いたリダイレクトを作らない）
    - 元は `/` で始まる道筋（日本語も可。前後の `/` をそろえ、% の書き方を戻して比べる）と、あれば `?` の後ろ。元と行き先が同じなら断る
    - **鎖を作らない**: 行き先が別の転送の元なら、その転送の行き先へ寄せる。新しい元を行き先にしていた転送は、新しい行き先へ付け替える（ループが作れない）
    - 1 つの店で **1,000 件まで**
11. **slug を変えた時の自動の転送**: カテゴリと自由なページの slug を変えたら、古い URL から新しい URL への転送を自動で足す（上の決まりで寄せる。上限に達していれば足さず、slug の変更は通す）。商品は URL が ID なので変わらず、要らない

## 区切り

1. 核とショップ: 列と表・題と説明・OGP・JSON-LD・canonical・robots・サイトマップ・noindex・転送・4 つのテーマに部品を置く
2. 管理画面: 商品・カテゴリ・ページの「検索と共有」の欄と検索の結果の試し見、設定 › SEO（トップの題と説明・共有の既定の写真・転送の一覧）

## 作って決めたこと（2026-11-05、区切り 1・2）

- **置き場**: 商品・カテゴリ・自由なページに `seo_title`・`seo_description` の列。店の設定は別の表 `shop_seo`（1 行。トップの題と説明・共有の写真）にし、店の事実を持つ `shop_settings` とは分けた。転送は `redirects`。どれも核の `Shop` の文脈（`SeoSettingsService`・`RedirectService`・`Seo\SeoText`・`Seo\RedirectPath`）。変えるのはサービスだけで、連鎖のロックとイベント（`listing.updated`〔説明は「変わった」だけ〕・`category.updated`・`shop_page.updated`・`shop.seo_updated`〔変わった欄の名前だけ〕・`shop.redirect_added`・`shop.redirect_updated`・`shop.redirect_removed`）
- **題の区切り「 | 」は核が決める画面だけ**。検索に載せない画面（カート・注文など）の題はテーマのまま（「カート — 店の名前」）。載らない画面なので、そろえるのは急がない
- `og:title` には店の名前を付けない（共有の札には `og:site_name` が別に出る）。トップの題は店が入れたものをそのまま使う（店の名前も足さない）
- 自動の説明: カテゴリは「{店の名前}の{カテゴリ}の一覧です。」、すべての商品は「{店の名前}のすべての商品の一覧です。」。自由なページと特商法の表記はトップの説明。区画の中の文から作るのはテーマごとに形が違うのでしない
- 価格は円の整数をそのまま `price` に入れる（JPY だけ。商品フィードの App と同じ）。在庫の具合は「在庫あり」→ `InStock`、「残りわずか」→ `LimitedAvailability`、「売り切れ」→ `OutOfStock`
- サイトマップにはカテゴリを全部入れる（商品の無いカテゴリも。中身の無い一覧も 200 で開くため）。商品は直した日の新しい順で、5 万件を超えた分は入れない。`lastmod` は日付だけ
- `robots.txt` で止めるのは `/cart`・`/checkout`・`/orders`・`/account`・`/password`・`/consent`・`/preview/`・`/postal/`・`/p/`。写真（`/media/`）と App のスクリプト（`/apps/`）は止めない（画像検索と、画面を描いて確かめる検索エンジンのため）。どちらも `Cache-Control: no-cache`（準備中と公開の切り替えをすぐ効かせる）
- 転送のミドルウェア（`FollowRedirects`）は店頭の群のいちばん内側（準備中の関所の内側）。準備中のショップでは、パスワードを入れた人にだけ効く
- slug を元へ戻した時（knit → knits → knit）: 今ある画面になった `/categories/knit` からの転送は消し、`/categories/knits` → `/categories/knit` を足す（「今ある画面を上書きしない」と「鎖を作らない」の両方から）
- 店頭の `Catalog::published()` を公開した（サイトマップが同じ条件で商品を選ぶため）。`Catalog` は 600 行を超えているが、並べて動いている仕事（税率・送料など）とぶつかるので、今回は分けない
- 管理画面のホストの `/robots.txt` は全部を止める（中身は決まった 2 行）。ほかの中央のホストは今のまま（`/` の疎通の確かめだけ）

## 結果

- 得たもの: どのテーマでも同じ見え方。テーマの作り手は SEO を知らなくてよい。乗り換えの店が前の URL の評価を引き継げる
- 失ったもの: テーマが `<head>` の題・説明を自由に作る道は、検索に載せない画面だけになる。前のショップの `.php` で終わる URL（`/products/detail.php?product_id=1` など）は、Web サーバー（nginx）が PHP のファイルとして断るので転送できない（要るなら nginx の設定を別に決める）
