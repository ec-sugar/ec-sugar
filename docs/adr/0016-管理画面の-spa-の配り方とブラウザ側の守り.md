# 0016 管理画面の SPA の配り方とブラウザ側の守り

状態: 採用（2026-10-27）

## 文脈

管理画面は Vue の SPA ＋ API（ADR 0013）、本番で Node.js を常駐させない（ADR 0015）。
管理画面は全テナントに立ち入れるいちばん強い権限の画面なので、XSS（店頭の入力が管理画面で動く）・CSRF・クリックジャッキング・
依存パッケージの乗っ取りの影響がいちばん大きい。片 C で画面を載せるにあたり、配り方と守りを決める。

## 決定

- **配り方**: Vite でビルドした静的ファイル（`public/build`）を、Laravel が管理画面のホストで返す HTML の殻（`ShellController`）から読む。殻にはデータも秘密も入れず、キャッシュさせない。殻を返す経路は画面の経路だけを列挙する（`routes/admin.php` と `resources/admin/router.js` の両方）。それ以外は 404
- **開発でも Vite の開発サーバーを使わない**（`make watch` でビルドし直す）。開発と本番で CSP が同じになり、「開発では動くが本番の CSP で止まる」が起きない
- **CSP**（`config/security.php` の `admin_csp`）: `default-src 'none'`、script / style / img / font / connect は `'self'` だけ。インラインの script・style、`data:`、外部のオリジンを許さない。`frame-ancestors 'none'`。枠（iframe）は読まない（→ 2026-10-30 に足した例外: ページの編集の画面の殻だけ、その店のショップのオリジン 1 つを `frame-src` に足す。真ん中のプレビューのため。ADR 0039 の区切り 2、`AdminSecurityHeaders::allowFrame`。ほかの応答は今も枠を読まない）。**Trusted Types**（`require-trusted-types-for 'script'; trusted-types vue`）で、DOM に HTML を書き込めるのを Vue の経路だけにする。Vue の `vue` ポリシーは HTML をそのまま通すので、画面のコードで `v-html`・`innerHTML` などを使わないことをテストで検査する（`AdminShellTest`）
- **WebAuthn はブラウザ標準の `parse*OptionsFromJSON` / `toJSON()`** で扱い、変換のライブラリを入れない（依存を増やさない）。対応していないブラウザには使えない旨を出す
- **CSRF**: Laravel 13 の検査をそのまま使う。`Sec-Fetch-Site: same-origin` ならトークン無しで通し、それ以外は `X-XSRF-TOKEN` を求める。**same-site を信用する設定（`allowSameSite`）と、トークンを使わない設定（`originOnly`）は有効にしない**。本番では店頭（shop.example.com）と管理画面（admin.example.com）が same-site になるため。テストで見張る
- **他サイトからの通信への応答では、セッションと CSRF の Cookie を返さない**（`ConfigureAdminSession`）。SameSite=Strict の Cookie はその通信に付かないので、サーバーが新しいセッションを作って返すと、ブラウザの本物のセッションが上書きされ、リンクを踏むだけで運営がログアウトさせられる
- **応答の扱い**: 401 はログイン画面へ（開こうとした画面を覚えて、ログイン後に戻す。戻り先は自分の画面の経路だけ）、419 は CSRF の Cookie を取り直して 1 回だけ再送、423 は本人確認の画面（パスキーの操作は利用者のクリックの直後でないと拒むブラウザがあるので、「確認」と「続ける」をそれぞれボタンにする）、429 は待つ秒数を出す。画面の出し分けは表示のためだけで、守るのはサーバーの認可
- **ブラウザの保存領域（localStorage など）を使わない**。ログインの状態の正本はサーバーのセッション
- **画面のテストは Playwright**（本物の Chromium ＋ Chrome の仮想の認証器）。サーバーは本物の PHP（`php artisan serve`）と専用の DB（`ec_e2e`）。CSP と Trusted Types の違反がブラウザに 1 件でも出たら落とす

## 結果

- 得たもの: 管理画面で XSS の穴を作っても、インラインのスクリプト・外部への送信・HTML の書き込みがブラウザに止められる（Trusted Types で止まることをテストで確かめた）。CSRF とセッションの上書きを本物のブラウザで確かめられる。パスキーの登録からログイン・本人確認・削除までを、サーバーの本物の検証で通しで試せる
- 失ったもの: Vite の開発サーバーの即時反映（HMR）は使わない（ビルドし直してブラウザを読み込み直す。ビルドは 1 秒未満）。Playwright のブラウザ（約 100MB）を開発機と CI に入れる。対応ブラウザは parse*FromJSON を持つもの（Chrome / Edge 129 以降、Firefox 119 以降、Safari は対応バージョン）に限る
- ビルド済みの JS は、nginx が管理画面以外のホストでも返す（接続元の制限も通らない）。中身に秘密は無いが、管理画面の API の形が読める（で塞ぐか決める）
