# 0039 ページは区画を積んで作り、本物のプレビューの横で編集する

状態: **採用**（2026-10-30。トップページ全体を WordPress のブロックエディターのような形で作りたい → 見本の A・B から A を選び、トップページ以外も同じ形・パソコンとスマホで同じ並び・レスポンシブは必須）。ADR 0028（テーマは区画を宣言し、核は汎用の値と写真を持つ）の区切り 4（ライブプレビューの編集の画面）と、残りの作業だった「ページビルダーとライブエディター」（2026-10-29）の形を決める。一部置き換え（→ ADR 0040・: 2 の「足せる区画はテーマが用意したものだけ」を、核の共通の区画〔`basic_*`。どのテーマでも置ける〕と App の区画も足せる形に。→ ADR 0041: 2 の「お店の人は HTML を入れない」を、カスタム区画の HTML に限って、保存と描くときに決まった形へ整えて許す形に。JavaScript は今も入れない）

## 文脈

- 今はテーマが区画（ヒーロー・商品の並び・カテゴリ・お知らせの帯など）を `theme.json` で宣言し、お店の人は「テーマの中身」の画面で各区画の値を入れる（下書きと公開）。区画を足す・消す・並べ替える・見ながら直す、はできない
- 2026-10-29 の望み: 区画を複数のパターンから組み合わせて 1 つのページを作る、HTML を知らないお客さんでもプロのような見た目に、ライブエディターが欲しい
- WordPress のブロックエディター（Gutenberg）のコードは GPL で、商用の二重ライセンス（ADR 0033）と合わない。React で、HTML を書き込み、インラインの style を多く使うので、管理画面の CSP と Trusted Types とも合わない。考え方と使い方だけを借りる
- 見本（「トップページの編集の画面 A・B」）で 2 つの形を並べた
  - A（3 列の型。他社の EC の SaaS でよくある形）: 左に区画の一覧、真ん中に本物のプレビュー、右に設定
  - B（WordPress 型）: ページの上に直接ブロックを打つ

## 決めたこと

1. **A（3 列の型）で作る**: 編集の画面は 3 列。左に区画の一覧（「＋ 区画を足す」・ドラッグで並べ替え・消す・区画の中の小さなブロック〔見出し・文・ボタンなど〕）、真ん中にショップと同じ描き方の本物のプレビュー（押すとその区画を選ぶ）、右に選んだ区画の設定。上に「パソコン・スマホ」の切り替え・下書きは自動で保存・「公開する」
2. **足せる区画はテーマが用意したものだけ**。区画の種類ごとに見た目のパターンをテーマが持つ（例: ヒーローは全面・左右・格子。2026-10-29 の見本）。お店の人は HTML も JavaScript も入れない（CONCEPT 7.2）。中身は JSON で、描くのはテーマの Blade（→ 一部置き換え: 核の共通の区画と App の区画は ・ADR 0040、カスタム区画の整えた HTML は ADR 0041）
3. **トップページ以外のページも同じ形**: 「私たちについて」・キャンペーン・お問い合わせなどの自由なページを、区画を積んで作る。ページの住所（スラッグ）と題とメニューへの載せ方はページごと。商品・カテゴリ・カート・注文の画面は今までどおりテーマの決まった画面（区画を足せる場所はテーマが宣言する）
4. **パソコンとスマホで並びは同じ**。スマホだけ別の並びにする仕組みは作らない
5. **区画はどれもレスポンシブ**（画面の幅に合わせて組み変わる）。テーマの区画の決まりに入れ、テーマの確かめ（テストとブラウザのテスト）でスマホの幅でも崩れない・横にはみ出さないことを見る。プレビューの「スマホ」はその幅で同じ描き方を見せる
6. **仕組みは核、区画の種類はプラグインも足せる**（2026-10-30。プラグインか核かを比べて選んだ）: 並べる仕組み・編集の画面・プレビューは核（どの店も使い、全テーマがこの上で描く。外せる部品にすると止めた時に全テーマのトップページが崩れる。他社の EC の SaaS・WordPress も本体）。レビュー・メールの登録・Instagram などの区画は、中身の仕組みごとプラグインが足せる（他社の EC の SaaS の App のブロック、WordPress のプラグインのブロックと同じ考え）。プラグインが種類を足す口は、区切り 4 の後にレビューのプラグインを作る時に足す
7. 区画の値は今の仕組み（店 × テーマ × バージョン、各バージョンに下書きと公開、改訂で同時の編集を断る）に、「区画の並び（どの種類を・どのパターンで・何番目に）」を足す。ページごとに並びを持つ

## 結果

- 見た目はテーマのデザインの中に収まり、崩れにくい。HTML を知らないお店の人でも、パターンを選んで並べるだけでページを作れる
- 自由度は B より低い（テーマが用意していない区画は置けない）。足りない区画はテーマかプラグインが足す
- 作る順（案、運営が決める）: ① 区画の並び（足す・消す・並べ替え・パターン）の核と API → ② 編集の画面（3 列・本物のプレビュー・押して選ぶ）→ ③ 自由なページ → ④ 公式テーマの区画をパターンつきに作り直す。ADR 0028 の 2d（親テーマ）と区切り 3（購入まわりを核へ）との順番も決める

## 作って決めたこと（2026-10-30、区切り 1「区画の並びの核と API」）

- **宣言の書き方**（theme.json。テーマ API 2 の付け足しで、バージョンは上げない）: `sections` は区画の「種類」の宣言のまま（キーが種類の名前）。種類ごとに `patterns`（パターンの名前 => `{ label }`、1〜6 個。書かなければ `default` の 1 つ）・`blocks`（区画の中の小さなブロックの種類 => `{ label, fields }`、1〜10 種類。欄は区画と同じ核の 7 種類）・`max_blocks`（1〜20、書かなければ 20）・`limit`（1 つのページに置ける数）を足せる。新しく `pages` を書けて、ページごとに `types`（置ける種類）と `default`（最初の並び。`{ type, pattern }` の並び）を持つ。ページは今は核が知っている `home` だけ（自由なページは区切り 3）。`pages` を書くなら `home` が要り、どのページにも置けない種類は登録で止める
- **今の書き方のテーマ**（`pages` を書かない。今の公式テーマ 4 つ）は、宣言した区画を宣言の順に 1 つずつ・パターン `default` で置いた「決まった並び」のトップとして読む（`fixed`）。値と隠す・出すは変えられ、足す・消す・並べ替えは断る（テーマの画面が `$sections->get('hero')` と名前で読むので、並びを変えても見た目に出ない）
- **値の持ち方**: バージョンの下書きと公開を `{ pages: { home: [ 区画, … ] } }` にした。区画は `{ id, type, pattern, hidden, values, items, blocks: [ { type, values } ] }`。ID は英小文字・数字・`_`・`-` の 40 文字まで（新しく足した区画には小文字の ULID をサーバーが付ける。最初の並びと今の値からの写しは種類の名前）。まだ保存していないページは、テーマの最初の並びを空の値で読む（空の並び `[]` は「区画を全部外したページ」で、別のもの）
- **上限（核の決まり）**: 1 ページ 40 区画・1 区画のブロック 20 個（テーマは小さくできる）・繰り返し 12 個（今まで）・1 つのバージョンの全体 256KB（今まで。ページが増えても全体で数える）。DB は関数 `sugar_theme_document_ok` の検査で、ページの名前の形・並びであること・40 区画・ID と種類とパターンの文字の形・ページの中で ID が重ならない・ブロック 20・繰り返し 12・全体 512KB を守り、前の形（`sections`）は受け付けない
- **読むときの直し**（テーマを更新して宣言が変わった時もショップを止めない）: 置けなくなった種類・ID の崩れた区画は外し、無くなったパターンは最初のパターンに戻し、無くなった欄・ブロックは捨てる。下書きは書き換えない（今までどおり、テーマを戻せば取り戻せる）
- **API**: `GET /api/tenants/{店}/themes/{テーマ}/pages/{ページ}`（宣言・ページの宣言・バージョン・下書きの並び）、`PUT …/pages/{ページ}/draft`（`version_id`・`revision`・`sections` の並びをまとめて置き換える）、`POST …/pages/{ページ}/publish`（公開はバージョンごと。すべてのページを今の宣言で読み直して出す）。権限は「テーマの中身」と同じ（読むのは閲覧、変えるのは運用）。誤りは道筋つきの 422（`sections.0.pattern` など）、同時の編集は 409
- **今の「テーマの中身」の API（種類 => 値）は残した**: 今の画面・今の値を写すコマンド・見本の店が使う。トップの並びの、種類ごとの最初の区画を読み書きする（決まった並びでは今までと同じ。並びのあるテーマでは、送らなかった種類の区画を外し、並びに無い種類を後ろに足す）。区切り 2 の編集の画面ができたら、画面はページの API へ移す
- **ショップ**: トップの画面に `$page`（`PageView`）を渡す。公開した順に、隠した区画とテーマに部品が無い種類を除いた区画が入り、それぞれ `view`（部品の名前）を持つ。部品は `sections/{種類}/{パターン}.blade.php`、無ければ `sections/{種類}.blade.php`。どちらも無い種類は描かずに飛ばす（お知らせの帯のように外枠が読む種類のため）。`$sections->get('種類')` はトップの並びの、その種類の最初の区画（すべての画面で今までどおり）
- **移行**: 今の値（`{ sections: { 区画: 値 } }`）はトップの並びへ写す。ID は区画の名前・パターンは `default`・ブロックは無し、中の値はそのまま。並びは入っているテーマの宣言の順（今のアプリが書く順と同じ）。下書きと公開が同じ ID で写るので「公開していない変更」の印も変わらない。何も入れていなかった値は「トップを保存していない」形にする
- **記録**: `theme.draft_saved` にページの名前と区画の種類の並び（文言は入れない）
- **レスポンシブ**（決めたことの 5）: 区切り 1 では核の仕組みは持たない（並びはパソコンとスマホで同じで、組み変わりはテーマの CSS）。テーマ API の文書に区画の決まりとして書き、確かめ（スマホの幅で横にはみ出さない）は公式テーマを作り直す区切り 4 でブラウザのテストに入れる

## 作って決めたこと（2026-10-30、区切り 2「編集の画面」）

- **画面**: `/tenants/{店}/theme/pages/home?theme=テーマ`（無ければショップで使っているテーマ）。入口は「テーマの中身」の画面のボタン。メニューを出さず画面の全体を使う（経路の `meta.fullscreen` と部品 `EditorLayout`）。並び方と部品は docs/design/admin-ui.md の「ページの編集の画面」
- **保存は自動**（決めたことの 1 のとおり）: 変えて 0.8 秒待つと並びを丸ごと下書きに保存する。「下書きを保存」のボタンは置かず、上の帯の印（保存中・保存していない変更・保存できなかった・下書き・公開中と同じ）で状態を見せる。送った後に打った分は答えで上書きせず、足した区画の ID だけを写す
- **プレビュー**: 店頭に下書きのプレビューの経路 `/preview/themes/{テーマ}/{ページ}` を足した（商品のプレビューと同じく署名つき・30 分・noindex・no-store・no-referrer・App なし・準備中の店の関所の外）。描くのはそのテーマのいつもの画面で、区画は使うバージョンの**下書き**（`$page` と外枠の `$sections` のどちらも）。店で使っていないテーマも開ける（切り替える前に用意できる）
- **枠の許し**: ショップ側は、この応答だけ `frame-ancestors` を管理画面のオリジン（`ADMIN_URL`）にし、`X-Frame-Options` を付けない。管理画面側は、編集の画面の殻にだけ、ログイン中でその店に入れる運営のとき、その店のショップのオリジンを `frame-src` に足す。SPA は画面を移る時に殻を読み直さないので、ほかの画面から編集の画面へは文書ごと読み直して入る。枠は `sandbox="allow-scripts allow-same-origin"`（フォームの送信・窓を開く・管理画面の窓を動かすは許さない）
- **押して選ぶ**: テーマは区画の部品のいちばん外に `data-section="{{ $section->id }}"` を置く（必須の決まりにした。theme-api.md）。店頭の核の部品 `resources/storefront/editor.js`（`cart.js` から読む）が、編集の印（`<x-storefront.apps>` が置く `data-sugar-editor`）のある画面でだけ動き、押した区画の ID を親へ postMessage する（送り先は管理画面のオリジンだけ）。管理画面は、そのリンクのオリジンから・その枠の窓から来た知らせだけを受ける。逆向き（左で選んだ区画）も同じ確かめで送り、核の CSS が輪郭（outline）を付ける。プレビューの中のリンク・ボタン・フォームは押しても動かない
- **決まった並びのテーマ**（今の公式テーマ 4 つ）: 一覧と設定は出し、足す・消す・並べ替え・ブロックの操作は出さない
- **ブラウザのテスト**: 公式テーマはまだ決まった並びなので、区画を並べられる見本のテーマ（`tests/Support/Themes/sample`）を、本番でない環境で `STOREFRONT_SAMPLE_THEME` を真にしたときだけ登録する（`config/storefront.php` の `sample_theme`。ブラウザのテストの環境だけが真にする）
- **区切り 3（自由なページ）への申し送り**: 経路（`router.js` の `theme-page`）は今 `pages/home` の決まった形。自由なページでは `:page` にし、殻の正規表現（`routes/admin.php`）と `ShellController` の形はもう `pages/{ページ}` を受ける。店頭のプレビューは `ThemePreviewController::PAGES`（ページの名前 → テーマの画面の名前）に足す。署名はページの名前を含むので、そのまま使える。画面の題は `page.label` から作っている

## 作って決めたこと（2026-10-30、区切り 3「自由なページ」）

- **住所**: ショップの `/pages/{slug}`（`/{slug}` は今の経路〔`/products`・`/cart`・`/p/…` のプラグイン・見つからない画面〕とぶつかり、経路を足すたびに店のページを壊しうるので選ばなかった）。slug は英小文字・数字・ハイフン（間だけ）の 60 文字まで。今ある経路の名前と、これから足しそうな名前（`products`・`cart`・`checkout`・`orders`・`password`・`preview`・`media`・`apps`・`legal`・`pages`・`p`・`api`・`admin` など 35 語。`ShopPage::RESERVED_SLUGS`）は使えない。`/pages/` の下ではぶつからないが、後で `/{slug}` の短い住所に移せるよう、また店の人が決まった画面と同じ名前で迷わないよう、先に取っておく
- **データの形**: 店の DB の表 `shop_pages`（`slug`・`title`・`in_nav`〔メニューに載せる〕・`position`〔並び順＝メニューの順〕・`status`〔`draft`・`published`〕・`deleted_at`〔ゴミ箱〕）。題と住所と公開の状態は店ごと（テーマを替えても残る）。中身（区画の並び）は今のテーマの値（店 × テーマ × バージョン）の中に、ページの名前 `page-{ID}`（ID は小文字の ULID）で持つ（DB のページの名前の形 `^[a-z][a-z0-9_-]{0,31}$` に収まる）。書くのは `ShopPageService`（`EventStore::lock()` → 行のロック → イベント `shop_page.created`・`updated`・`reordered`・`trashed`・`restored`。題は店の人の自由な文なので記録に入れず、slug と変えた項目の名前だけ）
- **守り**: slug の形・予約語は DB の制約でも断る（予約語の一覧はマイグレーションに書き写した。足すときは新しいマイグレーションで制約を作り直す）。重ならないことは、ゴミ箱でないページの一意の索引（`WHERE deleted_at IS NULL`）。ゴミ箱から戻すとき、同じ slug のページがあれば断る。1 つの店に 50 ページまで（ゴミ箱も数える。中身の置き場の数〔1 つのバージョンに 100 ページまで・全体 256KB〕を越えないため）
- **公開の状態**: ページが下書きなら、中身を公開していてもショップには出ない（「見つかりません」。下書きか無いかは見せない）。編集の画面の「公開する」は、中身の公開（バージョンごと）と、そのページを公開の状態にすることを 1 つのトランザクションで行う。一覧の「非公開にする」「公開する」は状態だけを変える（中身はそのまま）
- **テーマの宣言**: `theme.json` の `pages.page` が自由なページの雛形（置ける種類と最初の並び。`pages.home` と同じ書き方）。店の人が作ったページはどれもこの雛形を使う。**宣言しないテーマは核の汎用の区画**（`basic_text` 見出しと文・`basic_image_text` 写真と文・`basic_image` 写真・`basic_button` ボタン・`basic_products` 商品の並び。`CoreSections`）で作る（今の公式テーマ 4 つはこれ。区切り 4 を待たずにどのテーマでも自由なページを出せる方を選んだ）。核の汎用の区画は核の部品（`resources/views/storefront/sections/`）と核の CSS（`resources/storefront/sections.css`、テーマの色の変数・`:where()`）で描き、テーマは同じ名前の部品で描き直せる。雛形の `types` に核の汎用の区画を混ぜてもよい。テーマは `basic_` で始まる区画を宣言できない（登録で止める）
- **描き方**: テーマの画面 `page`（任意）に `$page`（`PageView`。`title`・`url` と区画の並び）。無ければ核の既定の画面 `storefront.page`（テーマの外枠の中に題と区画）。すべての画面に `$navPages`（公開していてメニューに載せるページ。`PageLink` の `title`・`url`・`current`）。準備中の画面では空。既定のテーマ（角砂糖）のヘッダのメニューに見本として入れた。App は差し込む（ふつうの画面）
- **公開の値の持ち方を変えた**: 公開するとき、下書きに値を保存したページだけを、下書きの順に写すようにした（前はテーマが宣言したページをいつも写していた）。自由なページだけを保存したバージョンで、まだ保存していないトップの最初の並びが公開の値に入り、「公開していない変更」の印がいつまでも消えなかったため。保存していないページは読むときにテーマの最初の並びになるので、ショップの見た目は変わらない
- **プレビュー**: `/preview/themes/{テーマ}/page-{ID}`（区切り 2 と同じ署名つきのリンク）。公開していないページも下書きの中身で描く。ゴミ箱・無いページは断る
- **管理画面**: メニューの「ページ」（`/tenants/{店}/pages`）で一覧・作る・題と URL・メニュー・公開と非公開・上へ下へ・ゴミ箱と戻す。「中身を作る」で区切り 2 の編集の画面（経路は `theme/pages/:page`）へ。戻るボタンはページの一覧へ
- **区切り 4（公式テーマの作り直し）への申し送り**:
  - 公式テーマのメニュー（`layout`）に `$navPages` を入れる（既定のテーマだけ済。kinari・fashion・botanica はまだ）。フッターに入れるかはテーマごとに
  - 公式テーマに `page` の画面を作るか（無ければ核の既定の画面で、題の見た目は核の CSS）。テーマの見た目に合わせるなら、`pages.page` の雛形と、核の汎用の区画をテーマの部品で描き直すかを決める
  - テーマを替えたときの中身と、ゴミ箱から完全に消す操作は、下の続きで作った

## 作って決めたこと（2026-10-30、「核の共通の区画 8 種類」）

- **由来**: 区画を足す欄をもっと充実させたい。世の中のセクションのデザインはパターンなので種類は多くない。デザインが得意でない人でもよいページを作れるようにする → 見本帳（13 種類・29 パターン・ページの雛形 6 つ）のうち「先に」の 8 種類を作った。残りの 5 種類（数字で見せる・ロゴの帯・手順と流れ・比べる表・余白と区切り）とページの雛形 6 つは

- **今の形（種類 => 値）の保存で外さない**: 「テーマの中身」の画面（`…/content`）はテーマの区画だけを送るので、並びのあるトップでは送らなかった種類が外れる（`SectionValues::fromKeyed`）。核の区画をトップに置けるようにしたので、送らなかった核の区画（`basic_*`）は外さずに残すようにした（その画面で保存しただけで、ページの編集の画面で足した区画が消えるのを防ぐ）
- **何も無ければ描かない**: 中身の要る所が空なら区画ごと出さない（ショップに空の箱や見本の文を出さない）。編集の画面のプレビュー（`$preview`）だけは、無地の枠と「…を入れるとここに出ます」の知らせを出し、押して選べるようにする
- **1 つの商品を大きく**: 商品は選ぶだけ（`products` の欄で `from: ["pick"]`・1 つ。新着から自動では選ばない）。店頭は選んだ ID を `Catalog::product`（公開中だけ）に直接渡して `ProductView` にする（ここが公開の関所。テストで、わざと公開に関係なく読む形にすると落ちることを確かめた）。選んでいない・下書きに戻した・消した・ほかの店の ID はどれも `null` で何も出さない（ページは落ちない）。「カートに入れる」と種類・オプションは商品の画面の核の部品をそのまま使う。種類の部品（`variants.js`）はページ全体の価格・写真の印を読むので、2 つ置くと互いの価格を書き換える。部品を区画ごとに閉じる直しはせず、**1 つのページに 1 つまで**（`limit: 1`）にした。カートに入れられなかったときの戻り先は前のページ（`back()`）で、区画の中に知らせ（`$flash['error']`）を出す。オプションの入れた値を戻す（`addonValue`）のは商品の画面だけ

- **お客さんの声に星は付けない**: 作り話のレビューに見えないよう、いただいた言葉と名前と属性だけ。見本の文も「ここにお客さんの声が入ります」の形。レビューの仕組み（注文した人だけが書ける・星）はプラグインのレビューで別に作る（決めたことの 6）
