# 0005 核 ＋ プラグイン機構

状態: 採用（2026-10-27）

## 文脈

WordPress 型の「基本システム ＋ プラグイン」で機能を増やしたい。一方で WP の脆弱性の大半は
プラグイン由来で、原因は「管理画面からコードが入る」「拡張点に互換性の約束がない」の 2 点。

## 決定

- プラグインは composer パッケージ。インストールは CLI / composer のみ。管理画面からのコード投入は将来も作らない
- マニフェスト必須（名前、バージョン、対応する核のバージョン、必要な権限、設定スキーマ、マイグレーション）
- 拡張点は 6 種類（イベント、フィルタ、取引の種類、ドライバ、管理画面、店頭）に限定し、Plugin API として semver 管理
- 自社の縦（買取・仕事・定期・店舗・マーケット）も核に入れず、同じ機構でプラグインとして実装する
- 外部プラグインの管理画面はサーバー駆動 UI（JSON で宣言し SPA が描画）のみ。JS 同梱は自社プラグインだけ

## 結果

- 得たもの: WP の利点（拡張性、配布と収益の場）を、WP の弱点なしで得る。更新時にプラグインの互換検査ができる（ADR 0006）。自社プラグインを先に書くことで拡張点の不足が早く分かる
- 失ったもの: 外部プラグインの管理画面の自由度。プロセス外プラグイン（Saleor の App 型）の併用は検討中
