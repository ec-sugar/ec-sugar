# 0023 店の人はパスキー、お客さんはメールのコードとパスキー

状態: 採用（2026-10-28）。未決だった「テナントのスタッフ（店の人）と顧客のログイン方式」を決める

## 文脈

運営のログインはパスキーだけ（ADR 0013）。SaaS 版の店主向けの管理画面（見方の違い）と、お客さんの会員（よくある EC の会員管理）を作るには、店の人とお客さんのログインの方式が要る。

- 店の人は、売上・お客さんの個人情報・お金の設定に触れる。乗っ取られたときの被害が大きい
- お客さんは、毎回のハードルが低いことが大事（面倒だと買わずに帰る）。一方でパスワードは、使い回し・総当たり・偽のサイトで盗まれる入口になり、AI で攻撃が安く速くなった（脅威モデル「AI の発達で増えた攻撃」）

## 決定

- **店の人（店主・スタッフ）はパスキーだけ**。最初の登録と端末の追加はメールで届くリンク（1 回だけ・短い期限）から。端末を全部なくしたときは、運営が登録のリンクを出し直す（運営の ADR 0013 の仕組みを店の人にも使う）
- **お客さん（会員）はパスワードを持たない**。メールに届く 6 桁のコード（1 回だけ・短い期限・試行の回数制限）で入り、対応した端末ならパスキーを任意で足せる。LINE・Google・Apple でのログインは後で足せる形にしておく（今は作らない）
- 会員にならずに買う（ゲスト購入）は残す。注文の照会は

## 結果

- 得たもの: どちらも漏れて困るパスワードが無い。店の人は偽のサイトに反応しない認証だけ
- 失ったもの・気をつけること: お客さんはメールの受け取りに頼る（届かない・迷惑メールに入る）。コードは偽のサイトに入力させられうるので、コードで入った会員の重要な操作（メールの変更など）は再確認を挟む。店の人がパスキーに不慣れな場合の案内が要る
