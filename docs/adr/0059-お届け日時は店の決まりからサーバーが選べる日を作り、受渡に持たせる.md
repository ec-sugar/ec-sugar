# 0059 お届け日時は、店の決まりからサーバーが選べる日を作り、受渡に持たせる

状態: **採用**（2026-11-05。運営が作ると選んだ。日本の店に特有）。

## 文脈

- 日本のネットの店では、お客さんがお届けの日と時間帯を選べるのがふつう。運送会社（ヤマト運輸・佐川急便・日本郵便）の送り状にも、配達の日と時間帯の欄がある
- 今の注文は、送り先は受渡（Fulfillment）に持つが、届く日の希望は持たない。配送の CSV の Appの README は「配達の日と時間帯は区切り 2（注文の入力に欄が要る）」としていた
- 選べる日は、店の発送の都合（発送までの日数・休み・締め切りの時刻）と配達の日数で決まる。選んだ後で日が変わると、選んだ日が間に合わなくなることがある

## 決定

1. **店の設定「お届け日時」**（`shop_settings.delivery_dates`、形は `App\Core\Shop\DeliveryPolicy`。変えるのは `DeliveryDates` だけ。連鎖のロックとイベント `shop.delivery_dates_updated`。値は個人情報を含まないのでそのまま記録に残す）
   - 日付の指定を受けるか（既定は受けない）
   - 受ける時間帯: 3 社のどこでも選べる共通の区分（午前中・14〜16・16〜18・18〜20・19〜21。`DeliverySlot`）から店が選ぶ。空なら時間帯は選べない。日付を受けない店でも時間帯だけは受けられる
   - 発送までの日数（営業日。0〜30）・お届けまでの日数（暦の日。0〜14。**今は全国一律の「最短 ◯日後」**。送料の地域〔〕とつなぎ、地域ごとの日数にするのは後）・選べる日数（1〜60）
   - 締め切りの時刻（その時刻を過ぎた注文は翌日の受付。空なら区切らない）
   - 休み（発送しない日）: 曜日（6 つまで。毎日休みは断る）と特定の日（120 日まで。年末年始・臨時）
2. **選べる日の決まり**（日本の時間 Asia/Tokyo で計算。サーバーの時計は UTC のまま）: 受付の日（注文の日。締め切りの後は翌日。休みなら次の営業日）→ 発送の日（受付の日から発送までの日数だけ営業日を数える。0 なら受付の日）→ 選べる最初の日（発送の日 ＋ お届けまでの日数。届く日は休みの日でもよい）→ 最後の日（最初の日から選べる日数の分）
3. **選ばない（指定なし）も選べる**。日付だけ・時間帯だけ・両方のどれでもよい
4. **注文の入力**: 核の部品 `<x-storefront::delivery-fields>` が `<select>` を出す（JavaScript なし。選択肢はサーバーが作る）。テーマは置くだけ。送られた値は 3 回確かめる: 入力の受け口（形と範囲。誤りは欄の下に）、確認の画面を出す時（範囲外になっていれば入力の画面へ戻して選び直し）、**確定の錠の中**（`PlaceOrder`。範囲外なら確定しない）。店が受けていないのに送られてきた値は使わない（欄を出していないため）
5. **受渡に持たせる**（`fulfillments.delivery_date`・`delivery_slot`。平文。個人情報ではない）。配送の受渡だけ（`FulfillmentService::create` と DB の制約の両方で守る。時間帯は DB でも区分の値だけ）。受渡を作るイベント `fulfillment.created` に `delivery` を残す（指定のある時だけ）
6. **見せる所**: 確認の画面・ご注文の状況・ご注文の確認と発送のメール（「お届け日時のご希望」）、管理画面の注文の「受渡」の表（「お届けの希望」）、配送の CSV の各社の配達の日・時間帯の欄（各社の区分の値で。クリックポストは指定が無い）
7. **贈り物では持たない**: 届く日は受け取る人が住所を入れた後に決まり、買う時に選んだ日は受け取りを待つ間に過ぎうる。注文の入力でも欄を隠し、サーバーも使わない。受け取る人が住所を入れる画面で選べるようにするのは後（贈り物の App の画面と、受渡に後から日時を入れる核の口が要る）
8. **定期便の回は持たない**: 回の日は定期便の周期で決まり（ADR 0049）、回ごとに選ぶ画面が無い。1 回目の申し込み（`PlaceSingleOrder`）も持たない。回ごとの希望は、定期便の側で決める時に別に考える

## 結果

- 得たもの: お客さんが届く日と時間帯を選べ、店は送り状に写せる（配送の CSV ならそのまま）。選べる日はサーバーが決めるので、改ざんした値や間に合わない日で確定しない
- 失ったもの: 地域ごとの配達の日数は持たない（遠い地域にも同じ最短の日を出すので、店はお届けまでの日数を遠い地域に合わせて決める）。確定の後にお届け日時を変える画面はまだ無い（お客さんから連絡があれば店が送り状で直す）

## 作って決めたこと

- **店の設定の列は核の設定のモデル（`ShopSettings`）に足さず、`DeliveryDates` が 1 列だけを読み書きする**（並べて作っている送料の細かい設定と同じファイルを触らないため）。崩れた値を読んだら「受けない」に倒す（ショップを止めない）
- **画面の誤りの名前は `delivery.date`・`delivery.slot`**。確定の後に範囲外になった時は、確認の画面へ戻した後に入力の画面へ送り、欄の下に「お選びのお届け日（…）は、今は選べません」を出す。店が受けるのをやめた後は欄が無いので、部品が理由だけを出す
- 管理画面の設定の画面は、保存した決まりで「今注文すると ◯から◯までを選べます」をサーバーが計算して返す（決まりの効き方を店の人が確かめられる）
- 時間帯の区分の値（`am`・`14-16` など）は核の値で、運送会社ごとの値（B2 の `0812` など）は配送の CSV の App が持つ（`CsvFormat::slotCode`。出どころと確かめが要る点は App の README）
- **お届け日を選んだ注文にはコンビニ払いを出さない**（2026-11-05、PR 89 の見直し。ADR 0058 の作って決めたことと組み）。時間帯だけの指定なら出す
- **確かめの画面の指紋にお届けの希望（日と時間帯）を入れる**（同じ見直し）。見せた希望と違う希望で確定させない（希望が変われば確かめの画面を出し直す）
