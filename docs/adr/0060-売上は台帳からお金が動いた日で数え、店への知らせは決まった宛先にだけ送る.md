# 0060 売上は台帳からお金が動いた日で数え、店への知らせは決まった宛先にだけ送る

状態: **採用**（2026-11-05。売上の集計と店への知らせを作ることは運営が「運営」の束として決めた。数え方と宛先の制限は作る時の案で、取り込んだ後、2026-11-05 夜に運営が採用にした）。ADR 0011（取引と仕訳）・0024（お金の段階）・0042（運営の様子）・0051（App の画面）・0054（クーポン）の上に置く

## 要点（先に）

1. 管理画面の「売上」（核）: 金額は**台帳から、お金が動いた日**で数える（入金は払った日、返金は返した日）。注文の数は**払いが確かになった日**。締めた期間の金額は後から変わらない
2. お金の段階（ADR 0024）の人だけ。期間は 366 日まで。CSV（日ごと・商品ごと）は式よけと監査ログ
3. App「店への知らせ」: 注文が入った・取り消された・在庫が少ないを、**Slack の Incoming Webhook（`https://hooks.slack.com/services/…` だけ）か店のメール**へ。個人情報は載せない。送るのはキューで、送れなくても注文は止めない

## 文脈

- 店の人が「今月いくら売れたか」「何が売れたか」を見る画面が無い。ホームの数（`ShopHome`）は今日と今月だけで、注文を受けた日で数え、取り消した注文を外す（運営の様子 ADR 0042 も同じ）
- お金の正本は台帳（ADR 0011）。取消・返金は逆仕訳か返金の仕訳で残り、決済代行に依存しない
- 注文が入っても、管理画面を開くまで気づけない。メールでお客さんに知らせる仕組み（`SendOrderMail`）はあるが、店の人への知らせは無い

## 決めたこと

### 1. 売上の数え方（`App\Admin\Services\SalesReport`）

- **金額は台帳から、お金が動いた時刻で数える**: 入金 = 支払いの仕訳（`payment`）のお客さんの口座の動き、返金 = 返金の仕訳（`refund`）。**売上 = 入金 − 返金**（税込みの円の整数）。日は日本の時刻（`app.display_timezone`）の日付
  - 返金は**返した日の期間**で引く。先月の注文を今月に返金すると、先月の売上はそのままで今月が減る。締めた月の数字が後から動かない（帳簿と同じ）。返金の多い日は売上が負になる
  - 採らなかった案: 注文の日で数え、取り消した注文を外す（ホームと運営の様子の形）。後の取消で過去の月の数が変わり、台帳の動きと合わない。ホームは「今月の様子」なのでそのままにし、ヘルプに数え方の違いを書いた
- **注文の数は、払いが確かになった時刻（その注文の最初の支払いの仕訳）の期間**。夜中に注文して日付が変わってから払われた注文は、払った日に入る。後で取り消した注文も数え、「うち取消・返金」を添える（今の状態で数えるので、この数だけは後で増える）
- **0 円の注文**（0 円の品・クーポンで 0 円）は支払いの仕訳が無いので、受け付けた時刻（`created_at`。0 円の注文は受けたその場で確定する）で数える。取り消した 0 円の注文は数えない（お金が動かない）
- 数える取引は物販（`sale`）・円・お客さんが払う向き。**テストの注文**（Stripe のテストのモードで払われた。`ShopHome` と同じ見分け方）は入金・返金・件数のどれにも入れず、件数だけを別に返す
- 平均の注文額 = 入金 ÷ 注文の数（1 円未満は切り捨て）
- クーポンの値引き = 数えた注文の使った記録（`coupon_redemptions`、払われずに消えたものを除く）の額。送料無料の分も含む（送料無料は値引きの行を作らないため。ADR 0054 の作って決めたこと）。送料 = 数えた注文の送料の行
- 商品別 = 数えた注文のうち、今も取り消されていないものの品の行（数と行の額。オプションの料金と値引きの割り振りの前）。商品名は今の名前（消した商品は注文の時の名前）
- 新しいお客さん・また来たお客さん = 期間に数えた注文のお客さんの台帳（ADR 0044。まとめた記録はまとめた先の 1 人）ごとに、期間より前に数える注文があったかで分ける。台帳につながらない注文は件数だけ
- 1 回の画面の数の時点をそろえるため、読むだけの REPEATABLE READ のトランザクションで読む

### 2. 期間と重さ

- 期間は 今日・今週（月曜から）・今月・先月・好きな期間（始まりと終わりの日）。**長さは 366 日まで、終わりは今日まで**（`SalesPeriod`。超えたら 422）
- 台帳の仕訳を時刻の範囲で引くため、`ledger_journals` に **`(type, occurred_at)` の索引**を足した（店の DB の移行 `2026_11_05_000100`）。索引が使えることはテストが EXPLAIN で確かめる。明細は `(transaction_id, account)` の索引で引く（`journal_id` の索引は無いので、取引の ID も合わせて結ぶ）。0 円の注文は今の `(kind, created_at)` の索引
- 店の文脈の中だけで読み、店をまたがない（中央へは何も置かない）

### 3. 権限と書き出し

- 経路は `GET /api/tenants/{店}/sales` と `/sales/csv`、どちらも **`tenant-level:money`**（お金の段階。運用・閲覧は 403）。メニューの「売上」もお金の段階の人にだけ出す
- CSV は日ごと（日付・注文の数・入金・返金・売上。何も無い日も 0 の行）と商品ごと（商品 ID・商品名・数・金額）。UTF-8 の BOM つき・CRLF。商品名は式よけ（`CsvCells::neutralize`）。書き出したことを中央の監査ログに `operator.sales_exported`（何を・期間・行の数だけ）
- 返すのは数と商品名だけで、お客さんの名前・連絡先は返さない（人数だけ）

### 4. 店への知らせ（App `plugin-shop-notify`）

- **知らせる出来事**: 注文が入った（核の `PaymentConfirmed`。0 円の注文の受付も）、注文が取り消された・返金された（取引の段が `cancel`・`refund` に移った物販で、支払いの仕訳があるか 0 円のもの。払われずに消えた注文は知らせない）、在庫が少なくなった（ショップで買える種類の「在庫 − 確保」がしきい値以下。種類ごとに 1 回、しきい値より多く戻ったら印を消してまた 1 回）。それぞれ切り替えられる
- **中身に個人情報を入れない**: 注文番号・金額・品数・商品の名前・管理画面へのリンクだけ。記録（`shop_notify_notices.facts`）にも同じものだけ
- **宛先は 2 つだけ**:
  - Slack の Incoming Webhook。**`https://hooks.slack.com/services/<英数字>/<英数字>/<英数字>` の形だけを受ける**（App の設定の形の決まりで保存の時に、`ShopNotifySettings::SLACK_URL` で送る直前にもう一度）。転送（リダイレクト）は追わない、待つのは 5 秒まで。任意の URL へサーバーから送らせない（サーバーから外への要求の悪用〔SSRF〕・店の人のなりすましの宛先を防ぐ）
  - 店のメール（知らせを受けるアドレス 1 つ）
  - どちらも App の設定の**秘密の項目**（店の鍵で暗号化、画面には「入っているか」だけ）。キューの仕事にも記録にも宛先を写さない（仕事は種類と ID だけを持ち、送る時に店の中で読む）
- Slack の書式の特別な文字（`&` `<` `>`）は逃がす（商品名で全員への呼び出し `<!channel>` やリンクを作らせない）
- **送るのはキュー**（`SendShopNotice`）。核の知らせの受け手は仕事を載せるだけで、誤りは報告して外へ出さない（注文・在庫の操作の答えを変えない、ほかの受け手を止めない）。同じ知らせは宛先ごとに 1 回（`kind × dedupe_key × channel` の一意と行のロック）。5xx・429・つながらない・メールの誤りは時間をおいて 3 回まで、4xx はやり直さない
- 管理画面の App の画面に送った知らせの一覧（状態・宛先の種類・理由）と「試しに 1 通送る」（運用の段階から、店ごとに 10 分に 5 回まで）。送れなかった知らせが 24 時間以内にあればホームの「やること」に出す
- 記録の行と在庫の印（`shop_notify_stock_marks`）は「送った記録」で、連鎖のロックとイベントの決まりの例外（conventions.md の 3。状態でもお金でも在庫でもなく、イベントが要らない）
- **LINE は作らない**（LINE Notify は提供が終わった。作るなら Messaging API。README に候補として書いた）

## 結果

- 得たもの: 台帳と同じ数字で売上を見られ、締めた期間が動かない。CSV で会計に渡せる。注文と在庫切れにすぐ気づける
- 失ったもの・気をつけること:
  - ホームの「今月の売上」（注文の日・取消を外す）と、ここの「今月の売上」（お金の日・返金を引く）は少しずれる（ヘルプに書いた）
  - 「うち取消・返金」と商品別は今の状態で数えるので、締めた期間でも後の取消で変わる
  - 一部返金（ADR 0048）が入ると、返金は台帳の返金の仕訳のまま正しく引かれるが、商品別は行ごとの返金をまだ引かない（返金の行ができたら引く）
  - 消費税の額は出していない（税込みの額だけ）。税率ごとの内訳は軽減税率と一緒に
  - Slack の Webhook の URL を持つ人は、その Slack の場所へ書き込める。URL は暗号化して置き、画面に出さず、記録・ログ・キューに写さない
