# 0028 テーマは区画を宣言し、核は汎用の値と写真を持つ

状態: **採用**（2026-10-28。決めてほしいことはすべて決まった）。ADR 0018（店頭は Blade とテーマのパッケージ）のテーマ API を 2 に上げた。ADR 0020（サードパーティのテーマ）とつながる。一部置き換え（→ ADR 0040・: 6 の「プラグインの区画は、テーマが宣言した場所にだけ置く」を、どのテーマでも置ける核の共通の区画〔`basic_*`〕と、店が App を使うと決まった並びでないページ〔トップと自由なページ〕に置ける App の区画に）

## 文脈

テーマを 3 つ（fashion・botanica・既定テーマの作り直し）作って、同じ壁に当たった。

- **区画が服向けで核に固定されている**: トップの区画（`HomeSections`）は「カテゴリ・コーディネート・人気・季節の特集」と決まっていて、植物のテーマは「コーディネート」を右の特集に読み替えた。管理画面の項目の名前と、実際の見え方がずれる
- **テーマが増えるたびに核が太る**: 既定テーマの作り直しでは、トップの見本どおりに描くために、核の店の設定に「説明の写真 2 枚・英字の一言・Powered by・ヘッダのカテゴリ」を足す案（別窓のパッチ）になった。テーマごとにこれをやると、核の店の設定がどのテーマにも要らない項目だらけになる（基本の機能から切り分けられるものは切り分け、余計なものを核に足したくない）
- **写真の置き方がちぐはぐ**: ヒーローの写真だけは店の設定の専用の欄、特集の写真は商品の写真を借りる（商品を取り下げると特集の写真も消える）。店の紹介やキャンペーンの写真を、商品から離れて置けない（店の設定の中で写真をあれこれ管理する形は筋が悪い）
- **購入の画面がテーマごとの写し**: カート・注文の入力・確認・完了・ご注文の確認は、見た目の差が小さいのに各テーマが写しを持つ。項目を直すたびに全テーマを直すことになる
- **選ぶときに完成形が分からない**: テーマは名前で選ぶだけで、見本の写真もプレビューも無い

## 決めたこと

> 決めたこと（2026-10-28）: テーマごとにやりたいことは異なるので、核の側にテーマ用の設定を用意しない。**核は、どのテーマ用の設定の項目も持たない**。核が持つのは汎用の道具だけ（欄の種類、値をしまう場所、宣言から画面を作る仕組み、ショップの写真の置き場）。どんな設定があるかは、各テーマが自分で宣言する。

### 1. 核は「店の事実」だけを持つ

店の名前・特定商取引法の表記・送料・注文の案内（届く目安・返品）は、どのテーマでも同じ意味なので核に残す。**見せ方のための項目（お知らせの帯・ヒーロー・特集・コーディネート・説明の写真・一言など）は、どれも必須ではないので核の店の設定から外し、テーマの区画にする**。

### 2. テーマは「区画」を宣言し、核は汎用の値を持つ

- テーマはパッケージの中の **`theme.json`**（コードでなく決まった形のデータ。2026-10-29）で、トップなどに置く**区画**と、区画ごとの**欄の形**を宣言する。欄の種類は核が決めた 7 つだけ: 文（1 行・複数行）・写真（下の 3）・リンク（店の中の道筋か https の URL）・商品の並び（新着・カテゴリ・選んだ商品）・カテゴリの並び（今のテーマの「カテゴリから探す」のため、区切り 2a で足した）・選択肢。「人気」は売れた数を数える仕組みができてから足す
  - 例（植物のテーマ）: `hero`（見出し・文・写真）、`features`（1〜3 個。題・文・写真・リンク）、`rail`（題・商品の並び）
- 核は値を、店ごと・テーマごとに、宣言された形で確かめてから保存する（長さ・種類・数。テーマが嘘の形を言っても、核の部品の決まりは越えられない）
- **管理画面は宣言から欄を作る**（サーバーが形を決める画面。プラグインの設定と同じ仕組みにする）。つまり**テーマごとに違う設定画面が、そのテーマの宣言どおりに出る**（テーマごとに違う設定の画面が要るため）。新しいテーマを作っても、管理画面と核を直さなくてよい
- テーマを切り替えると、そのテーマの値に切り替わる（前のテーマの値は残る）。同じ種類の区画（`hero` など）は、初めて切り替えたときに写して始められるようにする

### 3. 写真は「ショップの写真」に置く（商品の写真と分ける）

- 店ごとの写真の置き場（`shop_media`）を作り、商品と関係なく上げて、区画の写真の欄から選ぶ。作り直し（大きさ・形式・位置情報などを消す）は今のヒーローの写真と同じ。配り方は `/media/shop/{id}/{大きさ}` で、**置き場に今ある写真だけ**（使っていない写真も ID を知れば見える。ID は推測できない ULID で、出るのはその店の管理画面だけ。発表前の写真は ID が漏れれば見える、を受け入れる。区画の値から「使っている写真」を配るたびに引くのは重く間違えやすいため。ショップから見えなくするには削除する）
- 写真を「使っている所」は、ヒーローは外部キーで守る。区切り 2 の区画の値（JSON）は外部キーで守れないので、使っている所の確かめ（`ShopMediaService::usageMap`）を区画の値（下書き・公開・すべてのバージョン）まで広げ、削除と同じロックの中で数える
- 今のヒーローの写真は、ここへ移す
- 管理画面では、店の設定の中でなく**独立した「写真」の画面**に置く（WordPress のメディアと同じ置き方。2026-10-29）。置けるのは写真だけ。PDF などは要る場面が出てから（配るときの守りを足して）
- 商品の写真は今までどおり商品の持ち物（取り下げた商品の写真は出ない、を保つ）

### 4. 購入の画面は核が持ち、テーマは見た目の値で整える

- カート・注文の入力・確認・完了・ご注文の確認は、核が中立の画面（Blade の部品）を持つ。テーマは持たなくてよい（持てば上書きできる）
- テーマは色・文字・角の丸みなどの**見た目の値**（CSS の変数）を宣言し、核の画面はそれで整う
- テーマが必ず持つ画面は、外枠（layout）・トップ・商品の一覧・商品の詳細・エラーだけにする
- **動きの部品も核が持つ**（2026-10-28）: 出てくる動き（スクロールで現れる）・ページの移り変わり（View Transitions）・写真のスライダーを、核の CSS と JavaScript（`cart.js` と同じく自分のオリジンだけ、Trusted Types のまま、JS が無くても中身は読める）にする。テーマは `data-` の印と「動きの強さ」の見た目の値を出すだけで、編集の画面から入り切りできる。動きを減らす設定（prefers-reduced-motion）の人には止める。公式テーマは自分の JS も持てる（ADR 0020 のまま。外部の CDN とインラインは CSP で断る）

### 5. テーマを選ぶ前に見られる

- テーマのパッケージに見本の写真（画面の写し）と、見本の値（区画の中身）を入れる
- 管理画面のテーマの選び方は、見本の写真つき。選ぶ前に「プレビュー」で、その店の商品と見本の値で描いた画面を、運営だけが見られる（お客さんには出ない。署名つきの短い期限）

### 6. プラグインも区画を差し込める

- プラグイン（よくある質問など）は、区画の種類を足せる。テーマは「ここにはこの種類を置ける」と宣言した場所にだけ置く。プラグインを使わない店では出ない（ADR 0025 のまま）
- → 置き換え（ADR 0040）: App の区画は、店がその App を使うとき、テーマの宣言に核が足す（決まった並びでないページの置ける種類の後ろ）。テーマが場所を宣言しなくても置ける。核の共通の区画（`basic_*`）も、どのテーマのトップと自由なページにも置ける。「使わない店では出ない」はそのまま

### 5′. ライブプレビューで編集する（2026-10-28。写真の差し替えもライブプレビューから簡単にできるように）

- 編集の画面は、左に宣言から作った欄、右にその店の本物のショップの画面（プレビュー）。右の区画を押すと左にその区画の欄が開く。写真の欄は「ショップの写真から選ぶ／新しく上げる」
- 変えるとすぐ右に映る。描くのはサーバー（区画ごとに描き直す。本番で Node.js を常駐させない、ADR 0015 のまま）
- **区画の値は下書きと公開の 2 つを持つ**（区切り 2 から）。編集は下書きに入り、「公開」を押すまでお客さんには出ない。プレビューは運営だけ、署名つきの短い期限、検索に出さず控え（キャッシュ）に残さない。ショップの画面を埋め込めるのは管理画面だけ、画面同士のやりとりは相手の場所（オリジン）を確かめる

### 5″. テーマを元にしたカスタムテーマ（2026-10-28）

- **店の人（コード無し）**: テーマを「複製」して名前つきのバージョンを作れる（例「botanica 春のセール」）。バージョンは元のテーマの区画の値・並び・写真・見た目の値（色・文字・角の丸み）だけを持つ。編集の画面（5′）で、バージョンの複製・切り替え・公開ができる。区画の値は「店 × テーマ × バージョン」で持ち、各バージョンに下書きと公開がある（区切り 2 からこの形）。管理画面でテーマのコードを書き換える形は作らない（CONCEPT 7.2）
- **制作会社（コードあり）**: テーマの約束（テーマ API 2）に「親テーマ」と、親のバージョンの範囲を足す。子テーマは変えたい画面と宣言だけを持ち、無い画面は親から探す。公式テーマと同じ composer の形で、同じレビューの扱い。よその作者の子テーマは ADR 0020 の形式ができてから
- 親を更新しても子が壊れないよう、子の宣言は親の宣言に足すか上書きするだけにし、親のバージョンの範囲を外れたら使えない（一覧で知らせる）

### 「テーマビルダー」について

このあとに作れる「テーマビルダー」は、**テーマが許した区画を並べ替え、中身を入れる**もの（コードは書かない・入れない。CONCEPT 7.2 と ADR 0005 のまま）。上の 2・3・5 ができれば、その上に並べ替えとプレビューを足すだけになる。

## 区切り

1. ショップの写真の置き場（`shop_media`）と、ヒーローの写真の移し替え
2. 区画の宣言・値の保存（店 × テーマ × バージョン、各バージョンに下書きと公開）・管理画面の欄の自動生成（テーマ API 2。親テーマを含む）。今の 3 つのテーマを移す。今の `HomeSections` と店の設定の見せ方の項目を移して外す
   - 2a: `theme.json` の読み込みと確かめ・値の保存（バージョン・下書き・公開）・管理の API・ショップへの受け渡し・写真の使っている所の確かめを区画の値まで。テスト用のテーマで確かめる（今の値の写しを 1 回で済ませるため、テーマの移し替えは 2c にまとめた）
   - 2b: 管理画面の欄の自動生成と、独立した「写真」の画面。作った画面をすぐ見られるように fashion を移し（開発の demo の店が fashion）、店の設定の今の値を区画へ写すコマンドを作った
   - 2c: 残りのテーマ（kinari・default）を移す・店の設定の見せ方の項目を外す・テーマ API 1 をやめる。外した値は消さずに控えの表（`legacy_storefront_settings`）へ移し、区画のテーマへ初めて切り替えたときに写す（区画の無い既定のテーマを使う店の中身も、テーマを作り直した後に写せる。2026-10-29）
   - 2d: 親テーマ（区切り 2 の残り）
3. 購入の画面を核へ（見た目の値）。テーマの写しを消す
4. ライブプレビューの編集の画面（5′。バージョンの複製・切り替え・公開も、5″）と、見本の写真・見本の値（5）。このあと botanica と既定テーマの作り直しを仕上げる（2026-10-28）
5. プラグインの区画（の「よくある質問」をこの上に）
6. テーマビルダー（区画の並べ替え）

保管中のブランチ（`worktree-theme-default-a2`・`wip-botanica`）と別窓のパッチ（`storage/app/proposals/`）は、区切り 1〜3 の後に、新しい形に合わせて作り直す（パッチの ADR の番号 0027 は、main の 0027（返金）とぶつかっているので使わない）。

## 結果

- 得たもの: 新しいテーマは「区画の宣言・必須の画面・見た目の値」だけで作れ、核と管理画面を直さなくてよい。写真は商品から離れて置ける。購入の画面の直しが 1 か所で済む。選ぶ前に見られる
- 失ったもの・気をつけること: テーマ API を 2 に上げるので、今の 3 つのテーマを作り直す。区画の値をテーマごとに持つと、切り替えのたびに入れ直しが要る（初回の写しで和らげる）
