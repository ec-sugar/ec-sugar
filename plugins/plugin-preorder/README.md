# App「予約販売」（plugin-preorder）

発売日の前の商品を、在庫によらず予約で受ける EC-SUGAR 公式の App（ADR 0073）。お支払いは注文の時で、お金・支払い・返金・メールはいつもの物販の流れのまま。発売日の前は、予約の品のある注文を発送できない。

## 使い方

1. 管理画面のメニュー「App」で「予約販売」を使うにする
2. 商品の画面の App の欄「予約販売」で「予約販売にする」を入れ、発売日（`2026-11-20` の形。明日から 2 年先まで）を入れる。必要なら予約の締切日（その日まで受ける。発売日より前の日）と予約の数の上限（1〜100,000。空なら上限なし）
3. ショップの商品の画面とカートに「予約商品（11月20日ごろ発送）」、ボタンは「予約する」。発売日からはふつうの在庫の販売に戻る
4. メニュー「App」の下の「予約販売」で、予約の数・上限・発売日を見て、1 件の「直す」で発売日を変える（予約したお客さんへメールで知らせる）
5. 発売日になると、ホームのやることに「発送を始められる予約の注文」が出る。注文の画面からいつもどおり発送にする

## 決まり

- **在庫**: 予約の品は在庫を押さえず、発送しても在庫の数を減らさない。予約の数は App が数える。発売日の後のふつうの販売の在庫には、届いた数から予約の分を除いた数を入れる
- **混ざったカート**: 予約の品とふつうの品・発売日の違う予約の品は、分けずにいちばん遅い発売日にまとめて送る（送料は今のまま。方法の違う品は今までどおり便で分ける）。お届け日時の指定は受けない
- **上限と受付の終わり**: 注文を作る錠の中で数え直す（同時の注文でも超えない）。払われずに消えた・取り消した注文の分は戻る。受付の終わりはその日の 23:59:59 まで（日本の時間）
- **発売日を変える**: 発送の前の予約の注文と、その受渡の発送を始める日も直す（発売日を過ぎても、発送の前の注文が残っていれば延ばせる。同じ回の続き）。まとめて送る日が変わったお支払い済みの注文のお客さんへ、日の変わった商品と前の日・新しい日をメールで（キューで 1 通ずつ。名前とお届け先は載せない）。今日にすると、その場で発送できる。上限は今の予約の数より下げられない
- **次の予約**: 発売日を過ぎて発送も済んだら、App の画面の 1 件で「次の予約を始める」を押してから新しい発売日を入れる（前の予約を数えなくなる）
- **ほかの仕組み**: 再入荷のお知らせ・在庫の少ない知らせ・ホームの在庫切れは予約の商品を在庫と見ない。ホームの発送を待つ注文と配送の CSV の書き出しは発売日の前の予約の注文を入れない。商品フィードは `preorder` と発売日、JSON-LD は PreOrder。お客さんの注文のメール・ご注文の状況・マイページに発送の予定
- **取り消し**: お客さんは店に連絡し、店の人が注文の画面の「注文を取り消す」で全額を返金する（お客さんの自分での取消は無い）
- **やめる**: 商品の画面の欄で外すと、すぐにふつうの在庫の販売に戻る。受けた予約の注文は発売日から発送できる。App を使うのをやめても同じ（発送を始める日は注文に残る）
- **ポイント**: いつもどおり発送の時に付く

## 表

店の DB の `preorder_listings`（商品ごとの決まり。消さずに止める。回は始め直すたびに進む）と `preorder_items`（注文ごとの予約の数と約束した発売日）。個人情報は持たない。

## まだしないこと

- 予約の品とふつうの品を分けて送る
- お客さんの自分での予約の取消
