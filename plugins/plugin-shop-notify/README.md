# 店への知らせ（EC-SUGAR の App）

注文が入った・取り消された・在庫が少なくなったを、お店の人へ Slack かメールで知らせる App です（ADR 0060 の 2）。知らせにはお客さんの名前・住所・メールアドレス・電話番号を載せず、注文番号・金額・品数・商品の名前と、管理画面へのリンクだけを送ります。

## 使い方（お店の人）

1. 管理画面の店のメニュー「App」から「店への知らせ」を開き、「使う」にします。
2. App の設定に宛先を入れます（どちらか、または両方）。
   - **Slack の Webhook の URL**: Slack で Incoming Webhook を作り、`https://hooks.slack.com/services/` で始まる URL を入れます。**ほかの宛先の URL は受け付けません**。
   - **知らせを受けるメールアドレス**: お店の人のアドレスを 1 つ。
3. 知らせる出来事（注文が入った・取り消された・在庫が少なくなった）と、在庫が少ないとみなす数（売り切れた時だけ・1・3・5・10・20 点以下。既定は 3 点以下）を選んで保存します。
4. メニューの「App」の下の「店への知らせ」の「テストで 1 通送る」で、届くかを確かめます（10 分に 5 回まで）。

- 入れた URL とアドレスは店の鍵で暗号にして置き、画面には「入っています」とだけ出します
- 送った通知は「店への通知」の一覧に並びます（通知・通知先の種類・送れたか・送った日時）。送れなかった通知が 24 時間以内にあると、ホームの「やること」に出ます
- 知らせが送れなくても、注文・在庫の操作は止まりません

## いつ知らせるか

| 知らせ | いつ | 中身 |
|---|---|---|
| 注文が入った | お支払いが確かめられた時（核の `PaymentConfirmed`）。0 円の注文は受け付けた時 | 注文番号・金額・品数・注文へのリンク |
| 注文が取り消された | 取引の段が取消・返金に移った物販のうち、お支払いの仕訳がある（0 円の注文も）もの。払われずに期限切れで消えた注文は知らせない | 同じ |
| 在庫が少なくなった | ショップで買える種類の「在庫 − 確保」がしきい値以下になった時。種類ごとに 1 回で、しきい値より多く戻ったら印を消し、また減ったらもう 1 回 | 商品名（種類）・買える数・しきい値・商品へのリンク |

同じ知らせを同じ宛先へ 2 回送りません（Webhook と問い合わせの両方で払いを確かめた時など）。

## 守り

- Slack の宛先は `https://hooks.slack.com/services/<英数字>/<英数字>/<英数字>` の形だけ。保存の時にマニフェストの形の決まりで断り、**送る直前にも `ShopNotifySettings::SLACK_URL` でもう一度確かめる**。転送（リダイレクト）は追わず、待つのは 5 秒まで（任意の URL へサーバーから送らせない）
- Slack の書式の特別な文字（`&` `<` `>`）は逃がす（商品名で `<!channel>` の呼び出しやリンクを作らせない）
- キューの仕事（`SendShopNotice`・`CheckLowStock`）は種類と ID だけを持ち、宛先も中身も持たない。記録（`shop_notify_notices`）にも宛先を写さず、送れなかった理由は決まった言葉だけ（相手の答えは残さない）
- 核の知らせの受け手は仕事を載せるだけで、誤りは報告して外へ出さない
- 送れなかった時: 5xx・429・つながらない・メールの誤りは時間をおいて 3 回まで（60 秒・300 秒）。4xx（Webhook を消した・止められた）はやり直さない（URL を入れ直す）

## 作り

| ファイル | 役 |
|---|---|
| `database/migrations/…_create_shop_notify_tables.php` | 店の DB の表 `shop_notify_notices`（宛先ごとに 1 行。`kind × dedupe_key × channel` の一意）と `shop_notify_stock_marks`（在庫が少ないと知らせた種類の印） |
| `src/ShopNotifyServiceProvider.php` | 核の知らせ（`PaymentConfirmed`・`PaymentAwaiting`）と記録（取引の段の移り・入庫・在庫の調整）を、名前のある受け手（`EventReceivers`。`shop-notify.*`。落ちたら届け直す・App を止めている間の記録は届けない。ADR 0089）で受けてキューに載せる。App の登録 |
| `src/ShopNotifySettings.php` | 設定を読む（切り替え・しきい値・宛先。宛先は送る直前に形をもう一度確かめる） |
| `src/ShopNotices.php` | 中身の材料（個人情報なし）と文、宛先ごとに送って記録する |
| `src/LowStock.php` | 在庫が少なくなったかを見て、印を付けて 1 回だけ知らせる |
| `src/Jobs/SendShopNotice.php`・`src/Jobs/CheckLowStock.php` | キューの仕事 |
| `src/Mail/ShopNoticeMail.php` | お店の人へのメール（文字だけ） |
| `src/ShopNotifyAdminPage.php` | 管理画面の App の画面（送った通知の一覧と 1 件・「テストで 1 通送る」） |

テストは `tests/Feature/Plugin/ShopNotifyAppTest.php`（宛先の制限と 2 枚目の守り・個人情報が無い・1 回だけ・送れなくても注文が通る・取消は受け付けた注文だけ・在庫の印・使わない店・試しの 1 通と回数の上限と段階）。

## LINE は候補（今は作らない）

LINE Notify は提供が終わったため、LINE へ送るなら **LINE の Messaging API**（公式アカウントのチャネルのアクセストークンと、通知先のユーザー ID・グループ ID）になる。宛先は `https://api.line.me/v2/bot/message/push` に固定でき、トークンは秘密の項目に置ける。通知先の ID の取り方（友だち追加の Webhook を受ける口が要る）を決めてから足す。
