# お問い合わせ（EC-SUGAR の App）

ショップにお問い合わせのフォームを置く App です。届いたお問い合わせは管理画面で読み、メールでお返事できます。
核の口（プラグインの表・商品の画面の買い方の口・ご注文の画面のリンクの口・App の画面）だけで作っています（ADR 0025・0050・0051）。

## 使い方

1. 管理画面の店のメニュー「App」から「お問い合わせ」を開き、「使う」にします（運用の段階・直前の再確認）。設定は 2 つ:
   - **知らせを受け取るメールアドレス**: 新しいお問い合わせが届くと、このアドレスへ「新しいお問い合わせが 1 件あります」と管理画面のリンクを送ります（本文・名前・メールは載せません）。空なら送らず、管理画面のホームの「やること」にだけ出します。店の鍵で暗号化して置く秘密の項目です
   - **対応済みのお問い合わせを削除するまでの期間**: 半年・1 年（最初の値）・3 年
2. ショップのフォームは `/p/contact` です（メニューやページのリンクに置きます）。商品の画面には「この商品について問い合わせる」（売り切れでも出ます）、ご注文の画面（ご注文の確認・マイページの注文の履歴）には「この注文について問い合わせる」が出て、商品・注文を付けてフォームを開きます。
3. お客さんは種類（商品について・ご注文について・そのほか）・お名前・メール・内容（2,000 文字まで）を書いて送ります（JavaScript を使わないフォーム）。ログインしている会員は、メールの欄が無く、ログインのメールで受けます。
4. お客さんには受付確認のメール（受付番号つき）が届きます。
5. 管理画面のメニュー「App」の下の「お問い合わせ」で一覧（新着・対応中・済み・すべて）と 1 件を見て、「返信する」の欄からメールで返信します。済んだら「済みにする」。

- 使うのをやめると、ショップのフォーム・商品の画面とご注文の画面の入口・管理画面の画面は出ません（届いたお問い合わせは残り、済んだものは期間の後に消えます）

## 決めたこと

- **受け付けのメールに、お客さんの書いた文（名前・本文）の写しを載せない**: フォームには誰でも好きなアドレスを書けるので、写しを載せると、店のメールを使って他人へ好きな文（迷惑メール・偽の案内）を送れてしまう。載せるのは決まった文・受付番号・種類・付いた商品の名前（店のデータ）だけ。お客さんは自分の書いた文を手元に持っている
- **店への知らせにも本文を載せない**: メールは店の外の受信箱（転送・共有のアドレス）に残るため。「1 件あります」と管理画面のリンクだけで、読むのは管理画面（権限と記録のある場所）。店ごとに 1 時間 10 通まで（いたずらの連投で受信箱を埋めない。越えた分もホームの「やること」で気づける）
- **済んでから 1 年（設定で半年・3 年）で、行ごと消す**（名前・メール・本文・返信。毎日の `contact:prune`）: 個人情報は使う目的が済んだら長く持たない（個人情報保護法の「利用する必要がなくなったときは遅滞なく消去する」努力義務）。一方で、同じお客さんからの続きのお問い合わせ・返品や不具合の申し出は買ってから 1 年ほどの間に来ることが多いので、既定は 1 年。済んでいないお問い合わせは古くても消さない（返事をしないまま消さない。ホームの「やること」に出続ける）。使うのをやめた店でも、消す分が残っていれば消す
- **名前・メール・本文は「運用」の段階から**（ADR 0024 の「個人情報の表示」と同じ段階。閲覧の人には隠す）。見たことは中央の監査ログに残す（核の App の画面の個人情報の印。ADR 0051 の作って決めたこと）
- **ゲストのメールからお客さんの台帳をつながない**: 他人のアドレスを書けるため、つなぐと「その人からのお問い合わせ」に見えてしまう。お客さんの画面へのリンクは、ログインした会員が送った時だけ
- 注文を付けるのは、核が注文を見てよいと確かめたご注文の画面から渡す、署名と期限（24 時間）と店の ID つきの道筋だけ。署名の合わない道筋（書き換え・期限切れ・ほかの店）からは受け付けない（黙って注文を外さず、書いた文を残してふつうのフォームへ戻す）

## 守り

| こと | どうしているか |
|---|---|
| 名前・メール・本文・返信 | 店の鍵で暗号化した列だけ（ADR 0010）。メールは引くための索引（ブラインドインデックス `email_index`）も。記録（イベント）にはお問い合わせ・返信の ID と種類・状態だけ。キューの仕事にも ID だけ |
| 入力 | 名前は 1 行 50 文字、本文は 2,000 文字、メールは `email:rfc` と送れる形で 254 文字まで。制御文字・文字の向きを変える印・幅の無い空白・BOM は断る（本文の改行はよい。タブは空白に）。HTML として扱わず、ショップも管理画面もメールも文字として出す（メールは文だけのメール） |
| 回数の上限 | 接続元（IPv6 は /64）ごとに 1 時間 5 回、同じメールへ（接続元をまたいで）1 日 5 回、店全体で 1 日 300 件。越えたら受け付けず、書いた文を残して「しばらくしてから」。送る受付は店 × 接続元で 1 分に 10 回まで（`throttle:storefront-member`）。返信は 1 件に 20 通・1 時間に 10 通まで、同じ文を 10 分のうちに続けて送らない |
| ボットよけ | 見えない欄（`website`。hidden の囲みの中で人には見えない）と、書き始めの時刻（フォームを出した時刻と、店の ID と時刻への署名。APP_KEY から用途で分けた鍵の HMAC）。見えない欄を埋めた・印が無い・合わない・出してから 3 秒より前は、受け付けたのと同じ画面を返して何も残さず送らない。画像の文字を読ませる仕組み（CAPTCHA）は使わない（お客さんの手間を増やさない） |
| 商品と注文 | 商品はショップに出ているものだけ付ける。注文は署名つきの道筋だけ（上）。どちらもロックの中で店の DB にあるかを確かめ直す |
| 管理画面 | 一覧は種類・付いた商品と注文・状態・日時だけ。1 件の名前・メール・本文・返信は運用の段階から（閲覧には隠し、見たら監査ログ）。返信・状態の変更は運用から（核の経路）、消すのは直前の再確認の後 |
| 店の境界 | 表は店の DB。署名には店の ID が入る（ほかの店の同じ道筋では通らない）。ボットよけの印も店の ID で署名する |

## 作り

| ファイル | 役 |
|---|---|
| `database/migrations/…_create_contact_inquiries_table.php` | 店の DB の表 `contact_inquiries`（種類・商品・注文・会員・暗号化した名前とメールと本文・索引・状態と時刻）と `contact_replies`（暗号化した返信・送れた時刻）。種類と状態の言葉、済みと済んだ時刻のそろいは DB でも守る |
| `src/ContactInquiries.php` | 受け付け・返信・状態・消す・片付け（連鎖のロック → 行のロック → イベント。回数の上限もここ） |
| `src/ContactInput.php` | フォームの欄の確かめ |
| `src/BotGuard.php` | 見えない欄と書き始めの時刻 |
| `src/ContactLinks.php`・`src/ContactOrderLink.php`・`src/ContactPurchaseOption.php` | フォームの道筋（注文は署名つき）と、ご注文の画面・商品の画面の入口 |
| `src/Http/ContactController.php`・`resources/views/` | ショップのフォーム（`/p/contact`・`/p/contact/product/{商品}`・`/p/contact/order/{注文}`）と受け付けた画面 |
| `src/Jobs/SendContactMail.php`・`src/Mail/ContactMail.php`・`resources/views/mail/` | 受け付けの知らせ・返信・店への知らせのメール |
| `src/ContactAdminPage.php` | 管理画面の App の画面（一覧・1 件・状態・消す・返信の欄。個人情報の印と、欄の言葉「返信する」） |
| `src/Console/PruneContactCommand.php` | 毎日の `contact:prune`（済んでから期間のたったお問い合わせを消す） |

テストは `tests/Feature/Plugin/ContactAppTest.php`（送る・誤った入力・ボットよけ・回数の上限・商品と注文の付け方〔改ざん・期限・署名なし〕・会員・暗号の列・受け付けと店への知らせのメールの中身・管理画面の段階と監査・返信のメール・状態・消す・ほかの店・使わない店・片付け）。
