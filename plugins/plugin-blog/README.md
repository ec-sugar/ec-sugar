# お知らせ・ブログ（EC-SUGAR の App）

ショップに「お知らせ」のページ（`/news`）を作り、新商品・お休みの案内・読み物の記事を出す App です。記事は商品の説明と同じブロック（段落・見出し・箇条書き・写真・表・注意書き）で書き、下書き・公開・予約（日時を決めて出す）を選べます。
記事の一部や全部を「お買い上げいただいた方・ご購読中の方だけ」にもできます（下の「有料の記事」）。
トップなどのページに「新着のお知らせ」の区画を置けます。決めたことは [ADR 0072](../../docs/adr/0072-お知らせ・ブログはAppにし、検索に載せるページの口と記事のブロックは核の部品を使う.md)。

## 使い方

1. 管理画面の店のメニュー「App」から「お知らせ・ブログ」を開き、「使う」にします（運用の段階・直前の再確認）。
2. メニューの「App」の下に「お知らせ・ブログ」が出ます。右上の「記事を書く」から、タイトル・URL の末尾（`/news/〇〇` の〇〇。英小文字・数字・ハイフン）・種類・抜粋・一覧の写真・本文・予約の日時を入れて「足す」。書いた記事は下書きです（ショップには出ません）。
3. 一覧の記事を押すと 1 件の画面です。
   - 「直す」の欄で書き直して「保存する」（自動では保存しません）
   - 「プレビューの URL」を写してブラウザで開くと、下書きのままショップでの見え方を確かめられます（30 分だけ開けます）
   - 「公開する」で今すぐショップに出す。予約の日時を入れて保存してあれば「予約する」でその日時に出す
   - 「取り下げる」で下書きに戻す（ショップから消えます）。「消す」で消す（取り消せないので、パスキーでもう一度確認します）
4. ショップの `/news` に新しい順に 20 件ずつ並び、種類で絞れます。記事は `/news/{URL の名前}`。メニューに載せるときは、ページのリンクに `/news` を入れます。
5. ページの編集の画面の「区画を足す」に「新着のお知らせ」が出ます（出す数 3・5・10 件、種類の名前で絞れます。並びは日付とタイトルの一覧か、写真つきのカード）。

- 種類は最初「お知らせ」「ブログ」。記事の欄の「新しい種類」に名前を入れると足せます（10 個まで。種類の名前を変える・消す画面はまだありません）
- 本文・タイトル・抜粋は文字として出ます（HTML のタグは使えません）
- 検索の結果と共有の見え方（題・説明・写真・記事の構造化データ）は EC-SUGAR が作り、サイトマップと Atom（`/news/feed`）にも載ります。下書き・予約中の記事はどこにも出ません
- 1 つの店に記事は 1,000 本まで
- 使うのをやめると、管理画面にもショップにも出なくなります（記事は残ります）

## 有料の記事

記事の欄の 2 つで決めます。

- **読める条件（鍵）**: 1 行に 1 つ（例 `membership:standard`・`post:01j…`）。入れた鍵の**どれか 1 つ**を持つお客さんが読めます。空なら誰でも読めます。10 個まで
- **ここから有料（続きの本文）**: 「読める条件」を持つお客さんにだけ出す本文です

決まりはこうです。

- **権利の無い人には、有料のブロックを送りません**（画面で隠すのではなく、サーバーが組み立てません。HTML にも検索の説明にも入りません）
- 「読める条件」を入れて「ここから有料」を空にすると、**本文の全部が有料**になります（題・抜き書き・一覧の写真だけが出ます）
- 無料の分は誰にでも出します。一覧の札・新着のお知らせの区画・Atom に出るのは題と抜き書きだけで、サイトマップには**無料の分がある記事だけ**載ります
- どの鍵を持っているかに答えるのは**売る App**（買い切り・月額）です。入れていない・止めている・落ちている間は「誰も持っていない」として扱い、有料の分は誰にも出ません
- プレビューの URL では、書いた本人として全部を確かめられます
- 「読める条件」を空にするときは、「ここから有料」も空にします（誰も読めない記事を作らないため）

## 作り

| ファイル | 役 |
|---|---|
| `database/migrations/…_create_blog_tables.php` | 店の DB の表 `blog_categories`（種類）・`blog_posts`（記事）。形・長さ・状態の組み合わせ（公開の記事だけが公開の日時を持つ）・URL の名前の一意と予約語は DB でも守る |
| `database/migrations/…_add_blog_paywall_to_posts.php` | 有料の記事の列（`access_keys`・`paid_body`）。鍵の形と数・ブロックの合計・「有料の分があるなら読める条件がある」は DB でも守る |
| `src/BlogPaywall.php` | **どこで切るかを決めるただ 1 か所**（答えは `BlogReading`）。核の `ContentAccess` に聞き、無料の分と有料の分を分ける |
| `src/BlogPosts.php` | 書く・直す・公開・予約・取り下げ・消す・種類を足す。連鎖のロック → 行のロック → イベント（中身は ID と状態・日時・変えた欄の名前だけで、文は入れない） |
| `src/BlogAdminPage.php` | 管理画面の App の画面（一覧・1 件・操作）と、書く・直すの欄（核の `AdminPageHandler` と `AdminFormHandler`。写真・ブロック・日時は核の欄の型） |
| `src/BlogShopPages.php` | 検索に載せるページの口（核の `ShopPagesProvider`）: `/news` の経路とサイトマップの URL |
| `src/Http/BlogController.php` | `/news`・`/news/{slug}`・`/news/feed`（Atom）と、プレビュー（`/p/blog/preview/{ID}`） |
| `src/View/BlogReader.php` | ショップに出す記事を読む（いつも「公開で、公開の日時が今まで」の記事だけ） |
| `src/BlogSections.php` | 区画「新着のお知らせ」の係（核の `AppSectionHandler` と `AppSectionContent`） |
| `src/BlogPreviewLink.php` | プレビューの署名つきの URL（店の ID・記事の ID・期限の HMAC） |
| `resources/views/` | App の既定の画面（`news`・`post`・`paywall`。テーマに `news`・`news-post` があればそちら）と区画の Blade |

テストは `tests/Feature/Plugin/BlogAppTest.php`（使わない店では出ない・欄の確かめ・下書きと予約がどこにも出ない・予約の時刻の境界・取り下げ・プレビューの署名と期限とほかの店・閲覧の段階・店の境界・SEO の部品・ページ送りの境界・種類・区画・頭の予約語・サイトマップの絞り込み）と
`tests/Feature/Plugin/BlogPaywallTest.php`（有料の分が権利の無い人に出ない・無料の分は誰にでも出る・区切りの無い記事・ほかの店の会員・App を止めた店・出口ごと〔一覧・区画・Atom・サイトマップ・プレビュー〕・鍵の形と数）。
