# App「セット商品」（ec-sugar/plugin-bundle）

複数の品をまとめて 1 つの値段で売る公式の App。
「コーヒー 2 袋 ＋ カップ 1 つのギフトセット」のように、**セットそのものは在庫を持たず、売れるたびに構成の品の在庫から引く**。

- **決める所**: 管理画面の商品の画面の App の欄「セット商品」。「セットの中身（品番と 1 セットあたりの数）」に `COFFEE-200G*2, CUP-WHITE*1` のように書いて保存する（コンマ区切り、200 文字まで、構成の品は 20 つまで）。空にして保存すると、セットをやめる
- **品番**: 構成の品は**品番（SKU）**で書く。品番を付けていない品は、欄の案内に出る種類の ID（26 文字）でも書ける。品番は商品の画面（種類のある商品は種類ごと）で付ける
- **値段**: セットの値段は、セットの商品そのものの値段（`unit_amount`）。構成の品の値段を足し合わせたりはしない（値引きは店の人が値段で決める）
- **在庫**: 売れるたびに引くのは構成の品の在庫で、セットの商品の在庫は使わない。注文のときに**構成の品を全部まとめて押さえ、1 つでも足りなければ丸ごと断る**（部分的に押さえた状態を残さない）。取消で戻り、発送で出庫するのも構成の品（核の `LineStock` が 1 か所で行う）
- **作れるセットの数**: 構成の品それぞれの「（在庫 − 確保）÷ 1 セットあたりの数」の**いちばん小さい値**。0 なら、そのセットはショップの一覧・検索・商品の画面・サイトマップ・商品フィードに出さない（核の口 `ListingVisibilityProvider`。商品の画面は 404）
- **構成の品が売れなくなった時**: 構成の品を消した・下書きに戻した・終了にした・種類を止めた時も、そのセットは出さない（1 セットも作れないものとして扱う）
- **入れ子は作れない**: セットの中にセットは入れられない（核は構成を 1 段しか辿らないので、入れ子を許すと中のセットの在庫が引かれずに売れてしまう）。保存のときに断り、DB の引き金でも断る。自分自身を構成の品にすることもできない
- **管理画面の画面**: メニューの「App」の下の「セット商品」に、セットの商品が商品の名前の順に並ぶ（「構成の品の在庫切れ」で絞り込める）。1 件の画面では構成の品の表（品番・1 セットあたりの数・注文に使える在庫・この品の在庫で用意できるセット数）と、「セットをやめる」が出る。作れないセットはホームの「やること」にも出る
- **止めた店**: App を止めるとセットは効かなくなり、セットの商品は**自分の在庫で売れるふつうの商品**になる（構成の品は引かれない）。中身の行は残るので、使うに戻せば元に戻る。オーナーは App の画面の「この App のデータを消す」（か `php artisan plugin:purge <店> bundle`）で行を消せる（ADR 0092）

## 気をつけること（今の作りの前提）

- **セットの商品に在庫を入れる必要はない**: 売れる数も、どの拠点から出すかも、構成の品から核が数える（`Core\Inventory\Services\ComponentStock`）。セットそのものの在庫の行は作られず、触られない
- **セットと構成の品は同じ拠点に置く**: 数えるのは拠点ごと（「東京にコーヒーだけ・大阪にカップだけ」では 1 セットも作れない扱い）。揃っている拠点があればその拠点から出す
- **拠点が複数ある店**: 構成の品の在庫は、セットの行と同じ拠点のものから引く。拠点ごとに在庫を分けている店では、セットの商品と構成の品を同じ拠点に置く
- **出品者は同じ**: 構成の品は、セットの商品と同じ出品者の品だけ（違う出品者の品は、核が同じ注文に入れない）
- **構成の品を完全に消した時**: 商品を「消す」はゴミ箱（論理削除）なので、セットの中身は残り、セットはショップに出なくなる。DB から行ごと消した場合は中身の行も一緒に消え、その商品はセットでないふつうの商品に戻る（在庫はセットの商品のものを使う）

- **セットの中身は、いつ変えてもよい**: 入金待ち・発送待ちの注文は、ご注文の時の中身のまま取消・発送・返品ができる（核がご注文の時の中身を控えている）。変えた中身は、その後のご注文から効く。セットをやめても、App を止めても同じ
- **返品で在庫へ戻すと、構成の品へ戻る**（ご注文の時の中身で。セットそのものの在庫には入らない）
- **管理画面の在庫の欄と AI エージェントの在庫の答えでは、セットの商品は 0 に見える**: セットは自分の在庫を持たないため。売れる数は構成の品から数えていて、App の画面の「セット商品」の 1 件の画面と、商品の画面の App の欄の案内で確かめられる
- **セットの中身の欄は 200 文字まで**: 管理画面の App の欄の 1 行の文の上限。構成の品は 20 つまでだが、長い品番（や種類の ID）を並べると 20 つに届く前に欄がいっぱいになる（64 文字の品番なら 2〜3 つ、種類の ID なら 6 つまで）。品の多いセットは、構成の品に短い品番を付ける

## ほかの App との関係

- **抽選販売・予約販売など、売り方を押さえる App の対象になっている品**を含むセットは、押さえが外れるまで売り切れになる
- **「公開の予約と販売期間」「年齢確認」「会員だけ・ランクだけ」は、セットの商品そのものに付ける**: 構成の品に付けた分は、セットとして買う時には効かない（お酒を含むセットには、セットの商品に年齢確認を付ける）
- **予約販売の受付中の商品・在庫を使わない種類（ダウンロード・サービス・日時の予約など）の商品は、セットにできない**: 核はそういう商品を在庫を押さえずに注文にするので、セットにすると構成の品の在庫を引かずに売れてしまう。セットの中身を保存する時に断る（セットをやめる保存はいつでもできる）
- **セットにした商品を、後から送らない種類・予約販売にしないでください**: 逆の順（先にセットにして、後から予約販売の対象にする・商品の種類を変える）は、この App からは止められない。そうすると構成の品の在庫が引かれないまま売れる

- **公開の予約と販売期間**（`plugin-sale-period`）とは別の口で同じ見せ方の仕組みを使う。どちらかが「出さない」と言えば出ない
- **再入荷のお知らせ**（`plugin-restock`）の「入荷した」の見方は在庫で決まるので、セットの商品（在庫が動かない）では知らせを送らない。構成の品の再入荷は、その品の商品で知らせる
- **商品の CSV**（`plugin-product-csv`）はセットの中身を書き出さない（中身は App の表にある）

## 書き方

状態を変えるのは `BundleComponents` だけ（連鎖のロック → 行のロック → 同じトランザクションのイベント `bundle.set`・`bundle.cleared`）。
記録に入れるのは商品・種類の ID と数だけで、店の人の書いた文・個人情報は入れない。
読み出しは `BundleStock`（在庫の構成・作れるセットの数・構成の品の様子）と `BundleParts`（欄の書き方）。
在庫の構成を答える口（`BundleStockComponents`）は**落ちたら取引が止まる**ので、表を素直に読むだけにしてある。
