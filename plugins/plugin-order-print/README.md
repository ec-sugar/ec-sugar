# 納品書・領収書（EC-SUGAR の App）

注文の納品書と領収書を、印刷用のページで出す App です。ブラウザの「印刷」で A4 の紙に印刷するか、印刷の画面で送信先を「PDF に保存」にすると PDF になります（PDF を作る部品は使いません。日本語の字体を含む部品は重いため）。
核の「注文の書類」の口（ADR 0051 の作って決めたこと）と、プラグインの表・ショップの経路・App の設定だけで作っています。

## 使い方

1. 管理画面の店のメニュー「App」から「納品書・領収書」を開き、「使う」にします（運用の段階・直前の再確認）。
2. 同じ画面の設定で、必要なら次を入れます。
   - インボイスの登録番号（T と 13 桁の数字。形を確かめます）。入れると書類に「登録番号 T…」が出ます
   - 但し書きの既定（40 文字まで。空なら「お品代として」）
   - ロゴを出す（切り替え）とロゴの写真（ショップの写真から選ぶか、新しく上げる）
3. 注文の画面の右上に「納品書」「領収書」が出ます。押すと新しいタブで印刷用のページが開きます。
   - 納品書: 注文番号・ご注文日・発行日・届け先・品名・数・単価・小計・送料など・合計（税込み）・税率ごとの内訳・発行者。App「ラッピング・のし」で選んだものがあれば、いちばん下に「備考: ラッピング: リボン／のし: 御祝・外のし・名入れ ◯◯」（核の `OrderCharges::notes`。名入れは店の人の画面のこの書類にだけ。ADR 0078）
   - 領収書: 宛名（最初は注文した人の名前）と但し書きを入れて「領収書を発行する」。金額（税込み）・但し書き・発行日・発行者・登録番号・税率ごとの内訳が出ます。2 回目からは題の横に「再発行」の印と、番号に回数（No. 注文番号-2）が付きます
4. 注文の一覧で注文を選ぶと「納品書をまとめて開く」が出ます。選んだ注文の納品書を 1 つのページに続けて出します（印刷では 1 件ごとに改ページ。1 回に 50 件まで）。発送を待つ注文は、一覧を「入金済み」で絞ると選びやすくなります。
5. お客さんは、ご注文の状況のページ（確認のメールのリンク・ご注文番号とメールでの照会）とマイページの注文の履歴の「領収書」から、払い済みの注文の領収書を出せます。宛名はお客さんが入れ（最初は空。空のままなら手書きの欄）、但し書きは店の既定のままです。

- 発行者の名前・所在地・電話は、店の設定の「特定商取引法に基づく表記」の「販売業者」「所在地」「電話番号」から出します（無ければ店の名前だけ）
- 領収書を出せるのは、払い済みの注文（入金済み・発送済み・完了）だけです。入金待ち・取消・返金・0 円の注文には出せません（管理画面でもお客さんでも）
- 納品書は、払う前の注文でも出せます（発送の準備のため）
- 年齢の確かめをした注文（App「年齢確認」。ADR 0077）は、納品書の合計の下に「備考: 年齢確認済み（20 歳以上）」が出ます（運送会社の受け取りの時の確かめに。App をやめた後の注文の記録からも出ます）
- 宛名・但し書きは 1 行・40 文字まで。品名・宛名は文字として出します（HTML として扱いません）

## インボイス制度の表記について

- 書類に出すのは、発行者の名前と登録番号（入れたとき）・取引の日（ご注文日・お支払い日）・品名と金額・**税率ごとに区分した対価の額（税込み）と消費税額**・受け取る人の名前（領収書の宛名）です
- 税率ごとの対価と消費税額は、注文の明細に残っている税率から、核と同じ決まり（税率ごとに合計してから 1 回だけ丸める。`App\Core\Transaction\Totals`）で出します。今の注文はどれも明細に税率を持つので、「税込み」の合計と並べて税率ごとの内訳を必ず出せます
- 軽減税率（8%）の明細には「※」を付け、「※ は軽減税率（8%）の対象です」と書き添えます（今のショップは商品ごとの税率を持たず、すべて 10% です。税率を分けられるようになると、そのまま出ます）
- 登録番号は形（T＋13 桁）だけを確かめます。国税庁の公表サイトで登録されているかは確かめません。正しい番号を入れるのは店の責任です
- 部分的な返金を記録する仕組みはまだ無いので、領収書の金額はいつも注文の合計です

## 気をつけること

- 5 万円以上の領収書には、紙で渡す場合に収入印紙が要ることがあります（クレジットカードで払われた分は要りません）。この App は印紙の要否を判断しません
- お客さんの領収書のリンクは、ご注文の画面を開くたびに作り直す 24 時間の署名つきのリンクです。店の名前も署名に入るので、ほかの店では使えません
- 領収書を出した回数（と最初と最後の日時）だけを App の表に残します。宛名や但し書きは残しません。記録（イベント）には回数と、店の人かお客さんか（`operator:<ID>` か `storefront`）だけが残ります

## 作り

| ファイル | 役 |
|---|---|
| `database/migrations/…_create_order_print_receipts_table.php` | 店の DB の表 `order_print_receipts`（注文ごとに 1 行。出した回数と最初・最後の日時。回数は 1 以上、注文 1 つに 1 行を DB でも守る） |
| `src/OrderPrintDocuments.php` | 核の `OrderDocumentHandler`。書類の種類（納品書はまとめて出せる・領収書）と管理画面の印刷用のページ |
| `src/ReceiptOrderLink.php` | 核のご注文の画面のリンクの口（`OrderLinkProvider`）。払い済みの注文の「領収書」（24 時間の署名つき・新しいタブ） |
| `src/ReceiptIssues.php` | 領収書を出す。連鎖のロック → 注文と回数の行のロック → 払い済みかを確かめ直す → 回数を進める → `order_print.receipt_issued` |
| `src/ReceiptPage.php` | 領収書のページ（店の人とお客さんで同じ形。GET は欄、POST で数えて描く） |
| `src/OrderSheet.php`・`src/Issuer.php` | 注文を書類の形にする（金額は「¥5,400」の形・税率ごとの内訳・届け先）、発行者（特商法の表記と App の設定） |
| `src/Http/ReceiptController.php` | お客さんの領収書（`/p/order-print/receipt/{注文}`。署名・店・注文を確かめる） |
| `resources/views/` | 納品書・領収書・断りのページ（核の印刷の土台 `print.layout` の上） |

テストは `tests/Feature/Plugin/OrderPrintAppTest.php`（使わない店では出ない・まとめた納品書・再発行の印・払っていない注文・権限と店の境界・署名の違うリンク・期限切れ・エスケープ・印刷の CSP・ロゴ・マイページ）。
