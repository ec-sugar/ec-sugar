# App「購入の制限」（ec-sugar/plugin-purchase-limits）

1 回のご注文の決まりを 2 つ決める公式の App。
人気の商品を 1 人がまとめて買い占めないようにしたり、少額のご注文を受けないようにしたりできる。

- **1 回のご注文の上限**（商品ごと）: 管理画面の商品の画面の App の欄「購入の制限」に、半角の数字で 1〜999 を入れる。空にして保存すると、その商品の上限をやめる
- **最低購入金額**（店に 1 つ）: メニューの「App」でこの App の設定に、円の整数で入れる（100,000,000 まで）。0 か空なら決めない
- **ショップでの出方**: 上限を超えた行にはカートで「この商品は 1 回のご注文で 2 点までです。数を減らしてください。」と出て、数を選ぶ所も上限までになる。下限に届かないカートには「ご注文は商品の合計 ¥3,000 から承ります（あと ¥1,000）。」と出て、注文の入力へ進めない。どちらも注文の確定の時にもう一度確かめるので、画面を通さない要求でも通らない
- **核のデータは変えない**: 上限は App の表 `purchase_limits_listings`（1 商品に 1 行）、下限は App の設定に持つ。商品そのものは変わらない
- **止めた店**: App を止めると決まりは効かなくなり、いくつでも・いくらからでも買える（行と設定は残るので、使うに戻せば元の決まりに戻る）。オーナーは App の「この App のデータを消す」（か `php artisan plugin:purge <店> purchase-limits`）で商品ごとの上限の行を消せる（ADR 0092）

## 決まり

- **上限は「1 回のご注文ごと」で、「1 人 1 点」ではない**。同じお客さんでも、ご注文を分ければまた買える。お客さんを見分けて数えることはしない（会員でないお客さんも買えるため）
- **種類が違っても、同じ商品は合わせて数える**。上限 2 点の商品を「赤 1 点・青 2 点」で入れると、合わせて 3 点なので止まる
- **下限は、今買える商品の合計と比べる**。値引き（クーポン・自動の割引）・ポイント・ギフトカード・送料・手数料の前の額。売り切れなどで買えない行は合計に入らない。ちょうどの額は通る
- **下限はカートを通るご注文だけ**。カートを通らない 1 品のご注文（チケット・定期便の申し込みなど）には掛からない。上限はそちらにも掛かる
- **仕組みが作るご注文には掛からない**。定期便の 2 回目からのように、申し込みの時の約束で自動で作られるご注文は、上限でも下限でも止めない
- **決まりを読めない時は、ご注文を受けない**。上限や下限が分からないまま売ると決まりが破られるため、直るまでカートに「ただいまご注文を受けられません。」と出る（この App を使っている店だけ）

## ほかの App との関係

- **公開の予約と販売期間**（`plugin-sale-period`）・**予約販売**（`plugin-preorder`）と一緒に使える。売り方を押さえた商品は、上限の中でも買えない

## 書き方

核の口 `App\Core\Plugin\Contracts\PurchaseLimitProvider` に答えるのは `PurchaseLimitsProvider`（上限は頼まれた商品だけを 1 回で読み、下限は設定から読む。読めない時は例外のまま返し、核がご注文を受けない側に倒す）。
上限を変えるのは `ListingLimits` だけ（連鎖のロック → 行のロック → 同じトランザクションのイベント `purchase_limits.set`・`purchase_limits.cleared`）。
記録に入れるのは商品の ID と数だけで、店の人の書いた文・個人情報は入れない。上限の範囲（1〜999）は DB の CHECK でも守る。

## 知っておくこと

- 最低購入金額は、商品の種類を問わず「今買える商品の合計」で比べます。**サービス（役務）はほかの商品と同じ注文にできず、無料の品は合計が 0 円**なので、下限のあるお店ではそれだけの注文は届きません。サービスや無料の品だけを売ることがあるお店は、下限を使わないか、額をその品に合わせてください
- カートに入れる時は上限を見ません。カートの画面で「◯点までです」と出て、数を減らすまで注文に進めません
