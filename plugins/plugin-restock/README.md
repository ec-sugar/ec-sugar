# 再入荷のお知らせ（EC-SUGAR の App）

売り切れの商品（色・サイズなどの種類ごと）に、お客さんがメールのアドレスを登録できる App です。入荷したら、登録した人へ 1 回だけメールでお知らせします。
核の口（プラグインの表・商品の画面の買い方の口・App の画面・核の記録の知らせ）だけで作っています（ADR 0025・0050・0051）。

## 使い方

1. 管理画面の店のメニュー「App」から「再入荷のお知らせ」を開き、「使う」にします（運用の段階・直前の再確認）。設定の「確認メールに添える一言」は空でもかまいません。
2. ショップの商品の画面で、売り切れの種類があると「入荷のお知らせを受け取る」が出ます（商品の全部が売り切れなら「売り切れ」の下、一部の種類だけなら「カートに入れる」の下）。
3. お客さんは売り切れの種類を選び、メールアドレスを入れて送ります（JavaScript を使わないフォーム）。
   - **ゲスト**: 確認メールが届き、リンクの画面で「登録を確定する」を押すと登録が完了します（24 時間以内。過ぎると消えます）。本人が受け取れるメールアドレスだけが有効になります
   - **会員**（ログインしている人）: アドレスの欄は出ず、ログインのメールですぐ登録します。登録の知らせと取り消しのリンクをメールで送ります
4. 入荷すると（管理画面の入庫・在庫の調整で増やした時、注文の取消・返金で在庫が戻った時）、入荷を待っている人へ古い順に 1 通ずつ知らせます。メールには商品の画面のリンクを載せます。知らせた登録は終わりです（もう一度知らせてほしい人は、また登録します）。
5. 管理画面のメニュー「App」の下の「再入荷のお知らせ」で、種類ごとの「待っている人」「確認待ち」「知らせた数」を見られます。**誰が登録したか（メールアドレス）は出しません**。

- 取り消しは、確かめのメール（会員は登録の知らせのメール）のリンクから。押すとその登録だけが終わり、ほかの登録には触れません
- 一度に知らせる数は絞りません（待っている人の全部へ）。在庫の数で絞ると、残りの人は次に売り切れから戻るまで知らせが来ないためです。メールには「数に限りがあり、ご注文の時に売り切れていることがあります（お取り置きはしていません）」と書きます
- 使うのをやめると、ショップにも管理画面にも出ず、知らせも送りません（登録は残り、また使うと、入荷していれば次の定期チェックで知らせます）
- 退会した会員が登録した分は、退会と同時に取り消します

## これは宣伝のメールではありません

この App が送るのは、**お客さんが自分で「入荷したら知らせて」と頼んだ商品についての、1 回だけの知らせ**です（と、その登録を確かめるメール・登録の知らせ）。
店の新商品やセールの案内には使えず、登録したアドレスを店の人が見ることも、ほかのメールに使うこともできません（管理画面に出るのは数だけ）。
知らせを送ったら、その登録からアドレスを消します。どのメールにも「頼まれた方にだけお送りしている」ことを書き、確かめと登録の知らせには取り消しのリンクを載せます。
ゲストの登録は、確かめのメールのリンクを本人が押すまで有効にしません（他人のアドレスを入れても、知らせは届きません）。

## 守り

| こと | どうしているか |
|---|---|
| メールのアドレス | 店の鍵で暗号化した列（`email`）と、探すためのブラインドインデックス（`email_index`）だけ（ADR 0010。お客さんの台帳と同じ形）。知らせた・取り消した登録からは両方を消す。記録（イベント）にもキューの仕事にも載せない（仕事に載せるのは登録の ID だけ） |
| 確かめ・取り消しのリンク | 32 バイトの乱数の合い言葉（43 文字）。表にはハッシュだけを置き、メールに載せるまでの間だけ暗号化して置く（送ったら消す）。リンクの画面は開いただけでは変えず、ボタン（POST・CSRF）で変える（メールのリンクを先に開く仕組みで勝手に確かめない）。画面は `Referrer-Policy: no-referrer`・`noindex`・`no-store`。合い言葉を知っても、その 1 つの登録しか触れない。ほかの店では使えない |
| 回数の上限 | メール × 接続元で 1 時間に 5 回、接続元だけで 1 時間に 20 回、同じメールへ（接続元をまたいで）1 日に 10 回。ゲストは超えても同じ答え（送らないだけ。登録があるかを、ほかの人が確かめられない）。送る受付は店 × 接続元で 1 分に 10 回まで（`throttle:storefront-member`） |
| 数の上限 | 1 人が 1 つの種類に持てる進行中の登録は 1 つ（DB の部分の一意の索引）。1 つのメールの進行中の登録は 30 まで、店全体で 20,000 まで。確かめの期限の切れた登録は 1 時間ごとに消す |
| メールの形 | 注文の入力と同じ `email:rfc` に加え、送れる形（`FILTER_VALIDATE_EMAIL`）・254 文字まで |
| 2 回送らない | 「待っている → 知らせた」は 1 文の条件つきの更新（`FOR UPDATE SKIP LOCKED`）。同じ時に 2 つの処理が動いても、1 つの登録を取れるのはどちらか 1 つだけ |
| 店の境界 | 表は店の DB。登録できるのは、その店のショップに出ている商品の、売り切れの種類だけ |

## 作り

| ファイル | 役 |
|---|---|
| `database/migrations/…_create_restock_requests_table.php` | 店の DB の表 `restock_requests`（商品・種類・会員・暗号化したメールと索引・合い言葉のハッシュ・状態と時刻）。状態・進行中の登録のメール・1 人 1 種類に 1 つは DB でも守る |
| `src/RestockRequests.php` | 登録・確かめ・取り消し・退会・期限切れの片付け（回数と数の上限もここ） |
| `src/RestockNotifier.php` | 入荷したら、待っている登録を「知らせた」にしてメールの仕事を積む。定期の見直し（`sweep`） |
| `src/RestockTargets.php` | 売り切れの種類と、入荷したかの見方（ショップでカートに入れられるかと同じ決まり） |
| `src/Jobs/NotifyRestock.php`・`src/Jobs/SendRestockMail.php` | キューの仕事（種類の ID・登録の ID だけを載せる） |
| `src/RestockPurchaseOption.php` | 商品の画面の「入荷のお知らせを受け取る」（買い方の口。売り切れの時にも出す印つき） |
| `src/Http/RestockController.php`・`resources/views/` | ショップの画面（`/p/restock/{商品}`・`/p/restock/confirm/{合い言葉}`・`/p/restock/cancel/{合い言葉}`）とメールの文 |
| `src/RestockAdminPage.php` | 管理画面の App の画面（種類ごとの数だけ。操作は無い） |
| `src/Console/RunRestockCommand.php` | 1 時間ごとの `restock:run`（取りこぼした入荷の知らせと、期限切れの片付け） |

入荷は核の記録を名前のある受け手（`EventReceivers` の `restock.replenished`。落ちたら届け直す・App を止めている間の記録は届けない。ADR 0089）で受けて知ります: `inventory.received`・`inventory.adjusted`（増やす向き）・`transaction.phase_changed`（取消・返金）。記録の残らない在庫の変わり方（見積もりの受け入れで確保を解いた時など）と、商品を公開し直した時の分は、1 時間ごとの `restock:run` が拾います。

テストは `tests/Feature/Plugin/RestockAppTest.php`（商品の画面での出方・確かめ → 入荷 → 1 回だけ・確かめていない登録には送らない・取り消し・二重の登録・種類・会員と退会・回数の上限・ほかの店・暗号の列・同じ時の 2 つの処理・定期チェック・管理画面は数だけ）。
