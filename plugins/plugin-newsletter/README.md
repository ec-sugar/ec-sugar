# メルマガ・一斉メール（EC-SUGAR の App）

お知らせのメールに登録したお客さんへ、店からのお知らせ（新商品・セールなど）をメールで一斉に送る App です。
核の口（プラグインの表・ショップの画面・マイページの入口・App の画面と足す・直すの欄・注文の入力の「お知らせのメールを受け取る」）で作っています（ADR 0025・0051）。

## 使い方

1. 設定の「特商法の表記」に、**販売業者・所在地・電話番号かメールアドレス**を書きます（配信のメールに送り主として載せます。そろっていないと配信も予約もできません）。
2. 管理画面の店のメニュー「App」から「メルマガ・一斉メール」を開き、「使う」にします。設定は「1 分に送る数」（既定は 10 通）と「登録ページに添える一言」。
3. お客さんが登録できる所は 3 つです。どれも**本人が選んだ時だけ**で、最初から選んだ状態にはしません。
   - ショップの登録ページ `/p/newsletter`（メニューやページにリンクを置いてください）。メールアドレスを入れて登録すると、**登録の確認メール**が届き、リンクの画面で「配信の登録を確定する」を押すと届くようになります（24 時間以内。ダブルオプトイン）
   - 注文の入力の「ショップからのお知らせ（新商品・セールなど）をメールで受け取る」（いつも選んでいない状態から。選んだ人には、注文の確定の後に上と同じ登録の確認メール）
   - 会員のマイページの「お知らせのメール」（ログインで本人のものと確かめたメールアドレスなので、確認メールは送らず、すぐ届きます。停止も同じ画面）。注文の入力で選んだ会員も、注文のメールが会員のメールと同じならすぐ届きます
4. 管理画面の「App」の下の「メルマガ・一斉メール」で「配信を書く」を押し、件名と本文（テキストだけ。HTML は使えません）を書きます。
5. 1 件の画面で「自分あてにテスト送信」（ログインしているあなたのメールアドレスへ 1 通。件名に【テスト】）で見え方を確かめます。
6. 「今すぐ配信する」か、予約の日時を入れてから「予約する」。どちらも取り消せないので、パスキーでの直前の再確認の後に始まります。
7. 1 分ごとの `newsletter:run` が、設定の数ずつキューに積んで送ります。1 件の画面で、送った数・送っている数・失敗・送らなかった数・このメールから配信を止めた人の数を見られます。配信の途中で「配信を止める」と、まだ送っていない人へは送りません。

- 管理画面に出るのは**数だけ**です。受け取る人のメールのアドレスは画面にも応答にも出しません（書き出しもありません）
- 届けるのは、配信を始めた時までに登録を確定した人だけです（配信の途中で確定した人には、その配信は送りません）
- 使うのをやめると、ショップの画面・注文の入力の切り替え・管理画面が消え、予約も配信も進みません（購読は残り、また使うと続きから）。停止のリンクも開けなくなりますが、もうメールは送りません
- 退会した会員の購読は止めます

## 特定電子メール法に合わせたこと

「特定電子メールの送信の適正化等に関する法律」（[e-Gov 法令検索](https://laws.e-gov.go.jp/law/414AC0000000026)）は、広告や宣伝のメールについて次を求めます（総務省の[迷惑メール対策](https://www.soumu.go.jp/main_sosiki/joho_tsusin/d_syohi/m_mail.html)と、迷惑メール相談センターの[資料](https://www.dekyo.or.jp/soudan/)が詳しい）。

| 法が求めること | この App のしかた |
|---|---|
| 送ってよいのは、あらかじめ同意した人だけ（第 3 条 1 項。オプトイン） | 受け取りは本人が選んだ時だけ。注文の入力の切り替えも、いつも選んでいない状態から出す（核の部品が `checked` を付けない。テストが見張る）。ゲストは確かめのメールのリンクを押してから届ける（他人のアドレスを入れても届かない） |
| 同意を示す記録を残す（第 3 条 2 項） | 購読の行が記録: 同意した日時（`consented_at`）・経路（`source`: form・checkout・account）・確かめた日時（`confirmed_at`）・止めた日時と経路（`unsubscribed_at`・`unsubscribed_via`）。止めた人の記録は、施行規則の「送らないこととなった日から 1 か月」に合わせて、止めてから 31 日の後にメールを消す（`NewsletterSubscribers::RETAIN_DAYS`）。措置命令を受けた時に 1 年残す決まりは、この App は自動では扱わない（その時は運営が控えを取る） |
| 受け取らないと知らせた人には送らない（第 3 条 3 項。オプトアウト） | どのメールにも停止のリンク。押すとすぐ止まり、それ以降の配信は送らない（積んだ後でも送る直前に確かめる）。メールのソフトのワンクリックの停止（下）も |
| 送り主の名前・住所・問い合わせ先・止められることと止める先を表示する（第 4 条） | 本文の終わりに自動で付ける: 受け取ると選んだ人へ送っていること・配信の停止のリンクと止め方・送り主（特商法の表記の「販売業者」）・住所（「所在地」）・問い合わせ先（「電話番号」「メールアドレス」「お問い合わせ」など）。どれかが足りない・入れたときの見本のままなら、配信も予約もできず、予約の日時に足りなければ下書きに戻す |

確かめのメールは宣伝ではありません（受け取りを確かめるためだけ）。

## ワンクリックの配信停止（RFC 8058）

配信のメールには `List-Unsubscribe: <https://…/p/newsletter/unsubscribe/{合い言葉}>` と `List-Unsubscribe-Post: List-Unsubscribe=One-Click` のヘッダーを付けます（[RFC 8058](https://www.rfc-editor.org/rfc/rfc8058)。Gmail などの[送信者のガイドライン](https://support.google.com/a/answer/81126)が求める形）。
メールのソフトが同じ URL へ `List-Unsubscribe=One-Click` を POST すると、その人の購読が止まります（CSRF の合い言葉を持たない送信なので、この経路だけ CSRF の確かめを外しています）。
本文のリンクを開いた画面は、開くだけでは止めず「配信を止める」のボタンで止めます（メールのリンクを先に開く仕組みで勝手に止めない）。ショップが準備中に戻っても、停止のリンクは開けます（核の関所の外）。
ヘッダーが働くには、送り口が DKIM の署名でこのヘッダーも覆う必要があります（メールの送り口の設定。docs/install.md）。

## 守り

| こと | どうしているか |
|---|---|
| メールのアドレス | 店の鍵で暗号化した列（`email`）と、探すためのブラインドインデックス（`email_index`）だけ（ADR 0010。お客さんの台帳と同じ形）。記録（イベント）にもキューの仕事にも載せない（仕事に載せるのは購読・送った記録の ID だけ）。管理画面には数だけ |
| リンクの合い言葉 | 確かめ・停止とも 32 バイトの乱数（43 文字）。表にはハッシュだけ。確かめの合い言葉はメールに載せるまでの間だけ暗号化して置き、停止の合い言葉は送る時に作ってハッシュだけを置く（1 通ごと）。合い言葉を知っても、その 1 人の購読しか触れない。ほかの店では使えない。リンクの画面は `Referrer-Policy: no-referrer`・`noindex`・`no-store` |
| 回数の上限 | 受付: メール × 接続元で 1 時間に 5 回、接続元だけで 1 時間に 20 回、同じメールへ 1 日に 10 回（注文の入力からはメールごとだけ）。ゲストは超えても同じ答え（購読しているかを、ほかの人が確かめられない）。送る受付は店 × 接続元で 1 分に 10 回（`throttle:storefront-member`）。停止の POST には接続元の上限を掛けない（メールのソフトの送り元はまとまった住所から来るため。止める操作は断らない） |
| 数の上限 | 購読（確かめ待ちと届ける人）は店で 50,000 まで。配信は店に 500 件まで。配信を始める（予約を含む）のは店で 24 時間に 5 回まで。送るのは設定の「1 分に送る数」（5〜120 通）まで、まだ終わっていない仕事の数も引いて数える |
| 2 通送らない | 送った記録は「配信 × 購読者」で一意。送る仕事は「積んだ → 送っている」を 1 文の条件つきの更新で取り、試し直しはしない（送り口が断ったら失敗にする）。積んで 1 時間を過ぎても終わらない仕事は失敗にする（送り直さない） |
| 配信の中身 | 文だけ（`text/plain`）。HTML として読まれないので、`<` や `&` は文字のまま届く。題と店の名前の改行は取り除く（ヘッダーの差し込みを止める）。管理画面では核の部品が文字として描く |
| 権限 | 見るのは閲覧、書く・直す・試す・予約をやめるは運用、配信・予約・止める・消すは運用でパスキーの直前の再確認の後（ADR 0051）。試しのメールの宛先は、操作したログイン中の店の人のメールだけ |
| 店の境界 | 表は店の DB。管理画面は `EnterTenant` の下だけ。停止・確かめの合い言葉はその店のショップの経路でだけ引ける |

## 扱っていないこと（後で）

- **届かないアドレス（返ってきたメール）**: 送り口から返ってきたメール（バウンス）や苦情（迷惑メールの報告）を受け取って止める仕組みはありません。届かないアドレスへ送り続けると送り口の評判が下がるので、次の区切りで送り口の知らせ（Webhook など）を受けて自動で止める形を考えます（管理画面にアドレスを出さないので、店の人が手で止める形にはしない）。それまでは、送り口の管理画面で返ってきた数を見て、多ければ配信を控えます
- 書き出し（CSV）・HTML のメール・お客さんごとの差し込み（お名前など）・グループ分け・開いた数の計測
- 会員がメールのアドレスを変えた時: 前のアドレスの購読はそのまま残ります（新しいアドレスで届けるには、マイページでもう一度選ぶ）。マイページで止めると、前のアドレスの購読も止まります
