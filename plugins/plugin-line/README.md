# LINE 連携（EC-SUGAR の App）

お客さんが LINE のアカウントでショップにログイン・会員登録でき、LINE をつないで店の LINE 公式アカウントと友だちの会員には、注文の受付と発送のお知らせを LINE でも送る App です（ADR 0070）。メールは今までどおり送ります。LINE への知らせに、住所・名前・金額の明細は載せません。

## LINE の管理画面での準備（お店の人）

1. LINE Developers コンソールで、**同じプロバイダー**の中に 2 つのチャネルを作ります（プロバイダーが違うと、同じ人でも LINE の利用者の ID が違い、知らせが届きません）。
   - **LINE ログイン**のチャネル（アプリの種類は「ウェブアプリ」）
   - **Messaging API** のチャネル（お店の LINE 公式アカウント）
2. LINE ログインのチャネルの「チャネル基本設定」の「リンクされた LINE 公式アカウント」に、お店の公式アカウントを選びます（ログインの時の友だち追加に要ります）。
3. EC-SUGAR の管理画面で「App」から「LINE 連携」を「使う」にし、App の画面の「設定と利用状況」を開いて、2 つの URL を写します。
   - **LINE ログインのコールバック URL**（`https://<ショップのドメイン>/p/line/callback`）→ LINE ログインのチャネルの「LINE ログイン設定」のコールバック URL へ
   - **Messaging API の Webhook URL**（`https://<ショップのドメイン>/p/line/webhook`）→ Messaging API のチャネルの「Messaging API 設定」の Webhook URL へ。「Webhook の利用」を入にし、「検証」を押す
4. App の設定に 4 つの値を入れて保存します（設定を変えるのは運用の段階の人で、保存の前にパスキーでもう一度確かめます）。
   - LINE ログインのチャネル ID（10 桁）・チャネルシークレット
   - Messaging API のチャネルアクセストークン（長期）・チャネルシークレット
5. 管理画面の「設定 › プライバシーポリシー」（ショップの `/privacy`。ADR 0094）に、LINE での通知（LINE ヤフーへ送る情報: LINE の利用者の識別子・お店の名前・注文番号・マイページの URL）を書き足します。外部送信に関する公表のページ（`/legal/external`）には、App を使っている間 LINE が自動で載ります。
6. LINE 公式アカウントを**認証済みアカウント**にしておくと、お客さんに偽のアカウントと見分けてもらいやすくなります。

- 入れた秘密（シークレット・アクセストークン）は店の鍵で暗号にして置き、画面には「入っています」とだけ出します。記録にも値は残しません
- **鍵が漏れたかもしれない時**: LINE Developers コンソールでチャネルシークレットを「再発行」し、チャネルアクセストークンも発行し直して、App の設定に入れ直します（前の値はその時点で使えなくなります）
- LINE 公式アカウントの料金のプランには、月に送れる数の上限があります。超えると LINE が断り、App の画面に「送れなかった」と出ます

## お客さんから見た流れ

- ショップのログインの画面に「LINE でログイン」が出ます（LINE ログインの ID とシークレットが入っている時だけ）
- **初めての LINE**: LINE で確かめた後、メールアドレスを入れてもらい、6 桁のコード（ふつうのログインと同じ）で確かめてから、そのメールの会員に LINE をつなぎます（会員でなければ会員になります）。**LINE から来た情報だけで、今の会員に自動でつなぐことはしません**
- **2 回目から**: 「LINE でログイン」だけで入れます
- マイページの「LINE 連携」で、LINE をつなぐ・外す（どちらも本人の確認〔メールのコードかパスキー〕の後）。退会すると、LINE のつなぎも消えます
- LINE で入っても、メールの変更・パスキー・退会・LINE を外す・定期便の届け先の変更と数を増やす変更の前には、メールのコードかパスキーでもう一度確かめます
- 初めて LINE をつなぐ時のコードのメールは「LINE をつなぐためのコード」で、「心当たりがない場合は、このコードをだれにも伝えないでください」と添えます。確かめ待ちは 10 分で、違うコードを入れると最初から
- LINE をつないだ・外した・届け先を足した・直した時は、会員のメールへお知らせが届きます（何をしたかと日時だけ）。マイページの上に「LINE をつないでいます」、メールアドレスを変えた時の前のアドレスへの知らせにも LINE のつなぎを載せます

## 知らせ

| 知らせ | いつ | 中身 |
|---|---|---|
| 注文を受けた | お支払いが確かめられた時（0 円の注文は受け付けた時） | 店の名前・注文番号・マイページの URL |
| 発送した | 発送を登録した時 | 同じ ＋ 運送会社と追跡番号（あれば） |

- 送るのは、LINE をつなぎ、お店の公式アカウントと友だちの会員だけ（ブロックされたら送りません。友だちに戻ると、また送ります）
- 同じ知らせは 1 回だけ。送れなかった時は記録して終わり、送り直しません。注文や発送の操作は止まりません
- 店ごとに 1 分 60 通・1 人に 1 時間 10 通まで（超えた分は送らずに記録します）

## App の画面

- 「設定と利用状況」: LINE の管理画面に写す 2 つの URL（写すボタンつき）、設定がそろっているか、LINE をつないだ会員の数・そのうち友だちの数・この 7 日に送った数と送れなかった数（誰がつないだかは出しません）
- 「送った通知」「送信できなかった」: 通知の種類・状態・日時と、注文へのリンク。宛先の LINE も本文も持っていません
- 送れなかった知らせがこの 24 時間にあると、ホームの「やること」に出ます

## 作りの要点（開発者向け）

- 認可コードフロー ＋ PKCE（S256）＋ state ＋ nonce。ID トークンは HS256 だけを受け、署名・iss・aud・exp・iat・nonce・sub を確かめる（`IdToken`）
- 会員の印は核の口 `App\Storefront\Members\MemberSignIn::forApp` だけが出す（App は台帳の ID を渡すだけ）
- 表: `line_links`（会員と LINE のつなぎ。LINE の ID は店の鍵で暗号化、引くのは HMAC）・`line_messages`（送った記録。宛先と本文は持たない）
- 核の口・決めたことは ADR 0070、脅威は docs/security/threat-model.md の「App「LINE 連携」」の行
